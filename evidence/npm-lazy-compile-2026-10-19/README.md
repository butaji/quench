# Compile on first call: npm peak RSS, Test262, replay check and cost (2026-10-19)

This change implements TOD-21 P-07/P-08 for the npm RSS lane (TOD-123). A program still
compiles whole at load. After that, a replayable function keeps only its
`FunctionHeader`, and its record compiles again from its own source on first read
(`ResidualProgram::function`). `docs/README.md` ("Compile on first call") states the
contract and lists which functions can be replayed.

- Quench candidate: release `quench-node` built from `v2-npm` at the commit that adds
  this directory (sha256 `a60d1c19b051…`).
- Base: release `quench-node` at e18cd604d.
- Node v26.12.0 and Bun 1.4.2.
- Host: `host.txt` (x86_64 Linux 6.18.44 VM, 4 CPUs, 16 GiB RAM, no cgroup limits).

## npm peak RSS

`run-npm NODE QUENCH REPORT 60 --rss BUN` runs the 300 scenarios in `tests/npm-top300`.

- Raw data: `npm-scenarios.json.gz`.
- Table: `rss-report.txt`, generated by `../npm-rss-2026-10-17/rss_report.py`.

Behaviour: all 300 pass on Quench. The musl rollup addon is oracle-failed: it also fails
on glibc Node.

| | Quench | Node | Bun |
| --- | --- | --- | --- |
| median peak RSS | 17.6 MiB | 69.8 MiB | 38.0 MiB |

Quench is lowest on 283 of 300 packages. The other 17 fall into three groups:

- **Eight declaration scenarios** are within 0.5 MiB of Bun or Node. Their peak is the
  native Go `tsc` child, so they count as ties. Which eight lands on the wrong side
  changes from run to run; the l6 run had seven.
- **Eight typescript-eslint packages.** Their peak is compiling `typescript.js` (9 MB of
  source) at load: the OXC arena, the semantic tables and the source itself, about
  52 MiB together. Compiling on first call shrinks what stays resident after the load
  but not this load-time peak. Lowering it needs a load that does not parse the whole
  program at once.
- **jiti** (48.2 against Bun's 42.4). Bun skips Babel through jiti's `tryNative` path.

Peaks of the `require` step alone, base → candidate:

| package | base MiB | candidate MiB |
| --- | --- | --- |
| typescript | 112.1 | 98.1 |
| jsdom | 98.5 | 89.0 (now lowest) |
| playwright | 113.9 | ~107 |
| @babel/core | 36.1 | 32.8 |

Small packages cost about 0.5 MiB more (median 17.3 → 17.5 MiB in l6). That is the
replay data: table cursors, exit cursors and layout inputs. A compact encoding of the
replay data is a possible follow-up.

## Test262

Release `run-all` with 4 jobs gives 53,353 passed, 53 waived and 0 failed. The base
e18cd604d result is identical.

With `--features verify-replay`, every replayable function compiles again after load
and is compared with its load record: 1,306,705 functions are identical, none differs
and none fails.

## Cost

`../tod123-rss-linux-2026-10-14/callgrind-guard.sh` gives the instruction counts below
(`callgrind-guard.txt`, raw lines in `callgrind-guard-raw.txt`).

- Startup: 0.1–0.9% more instructions. The entry module's functions stay compiled.
- Per run: crypto +0.37%, deltablue +0.26%, earley-boyer +0.21%, navier-stokes 0.00%,
  raytrace +0.62%, regexp −0.13%, richards +0.09%, splay +0.08%.

The steady-state cost is one extra dependent load on each read of a function record,
through the slot's `OnceCell`. V8-v7 max RSS is unchanged within ±0.2 MiB.

## Limits

- **Kept records.** These functions stay compiled and are never released:
  - functions that may be reached by a dynamic lookup or bound dynamically (direct
    eval, `with`, `delete name`);
  - functions that resolve private names;
  - constructors, field initializers, static blocks and decorated methods;
  - functions invoked where they are made;
  - host static bodies and the CommonJS main entry.
- **Replay context.** A replay depends on the program's interned atoms and recorded
  cursors. The program keeps its replay data for as long as any record can be read.
