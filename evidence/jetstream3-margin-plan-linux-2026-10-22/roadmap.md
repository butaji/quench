# Quench vs Bun: prioritized roadmap (synthesis of six verified dimensions)

Baseline: geomean score ratio **0.6556** (34 tests, quench 0028c07f vs Bun no-JIT), RSS better on 32/34. Target 1.2 requires a uniform **1.83x**; the ten worst tests fixed to exactly 1.2x only reach 1.028. All multipliers below are the **verifier-adjusted** values (midpoint of the adjusted range); geomean effect of a multiplier m on one test is m^(1/34). Running geomean is chained item by item. Bun scores from `sweep-default-bun.txt`, quench from `scores-0028c07f.txt`; I use those, not the 36.32/39.25 baselines quoted from commit 08f3a15f's message.

## Track NO-JIT

### 0. Measure before building (no gain, 2-3 days, gates items 4, 6, 9)
- Run the existing `profile-lane-exits` census (`vm/lane_exits.rs`, prints exits by opcode and "materializes for native X") on UniPoker, lazy-collections, babylon/acorn/prettier/postcss, web-ssr, typescript-lib. No evidence directory records this counter; it sizes item 9.

- Run both alone on the 4-vCPU host; record platform in a new evidence dir.

### 1. Wide-string O(1) slices (`FlatUnits::WideSlice`)
**Mechanism.** `wtf16.rs:171-186` `run` shares storage only when `shared_ascii()` is Some; for `Wide` it falls through to `flat_units` and copies. source-map's 136,901-byte lodash fixture has 386 non-ASCII bytes (last at offset 4724), so each `nextLine.substr(k)` copies ~270 KB: 25,651 copies / 15 iterations, memcpy 4.5 G Ir (3.99% of total) and ~7.3 M GC weight per iteration (each copy charged 274 KB/64 B) into a collector that was 41% of instructions. Add `WideSlice` re-based on the root Rc, keep the all-ASCII narrowing copy for short runs, extend `same_storage`/`memory_parts`/`flat_unit_bytes`.
**Files.** `crates/quench-runtime/src/vm/wtf16.rs`.
**Tests.** source-map-wtb **1.15x** (1.10-1.25), RSS -3 to -5 MB.
**Geomean.** 0.6556 -> **0.6583**.
**Effort.** Medium, 1-2 days. **Validate.** callgrind pair on source-map (flat_units memcpy -> ~0), `QUENCH_GC_TRACE` collections per iteration -40%, Node oracle on Wide/ASCII equality and atom lookup.

### 2. One OXC parse per eval
**Mechanism.** web-ssr evals a 755,683-byte bundle from a strict class method every iteration, which today costs three full parses and two SemanticBuilder runs: `eval.rs:104-106` regexp probe (full `Parser::parse`), `eval.rs:189-190` -> `strict_eval_syntax_error` (compile.rs:1047-1072, parse + `SemanticBuilder::with_check_syntax_error`), then the real compile (which already prepends `'use strict'` and runs SemanticBuilder, compile.rs:669-673, 931-933), plus ~4 whole-source `format!`/`to_owned` copies (eval.rs:135, 892-898; compile.rs:667-675). Make the compile the one authority: `specialize_eval_with_context` returns `RegExpLiteral | Program`; strict validation derives from the compile's own SemanticBuilder; preserve error order (regexp probe -> strict syntax -> `class_eval_references_arguments` -> compile diagnostics) against the Node oracle.
**Files.** `vm/eval.rs`, `compile.rs`.
**Tests.** web-ssr **1.08x** (1.05-1.12); prismjs similar.
**Geomean.** 0.6583 -> **0.6598**. **Effort.** Low, 1-2 days. **Validate.** item 0 callgrind re-run shows one parse line; Test262 eval negative tests; oracle error-order tests.

### 3. Register locals for functions nested in eval code
**Mechanism.** `compile.rs:3182-3191` and `compile/arrow.rs:81-88` require `eval_context.is_none()` for `promote_plain_locals`; `Compiler.eval_context` is set for the whole program (compile.rs:1030), so every React/react-dom-server function compiles with frame-slot locals, `addresses_locals = true`, `CallPlan::registers_only = false` (bytecode.rs:2022-2026), i.e. no frameless lane activation (dispatch_fast.rs:6165-6178). The only eval-specific binding path is root-only (`ast.rs:540-547`, `StoreVarBinding` when `function_id == 0`). Restrict the guard to the root and `capture_script_completion`; functions containing direct eval stay excluded via `dynamic_eval` (compile.rs:3175-3177). Budget caveat: `PROMOTED_LOCAL_REGISTER_BUDGET` (compile.rs:3031-3057) may exclude webpack wrappers.
**Files.** `compile.rs`, `compile/arrow.rs`, `compile/ast.rs`, `bytecode.rs`.
**Tests.** web-ssr **1.15x** (1.05-1.25; upper end only if item 0 shows render >= 50%).

### 4. Unobserved promise jobs carry no host context
**Mechanism.** `async_hooks_shared_vm.rs:324-346` `capture_job_context` always returns `Some(token)` and calls `inherit_stores`; every reaction then runs enter/boundary x2/restore/release (`promise_jobs.rs:467-523`), each a `SharedNodeState` borrow_mut plus `job_resources` hash get/remove, `job_stack` push/pop (~5 RefCell borrows, 3-4 hash ops per job). Return `None` unless `tracks_promises() || !local_stores.is_empty()`; add a host hook that only swaps the two AsyncIdentity cells so `executionAsyncId()` reads 0 inside unobserved jobs; derive `observes_promise_job_boundaries` as a bool on hook/ALS transitions. Per-job budget: 240K jobs/iteration, ~575 ns/job at the commit-message score vs Bun 263 ns.
**Files.** `quench-node/src/modules/async_hooks_shared_vm.rs`, `quench-node/src/host/shared_vm.rs`, `quench-runtime/src/host.rs`, `vm/promise_jobs.rs`, `vm/gc.rs`, `vm/host_function.rs`.
**Tests.** doxbee-promise **1.10x** (1.07-1.14), doxbee-async **1.06x**, async-fs **1.035x**. No RSS effect (Option<u64> is 16 B either way).
**Geomean.** 0.6625 -> **0.6662**. **Effort.** Low-medium. **Validate.** Node oracle for `executionAsyncId`/`triggerAsyncId` in then callbacks, ALS.run inside a chain making later jobs observable; doxbee-promise 11-round pair.

### 5. Intrinsic promise proofs on the general paths + realm fields

Make the proven path the first arm with exact fallback; store realm intrinsics as Realm fields re-derived on realm switch.
**Files.** `vm/promise.rs`, `vm/promise_jobs.rs`, `vm/promise_async.rs`.
**Tests.** doxbee-promise **1.06x** (1.03-1.10), doxbee-async **1.05x**, async-fs **1.025x**.
**Geomean.** 0.6662 -> **0.6688**. **Effort.** Medium. **Validate.** Existing promise-semantics oracle (species, own constructor, getter `then`, thenable order) rerun; note 08f3a15f left doxbee-async flat (39.76 -> 39.25), so expect the low end there.

### 6. Resident job lane (handlers as frameless activations from one drain frame)
**Mechanism.** `promise_jobs.rs:497` calls `call_value` per handler, which runs `run_user_frame -> activate_plain_frame` (dispatch_frame.rs:439-485) -> `run_general_loop` (1270-1310) and rebuilds a ~20-field `LaneContext` plus thread-local swaps per entry (dispatch_fast.rs:11276-11330). Push one generic trampoline frame per drain, keep a resident `LaneContext`, write handler/value into trampoline registers and resume the lane at pc 0; `lane_script_call` activates the handler framelessly through `ScriptCallTarget`/`CallEntry`, bypassing `LANE_ENTRY_MIN_CALL_RUN=8` (dispatch_fast.rs:10101) which keeps 3-4 instruction bodies (@3402/@3475/@3900 arrows at 0 lane instructions; dummy_2 9.6M general of 28.8M) off the lane. Exact fallback: `materialize_lane_activations` (11318). Keep the `maybe_collect` safepoint at gc.rs:1054. Cost basis: 08f3a15f removed 2.5M materializations + 90K exits for 28 ms of 166 ms, so an exit+re-entry is ~200-300 ns; ~150K per-job frame entries remain.
**Files.** `vm/dispatch_fast.rs`, `vm/promise_jobs.rs`, `vm/gc.rs`, `vm/dispatch_frame.rs`.
**Tests.** doxbee-promise **1.30x** alone (1.2-1.4; combined with 4+5 about 1.5-1.9x total, 24.5 -> 37-47, still under Bun 79), doxbee-async **1.08x**, async-fs **1.07x**.
**Geomean.** 0.6688 -> **0.6768**. **Effort.** High, 2-3 weeks. **Validate.** `profile-lane-exits` exits/iteration ~150K -> <20K; handler-throw unwinding to `settle_reaction`; nested `native_microtask_checkpoint` reentrancy tests; Error stack traces inside then handlers vs Node.

### 7. A suspended async activation is its frame
**Mechanism.** `activation.rs:144-171` `from_frame` takes 6 Vecs; `promise_async.rs:103-124` boxes the Continuation; on resume `adopt_frame` (dispatch_frame.rs:1159-1167) does `*slot = frame`, freeing the pooled buffers while the suspended Box<Frame> with empty Vecs is dropped (promise_async.rs:71-84), so each await cycle is >=1 Box alloc/free, 1-6 Vec frees and a reallocation. `generator.rs:1607-1622` `record.continuation = Some(continuation.clone())` deep-clones per async-generator yield, async-fs's hot path (`for await` over 2-3 nested `async*` levels). Let AwaitState/generator record own the suspended Box<Frame> (swap buffers in adopt_frame, never clone), modeled as the existing running/suspended/done state machine; roots follow the frame as `Continuation::roots` does today.
**Files.** `vm/activation.rs`, `vm/promise_async.rs`, `vm/generator.rs`, `vm/dispatch_frame.rs`, `heap.rs`.
**Tests.** doxbee-async **1.08x** (1.05-1.12), async-fs **1.10x** (1.05-1.15).
**Geomean.** 0.6768 -> **0.6803**. **Effort.** Medium-high. **Validate.** malloc counts per await cycle (callgrind on doxbee-async); generator return()/throw() on suspended async generators vs Node.

### 8. argon2: per-activation v128 register bank + quickened lane SIMD kernels
**Mechanism.** Every v128 is a heap cell: `cell.rs:3095 WasmV128`, `wasm.rs:1533` alloc per result, `:1673` `heap.get` per operand; `dispatch_wasm.rs:252-282` runs each `Op::WasmSimd` through double enum dispatch and `map_lanes` per-lane shift loops (simd.rs:44-60); zero `WasmSimd` handlers in dispatch_fast.rs, so every SIMD instruction in the hot loop forces `exit(ip)` -> `materialize_lane_activations` (11352-11354) -> per-instruction lane re-entry (dispatch_frame.rs:1340-1342). That thrash, not allocation (measured "a quarter of samples" in WasmV128/WasmBits64 cells, memory-management-design.md:89), is the likely dominant cost. Phase A: dense register->bank map derived at lowering, `Vec<u128>` bank window per Wasm activation beside `stack.values` (GC never scans it; v128 holds no refs), boxed cell remains the exact representation at the closed escape set (global.get/set, host callables at wasm_host.rs:226; the JS boundary already throws). Phase B: quickened monomorphic lane handler per `SimdOperator`, kernels on u128/two-u64, as scalar f32/f64/i64 ops are quickened (dispatch_fast.rs:9740-9748). Also removes one young GC per ~131K SIMD ops (pacing floor 2^16).
**Files.** `vm/dispatch_wasm.rs`, `vm/wasm.rs`, `wasm/simd.rs`, `vm/dispatch_fast.rs`, `wasm/memory.rs`, `heap/cell.rs`.
**Tests.** argon2-wasm **4x** (2.5-6x; 0.23 -> 0.6-1.4 vs Bun 2.17: still 0.27-0.65 ratio, not 1.2). Bank alone 1.3-1.8x; phase B carries the rest.
**Geomean.** 0.6803 -> **0.7086** (largest single item: 9.2% of total drag). **Effort.** Large, phased. **Validate.** wast suite + task37-wasm-simd-* oracles; `profile-lane-exits` on argon2 (SIMD exits -> 0); RSS unchanged (bank is per-activation).

### 9. Natives and in-place general steps from frameless activations (lazy frames)

**Files.** `vm/dispatch_fast.rs`, `heap/cell.rs`, `vm/dispatch_frame.rs`, `vm/error.rs`.
**Tests.** UniPoker **1.12x** (1.05-1.2), lazy-collections **1.10x**, nine parser/transpiler WTB tests **1.05x** each (1.02-1.08), web-ssr and typescript-lib **1.05x**. Sized only after item 0's materialization counts; UniPoker's sort/forEach callbacks still materialize.
**Geomean.** 0.7086 -> **0.7243**. **Effort.** Large, 2-4 weeks. **Validate.** "materializes for native" counter before/after; Error.captureStackTrace/console.trace/async_hooks stack correctness vs Node; test262.

Reuse the existing field-cache slot rather than a second table (AGENTS: caches need measured benefit).

### Where this leaves NO-JIT
Chained grounded result: **~0.74** (band 0.72-0.78 at verifier lower/upper bounds). RSS wins are preserved (every item is allocation-neutral or negative; item 12 narrows the doxbee loss). Remaining gap to 1.2 is a uniform **1.62x** across all 34, concentrated where no dimension produced a grounded mechanism: the parser/compiler cluster (42% of drag; after items 9-11 babylon/acorn/espree/esprima/prettier/postcss/chai/babel still need 1.5-2.5x), source-map's residual 0.19 (Wasm->JS import calls and property/string ops), JSON serialize (0.41, native builtin bound), bigint-noble (0.41, `Cell::BigInt` allocation per op), validatorjs (0.35, RegExp engine). The researched-but-unmeasured levers for that cluster are inline bump allocation in the young heap and a rope/flat Latin1 string representation; both need a callgrind census on babylon-wtb and source-map before they can be sized. **Honest statement: the plan above is necessary and does not reach 1.2x; it buys ~0.74 and the measurements that size the rest.**

## Track JIT

**Fact that reorders everything:** every `--jit` artifact in `evidence/jit-jetstream3-2026-10-21` is from revision 3ce8c959 and siblings, on a branch whose merge-base with the measured interpreter build is 51e32ab4; at that revision dispatch_fast.rs was 6,421 of today's 11,364 lines, heap/pacing.rs did not exist, and `js_tier_may_claim` did not exist. Wall times there (js-tokens 105 s wall vs 5.3 s timed; doxbee-promise 203 s vs 6 s; ~1 GB RSS) show the loss sits mostly outside timed iterations. **HEAD `--jit` has never been measured.** The "quench --jit at ~6% of Bun" number is not a property of the current VM.

### M0 (1-2 weeks): measure, then make --jit a superset of the lane
1. 11-round paired `--jit` vs interpreter screen of all 34 at HEAD (docs/jetstream3.md protocol); any fixture where JIT < interpreter is a P0.
2. Remove frame-forcing: `js_tier_may_claim` (compiled.rs:6512) makes `resolve_script_call_target` return None (dispatch_fast.rs:6115) for any undecided candidate; move tier counting onto `ScriptCallTarget` entries and `lane_jump` backedges. Note scope: `eligible()` (js_compiled.rs:4027-4045) already excludes arrows/async/generators, so doxbee handlers are not affected; plain functions are. Fix the real decline bug: `js_tier_declined` (program_store.rs:1151-1155) matches only `Unsupported`, so bytecode-scan `Rejected` candidates keep frames forever.
3. One per-function tier slot beside the `OnceCell<LaneView>` (replaces `js_tiers`/`wasm_tiers` FxHashMaps, program_store.rs:116/119; `js_tier` Rc-clones per entry at 1146-1148); `js_jit_at_entry` (compiled.rs:6700-6793) runs matchers once, not per entry.
4. Wasm: `lane_call_known` (dispatch_fast.rs:8435-8447) stops `exit(ip)` on compiled callees; enter native through `direct_reference_entry` (compiled.rs:1541) with the entry pointer from the slot, keeping `COMPILED_STACK_BUDGET`/interrupt checks. Add an O(1) per-function `Interpreted|Baseline|Tier` table replacing `has_wasm_tier_containing` scans (program_store.rs:942-955).
5. Fix the hidden budget policy: `set_compiled` silently drops artifacts over `JIT_MAX_MAPPED_BYTES` = 4 MiB (program_store.rs:67, 974-980; sqlite3's 24.7 s / 8.04 MB compile never ran), and `note_wasm_tier_entry` keeps compiling after `install_wasm_tier` is over budget (539 discarded attempts, ~45 s per sqlite3 run). One budget owner with documented exhaustion = stop compiling, interpreter continues.
**Expected.** JS fixtures: parity with the no-JIT lane (unmeasured over HEAD). HashSet-wasm 24 -> 35-50; sqlite3 JIT 0.27 -> 0.7-1.0 (still below its interpreter 4.41). **Validate:** item 1 rerun; `--jit-diagnostics` compile ms and Cranelift high-water per tier.

### M2/M3 (26-46 weeks): JS tiers from the lane view
