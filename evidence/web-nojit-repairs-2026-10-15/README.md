# Node parity repairs, 2026-10-15

These are correctness repairs on `v2-web`, using checksum-verified stable Node
v26.12.0 as the oracle. They do **not** establish total Node parity and do not
permit optimization. The initial counterexamples and broad diagnostic failure
ledger remain in `../web-nojit-2026-10-15/`.

## Repairs

- HTTP writes preserve Buffer/typed-view bytes, offsets and string encodings.
  HTTP Date uses the actual clock; incoming request/response header objects use
  the ordinary object prototype. `http.Server` supports calls without `new`.
- Stable Node’s observable status-line cache preserves getter ordering and
  previously cached wire reasons when the public status map changes.
- CommonJS package scope stops at the nearest `node_modules` boundary while
  respecting package-local module/commonjs declarations.
- The pinned Node library and Undici execute as unmodified guest code inside
  Quench's interpreter. Their sources are embedded in the executable, resolved
  through a normalized module identity, rather than requiring a development
  checkout at runtime. The submodule retains the upstream license/notices.
- HTTP/2 compatibility classes and constant descriptors replace the empty
  module export. Native HTTP/2 transport remains unsupported.
- Headers/Request/Response/FormData share Node's Undici algorithms. Their
  global descriptors are writable, configurable and nonenumerable. File retains
  Quench's existing Blob/File implementation, shared with the buffer export;
  its complete behavior still needs qualification.
- `markAsUncloneable` is GC-safe host metadata without visible object properties.
  Clone-algorithm failures become DOMException DataCloneError (code 25), while
  exceptions thrown by getters retain their original identity.

## Verification

`verification-final/final.json` retains a verification-only run: all nine Node/Bun/
Quench combinations pass ping, query, dynamic query, JSON and full-video hash
checks. Node uses `--jitless`; Bun preflight proves `useJIT=false`; Quench is
interpreted. This iteration build provides no production performance claim.

The stable-source framework-core profile passes 43/43. Four prior Node-main-only
filenames are explicitly retained as comments in the manifest because they do
not exist in v26.12.0; no available failing fixture was removed.

Five differential regressions compare package scope, binary HTTP/Date/header
behavior, web API descriptors/Headers/clone markers, status-line cache effects
and util extension against Node v26.12.0.
The final merged source passes all 617 runtime-library tests in the standard
test profile, the workspace/all-target check and the Rust benchmark runner
checks. The initial repair set also passed all 616 tests in the optimized
iteration profile. Earlier verification directories retain prior sync points;
`verification-final/` and `latest-node-focused-final/` qualify the final repair set.

`latest-node-focused-final/` repeats the original ten unchanged stable HTTP CLI
fixtures and retains stdout, stderr, exit status and timeouts. Entry scope is
repaired, but remaining API/harness failures are still compatibility gaps;
exit code alone does not prove that a Node fixture passed.

The earlier concurrent JSON load finding was a socket timeout at 500 connections,
not an HTTP 4xx/5xx response. Invalid rows remain unscored. No throughput result
or speed improvement is claimed here.

## Instruction-count finding

The complete all-eight guard is retained in `instruction-guard.json` and the
raw/summary files. RegExp (+2.25%) exceeds the 1% limit; the other seven are within it;
startup also rises substantially. [TOD-135](https://linear.app/todoxapp/issue/TOD-135)
records these costs. Baseline counts are reused for the identical frozen
executable and identical input scripts on the same host; every candidate count
is refreshed after final sync. This includes other merged lane changes and
does not isolate attribution. These are iteration-build instruction counts,
not production throughput or RSS results. No regression is hidden or called
a performance improvement.

## Reproduction

See `docs/web-benchmarks.md` for the pinned suite, build and verification command.
The HTTP/2 descriptor snapshot is generated by the stable oracle with
`JSON.stringify(Object.getOwnPropertyDescriptors(require('http2').constants))`.
It includes nonenumerable constants and exact attributes, not just Object.keys.
