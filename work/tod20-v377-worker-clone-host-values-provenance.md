## v381 HTTP/2 response flags and HEAD lifecycle candidate (2026-10-26)

The v380 HTTP/2 failures showed that client `response`/`headers` events always emitted flags `0`, and the server suppressed END_STREAM on HEAD responses because Node's compatibility layer requests trailer deferral. The candidate now projects `END_HEADERS | END_STREAM` from the native event, sends END_STREAM with bodyless HEAD/status headers even when trailers were requested, leaves compatibility Writable completion for the later `response.end()` call, and drops HEAD body chunks while still completing write callbacks. This preserves both wire-level closure and Node's `finish`/callback ordering.
