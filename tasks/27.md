# 27: Cut over to the single VM and delete the legacy runtime

## Outcome

Make the shared OXC/Wasm core the only production `quench-runtime` and delete
legacy execution code. This remains Stage A; task 86 removes remaining clutter
and verifies the final build before Stage B can start.

## Current gap

Two VMs exist. The legacy `crates/quench-runtime` (OXC 0.47, its own Wasm
binary parser in `src/wasm/`) is what production uses: `quench-node` reaches
its internals about 3,800 times (`execute`, `ops`, `vm`, `value`,
`builtins`). The single shared VM lives under transitional names:

- the package `quench-runtime-next` with library name `rqj`;
- the binaries `quench-next`, `quench-node-next`, `run-stages-next` and
  `run-all-next` (in `quench-runtime-next` and `quench-test262`);
- the tools `tools/diff-next.mjs` and `tools/run-all-next.mjs`;
- the workspace aliases `oxc_parser_next`/`oxc_parser_legacy` and the vendors
  `vendor/oxc-parser-{next,legacy}`.

`quench-wasm`, `quench-test262` and `quench-node` depend on both runtimes, and
`quench-node-test` depends on the legacy runtime directly. Task 24 supplies
integrated correctness proof.

## Dependencies

See `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Move the verified shared implementation into the canonical
   `crates/quench-runtime` package with library name `quench_runtime`, and
   update every host, runner, workspace dependency and CLI entry. Fold each
   `*-next` binary and tool into its canonical name, and remove the transitional
   names listed above.
   Keep production entry points and suite runners on that same core. Extract a
   CLI or shared runner crate only if a concrete cutover requirement needs it;
   crate reshuffling itself is not a prerequisite.

2. Delete the legacy runtime, legacy Wasm executor, legacy host adapters,
   backend selection plumbing, and legacy-only conformance binaries. Retain
   the shared core's comparison and triage operations under canonical names.
3. Update affected commands and contracts so they point at the single VM.
   Task 86 audits and removes remaining unused tools, vendors, and documents.

Derive deletions from current consumers. Preserve needed algorithms in their
single surviving authority, without retaining an executable legacy fallback.
Do not make cutover depend on v2 parity or benchmark rankings.

## Verification and definition of done

- One runtime package (`quench-runtime`) and one production execution core
  remain; every host and runner uses them without runtime selection flags.
- No crate, library, binary, tool or dependency alias names a second VM, and
  `cargo metadata` confirms every execution consumer reaches that one core.
- OXC and Wasm use the same VM, heap, roots, values, dispatch, and activations.
- No legacy semantic fallback, guest JIT, executable-memory path, or sibling
  build dependency remains.
- From a clean build, verify workspace checks, CLI behavior, and all three
  inventories (Test262, Wasm and implemented Node) against task 24's baseline
  with compare-runs.
- Record source/build provenance and the deletion audit. Performance work
  waits for task 86's final Stage A verification.
