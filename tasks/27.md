# 27: Cut over to the single VM and clean the repository

## Outcome

Atomically make the next core the sole production `quench-runtime`, delete
the legacy runtime, and remove every stale or migration-only artifact from the
repository. This closes phase A (correctness). After this task the repository
contains one core that runs JavaScript and Wasm on one VM, and nothing that
exists only to support the old engine or the migration. Phase B (efficiency:
the staging spine 46 → 47, v2 parity, and the specializers) starts from that
clean tree; no phase-B task starts before this one is done.

## Current gap

The feature-complete engine still has a temporary package/name and production hosts still target the legacy package.

Legacy removal happens at the correctness gate (task 24), not after performance
parity. This keeps a second engine from being maintained while efficiency
work (phase B) proceeds. Task 26 then reaches parity with the
pinned v2 binary on the single core, and task 61 leads the no-JIT reference
engines. Until then, production may be slower than the legacy runtime. That
difference is recorded at cutover as measurement only, and it does not block
the cutover.

Legacy material to delete (derive the final list from the tree at cutover time):

- `crates/quench-runtime` (evaluator, heap, value model, `builtin_meta/`, and
  the legacy copies of Temporal, Intl and Date; the next core already owns
  those authorities, and task 45 finishes extracting them in phase B)
- legacy runners: `run-stages`, `run-all`, `compare-runs`, `triage` (the `-next`
  runners are renamed to the canonical names)
- `quench-node`'s legacy host bindings and any adapter that exists only to feed
  both runtimes
- legacy implementations of the `AlgorithmBoundary` trait, if any exist at
  cutover
- the legacy Wasm execution path (`crate::hir`, `wasm/emit/*`) and any other
  executor of Wasm outside the shared VM

Repository clutter to delete or fix at the same gate (re-derive from the tree;
each item is deleted unless a phase-B task names it as an input):

- `vendor/oxc-parser-legacy`: unify OXC on one exact release (moved here from
  task 28) so `cargo tree -d` has no duplicate OXC family from workspace code
- migration-only tools and scripts under `tools/` (differential next-versus-
  legacy runners such as `diff-next.mjs` and `run-all-next.mjs`, orchestration
  and audit scripts with no remaining consumer) and their `package.json`
  entries; measurement tools that phase B still uses stay
- stale paths in `package.json`, lint and format configs, git hooks, and CI
  scripts (for example the deleted `native_core/PROVENANCE.md`)
- documents that describe the legacy engine or migration state: `docs/spec.md`'s
  legacy ownership, `CONTEXT.md`, `GOAL.md`, and any `docs/` page or README
  section whose subject no longer exists; `AGENTS.md` and `docs/README.md`
  describe only the single VM
- tracked reports, logs, generated artifacts, and dead fixtures or examples
  that no runner reads
- `Implementation evidence` diaries in task files: done tasks keep their
  specification plus a short completion record; Git history keeps the log
- dead code the deletion exposes: `#[allow(dead_code)]`, unused features,
  dependencies, re-exports, and compatibility shims

## Scope and implementation sequence

1. Freeze the green commit (task 24), move the next implementation into
   `crates/quench-runtime`, update all workspace dependencies and production
   binaries, and remove the legacy source tree and migration-only
   compatibility adapters. Rename next development targets to canonical
   production targets and remove backend selection plumbing.
2. Remove the repository clutter listed above, one reviewable commit per
   category, each re-running the three-suite ratchet.
3. Update `AGENTS.md`, `docs/`, and `tasks/README.md` so every command and
   contract they name exists in the tree.

## Verification

From a clean build directory, run workspace check/test/clippy, CLI smoke/error/exit tests, complete Test262, tracked Node compatibility, complete Wasm, residual phase tests, and a recorded (not gating) eight-fixture V8-v7 Score/RSS measurement against legacy, v2, and the no-JIT reference engines when task 62 has landed. Search for legacy crate names, reducers, value models, runtime flags, JIT/stencil/native code, `-next` names, and sibling paths. Run warning-denied check/clippy, the task-queue coherence check, and a local-link check over all Markdown.

## Definition of done

- One `quench-runtime` package and one engine implementation remain; `quench-runtime-next` no longer exists as a name.
- All hosts and runners use it by default without flags.
- No legacy semantic fallback, guest JIT, executable-memory path, or sibling build dependency remains.
- No tool, script, document, config entry, vendored crate, or tracked artifact exists only for the legacy engine or the migration; every Markdown link resolves; workspace builds are warning-free.

## Performance evidence

Record V8-v7 Score/RSS for the last legacy production binary and the first single-core binary, with matched provenance. This is the starting point for task 26. It is not a gate.
