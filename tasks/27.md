# 27: Cut over to the single VM and delete the legacy runtime

## Outcome

Make the shared OXC/Wasm core the only production `quench-runtime` and delete
legacy execution code. This remains Stage A; task 86 removes remaining clutter
and verifies the final build before Stage B can start.

## Current gap

Two VMs still exist. The canonical `quench-node` executable and Test262
`run-stages` and `run-all` runners now enter the shared VM. The 43-fixture
`framework-core` profile plus Express, Koa, and Fastify scenarios were qualified
against local Node in the [current framework evidence](evidence/task21-framework-core-current-2026-10-07.json).
The `run-all` promotion compile and no-case CLI guard are recorded in
[its focused runner evidence](evidence/task27-canonical-test262-run-all-2026-10-07.json).
However, `quench-node` and the workspace still compile and depend on the
legacy `crates/quench-runtime` (OXC 0.47, with its own Wasm binary parser in
`src/wasm/`). Remaining shared runtime paths still use transitional names:

- the package `quench-runtime-next` with library name `quench_runtime_next`;
- the binary `quench-next` in the runtime crate;
- the tools `tools/diff-next.mjs` and `tools/run-all-next.mjs`;
- the workspace aliases `oxc_parser_next`/`oxc_parser_legacy` and the vendors
  `vendor/oxc-parser-{next,legacy}`.

The canonical Wasm suite uses the shared VM, and `quench-wasm` has no legacy
runtime dependency. The canonical `run-all` and `run-stages` runners,
`run-parallel` worker, and isolated `run-compat` case worker now use the shared
VM; the 43-case framework-core profile passes through that canonical worker.
`quench-node` still depends on both runtimes. `quench-test262` now has one
shared host and no direct legacy runtime dependency; its legacy host, module
graph, and regression helpers have been removed. `quench-node-test` still
keeps legacy code for its standalone runner and directly depends on the legacy
runtime. Test262 `triage` and `compare-runs` execution now use the shared host.
The narrow stage-8 shared-runner smoke is recorded in
[Test262 runner evidence](evidence/task27-canonical-test262-stage-runner-2026-10-07.json).
The shared single-test path's Stage 8 smoke is recorded in
[single-case runner evidence](evidence/task27-canonical-test262-single-runner-2026-10-07.json).
Task 24 supplies the integrated correctness proof for the remaining production
cutover.
The canonical worker rerun and focused crate checks are recorded in
[the worker-routing evidence](evidence/task27-canonical-node-workers-2026-10-07.json).

The remaining host boundary is concrete. `NodeHost` still carries legacy
`Value`/`RealmId` state beside shared `RootId` state; `ProcessModule` and
`ModuleCache` retain both variants, and Buffer decoding crosses between runtime
representations. Remove these bridges as their consumers move. Keep
`legacy_try` in `quench-wasm`: it normalizes pinned WAST syntax before shared
execution and is not a VM.

## Scope and implementation sequence

1. The canonical `quench-node` binary and isolated Node suite workers now use
   shared entrypoints. Make the shared Node host next-only: move host state and
   Buffer codec boundaries to shared-runtime types, remove the `Legacy`
   variants and legacy Node exports, then remove the remaining legacy
   standalone test runner.
2. Complete the Test262 cutover. `triage` and execution modes of
   `compare-runs` use the shared host, and the legacy adapter/module graph are
   removed. Retain report-only `compare-runs` as the gate's report-diff
   authority; continue the legacy consumer audit in `quench-node`.
3. After the old-runtime consumer search is empty, move the shared code into
   the canonical `crates/quench-runtime` package and library name, then delete
   the old VM package and dependencies. Remove parser aliases/vendors only
   after `cargo metadata`, `cargo tree` and source search confirm no consumers.
4. Update commands and contracts. Task 86 removes only audited dead tools,
   vendors, duplicate suite tests and stale documents; preserve required WAST
   syntax normalization and suite-uncovered internal tests.

Derive deletions from current consumers. Preserve needed algorithms in their
single surviving authority, without retaining an executable legacy fallback.
Do not make cutover depend on v2 parity or benchmark rankings.

## Verification and definition of done

- One runtime package (`quench-runtime`) and one production execution core
  remain; every host and runner uses them without runtime selection flags.
- No crate, library, binary, tool or dependency alias names a second VM, and
  `cargo metadata` confirms every execution consumer reaches that one core.
- OXC and Wasm use the same VM, heap, roots, values, dispatch, and activations.
- No legacy semantic fallback, guest JIT, executable-memory path, or sibling
  build dependency remains.
- From a clean build, verify workspace checks, CLI behavior, the complete
  pinned Test262 inventory by stage, the Wasm inventory, and the scoped Node
  framework gate against task 24's baseline with compare-runs.
- Record source/build provenance and the deletion audit. Performance work
  waits for task 86's final Stage A verification.
