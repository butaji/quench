# 27: Cut over to the single VM and delete the legacy runtime

## Outcome

Make the shared OXC/Wasm core the only production `quench-runtime` and delete
legacy execution code. This remains Stage A; task 86 removes remaining clutter
and verifies the final build before Stage B can start.

## Current gap

The working tree now promotes the shared core into the sole `quench-runtime`
package and `quench_runtime` library, with the `quench` binary. `quench-node`,
Test262 and Wasm all depend on that package. The old VM package, legacy Node
execution exports and 0.47 parser vendor have been removed; the shared OXC
0.150 parser now has a neutral vendor path. Tool and runner commands use
canonical names. The qnode manifest was reduced to dependencies found in the
surviving host and selected modules.

The cleaned candidate builds all gate binaries without a lint cap. Its
`framework-core` profile passes 26/26 fixtures, and pinned Express, Koa and
Fastify scenarios match local Node byte for byte. The complete Test262 and WAST
inventories still need to be rerun against these final binaries; Task 27 and
Stage A remain open until those reports and the consumer audit are recorded.
Task 86 owns the final clutter audit and same-build qualification. Keep
`legacy_try` in `quench-wasm`: it normalizes pinned WAST syntax before execution
and is not a VM.

See `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. The canonical Node and Test262 runners now use the shared entrypoints. Make
   the shared Node host next-only: move host state and Buffer codec boundaries
   to shared-runtime types, remove the `Legacy` variants and legacy Node
   exports.
2. Keep the promoted shared Test262 runners; remove legacy runtime and
   module-graph adapters. Retain report-only `compare-runs`, and either move
   its execution mode and triage to the shared host or remove them if no
   consumer needs them. Keep `run-test` only if it uses the shared host.
3. After the old-runtime consumer search is empty, move the shared code into
   the canonical `crates/quench-runtime` package and library name, then delete
   the old VM package and dependencies. Remove parser aliases/vendors only
   after `cargo metadata`, `cargo tree` and source search confirm no consumers.
4. Update commands and contracts. Task 86 removes only audited dead tools,
   vendors, duplicate suite tests and stale documents; preserve required WAST
   syntax normalization and suite-uncovered internal tests.

Derive deletions from current consumers. Preserve needed algorithms in their
single surviving authority, without retaining an executable legacy fallback.
Do not make cutover depend on v2 parity or benchmark rankings.

## Verification and definition of done

- One runtime package (`quench-runtime`) and one production execution core
  remain; every host and runner uses them without runtime selection flags.
- No crate, library, binary, tool or dependency alias names a second VM, and
  `cargo metadata` confirms every execution consumer reaches that one core.
- OXC and Wasm use the same VM, heap, roots, values, dispatch, and activations.
- No legacy semantic fallback, guest JIT, executable-memory path, or sibling
  build dependency remains.
- From a clean build, verify workspace checks, CLI behavior, the complete
  Test262 and Wasm inventories, and the scoped Node framework gate against task
  24's baseline with compare-runs.
- Record source/build provenance and the deletion audit. Performance work
  waits for task 86's final Stage A verification.
