# 10: Extend the direct OXC specializer

## Outcome

Compile complete modern JavaScript directly from OXC ASTs into the verified residual program.

## Current gap

The reference generating extension handles an ES5-oriented subset, while Quench's complete syntax currently flows through a separate reducer and operation model that must not survive cutover.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Use one exact OXC version for parsing and semantic facts; distinguish Script, Module, and Eval goals and preserve source diagnostics.
2. Extend lexical-address, capture, declaration-instantiation, binding-time, effect, control-flow, liveness, and root-map analyses as data passes.
3. Lower all supported syntax through the macro-declared opcode vocabulary and canonical semantic operations; use side tables for rich metadata.
4. Reject only actual parse/early errors or explicit resource exhaustion; compact-domain overflow selects the wide representation.
5. Preserve v2's integrity rule: specialization may use syntax, constants, lexical facts, and bounded local patterns, never names, fixture identity, checksums, benchmark vocabulary, or whole-body matching.

## Verification

Add compile-only and execute tests per OXC syntax family, early-error differentials against Node/Test262, residual verification/round trips, identifier-renaming controls, and small source-perturbation controls.

## Definition of done

- The next engine does not call the legacy reducer or execute legacy operations.
- Every emitted residual verifies before execution.
- Static facts have one analysis authority and exact dynamic fallback.

## Performance evidence

Report parse/specialization time, allocator capacity, residual size, and peak compile RSS on representative small and large sources.

## Implementation evidence

The OXC specializer now lowers both block and concise arrow functions through
the same residual closure path as ordinary functions. Arrow bodies receive the
same parameter/local analysis, capture conversion, and verifier checks; an API
regression executes `(x) => x + 1` through the next runtime.

Template literals now lower directly from OXC as ordered string-addition
operations, preserving interpolation evaluation order and cooked-template
diagnostics without introducing a second execution path. Lexical `let` and
`const` declarations use the existing analyzed local-slot representation.
Sequence expressions likewise compile as ordered residual expressions and
return their final value, preserving side effects without a legacy reducer.
Nullish coalescing is lowered with explicit null/undefined checks so falsy
non-nullish values remain observable and the right operand stays lazy.
Optional static and computed member chains now lower through a guarded
residual prefix that evaluates property keys only for non-nullish bases and
returns `undefined` otherwise; the subset suite covers both ordinary and
chained optional access.
