# 10: Close Test262-driven OXC lowering gaps

## Outcome

Compile JavaScript directly from OXC ASTs into the verified residual program,
extending coverage in response to the full Test262 failure inventory.

## Current gap

The reference generating extension handles an ES5-oriented subset, while Quench's complete syntax currently flows through a separate reducer and operation model that must not survive cutover.

Regression against the reference subset (2026-09-23 core review,
`target/reviews/core-review-2026-09-23/`): the next core rejects pinned v2's
own bundled Richards, DeltaBlue, and Splay fixtures with `invalid residual
program: function N call is invalid` (`bytecode/validate.rs`, `Op::Call` /
`Op::CallKnown`). DeltaBlue and Splay also fail through the base.js harness.
The compiler emits call instructions that the validator's register-window or
known-target rules reject. This historical observation guides later performance triage; v2 parity is
not a Stage A requirement or a separate performance gate. Fix current lowering
failures required by the pinned Test262 inventory.

## Scope and implementation sequence

1. Use one exact OXC version for parsing and semantic facts; distinguish Script, Module, and Eval goals and preserve source diagnostics.
2. Extend lexical-address, capture, declaration-instantiation, binding-time, effect, control-flow, liveness, and root-map analyses as data passes.
3. Lower all supported syntax through the macro-declared opcode vocabulary and canonical semantic operations; use side tables for rich metadata.
4. Reject only actual parse/early errors or explicit resource exhaustion; compact-domain overflow selects the wide representation.
5. Preserve v2's integrity rule: specialization may use syntax, constants, lexical facts, and bounded local patterns, never names, fixture identity, checksums, benchmark vocabulary, or whole-body matching.
6. Implement syntax and semantic lowering in failure-family slices. Start with
   the next unsupported constructs exposed by the Test262 sweep (currently
   destructuring/rest/spread as applicable); do not attempt a speculative
   "complete modern JavaScript" pass before the suite identifies demand.

## Verification

Use existing Test262 cases to drive OXC syntax-family coverage and early-error
behavior. Run only affected stages plus compare-runs during changes; full runs
belong at the designated gates. Keep suite inputs and the harness unchanged.
Retain units only for internals or scenarios absent from the suites. Inspect
residual verification and specialization decisions as part of implementation.

## Definition of done

- The next engine does not call the legacy reducer or execute legacy operations.
- Every emitted residual verifies before execution.
- Static facts have one analysis authority and exact dynamic fallback.
