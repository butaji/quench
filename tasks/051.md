# 051: Fix Splay benchmark output correctness (v8-v7 suite)

- **Theme:** vm_completeness
- **Executor:** codex
- **Depends on:** 050

## Context

A recorded run (`target/v8v7-forin-fix-splay.json`) shows Splay from the
v8-v7 suite producing `"output_equal": false` against Node — a correctness
bug, separate from and prior to any performance question about this
benchmark. No performance number from this benchmark means anything until
its output is correct.

## Scope
- Whatever quench-runtime code path Splay's tree operations exercise (bisect
  from the actual diff first — do not guess the subsystem)

## Deliverables
- Reproduce the mismatch with a minimal extracted case from Splay's actual
  operations (tree insert/remove/splay-rotate), not the full benchmark
- Diff quench's output against Node's for that minimal case to find the
  exact divergence point
- Fix the root cause; this is a correctness bug, not a performance one — do
  not paper over it with a workaround in benchmark code (benchmark code is
  measurement-only per `docs/benchmark-integrity.md`)

## Validation

1. Full v8-v7 Splay benchmark run: output matches Node exactly (`output_equal:
   true`)
2. A minimal differential test capturing the specific divergence, added to
   the regular test suite (not just fixed ad hoc)
3. `cargo test -p quench-runtime --lib` — no regressions
4. Re-run the full v8-v7 suite (once task 052 wires it up) to confirm no
   other benchmark's output regressed from this fix

**Fail condition**: fixing the specific reported case without a root-cause
test that would catch a recurrence is incomplete.
