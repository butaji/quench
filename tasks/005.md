# 005: Event-loop tick ordering: setImmediate/microtask vs stream pipe finish/write-callback

- **Theme:** event_loop_ordering
- **Executor:** codex
- **Depends on:** (none)

## Context

This is what the live codex session in this same repo has been working on
directly (observed via `herdr agent read` on pane wCF:p1, 9h49m+ elapsed at
time of writing). Confirmed failure shapes from its own repro scripts:

- `Readable.pipe(Writable)` — a `setImmediate` callback scheduled *outside*
  the pipe (before or alongside it) was not observed to fire in the expected
  tick relative to the writable's internal `write()` callback and `'finish'`
  event
- A minimal repro (`const r=Readable.from([{}]); const w=new Writable(...);
  r.pipe(w);` plus an outer `setImmediate`) failed with "outside immediate
  not called" — isolating this to pipe-triggered scheduling, not
  `setImmediate` in general (a bare `setImmediate` with no pipe involved
  passed)
- `Readable.from()`'s async-iterator-source settle/reject path had a bug
  already fixed in that session's own uncommitted edit to
  `stream_prelude.js` (wrapping `Promise.resolve(result).then(...)` to
  handle both promise and non-promise `result` via an explicit `settle`/
  `reject` split) — check `git diff -- crates/quench-node/src/modules/stream_prelude.js`
  for what's already in flight before duplicating work

Relevant files already identified in that session: `crates/quench-node/src/modules/stream_prelude.js`,
`crates/quench-node/src/js_runtime_*` pump/event-loop dispatch, `pump.rs`
(host-side timer/immediate poll), `globals_tail.rs`
(`__quench_timer_poll`/`setImmediate` glue).

## Scope
- The host-side event-loop tick/turn boundary (immediate queue vs
  microtask/promise queue vs timer queue ordering) and its interaction with
  `stream_prelude.js`'s pipe/write/finish state machine
- Do not touch unrelated modules

## Deliverables
- `setImmediate` callbacks scheduled around a `.pipe()` call fire in the
  same relative tick order Node does, verified against real Node
  (`node --version` fixtures under `tests/node/test/parallel`, not just the
  ad hoc `/tmp` repros already used this session)
- The stream-pipe finish/write-callback fixtures below passing

**Fail condition:** step 3 not improved, any regression in steps 4-5.

## Non-goals
- Do not just make the specific `/tmp` repro scripts from the live session
  pass — those were diagnostic, not the gate. Fix the underlying ordering
  rule (documented in Node's docs: `setImmediate` runs in the "check" phase
  after I/O callbacks in the same turn; microtasks/promises drain between
  every phase transition) so it generalizes.
