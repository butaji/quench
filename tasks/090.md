# 090. Avoid giant generic functions

**Phase:** Native code quality  
**Prerequisites:** 089

## Intent

Split semantic subsystems to preserve instruction-cache locality and inlining quality.

- The dispatcher’s canonical hot-path input is one immutable operation record: `(opcode, receiver, arguments, execution context)`. The dispatcher borrows this record for one call and returns one completion (`value`, `throw`, or `pending`); it does not own receiver/argument values or queue storage.
- Hot code owns only opcode classification, compact dispatch-table lookup, and completion handoff. Each semantic subsystem owns its cold handler and any subsystem-specific decoding, validation, host effects, and error construction; handlers must not mutate the dispatch record.
- The record is created at the call boundary, remains valid through the handler call, and is released by the caller after completion. A handler may retain values only by using the runtime’s existing rooted/queued ownership mechanism; raw borrowed references must never escape.
- Invalid states are an unknown opcode, a malformed record (missing context or inconsistent argument span), and a handler that returns without a completion. These states go exclusively to a cold error path; the hot dispatcher must not construct errors, scan all subsystems, or duplicate semantic state.
- A dispatcher change is acceptable only when hot-path code size stays within the repository’s existing native size limit and cold semantic handlers remain independently measurable and callable.

## Focused dispatcher-locality evidence

- Add/run one focused dispatcher script through both Node and `quench-node`: repeatedly invoke a valid operation from one subsystem, then exercise an unknown opcode, malformed arguments, and a throwing handler. Assert identical stdout/stderr, exit status, thrown error class/message, and host-boundary effects; keep the error cases outside the steady-state loop.
- Capture the dispatcher’s generated symbol/assembly or compiler size report and show that the hot entry point contains only classification, table selection, and handoff (no subsystem error construction or broad semantic switch). Record hot-entry and cold-handler sizes.
- Run the repository’s full runtime suite after the focused check. Record wall time and peak RSS for the focused workload before/after the change (and operations/second when applicable); state the measured tradeoff rather than treating locality as an unmeasured assumption.

## Architecture contract

- Define the canonical runtime data shape, ownership, lifecycle, and invalid states before editing code.
- Preserve complete slow-path JavaScript semantics; derive any fast path, cache, or native path from the same facts.
- Keep effects at the host boundary and remove duplicate representations rather than adding compatibility shims.

## Definition of done

- Canonical data shape, ownership, lifecycle, and invalid states are documented before implementation.
- Complete slow-path JavaScript semantics remain authoritative; optimized paths are derived from the same facts.
- Focused evidence proves the invariant and compares Node with quench-node for output, exit status, errors, and boundary behavior.
- Before/after quench-node efficiency evidence records wall time and peak RSS, plus throughput when applicable; the stated budget or measured tradeoff is explicit.
- No duplicate semantic model, placeholder, or speculative abstraction remains; size limits and focused tests are satisfied.
