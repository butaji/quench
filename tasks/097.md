# 097: Tune M4 code generation and production tier policy

## Outcome

Qualify profitable native execution policy and machine-code quality on this Apple M4.

## Current gap

Build profiles, ARM admission modes and current physical recipes need matched
native-code and amortization evidence. Architecture-specific modes remain
diagnostic until they pass the shared contract, native-entry and M4 qualification
gates; their
mode-by-mode failures are recorded in the
[execution-profile contract](../docs/execution-contract-tests.md), not repeated
in this task.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering live there.
Profiled subsystem work in task 096 may run independently and cannot block this
qualification milestone.

## Scope and implementation sequence

1. Inspect representative generated code for dispatch, spills, redundant checks, branches, literal traffic and hot/cold placement.

2. Compare rustc/codegen options, register conventions, layout and CPU-specific/SIMD variants with exact arithmetic and alias proofs.

3. Tune compilation thresholds, cache/region budgets and invalidation policy from warmup/churn data; preserve interrupts and safe exhaustion.

4. Enable only the policy whose complete candidate mode has passed the same
   342-contract, native-entry and M4 evidence gates; make that qualified general
   baseline default on supported M4/macOS configurations. Keep experimental
   modes opt-in and retain safe fallback for unavailable artifacts/features.

## Verification

Production and profiling builds; full runtime, Node, Test262 and 342 contracts; complete V8-v7 and reserved micros. Test cold startup, repeated hot execution, churn, disabled artifacts, unsupported CPU features and teardown.

Apply the shared [completion checks](README.md), including named baseline failures
and independent semantic controls. Record commands and artifact identity.

## Definition of done

- Guard-eligible ordinary execution reaches the qualified general JIT without
  test-only activation; every rejected or unsupported path retains exact fallback
  semantics.
- All retained tuning has reproducible benefit beyond uncertainty with no unresolved semantic regression.
- Compilation/startup/code/cache/RSS tradeoffs and comparator ratios are published; policy limits have measured justifications.

## Performance evidence

Final qualification milestone: report full-suite and per-fixture V8-v7 scores
with uncertainty, including losses, plus matched Bun/JSC/Node comparator results
when available under the protocol. Completion certifies this measured milestone,
not fastest-VM status for all JavaScript.
