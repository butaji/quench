# 036: Verify and document the beyond-paper Optimizing tier as a kept, measured net win

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 035

## Context

`machine.rs` has a third promotion tier (`ExecutionTier::Optimizing`,
`OptimizingPlan`) beyond the paper's two tiers. Its own doc comment is
explicit: "a physical execution view, not a second semantic IR" — it
re-wraps the same baseline entries/stencil plans, gated to `x86_64`, with no
real instruction selection, register allocation, or speculation (so it needs
no deopt — it never speculates). User decision: keep it. This task is to
confirm it earns its keep and stop it from being mistaken for the paper's
(unimplemented) optimizing JIT.

## Scope
- crates/quench-runtime/src/machine.rs
- docs/deegen-alignment.md

## Deliverables
- Measure the neutral micro-corpus with the `Optimizing` promotion enabled
  vs. disabled (e.g. clamp `OPTIMIZATION_WARMUP_MULTIPLIER` effectively to
  never promote) to confirm it's a real, positive delta and not dead weight
  carried for free
- Document it plainly in `docs/deegen-alignment.md` (already drafted) and in
  a code comment at `ExecutionTier::Optimizing`'s definition: this is a
  quench-specific extra layer, not part of Deegen's own two-tier design, and
  never claims to be an optimizing compiler

## Acceptance
- A recorded before/after neutral-corpus measurement showing the tier is a
  net win
- No stale or misleading comment anywhere calls this "the optimizing JIT" in
  a way that implies paper parity

## Non-goals
- Building it out further into a real optimizing compiler (out of scope
  unless separately requested) — this task only verifies and documents what
  already exists
