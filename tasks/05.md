# 05: Establish engine and residual-program contracts

## Outcome

Define the final compile/execute boundary and a validated, versioned residual representation that scales beyond v2's ES5 subset.

## Current gap

V2 exposes `Engine::specialize` and `Vm::execute`, but its packed domains and decoder do not cover full Quench programs or comprehensively verify unsafe execution assumptions.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Define `Engine`, `SourceKind` (`Script`, `Module`, `Eval`), `ResidualProgram`, `Runtime<H>`, diagnostics, and explicit execution requests.
2. Keep the macro-declared opcode/effect/operand table authoritative; derive names, decoding, disassembly, profiling IDs, and validation from it.
3. Retain the eight-byte compact instruction and add a validated wide side-table form when registers, tables, targets, or immediates exceed compact domains.
4. Version serialized residuals with format and runtime-ABI fingerprints; reject mismatch, truncation, overflow, and trailing corruption before effects.
5. Verify function/table references, operands, branches, handlers, termination, defined-before-use, root maps, and nested/superinstruction contracts.

## Verification

Test compiler output, compact/wide boundaries, deterministic round trips, malformed and fuzz-generated inputs, and execution equivalence before/after serialization. Never execute a known-invalid residual.

## Definition of done

- Compiler output and decoded input pass one shared verifier.
- No source-size limit is introduced merely by compact encoding.
- Validation is outside the per-op hot path and failed validation has no host effects.

## Performance evidence

Measure residual size and validation/startup cost on the four reference workloads; no speed threshold applies yet.

## Implementation evidence

The imported crate now exposes `SourceKind`, `ExecutionRequest`, and an owning
`Runtime<H>` wrapper. `Runtime::execute` validates cross-function references,
branch targets, handler ranges, root maps, and call/closure targets before the
VM is entered. The residual wire format carries the `RQJ\0\x08` version
header and rejects truncation/trailing bytes in its decoder.

The isolated `quench-next` runner exercises this boundary without changing the
legacy `quench-node` production path; its `-e` smoke prints `42` through the
new host ABI.

Packed-domain overflow now lowers to a per-function wide side table. The
general interpreter resolves the marker before dispatch, wide functions use
conservative register roots, and the binary encoder/decoder preserves and
validates the side table before execution. A 4097-element literal executes
and round-trips through the residual format in the focused API test.

The shared verifier also accepts the compiler's unmapped-root sentinel, checks
mapped roots for every program-counter entry, and rejects register bits outside
the declared register domain before execution.

Serialized residuals now carry format version 8 plus an explicit runtime ABI
fingerprint; decoding rejects mismatches before reading tables or executing
effects, with focused coverage for ABI corruption and wide-instruction
round-trips.

The pre-execution verifier now rejects out-of-range constants, atoms, cache and
method/field/object sites, locals, registers, packed operands, call argument
ranges, and constructor/array bounds. Focused malformed-program tests cover
constant, field, and call references; the all-target runtime-next suite passes
57 unit, 1 module-structure, and 204 subset tests with warnings denied when all
profile features are enabled.
Binary residual decoding invokes the same verifier before returning a program,
so malformed table references cannot be handed to an execution caller.
The verifier now distinguishes ordinary `GetField` atoms from the nested-field
site operand used by fused/nested loads; this keeps valid property programs
from being rejected while retaining bounds checks for both representations.

Reachable control flow is now validated before execution: ordinary fallthrough
past the function body is rejected, handler entry paths are included, and
terminal return-register operations plus intentional infinite loops remain
valid. This closes the unchecked `pc` read invariant without adding a hot-path
branch. Validation evidence: 58 unit tests, 204 aggregate subset tests,
module-size guard, strict all-target clippy, and differential self-test pass.
