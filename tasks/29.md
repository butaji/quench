# 29: Measure property-access inline caches

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select changes only for a
measured V8-v7 Score or RSS gap; this is not a stage-completion gate. Use
affected suite scopes during changes. The current dependencies in
[index.json](index.json) supersede older prerequisite claims.

## Outcome

Use shape-guarded field-site caches for `GetProp`/`SetProp` and statically
known computed keys, with the generic property resolver as the exact fallback.
Keep field lookup and method-call target caching as distinct semantic tables.

## Current state and gap

Quench already has direct field-site indexing, bounded megamorphic field tables,
static computed-string lowering, GC invalidation, and a generic fallback. V2
task 121's direct field-site index is therefore already represented. The
remaining candidate is narrower: Quench caches inherited-property reads and
checks prototype ownership on cache hits, while v2 task 128 retained a smaller
own-property cache and used the generic resolver for prototype reads. Measure
whether an own-property-only fast path improves Quench before changing it.

The v2 evidence supports a bounded experiment, not an assumed win. Task 127's
depth census measured own/inherited hits of 149,463,457/2,054 for Richards,
85,238,955/91,487 for DeltaBlue, and 47,606,399/427 for Splay, with no
depth-two-or-greater hits. Task 128's seven-run predecessor comparison improved
Score by 27/11/36 on Richards/DeltaBlue/Splay; RSS was unchanged for DeltaBlue and rose
by one 16 KiB page for Richards and Splay. Its eleven-run final ratchet also
includes later task 129 changes, so those final totals do not isolate the
own-property cache. See [v2 task 127](../../v2/tasks/127-field-cache-depth-profile.md)
and [v2 task 128](../../v2/tasks/128-own-property-field-cache.md).

Quench's current depth histogram cannot yet support that census: all four
`field_cache_hit` call sites pass literal depth zero, including inherited read
hits, even though each cached read carries its resolved `FieldCache.depth`.
First make aggregate profiling report the actual read depth while keeping
production profiling overhead absent; depth-zero stores remain depth zero by
their existing guard. Do not select the cache change until the corrected
Quench census and matched task 62 baseline show a relevant opportunity.

V2 task 122's direct megamorphic method index was removed after its expanded
paired run; it is negative evidence for extending field-cache indexing to
method caches. Quench uses separate field and method site namespaces. Preserve
that separation; where a method site refers to a field site for callee loading,
keep the reference explicit rather than aliasing the namespaces.

## Scope and implementation sequence

1. After task 62 supplies the matched baseline, fix the aggregate depth
   counters and census own versus inherited cache hits, prototype validation
   work, entry size, and invalidation cost on affected V8-v7 workloads. Reuse
   the direct field-site table already present; do not rebuild its site index.
2. Compare the current cache with an own-property fast path that routes
   inherited reads through the generic resolver. Preserve exact behavior for
   getters, proxies, prototype mutation, accessors and shape transitions.
3. Treat a prior-shape-to-new-shape store transition as a separate candidate.
   The current miss path performs the generic mutation and then records the
   resulting shape. Add a transition fast path only if Quench measurements
   identify meaningful cost and a guard can preserve exact fallback behavior.
4. Keep cache admission based on semantic shape, slot and descriptor facts;
   never use fixture identity or benchmark vocabulary.
5. Preserve GC invalidation and cache-root rules already in place. Verify
   megamorphic entries across collection rather than adding another cache
   lifecycle or hidden roots.
6. Keep field and method caches separate. Do not add a direct method-site
   overflow index unless a Quench census identifies a hot scan and paired
   Score/RSS runs justify the extra structure.

## Definition of done

- Every cache hit is guarded by facts that remain valid for that operation;
  the generic resolver remains the exact fallback.
- Any retained cache change has affected-case equivalence and paired
  Quench Score/RSS evidence. A negative experiment is removed and recorded.
- No behavior depends on fixture identity, checksums or benchmark markers.

## Performance evidence

Report own/inherited hit counts, prototype-check work, cache bytes and paired
Score/RSS changes for the affected V8-v7 benchmarks. The task 61 gate decides
whether the retained change improves the all-eight result.

## Implementation note

Computed accesses with a statically known string literal already lower to the
same shape-guarded `GetField` cache site as dot access; dynamic keys retain the
exact `GetIndex` fallback. Field-cache entries retain owner identity, owner
shape, slot and prototype depth. Stores currently cache depth-zero entries;
prototype reads use a guarded path. All field caches are invalidated at GC
boundaries so owner handles do not become hidden roots. Full megamorphic/GC
hit-rate qualification remains open.
