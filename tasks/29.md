# 29: Add property-access inline caches

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select this work only for a
measured V8-v7 Score or RSS gap; finishing it is not a stage-completion gate.
Use affected-stage checks plus compare-runs during changes. The current
dependencies in [index.json](index.json) supersede older prerequisite claims.

## Outcome

Give `Op::GetProp`/`Op::SetProp` (and computed-key variants) the same shape-guarded,
exact-fallback specialization that call sites already get from the method cache.

## Current gap

Correction: v2 already has shape-guarded field caches (monomorphic entry plus a
bounded megamorphic set) in flat VM-owned arrays indexed by the instruction's
site ID, and the next core imported them. The remaining work is prototype-depth
entries, guarded add-property transitions, and bounded polymorphism. Keep v2's
[inline-cache layout decision](../docs/v2/inline-cache-layout.md): cache state
stays in the flat arrays, not in or beside instructions. A cache hit must be
provable from the shape alone; while descriptor attributes live in a side table
(task 44), every "cached" write pays a hash lookup and is not an inline cache
in v2's sense.

Original gap statement:

`method_cache.rs` caches call targets by `(shape, proto)`, but plain property load
and store still walk the shape/descriptor chain on every execution. Property access
outnumbers method calls in most JavaScript, so this is the largest unspecialized
opcode class in the interpreter.

## Scope and implementation sequence

1. Extend the per-site cache representation used by `method_cache.rs` to cover
   property get/set, keyed on `(shape, offset)` for the monomorphic case and a
   megamorphic table beyond a fixed polymorphism degree, mirroring the existing
   2-slot-plus-overflow structure rather than inventing a second mechanism.
2. Add a shape-transition guard for stores that add a new own property, so a cached
   "add property X at offset N" entry is only reused when the receiver's prior
   shape matches exactly.
3. Reuse the existing cache invalidation and GC-liveness retention paths
   (`invalidate_method_caches`, `retain_live_method_caches`) for the new cache
   rather than duplicating clear/retain logic.
4. Cover computed-key access (`obj[key]`) once the key is observed to be a stable
   string constant at a given site; fall back exactly to generic lookup otherwise.
5. Preserve the integrity rule from task 10: cache admission may use shape, offset,
   and descriptor facts only, never fixture identity or benchmark vocabulary.
6. Guard prototype-depth entries with a prototype-chain validity cell (an
   explicit prototype validity guard) rather than re-checking each level's
   shape on every hit. The cell is owned by the prototype objects' shapes, and
   any prototype replacement or property transition on the chain trips it. It
   replaces task 08's per-chain invalidation walk for these entries. Retain it
   only if it wins the paired gate against the per-level check.
7. Key the site cache by the essential internal method (`Get`, `Set`, `Has`,
   `DefineOwnProperty`, `Call`) as well as by shape. Property access, `in`,
   method calls, and task 34's `@@iterator` lookup then share one site
   mechanism, in the way that every Smalltalk operation is one message send.
   There is no per-operation cache family.
8. Cache-degree transitions (uninitialized, monomorphic, polymorphic,
   megamorphic) only move up between the named resets in the README. A
   megamorphic site does not return to monomorphic until a reset.
9. Confirm `Compiler::cache_site` draws from the same site-numbering space
   `ResidualProgram` already uses for `method_sites`/`field_sites`/
   `object_sites`, and that adding property-access cache sites to it cannot
   collide with existing method-cache site numbers; if there are actually
   separate counters today, unify them onto one before wiring the new cache
   in.

## Definition of done

- Generic property access remains correct and is the exact fallback for every
  cached path.
- Cache hit/miss behavior is covered by tests, not asserted only by benchmark
  score.
- No behavior depends on fixture identity, checksums, or benchmark markers.

## Performance evidence

Report hit rate, cache size/RSS delta, and opcode-level dispatch time for
property-access-heavy workloads alongside the existing Richards/DeltaBlue/Crypto/
Splay suite.

Implementation note: computed accesses with a statically known string literal
now lower to the same shape-guarded `GetField` cache site as dot access; dynamic
keys retain the exact `GetIndex` fallback. Field-cache entries now retain the
owner identity, owner shape, and prototype depth, so guarded prototype reads
can hit the same monomorphic/megamorphic tables while stores require depth
zero; all field caches are invalidated at GC boundaries so owner handles do
not become hidden roots. Full megamorphic/GC hit-rate verification remains
open.
