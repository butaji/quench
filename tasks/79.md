# 79: Make strings and number conversion fast and small

## Outcome

Strings use one representation lattice (flat Latin-1, flat UTF-16, rope,
slice, and interned atom) with named transitions between its states. The
common string operations, and conversions between numbers and strings, run in
time proportional to their output, with no avoidable allocation.

## Current gap

Task 50 makes UTF-16 with a Latin-1 form the single authority and adds a
concatenation builder. That covers footprint and repeated `+=`. It does not
cover substring views, hash caching, number-to-string conversion, or fast
search, which dominate RegExp, EarleyBoyer, and Splay (`"String for key " +
key` payloads). v2 evaluated ropes (160), inline short payloads (277), and
UTF-16 re-encoding costs (284).

## Scope and implementation sequence

1. Declare the lattice as one cell kind with explicit transitions: rope to
   flat (flattening), slice to flat (on GC when the parent would otherwise die,
   so a small slice never keeps a large parent alive), and flat to atom
   (interning). Every consumer reads through one flat-view operation.
2. Slices: `substring`, `slice`, `substr`, and RegExp captures return a slice
   above a named minimum length derived from the header cost, and a copy below
   it.
3. Cache each string's hash in its header once computed. Property keys that
   are strings intern to atoms, so key comparison is identity comparison.
4. Number to string: shortest round-trip conversion (Ryu-family algorithm
   meeting the `Number::toString` specification), a static table for small
   integers, and a bounded number-string cache whose size comes from the
   paired gate.
5. String to number and `parseInt`/`parseFloat`: a single-pass Latin-1 fast
   path with the full grammar as the reference definition.
6. Search, compare, and case mapping: `indexOf`, `includes`, `split` with a
   string separator, and comparison use SIMD-accelerated byte search on
   Latin-1 (for example, the `memchr` crate) and word-at-a-time comparison.
7. `Array.prototype.join` and template literals compute the output length
   first and build one flat string.

## Verification

The Test262 `built-ins/String`, `Number.prototype.toString`, `parseFloat`,
and `parseInt` inventories. Round-trip property tests for number conversion
against the reference definition. GC tests showing that slices do not keep
dead parents alive.

## Definition of done

- One string cell kind with a named state lattice. Every transition is
  explicit and counted.
- No retained string operation is quadratic in the length of its input or
  output.
- Slices never extend a parent's lifetime beyond the slice's own reachable
  bytes plus the named bound.

## Performance evidence

Report string bytes by state at peak, flatten and slice counts, and hash
recomputations, plus the paired gate on RegExp, EarleyBoyer, and Splay.
