# 22: Close tracked Node compatibility at the frozen legacy baseline

## Outcome

Make every tracked Node compatibility fixture that the legacy engine implements
(task 19's frozen passing set) pass on the next engine with exact local-Node
behavior. Fixtures outside that set are not a gate; they may be fixed, but only
added to the set, never used to excuse a regression.

## Current gap

Core adaptation does not cover the full tracked inventory: scheduling, events, streams, network/protocols, workers/processes, crypto, compression, diagnostics, and web/special modules remain.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Port timers/microtasks/async context (on task 53's readiness-driven phase loop and single microtask queue), events, streams/backpressure, net/DNS/HTTP/TLS, workers/child processes/cluster, crypto/security, zlib, diagnostics/observability, WASI, and web/special modules through capabilities. Preserve real host effects and remove inert stubs used as false positives.

## Verification

Run every fixture under `tests/node-compat` discovered by `quench-node-test`; compare values, descriptors, identity, ordering, errors, exit status, stdout/stderr, filesystem/network effects, and callback order with local Node.

## Definition of done

- Every fixture in the frozen legacy passing set passes; none crashes or times
  out, and the set was not edited to reach that result.
- Every pass executes its assertions and required host effects.
- No Node module reaches into runtime internals or the legacy engine.

## Performance evidence

Report startup, representative I/O throughput, event-loop latency, and RSS without imposing a cutover threshold.
