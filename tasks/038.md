# 038: Build the gradual Deegen-mechanism validation curriculum

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 037

## Context

`quench-bench/micros/` is a neutral 100-case general-JS regression corpus and
must not be repurposed — tasks 027-037's gates depend on it staying exactly
as-is. Full design for this new, separate suite is in
`docs/deegen-micro-curriculum.md` — read it in full before starting. Short
version: a new `quench-bench/deegen-curriculum/` directory, numbered
`001.js` upward, where each case is a general/neutral JS program (never one
that detects the engine, per `docs/benchmark-integrity.md`) proving one
specific paper mechanism engages, verified via `execution_trace`/
`tier_profile()` instrumentation counters — not just oracle-match output.

Case count is not fixed at 100 or any other number — build as many as each
stage genuinely needs (positive-engagement case + fallback/degrade-path
case, per mechanism), per the 10-stage curriculum in the design doc.

## Scope
- New: `quench-bench/deegen-curriculum/` (manifest.json + numbered `.js`
  cases, per the design doc's manifest shape)
- New: `quench-bench/deegen-curriculum/deegen-verify.mjs` (same CLI contract
  as `micros/verify.mjs`, plus instrumentation-expectation checking against
  the `execution_trace` JSON report)
- crates/quench-runtime/src/execution_trace.rs — extend counters only if a
  stage's `expect.instrumentation` needs a signal that doesn't exist yet
  (e.g. call-IC hit-state counters, region-stencil selection hit counters,
  stub-chain length) — additive, feature-gated, zero cost when disabled,
  matching this file's existing discipline

## Deliverables
Build stage by stage, in the order given in `docs/deegen-micro-curriculum.md`
(stages 1-10). For each stage:
1. Author the cases (positive-engagement + fallback/degrade-path pairs where
   applicable)
2. Add/confirm the instrumentation counter each case's `expect` block needs
   actually exists and is exposed in the JSON report
3. Run `deegen-verify.mjs` for that stage's case range and confirm both the
   oracle-match AND the instrumentation assertion pass
4. Do not proceed to the next stage until the current stage is green —
   stages 7-8 are gated on tasks 033/030/031/034 landing first; if you reach
   this task before those are done, build stages 1-6+9-10 first and return
   for 7-8 once their prerequisite tasks close

## Validation

1. `node quench-bench/deegen-curriculum/deegen-verify.mjs --engine target/debug/quench-node --oracle node --from 1 --to <N>` — every case reports both oracle-match AND its declared instrumentation assertion satisfied
2. For every mechanism marked Present in `docs/deegen-alignment.md`'s status
   table, confirm at least one curriculum case exists proving it engages, and
   (where the mechanism has a documented degrade/fallback path) at least one
   case proving that path is also correct — cross-check the table row by row,
   don't just count cases
3. Stage 10 (adversarial fallback-safety) cases must pass with the SAME
   correctness as stages 1-9 even though they deliberately defeat every fast
   path — a failure here is a correctness bug in the fast-path guards, not a
   suite bug
4. `cargo test -p quench-runtime --lib` still passes (any counters added to
   `execution_trace.rs` must be feature-gated and zero-cost when
   `execution-trace` is disabled — confirm with `cargo test -p quench-runtime
   --lib --no-default-features` too)
5. Record final case count, per-stage breakdown, and a link to this
   curriculum's location in `docs/architecture-evidence.md`, clearly labeled
   as a mechanism-verification suite distinct from the neutral-corpus
   perf-regression snapshot already recorded there

**Fail condition**: a case that passes oracle-match but whose instrumentation
assertion is skipped, hardcoded to always pass, or removed to make the suite
green is worse than not having the case at all — it would hide exactly the
kind of "present in name only" gap this session's audit already found once
(task 032's quickening naming). Treat a failing instrumentation assertion as
a real finding to report, not an obstacle to route around.

## Non-goals
- Modifying `quench-bench/micros/` — it stays exactly as-is
- Treating this suite's timing numbers as regression-gate evidence — that
  role stays with the neutral corpus; this suite is correctness+engagement
  evidence
