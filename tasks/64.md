# 64: Preserve implemented Node async context

## Outcome

Preserve promise hooks and async-context behavior observed by task 19’s frozen
implemented Node cases. Share runtime job transitions and root lifecycle
operations. Additional hook APIs and allocation targets are not Stage A gates.

## Current gap

Audit the observations below against the frozen inventories before implementing
changes. Fix only remaining required behavior; existing correct paths need no
replacement. Historical observations are not proof of a current failure.

- Legacy `quench-node` implements `async_hooks` through a `PromiseHook`
  capability (`crates/quench-node/src/host.rs`,
  `HostCapabilityKind::PromiseHook`) over legacy promise internals.
- Tasks 09 and 17 define the job queue and promise state machines but no hook or
  context-propagation point. Only task 22 mentions "async context", and it is a
  host task that cannot add runtime behavior.

## Dependencies

See this task's `depends_on` in [index.json](index.json). Task 22 checks the
async-context observations required by the frozen implemented cases directly;
the optional mechanisms below add no independent gate.

## Required scope and optional mechanisms

Stage A implements only the behavior observed by the pinned Test262 inventory or
task 19's frozen implemented Node cases, and the internal lifecycle/safety
invariants needed to run them on the single VM. The mechanisms below are
implementation options within that scope, not a requirement to expand Node
coverage or finish a broader host/architecture rewrite.

1. Define the promise lifecycle events (init, before, after, resolve) as named
   transitions of task 17's promise and job state machines. Emit them only when
   a hook is installed, and never allocate otherwise.
2. Add one continuation-preserved context slot, held as a `RootId`-rooted value
   in the realm. Every job (promise reaction, thenable job, async resumption,
   FinalizationRegistry cleanup) captures the slot at enqueue and restores it
   around the run. This is the same mechanism as V8's continuation-preserved
   embedder data, and it matches the TC39 AsyncContext proposal's snapshot
   model.
3. Expose install, remove, get, and set through the host facade (task 43). Hooks
   are host capabilities that receive borrowed handles, per task 09.
4. Define hook re-entry and hook exceptions as explicit transitions: a throw
   from a hook follows the host's rule and does not corrupt job state.

## Verification

Compare the tracked `async_hooks` and `AsyncLocalStorage` node-compat fixtures
with the local Node oracle, including context across `await`, `then`, timers,
and `queueMicrotask`. Rust regression tests cover capture/restore ordering and
hook-less zero allocation. Run affected Test262 stages plus compare-runs; retain
units only for internal invariants or scenarios absent from the pinned suites.

## Definition of done

- Frozen implemented Node cases for hooks and async context match the local Node
  oracle, including re-entry, ordering, errors and identity.
- Required context transitions share one authority and preserve root and
  lifecycle invariants across the job kinds those cases exercise.
- New hook APIs, unimplemented cases and allocation targets do not add gates.
