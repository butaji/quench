# 64: Expose promise and job hooks for host async context

## Outcome

The runtime exposes the hooks that Node's `async_hooks` and
`AsyncLocalStorage` need: promise lifecycle hooks and a per-job context value
that the runtime carries from job enqueue to job run. The host decides what the
context value means; the runtime only preserves it.

## Current gap

- Legacy `quench-node` implements `async_hooks` through a `PromiseHook`
  capability (`crates/quench-node/src/host.rs`,
  `HostCapabilityKind::PromiseHook`) over legacy promise internals.
- Tasks 09 and 17 define the job queue and promise state machines but no hook
  or context-propagation point. Only task 22 mentions "async context", and it
  is a host task that cannot add runtime behavior.

## Dependencies

See this task's `depends_on` in [index.json](index.json). Task 22 depends on
this task.

## Scope and implementation sequence

1. Define the promise lifecycle events (init, before, after, resolve) as named
   transitions of task 17's promise and job state machines. Emit them only when
   a hook is installed, and never allocate otherwise.
2. Add one continuation-preserved context slot, held as a `RootId`-rooted
   value in the realm. Every job (promise reaction, thenable job, async
   resumption, FinalizationRegistry cleanup) captures the slot at enqueue and
   restores it around the run. This is the same mechanism as V8's
   continuation-preserved embedder data, and it matches the TC39 AsyncContext
   proposal's snapshot model.
3. Expose install, remove, get, and set through the host facade (task 43).
   Hooks are host capabilities that receive borrowed handles, per task 09.
4. Define hook re-entry and hook exceptions as explicit transitions: a throw
   from a hook follows the host's rule and does not corrupt job state.

## Verification

Compare the tracked `async_hooks` and `AsyncLocalStorage` node-compat fixtures
with the local Node oracle, including context across `await`, `then`, timers,
and `queueMicrotask`. Rust regression tests cover capture/restore ordering and
hook-less zero allocation. Test262 must not regress.

## Definition of done

- One context slot and one hook table, both owned by the runtime and set only
  through the facade.
- Every job kind captures and restores context exactly once.
- With no hook installed, promise and job paths do no extra allocation.

Report promise/job overhead with and without hooks installed. Measurement only.
