# 001: child_process: fork() + IPC channel messaging

- **Theme:** ipc_foundation
- **Executor:** codex
- **Depends on:** (none)

## Context

A partial `run-parallel --all` sweep this session (timeout=5s, isolated build,
covering only the alphabetical prefix a..child-process before the run was
aborted) showed nearly every `test-child-process-*` fixture failing or timing
out, including the basics: `test-child-process-ipc.js`,
`test-child-process-fork-and-spawn.js`, `test-child-process-fork-exec-argv.js`,
`test-child-process-kill.js`, `test-child-process-exit-code.js`,
`test-child-process-detached.js`, `test-child-process-can-write-to-stdout.js`.
This is a systemic gap, not scattered edge cases — cluster (003) and dgram
reuseport (004) both fork workers and inherit whatever is broken here, so
this task blocks them.

`crates/quench-node/src/modules/child_process.rs` exists (some spawn support
is present, e.g. stdio pipes for `exec`), but `fork()` — a Node child process
running quench-node itself with an IPC channel on fd 3 — and `.send()`/
`process.send()`/`'message'` event plumbing are the suspected missing piece.
Confirm the actual gap by reading the module before assuming; do not treat
this Context as a substitute for reading the current code.

## Scope
- `crates/quench-node/src/modules/child_process.rs` and any process-spawn
  plumbing it depends on in `quench-runtime`/`quench-node` (event loop
  integration, pipe/fd handling)
- `child_process.fork()`, the IPC channel (`process.send`, `child.send`,
  `'message'`/`'disconnect'` events, `child.channel`, `.disconnect()`)
- Whatever `test-child-process-ipc.js`, `test-child-process-fork-and-spawn.js`,
  `test-child-process-fork-exec-argv.js`, `test-child-process-kill.js`,
  `test-child-process-detached.js`, `test-child-process-exit-code.js` actually
  require to pass — read each fixture, don't guess the API surface

## Deliverables
- A real IPC transport between a quench-node parent and a forked quench-node
  child (in-process or OS-process — pick whichever the current process/spawn
  architecture supports; must stay 100% Rust, no shelling to a real `node`
  binary)
- `process.send`/`child.send`/`'message'` event delivery, `'exit'`/`'close'`
  with correct codes, `.kill()` semantics
- The fixtures below passing

## Non-goals
- Windows named-pipe IPC semantics (this runtime targets POSIX)
- `child_process.fork()` with a real separate OS process if the current
  architecture only supports in-process child emulation — that's fine as
  long as the observable JS-level behavior (events, timing, exit codes)
  matches what the fixtures assert
