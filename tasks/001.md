# 001. Make execution stackless

**Phase:** Foundation and execution model  
**Prerequisites:** none

## Intent

Replace Rust-recursive JS calls with explicit Vec<Frame> or frame-arena transitions; verify native stack depth stays flat.

## Architecture contract

- Define the canonical runtime data shape, ownership, lifecycle, and invalid states before editing code.

## Current implementation contract

The canonical suspended-call shape is `Completion::Call(CallContinuation)`.  A continuation owns the callee, receiver, argument vector, immutable caller instruction slice, caller program counter, caller register window, caller environment reference, destination register, and opaque guard flags.  `Machine` owns the active frame stack and a LIFO `Vec<CallContinuation>` for callers suspended at ordinary-call boundaries; tail calls remain transition requests and do not allocate a caller continuation.

The dispatch lifecycle is: execute an operation until it produces a completion, flush pending declaration batches at the transition boundary, move the completion into the machine-owned transition state, execute/resume the callee, then restore the saved caller window/environment and write the result to its destination.  `Completion::Call` and `Completion::TailCall` are invalid at the public value boundary and must be consumed by the machine transition loop; `Throw`, `Return`, `Yield`, and `Suspend` remain observable completion states.

The remaining implementation gap is wiring every ordinary `Call` opcode through this continuation lifecycle.  The storage and completion representation are present, while legacy synchronous invocation still exists in some VM dispatch paths and must be removed only after all caller/environment restoration paths are covered.
- Preserve complete slow-path JavaScript semantics; derive any fast path, cache, or native path from the same facts.
- Keep effects at the host boundary and remove duplicate representations rather than adding compatibility shims.

## Definition of done

- Canonical data shape, ownership, lifecycle, and invalid states are documented before implementation.
- Complete slow-path JavaScript semantics remain authoritative; optimized paths are derived from the same facts.
- Focused evidence proves the invariant and compares Node with quench-node for output, exit status, errors, and boundary behavior.
- Before/after quench-node efficiency evidence records wall time and peak RSS, plus throughput when applicable; the stated budget or measured tradeoff is explicit.
- No duplicate semantic model, placeholder, or speculative abstraction remains; size limits and focused tests are satisfied.
