# 71: Build a static call graph with per-function summaries

## Outcome

Before execution, the compiler knows which call sites have a statically
known callee. For every function it also knows a summary: arity, use of
`arguments`, `this`, `new.target`, and `super`, strictness, recursion, and the
effect set of a call. Known-callee sites bind arguments directly, and
facts in callers survive calls whose summary excludes `reenters`.

## Current gap

`binding_time::materialize_calls` emits `CallKnown` only for root-function
bindings with a single assignment. Task 31 plans to derive argument-binding
shortcuts from the runtime call-target cache, which needs a guard even when
the callee is statically known. Every call is treated as `reenters`, so no
heap or kind fact survives any call.

## Scope and implementation sequence

1. Add the call-graph domain to the binding-time analysis: a call site has a known callee when
   its callee binding is a function declaration or single-assignment binding
   in a closed scope with no writes. Extend this to every function, not only
   the root.
2. Derive each function's summary from its body: formal count, rest and
   default parameters, `arguments`, `this`, `new.target` and `super` use,
   strictness, and whether it is recursive. Store the summary on the residual
   function record, not as a side table.
3. Derive each function's effect set as the union of its body's opcode
   effect sets and its callees' summaries, with a fixpoint over recursive
   cycles. Unknown callees take `reenters`.
4. At known-callee sites with a matching arity and no `arguments` use, bind
   arguments directly into parameter slots where scope and parameter proofs
   permit it. Dynamic callees consume the same metadata from task 31, with
   exact callee guards or generic binding; observed stability is not proof.
5. Let task 57's kind facts and task 73's escape facts survive calls whose
   callee summary is at most `{allocates}`.
6. Lower `f.call(this, …)`, `f.apply(this, arguments)`, and calls through
   bound functions to direct calls, guarded by the protector on
   `Function.prototype.call`/`apply` (an explicit intrinsic identity guard).

## Verification

Test262 cases for `arguments` aliasing, default parameters, `new.target`,
`Function.prototype.caller` in sloppy mode, and reassignment of a function
binding through a closure, `eval`, or `with`. Task 42's gate. Compare with the existing generic path. Effect-domain transitions only move up its lattice.

## Definition of done

- Every summary field is derived from the body in the binding-time analysis.
- Static argument binding needs no runtime guard, and every other site keeps
  its generic or cached path.
- No summary's effect set omits an effect of any path it can execute.
