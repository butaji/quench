# 028: Audit and complete OSR-entry wiring end-to-end

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 027

## Context

Per the paper (§7.1): "OSR-entry is thus simply a branch to the right JIT
code location." `machine.rs` has `is_osr_candidate`/`is_osr_entry` computing
admission (back-edge branches/jumps only; `ForI` structured loops explicitly
excluded, per an existing code comment, because they have no bytecode
back-edge to resume from). What's unverified: whether the interpreter's
branch/jump dispatch path actually *consults* this and transfers control into
baseline-JIT code mid-loop, or whether it's computed and currently unused.

## Scope
- crates/quench-runtime/src/machine.rs
- crates/quench-runtime/src/vm/vm_runtime.rs
- crates/quench-runtime/src/loops.rs / loops_run.rs

## Deliverables
- Trace (and if missing, wire) the path from a hot back-edge branch/jump,
  through `is_osr_entry`, into an actual transfer to baseline-JIT-compiled
  code at the matching PC
- Confirm the `ForI` exclusion is correct as documented (no back-edge to OSR
  from) rather than a silently-dropped case; if a real gap, decide and record
  whether a second admission path for structured loops is worth adding
- Differential test: a hot loop that should OSR-enter produces identical
  observable output whether OSR fires or not

## Validation

1. **Trace, don't assume.** Add a temporary counter/log (or use the
   `execution-trace` feature) at the actual call site that would invoke
   OSR-entry; run a synthetic hot back-edge loop and confirm the counter
   increments — a code path existing is not evidence it fires.
2. Write a differential test: a loop with a hot back-edge, run once with OSR
   admission forced-enabled and once with it forced-disabled; assert
   identical observable output (values, iteration count, side effects).
3. Write a second test using a `ForI` structured loop; confirm it never
   attempts OSR-entry and still produces correct output via the ordinary
   path — this proves the exclusion is a real fallback, not a silent skip of
   the loop body.
4. `cargo test -p quench-runtime --lib` — both new tests pass, nothing else
   regresses.
5. `node quench-bench/micros/verify.mjs --engine target/debug/quench-node --oracle node --from 1 --to 100 --runs 3` — 100/100, geomean within noise of the task-027 baseline.

**Fail condition**: if step 1 shows the counter never increments under a
workload designed to trigger it, OSR-entry is not actually wired — that is
the finding to report, not something to paper over by writing the test
around the gap.

## Non-goals
- Any optimizing-JIT or deoptimization work — not paper scope
