# 65: Bound heap and resource exhaustion as explicit transitions

## Outcome

Implement the obligations below only where required by the pinned Test262
inventory, task 19's frozen implemented Node cases, or internal correctness
of those execution paths. Broader mechanisms are not completion gates.

Allocation failure and resource exhaustion are named runtime transitions with
one policy: a configurable heap limit, spec length limits, and a defined result
for each (a catchable `RangeError` where the spec or V8 throws one, otherwise
an uncatchable termination the host observes). Implement the required checked
allocation transitions and safe unwind behavior; a speculative workspace-wide
allocation policy does not block Stage A.

## Current gap

- The [README](README.md#checks-and-evidence) requires allocation failure
  to be an explicit checked transition, and task 24 tests allocation failure,
  but no task implements the policy.
- The heap has no configured limit (Node's `--max-old-space-size` has no
  equivalent), and Rust allocation failure in `Vec`, string, or backing growth
  aborts the process.
- Task 56 bounds stack depth only. Task 09 owns interrupt and termination, and
  this task reuses that transition for out-of-memory termination.

## Dependencies

See this task's `depends_on` in [index.json](index.json). Task 24 checks
required exhaustion outcomes and internal invariants directly; it does not

## Scope and implementation sequence

Stage A implements only the behavior observed by the pinned Test262 inventory
or task 19's frozen implemented Node cases, and the internal lifecycle/safety
invariants needed to run them on the single VM. The mechanisms below are
implementation options within that scope, not a requirement to expand Node
coverage or finish a broader host/architecture rewrite.

1. Define one resource-limit record owned by the runtime: heap byte limit,
   external-backing limit, and the named spec limits (maximum string length,
   array length, typed-array and ArrayBuffer byte length). Derive every check
   from this record, with no literals in individual builtins.
2. Route heap, property-storage, string, and backing growth through fallible
   allocation (`try_reserve` or equivalent) at the heap boundary.
3. Classify each exhaustion: spec length violations throw the realm's
   `RangeError`; heap-limit exhaustion first collects, then terminates through
   task 09's termination transition, which reports to the host and unwinds
   without running guest code.
4. Expose the limits and the out-of-memory event through the host facade, so
   `quench-node` can map its flags and report failure as Node does.

## Verification

Rust regression tests allocate past each limit, in interpreter and specialized
execution, and check the error or termination and that the heap stays
consistent afterwards. Compare `RangeError` messages for length limits with
the local Node oracle. Run affected Test262 stages plus compare-runs; retain units only for internal
invariants or scenarios absent from the pinned suites.

## Definition of done

- Resource limits and exhaustion observed by the pinned Test262 and frozen
  implemented Node cases have the required errors or termination outcomes.
- Changed allocation paths preserve root, unwind and heap invariants, and
  their limit policies have one authority.
- A new configurable heap policy or a workspace-wide allocation rewrite is
  not a separate gate; implement only what the suite and internal correctness
  obligations require.

## Implementation evidence

Replacement assembly now uses one transient checked UTF-16 slice plan in
String.replace/replaceAll and RegExp @@replace/GetSubstitution. It shares
canonical unit storage, merges adjacent slices, and stops growing on length
or reservation failure. Replacement effects continue in order; finalization
raises RangeError before materializing an oversized result. The limit is the
existing Node-compatible MAX_STRING_UNITS policy, verified against local
buffer.constants and V8's public String::kMaxLength. No guest rope, side map,
or serialized metadata is added.

Five focused Rust checks pass, including both compilation modes, binary round
trips, internal length/slice invariants, and existing GC-root regressions.
All 170 affected official cases and seven selected staged replacement cases
retain their passes with unchanged inventories. The previously killed
staging/sm/String/replace-math.js now passes. Fifteen outputs match Node,
including oversized regex/plain replacement, named getters after overflow,
all 600 callback effects, abrupt identity, UTF-16 surrogates and substitutions.
The complete current library audit passes 491 tests, zero failed/ignored.
Profile-memory checks pass. Evidence is in
`target/iteration/task20-string-growth-provenance.json`; raw suite comparisons
