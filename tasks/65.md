# 65: Bound heap and resource exhaustion as explicit transitions

## Outcome

Allocation failure and resource exhaustion are named runtime transitions with
one policy: a configurable heap limit, spec length limits, and a defined result
for each (a catchable `RangeError` where the spec or V8 throws one, otherwise
an uncatchable termination the host observes). The process never aborts on
guest-driven allocation.

## Current gap

- The [README](README.md#shared-completion-rules) requires allocation failure
  to be an explicit checked transition, and task 24 tests allocation failure,
  but no task implements the policy.
- The heap has no configured limit (Node's `--max-old-space-size` has no
  equivalent), and Rust allocation failure in `Vec`, string, or backing growth
  aborts the process.
- Task 56 bounds stack depth only. Task 09 owns interrupt and termination, and
  this task reuses that transition for out-of-memory termination.

## Dependencies

See this task's `depends_on` in [index.json](index.json). Task 24 depends on
this task.

## Scope and implementation sequence

1. Define one resource-limit record owned by the runtime: heap byte limit,
   external-backing limit, and the named spec limits (maximum string length,
   array length, typed-array and ArrayBuffer byte length). Derive every check
   from this record, with no literals in individual builtins.
2. Route heap, property-storage, string, and backing growth through fallible
   allocation (`try_reserve` or equivalent) at the heap boundary.
3. Classify each exhaustion: spec length violations throw the realm's
   `RangeError`; heap-limit exhaustion first collects, then terminates through
   task 09's termination transition, which reports to the host and unwinds
   without running guest code.
4. Expose the limits and the out-of-memory event through the host facade, so
   `quench-node` can map its flags and report failure as Node does.

## Verification

Rust regression tests allocate past each limit, in interpreter and specialized
execution, and check the error or termination and that the heap stays
consistent afterwards. Compare `RangeError` messages for length limits with
the local Node oracle. Test262 must not regress.

## Definition of done

- One record owns every resource limit.
- No guest-reachable allocation path aborts the process.
- Each exhaustion has one named outcome, and the host observes termination.

## Performance evidence

Report the cost of fallible allocation on the allocation-heavy V8-v7 fixtures.
Measurement only.
