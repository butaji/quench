# 052: Wire the v8-v7 benchmark suite into the tracked verification loop

- **Theme:** vm_completeness
- **Executor:** codex
- **Depends on:** 050, 051

## Context

`quench-bench/js-engine-benchmark/v8-v7` (the classic Octane-derived V8
benchmark suite: Richards, DeltaBlue, Crypto, RayTrace, EarleyBoyer, RegExp,
Splay, NavierStokes) currently only has stale, one-off JSON snapshots in
`target/` — no regular, reproducible tracking the way `quench-bench/micros/`
(`verify.mjs`) and `quench-bench/deegen-curriculum/` (`deegen-verify.mjs`)
already have. Once 050/051 unblock it from crashing/mismatching, this
suite is the actual comparison point for "how close to V8" — it should be
tracked the same rigorous way, not left as manual one-off runs.

## Scope
- New: a runner script following the existing `verify.mjs`/`deegen-verify.mjs`
  CLI pattern (`--engine`, `--oracle`, `--out`), adapted to this suite's own
  `BenchmarkSuite`/score-reporting format rather than the numbered-case
  manifest pattern (this suite's structure is fixed, imported wholesale from
  upstream — don't restructure it to fit the other harnesses' shape)
- `docs/architecture-evidence.md` — a new recorded snapshot section

## Deliverables
- Run all 8 benchmarks against quench-node and Node, recording: per-benchmark
  score, output-equality, wall time, peak RSS
- Record the aggregate score comparison in `docs/architecture-evidence.md`
  alongside the existing neutral-corpus and curriculum snapshots, clearly
  labeled as the v8-v7/Octane-derived comparison, distinct from both

## Validation

1. All 8 benchmarks run to completion (no crash, per task 050)
2. All 8 benchmarks report `output_equal: true` (per task 051 for Splay;
   confirm the other 7 too — do not assume they're already correct just
   because they weren't specifically flagged)
3. Recorded snapshot in `docs/architecture-evidence.md` with per-benchmark
   numbers, not just the aggregate score
4. `cargo test -p quench-runtime --lib` — no regressions

**Fail condition**: recording an aggregate score while any individual
benchmark's output doesn't match Node is misleading — every benchmark must
be correctness-verified before its score counts as evidence.

## Non-goals
- Performance tuning based on these numbers — that's tasks 053+; this task
  is measurement infrastructure only
