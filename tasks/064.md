# 064: String operation algorithmic-complexity invariants

- **Theme:** architecture_invariants
- **Executor:** codex
- **Depends on:** none

## Context

Same technique as 062/063, scoped to string operations. Task 046 already
found (profile-gated no-go) that curriculum case 032's real cost is
`trim().split(/\s+/)`, not concatenation — this task turns that one-off
finding into a permanent, general invariant instead of leaving it as a
closed investigation that could silently regress later.

## Scope
- `crates/quench-runtime/src/architecture_invariants.rs` (same module)

## Deliverables — invariants to pin
1. Single-append string-building cost (`s += x` in a loop) doesn't blow up
   superlinearly with total accumulated length — assert near-linear
   scaling (ratio-bounded, not strictly O(1) — concatenation of growing
   strings is inherently at least O(n) over the whole loop; the invariant
   is "not O(n²)", matching QuickJS's rope-threshold rationale read from
   `../quickjs/quickjs.c` during task 046).
2. `split`/`indexOf`/`includes` cost is proportional to input length, not
   to unrelated program state (total string count ever created, etc.).
3. String comparison (`===`, `<`) cost for equal-length strings is
   proportional to the compared length, not some larger unrelated
   dimension.
