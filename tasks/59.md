# 59: Reduce the kernel to a metacircular fundamental set

## Outcome

The next core is one kernel with a small, named set of **fundamental
primitives**. Every other operation is defined on top of that set: abstract
operations, builtins, exotic behavior, and opcode fallbacks. This is how a Lisp
defines itself from `eval`/`apply` plus a handful of primitives. Every other
kernel entry is an **accelerated** primitive with a library reference
definition, and deleting it changes speed, never behavior. This is the core that
remains after legacy is removed (task 27).

## Current gap

Task 46 declares the watermark tables and the fundamental/accelerated roles.
Task 47 derives the generating extension and checks the Futamura equation. Two
things remain open:

- No task bounds the fundamental set. Operations can keep landing in the kernel
  because declaring a row is cheap, and the kernel API grows to match whatever
  existed at the time of the split.
- The reference kernel (no accelerations) is only checked against Test262. The
  claim that everything is built on the fundamentals also has to hold for the
  frozen Node set and the Wasm suite.

## Dependencies

See `depends_on` in [index.json](index.json). This task needs the watermark
tables and reference kernel (46, 47) and the library families already on the
kernel API (11–18). Cutover (27) depends on it through task 24, so the legacy

## The fundamental set

Only these classes may hold `fundamental` rows. Each is irreducible because it
creates or inspects representation that nothing above the watermark can see:

| Class | Primitives |
| ----- | ---------- |
| Values | tag test and projection, primitive constructors, SameValue on raw representation |
| Strings | length, code-unit read, concatenation or builder, atom interning |
| Storage | cell allocation with a trace visitor, typed slot read/write, element and byte storage read/write |
| Objects | the essential internal methods (GetPrototypeOf, SetPrototypeOf, IsExtensible, PreventExtensions, GetOwnProperty, DefineOwnProperty, HasProperty, Get, Set, Delete, OwnPropertyKeys) dispatched through the object-kind table |
| Control | Call, Construct, throw/completion, activation suspend/resume |
| Lifetime | root, unroot, weak handle, finalization enqueue |
| Agent | job enqueue, realm intrinsic lookup by index, host capability call |

A row outside these classes is `accelerated`, or it moves to the library.
Adding a class is a reviewed change to this file. Its justification must be that
the representation cannot be observed through the existing classes.

## Scope and implementation sequence

1. Audit every primitive-table row. Mark it fundamental with its class, or
   accelerated with its reference definition, or move it to the library when it
   is only a composition of other rows. Record the counts before and after, per
   class.
2. For every accelerated row, check that its reference definition uses only
   fundamental rows. Checks that happen to hold because the accelerated
   definitions call each other do not count.
3. Build the reference kernel with every accelerated row replaced by its
   reference definition. Run the full Test262 inventory, the frozen Node set,
   and the Wasm suite on it. Every outcome must match the default kernel.
4. Generate the public kernel API reference from the table: one page, grouped
   by class, with effect class and static evaluability. This page is the
   contract a replacement kernel implements.
5. Remove the `Vm` methods, re-exports, and helpers that the audit left without
   a table row.

## Verification

- A structural check fails if a `fundamental` row has no class, or if an
  `accelerated` row has no reference definition or its reference definition
  reaches a non-fundamental row.
- The reference kernel matches the default kernel on all three conformance
  inventories (task 48 ratchet format).
- The crate graph still has no library-to-kernel-internal edge (task 46).

## Definition of done

- The fundamental set is closed, named by class, and documented from the table.
- Every other kernel entry is accelerated and removable without a behavior change.
- The reference kernel passes the same conformance run as the default kernel.

## Performance evidence

Report the row counts by class and role before and after, plus the reference
kernel's Test262 wall time. The reference kernel is a correctness oracle, not a
performance target.
