# 069: Crypto benchmark — profile and close the completion gap

- **Theme:** vm_completeness
- **Executor:** codex
- **Depends on:** 052

## Context

Crypto is one of the 5 v8-v7 benchmarks that did not complete within the
tracked runner's 10-second timeout, and unlike RegExp (053), NavierStokes
(054), and RayTrace/EarleyBoyer (055), no existing task owns it. Crypto is
bitwise/integer-arithmetic-heavy (a JS port of an RSA/bigint-style
implementation) — likely a different bottleneck class than the others
(string/regex, typed-array, allocation), so it needs its own investigation
rather than being assumed to be covered by one of them.

## Scope
- Investigation first — profile before assuming the subsystem
- Likely: bigint/large-integer arithmetic path, bitwise-op dispatch,
  array-of-digits manipulation (check what Crypto's actual JS source does
  before assuming)

## Deliverables
- Re-run Crypto alone with a long timeout (120s+) to get a real completion
  time first — don't assume it never terminates
- Profile where cost concentrates: bigint arithmetic, array manipulation,
  function-call overhead, or something else entirely
- Only if profiling justifies it: close the specific gap found, reusing
  existing mechanisms (region-stencil coverage, generic IC) rather than
  building Crypto-specific logic

## Anti-cheat validation (mandatory)

1. **Generalization check**: build a synthetic microbenchmark exercising
   the same operation class found to dominate Crypto's cost (e.g. bigint
   multiply-heavy loop, or whatever profiling actually finds), with
   different variable/function names and different literal moduli/constants
   than the real Crypto benchmark. The fix must help the synthetic clone
   comparably, not just the literal `crypto.js` file.
2. `grep -rniE "crypto\.js|BigInt_[a-z]+_helper|hex_digit_table" crates/quench-runtime/src crates/quench-node/src` (or whatever the benchmark's actual internal names turn out to be, checked directly, not guessed) — zero matches for anything that looks like fixture-identity detection.
3. Full gates: correctness suites, neutral corpus, curriculum, and full
   v8-v7 suite (task 052) — any fix must show general improvement across
   these, not just Crypto's own score.

**Fail condition**: closing this task with "no-go, Crypto is just slow" is
an acceptable outcome per this project's profile-gated discipline — but
only after actually profiling with a long enough timeout to see real
behavior, not from the 10-second timeout's absence of data alone.

## Non-goals
- Any change that only recognizes or special-cases Crypto's specific input
  values, moduli, or code shape — per the north_star anti-cheating
  constraint in `tasks/index.json`
