# 89: Run popular web frameworks on production quench-node

## Plan scope

Deferred outside the current two-stage strategy. This proposal adds no Stage A
suite gate, implemented Node membership, or cutover dependency. The retained
material below records prior investigation; it is not an active requirement.

## Outcome

Production `quench-node`, on the shared VM, runs Express, Koa, Fastify,
Hono, NestJS, h3/Nitro and Next.js applications without issues. Every
[`tests/frameworks`](../tests/frameworks/README.md) scenario matches local
Node, and every required fixture in
[node-framework-inventory.json](node-framework-inventory.json) passes.

## Scope and implementation sequence

Remove the package facsimiles and their registry entries first. Resolve real
packages through the ordinary CommonJS/ESM resolver, including `exports`
conditions and dual-format packages. Restore the affected `tests/node-compat`
cases with real packages through task 19's inventory process; do not delete
them.

Then close failures by dependency, running the affected scenarios after each
step:

1. Package loading for all seven frameworks: CommonJS/ESM interop,
   `require(esm)`, `exports`/`imports` conditions, and the `module` family.
2. `http` server/client core, `net`, `events`, `fs` and `path` together get
   Express, Koa and NestJS serving.
3. `stream`, `zlib` and `string_decoder`: piping, backpressure, `Readable.from`,
   compression and static files.
4. AsyncLocalStorage and `diagnostics_channel`: Fastify hooks, Koa/NestJS
   request context.
5. Web globals over Node streams: undici `Request`/`Response`/`Headers`,
   WHATWG streams and adapters, `TextEncoder`, `structuredClone`. These get
   Hono and h3 serving.
6. `tls`, `https` and `http2`: Fastify, h3 and Hono server variants.
7. Next.js production server: `vm`, `v8`, `perf_hooks`, `worker_threads`,
   `child_process`, `inspector`, `timers/promises` and `dns/promises`.

Keep Node behavior in `quench-node` and JavaScript semantics in the runtime,
with one authority per host operation. Production behavior must never depend
on package names, framework identity or scenario source. Building Next.js
(`next build` loads a native SWC addon) and installing packages remain
Node-side setup steps; native addons are outside the contract.

## Verification

During changes, run the affected inventory families and scenarios against
local Node. Compare values, descriptors, identity, ordering, errors, exit
status, stdout/stderr, response bytes and socket effects. At any future framework qualification,
run the complete required inventory and all scenarios once on the final build.

## Definition of done

- Every required inventory fixture passes on production `quench-node` with no
  crash, timeout or skip. The inventory was not edited to reach that result.
- All seven scenarios match local Node using real, unmodified packages from
  the tracked lock.
- No package facsimile, framework-specific module or name-keyed resolution
  shortcut remains in production.

## Performance evidence

None required. Stage B qualifies V8-v7 Score and RSS only.
