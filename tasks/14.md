## Scope and implementation sequence

Port String constructors/prototypes/iterators, normalization and casing, RegExp parsing/execution/state/captures/indices, replacement and splitting, JSON parse/stringify ordering and hooks, URI codecs, and legacy Annex B string/escape behavior. Adapt proven backends through code-unit-safe boundaries: RegExp execution uses the shared legacy-derived matcher from task 45, replacing the `regex`-crate backend, which cannot express backreferences, lookbehind, or UTF-16 matching.

## Verification

Run String, RegExp, JSON, URI, Annex B, and relevant Intl Test262 families with lone-surrogate, astral, zero-width, catastrophic-backtracking budget, accessor re-entry, and serialization controls.

## Definition of done

- No internal operation relies on lossy UTF-8 conversion.
- RegExp state and callback effects have exact ordering.
- JSON and URI results/errors match the oracle.

## Implementation evidence

Replacement assembly now uses one transient checked UTF-16 slice plan in
String.replace/replaceAll and RegExp @@replace/GetSubstitution. It shares
canonical unit storage, merges adjacent slices, and stops growing on length
or reservation failure. Replacement effects continue in order; finalization
raises RangeError before materializing an oversized result. The limit is the
existing Node-compatible MAX_STRING_UNITS policy, verified against local
buffer.constants and V8's public String::kMaxLength. No guest rope, side map,
or serialized metadata is added.

Five focused Rust checks pass, including both compilation modes, binary round
trips, internal length/slice invariants, and existing GC-root regressions.
All 170 affected official cases and seven selected staged replacement cases
retain their passes with unchanged inventories. The previously killed
staging/sm/String/replace-math.js now passes. Fifteen outputs match Node,
including oversized regex/plain replacement, named getters after overflow,
all 600 callback effects, abrupt identity, UTF-16 surrogates and substitutions.
The complete current library audit passes 491 tests, zero failed/ignored.
Profile-memory checks pass. Evidence is in
`target/iteration/task20-string-growth-provenance.json`; raw suite comparisons
are in `task20-string-growth-comparison.json`. Only affected replacement
scopes were replayed; no full Test262 run or production speed/RSS claim.

`JSON.parse` and `JSON.stringify` now route through the next VM's canonical
heap objects, arrays, atoms, and string cells. Cyclic structures raise a
serialization error, and non-finite numeric values serialize as JSON `null`.
JSON numbers retain their f64 value and finite serialization uses the same
Number::toString formatter as ordinary coercion, following
[SerializeJSONProperty](https://tc39.es/ecma262/multipage/structured-data.html#sec-serializejsonproperty).
This removes the saturating integer conversion and the runtime-next serde_json
dependency. Parsing preserves overflow to infinity and signed underflow to zero;
reviver source matching uses the shared SameValue operation.

Each realm owns its JSON object and native methods. Those methods use the realm's
function prototype and allocate parsed objects, reviver holders, and context
objects through the current realm's object prototype. TypeError.prototype
inherits from its own realm's Error.prototype; errors produced by JSON methods
retain the method's realm, while exceptions thrown by guest callbacks retain the
callback's realm. New JSON objects use intrinsic methods even after another
realm's JSON properties are replaced.

The numeric and realm regressions match 41 Node output lines in both execution
modes; thirteen focused Rust checks pass. Stage 53 passes 165/165, the stage-16
JSON import selection passes 13/13, and staging JSON passes 39/39, gaining
`parse-with-source.js`. All three comparisons retain identical inventories and
lose no passes (`target/iteration/task20-json-realm-comparison.json`). A focused
284-case realm-creation inventory gains the same fixture, retains every previous
pass, and now passes 276/284; eight other staging realm cases remain open
(`task20-json-realm-case-comparison.json`).
The four URI globals now share explicit UTF-8 percent-encode/decode helpers,
including reserved-character preservation for `decodeURI` and malformed escape
errors.
String primitive dispatch now also exposes `includes`, `startsWith`, and
`endsWith` through interned method atoms and the shared receiver helpers.
The next compiler now lowers RegExp literals through the same `RegExp`
constructor authority used by explicit construction. RegExp objects validate
flags and patterns, expose `source`/`flags`, and implement `exec` capture arrays
with `index`/`input` metadata plus `test`. Global/sticky execution now advances
and resets `lastIndex`; string `replace`, `split`, `match`, and `search` route
RegExp values through the same backend, including capture insertion and
replacement tokens; callable replacers receive match/capture/offset/input
arguments through the VM call path. `replaceAll` now handles string and global
RegExp patterns, including empty-search insertion; observable offsets use
UTF-16 code units. The same primitive receiver authority now covers `at`,
`codePointAt`, case conversion, and `concat`, with astral and surrogate
regressions. Replacement-context expansion now covers `$$`, `$&`, numbered
captures, ``$` ``, and `$'`; Unicode-set parity remains open.
String `normalize` now implements NFC, NFD, NFKC, and NFKD through the
explicit Unicode normalization boundary, including invalid-form rejection.
`String.prototype.indexOf` and `lastIndexOf` now search UTF-16 code units,
including empty-search and position handling, through the shared string native
dispatch.
String primitive `toString` and `valueOf` now return the canonical receiver
value through the same native dispatch.
`String.fromCodePoint` now emits astral scalars and rejects non-integer,
out-of-range, and surrogate code points through the shared numeric coercion
boundary.

The runtime now materializes a `String.prototype` object and installs the
instance methods from one canonical method table; primitive String property
reads consult that prototype after virtual index/length reads, so overrides
and `String.prototype` reflection share the same authority. Boxed String
objects carry immutable indexed properties and a non-writable `length`, and
string methods coerce their receiver through a shared entry path. Existing
stage-10 array-destructuring string cases pass 159/159; the `String.prototype`
property-accessor subtree is 13/21, with unrelated missing
Number/Date/Math/Function/Array properties still failing. No tests were added.

Math.atanh now has one shared sign-symmetric log1p numerical operation with a
named half-unit crossover. It preserves signed zero, domain/endpoints and the
existing coercion/descriptor contracts while avoiding the reproduced macOS
scalar accuracy failure. Task 20 records affected official/staged Math tests,
both-mode/binary-round-trip controls and a bounded 2,424-point Node comparison
in `target/iteration/task20-atanh-provenance.json`. Structural DoD remains open.
