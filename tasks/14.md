# 14: Port strings, RegExp, JSON, and URI semantics

## Outcome

Complete text processing over the exact UTF-16/WTF-16 representation.

## Current gap

V2 supplies only benchmark-oriented string primitives and no complete RegExp, JSON, or URI semantics.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Port String constructors/prototypes/iterators, normalization and casing, RegExp parsing/execution/state/captures/indices, replacement and splitting, JSON parse/stringify ordering and hooks, URI codecs, and legacy Annex B string/escape behavior. Adapt proven backends through code-unit-safe boundaries.

## Verification

Run String, RegExp, JSON, URI, Annex B, and relevant Intl Test262 families with lone-surrogate, astral, zero-width, catastrophic-backtracking budget, accessor re-entry, and serialization controls.

## Definition of done

- No internal operation relies on lossy UTF-8 conversion.
- RegExp state and callback effects have exact ordering.
- JSON and URI results/errors match the oracle.

## Performance evidence

Report string allocations/cache behavior and RegExp/Crypto workload effects.

## Implementation evidence

`JSON.parse` and `JSON.stringify` now route through the next VM's canonical
heap objects, arrays, atoms, and string cells. The regression suite verifies a
nested object/array round trip; replacers, revivers, cycles, and full numeric
rounding parity remain open. Cyclic structures now raise a serialization error,
and non-finite numeric values serialize as JSON `null`.
The four URI globals now share explicit UTF-8 percent-encode/decode helpers,
including reserved-character preservation for `decodeURI` and malformed escape
errors.
String primitive dispatch now also exposes `includes`, `startsWith`, and
`endsWith` through interned method atoms and the shared receiver helpers.
The next compiler now lowers RegExp literals through the same `RegExp`
constructor authority used by explicit construction. RegExp objects validate
flags and patterns, expose `source`/`flags`, and implement `exec` capture arrays
with `index`/`input` metadata plus `test`. Global/sticky execution now advances
and resets `lastIndex`; string `replace`, `split`, `match`, and `search` route
RegExp values through the same backend, including capture insertion and
replacement tokens; callable replacers receive match/capture/offset/input
arguments through the VM call path. `replaceAll` now handles string and global
RegExp patterns, including empty-search insertion; observable offsets use
UTF-16 code units. The same primitive receiver authority now covers `at`,
`codePointAt`, case conversion, and `concat`, with astral and surrogate
regressions. Replacement-context expansion now covers `$$`, `$&`, numbered
captures, ``$` ``, and `$'`; Unicode-set parity remains open.
String `normalize` now implements NFC, NFD, NFKC, and NFKD through the
explicit Unicode normalization boundary, including invalid-form rejection.
