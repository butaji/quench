# 14: Port strings, RegExp, JSON, and URI semantics

## Outcome

Complete text processing over the exact UTF-16/WTF-16 representation.

## Current gap

V2 supplies only benchmark-oriented string primitives and no complete RegExp, JSON, or URI semantics.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Port String constructors/prototypes/iterators, normalization and casing, RegExp parsing/execution/state/captures/indices, replacement and splitting, JSON parse/stringify ordering and hooks, URI codecs, and legacy Annex B string/escape behavior. Adapt proven backends through code-unit-safe boundaries.

## Verification

Run String, RegExp, JSON, URI, Annex B, and relevant Intl Test262 families with lone-surrogate, astral, zero-width, catastrophic-backtracking budget, accessor re-entry, and serialization controls.

## Definition of done

- No internal operation relies on lossy UTF-8 conversion.
- RegExp state and callback effects have exact ordering.
- JSON and URI results/errors match the oracle.

## Performance evidence

Report string allocations/cache behavior and RegExp/Crypto workload effects.

## Implementation evidence

`JSON.parse` and `JSON.stringify` now route through the next VM's canonical
heap objects, arrays, atoms, and string cells. The regression suite verifies a
nested object/array round trip; replacers, revivers, cycles, and full numeric
format parity remain open.
The four URI globals now share explicit UTF-8 percent-encode/decode helpers,
including reserved-character preservation for `decodeURI` and malformed escape
errors.
