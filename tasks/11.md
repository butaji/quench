# 11: Port core language, function, and class semantics

## Outcome

Implement the complete language execution core on the new frames, environments, objects, and residual compiler.

## Current gap

V2 lacks modern bindings, parameter forms, classes, private environments, many completion paths, and the observable edge cases already implemented by legacy Quench.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Port declaration instantiation, `var`/lexical/TDZ bindings, parameters, destructuring/rest/spread, all statements and control completions, functions/arrows, calls/constructors, `this`/`super`/`new.target`, classes/fields/static blocks, private environments, direct eval, `with`, and their early errors. Port proven algorithms but rewrite storage and activation around the new authorities.

## Verification

Run focused legacy tests and matching Test262 language directories, including abrupt completion, iterator closing, derived constructors, eval scope, mapped arguments, and single-evaluation cases.

## Definition of done

- Every covered construct compiles directly from OXC and executes without a legacy callback.
- Environment identity, declaration ordering, errors, and effects match the oracle.
- Recursive and suspended paths use the shared activation model.

## Performance evidence

Report frame/environment allocation and Richards/DeltaBlue regressions; correctness owns completion.
