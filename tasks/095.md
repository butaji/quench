# 095: Implement effect-aware optimizing compilation and register allocation

## Outcome

Remove redundant work across bytecodes while preserving exact JavaScript behavior.

## Current gap

Local value graphs, numeric DAGs and specialized covers duplicate analysis and
impose small fixed limits; patching alone cannot optimize across fragments. The
core deliverable is shared effect-aware dataflow plus register allocation;
inlining and scalar replacement are conditional extensions, not a reason to
keep a second analysis authority. The baseline CFG authority owns CFG shape,
liveness and baseline retirement; this task owns optimization dataflow and value-graph
capacity derived from those facts, plus its measured fallback.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering live there.

## Scope and implementation sequence

1. Unify derived value identity, use/def, effects and liveness over canonical PCs.

2. Implement safe constant propagation, value numbering, dead-pure-code/check elimination, range/type specialization and strength reduction in separately measurable increments.

3. Add last-use reuse, register allocation/spills, literal deduplication and costed fusion; extend beyond current fixed graph/input limits using justified compile budgets.

4. After the core allocator is proven, add profitable loop optimization, call
   inlining or allocation scalar replacement only where alias/escape proofs and
   full exit materialization are available; retain only measured transformations.

## Verification

`cargo test -p quench-runtime`; 342 contracts; full reserved/all-size micros and V8-v7. Test NaN/signed zero, coercive reads, overflow, aliases, throwing initializers, live joins, deoptimization and compilation-budget exhaustion. Compare each pass enabled/disabled.

Apply the shared [completion checks](README.md), including named baseline failures
and independent semantic controls. Record commands and artifact identity.

## Definition of done

- Every retained pass has independent semantic controls and attributable generated-code/work reduction.
- No arbitrary fixed expression size acts as a permanent architecture ceiling; exhausted budgets use correct fallback.
- Register/exit maps remain correct across calls and joins; superseded analysis representations are removed.
- Selected transformations produce repeatable performance gains with code/compile-time tradeoffs recorded.

## Performance evidence

Use pass ablations and held-out source variations; report spills, checks, boxing,
code bytes and full-suite regressions, with V8-v7 primary and Bun/JSC/Node
comparators captured under the shared performance protocol.
