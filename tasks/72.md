# 72: Derive allocation-site shapes statically

## Outcome

Object literals, array literals, and class bodies whose layout is fixed by
syntax allocate directly at their final shape. Their transition chains are
interned once at load, not rebuilt per allocation. Constructors reserve
inline slots from a static layout hint. The hint changes memory layout only,
never semantics.

## Current gap

An object literal `{x: 1, y: 2}` performs one add-property transition per
key on every evaluation, although its key sequence, attributes, and prototype
(`%Object.prototype%`) are fixed by syntax. Class prototypes and static
members are assembled property by property. Constructors grow objects one
`this.x =` at a time without a slot reservation.

## Dependencies

See this task's `depends_on` in [index.json](index.json). Phase C, ordered by

## Scope and implementation sequence

1. Add the allocation-site domain to the binding-time analysis. A literal has a static layout
   when every key is static and none is `__proto__: value`, a spread, a
   computed key, or a duplicate that changes attributes. Accessors and
   methods are allowed, and they fix the descriptor attributes.
2. Intern each static layout's shape chain in the realm shape table when the
   residual is loaded, sharing the chain with any runtime transitions to the
   same keys (task 08's transition interning). The allocation opcode carries
   the shape index and writes all slots at once, in source evaluation order.
3. Array literals with no holes and no spread allocate with their exact
   length. With task 50's element kinds, they also start at the kind their
   elements prove statically.
4. Class bodies: build the prototype and constructor shapes from the class
   element list at load, and keep evaluation order for computed keys,
   decorators, and static blocks. A class with a computed key uses the
   generic path for that element and all later ones.
5. Constructors: count the `this.x =` assignments that dominate the body's
   exit in the closed scope, and reserve that many inline slots at
   allocation. The receiver's shape still evolves by ordinary transitions.
   The hint affects only capacity.

## Verification

Test262 cases for literal evaluation order with throwing values and getters,
duplicate keys, `__proto__` forms, accessor pairs, class element order,
computed keys, and derived-class `this` initialization. Task 42's gate uses
per-key allocation. Task 47's Futamura check.

## Definition of done

- Static literal and class layouts are allocated at their final shape, with
  evaluation order unchanged.
- Shape chains produced by static layouts and by runtime transitions are the
  same chains.
- Slot reservation is a capacity hint whose misprediction costs only memory.

## Performance evidence

Report transitions avoided, shape-table bytes, reserved-but-unused slots,
and the paired V8-v7 Score/RSS delta (task 26's gate).
