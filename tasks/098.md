# 098: Integrate the native execution core

## Outcome

Make the native execution core a direct part of Quench's VM and opcode
generation path while retaining Quench semantic services needed by the complete
ECMAScript and Node surface.

## Current gap

The native import is a set of execution mechanisms, not a second semantic VM.
The value word is now integrated directly; remaining region and opcode
generation work must target Quench's canonical `Op` and semantic services.
No external sibling path or compatibility adapter may remain in the build.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering
live there. Existing runtime semantics and the 342 IR contracts are inputs.

## Scope and implementation sequence

1. Keep the one-word native representation authoritative for registers, slots,
   native entries and patch operands.
2. Generate region plans and opcode artifacts directly from Quench's canonical
   `Op` declarations and semantic facts.
3. Route execution through those artifacts with exact completion, identity,
   descriptor, ordering, exception and host rules.
4. Remove obsolete duplicate dispatch/frame/opcode representations after all
   consumers migrate; retain semantic modules and public host APIs.
5. Run focused parity, all runtime/Node/profile tests, then the uncapped full
   Test262 suite with zero failures before performance qualification.

## Verification

Run focused core/semantic parity, the full workspace and Node suites, all 342
execution-profile contracts, then the complete uncapped Test262 runner.

## Definition of done

- No Cargo manifest or build path depends on an external sibling checkout.
- `native_core` is the only execute-word representation; no adapter or parallel
  value layout remains on the hot path.
- Focused core/semantic parity and all existing workspace tests pass.
- All 342 execution-profile contracts pass in supported stencil modes.
- Test262 accounts for every discovered runnable file and has `failed == 0`;
  unsupported features and harness/host errors are failures.
- Docs, task queue and architecture describe the same migration boundary.

## Performance evidence

V8-v7, Bun/JSC and Node measurements are optional for functional completion and
required only when claiming a performance improvement.
- Any V8-v7/Bun/JSC/Node result is recorded only after correctness and includes
  production build identity and regression analysis.
