# 085: Eliminate warning-backed dead code

## Outcome

Make active runtime and Node targets warning-clean through verified cleanup.

## Current gap

Existing warnings mix unreachable code, cfg-specific paths, deprecated APIs and genuine ignored results; old warning totals are not current evidence.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering live there.

## Scope and implementation sequence

1. Capture current warnings for default and execution-trace builds by subsystem.

2. Audit reachability before deleting dead items; narrow cfg for target/test-only code and repair meaningful ignored results/deprecations.

3. Remove obsolete aliases/imports/arms; do not add blanket warning suppression.

4. Verify public compatibility and host effects after each subsystem migration.

## Verification

`cargo check -p quench-runtime -p quench-node`; `cargo check -p quench-node --features execution-trace`; full runtime/Node tests and compatibility runner.

Apply the shared [completion checks](README.md), including named baseline failures
and independent semantic controls. Record commands and artifact identity.

## Definition of done

- Active default and trace builds have no unresolved warnings.
- Every deletion is unreachable or has migrated consumers; target-specific behavior and observable semantics remain intact.

## Performance evidence

Cleanup milestone; binary/build effects are reported separately from measured runtime performance.
