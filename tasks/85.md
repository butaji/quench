# 85: Accelerate the builtins that dominate library time

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select this work only for a
measured V8-v7 Score or RSS gap; finishing it is not a stage-completion gate.
Use affected-stage checks plus compare-runs during changes. The current
dependencies in [index.json](index.json) supersede older prerequisite claims.

## Outcome

Accelerate only builtins measured to dominate a V8-v7 gap. Guard on receiver,
intrinsic identity and relevant mutable facts, with the existing spec algorithm
as exact fallback. Reuse shape semantics for enumeration where justified.

## Current gap

Builtins already use shared VM spec operations. Profile their current cost
before selecting a fast path; moving them to a new kernel API is unnecessary.
The V8-v7 fixtures lean on a small set: `Array.prototype.push`, `pop`,
`splice` and `join`; `String.prototype.charAt`, `charCodeAt`, `substring` and
`indexOf`; `Math.floor`, `sqrt`, `random` and friends; `Number` conversion;
`Object.keys` and `for-in`; and `Function.prototype.apply` and `call`.

## Dependencies

See `depends_on` in [index.json](index.json). A builtin time profile selects
work. Deferred tasks 46/47 and a generated kernel are not prerequisites.

## Scope and implementation sequence

1. Rank builtins by time share on each fixture and on the Node set from task
   77's profile. Accelerate in that order, and stop when the next builtin's
   share is below the gate's noise.
2. Each fast path guards on the receiver's brand or element kind and on the
   intrinsic identity and mutation guards, and falls
   back to its row's reference definition.
3. Array growth: choose the growth factor on the Score × RSS front, and
   shrink capacity at GC when an array keeps less than a named fraction of it.
4. Memoize `for-in` and `Object.keys` key lists on the shape, for shapes
   whose prototype chain has no enumerable properties, guarded by the
   chain's validity cell (task 29).
5. `Math` functions return integer-tagged values where the result is an
   exact int32, so the following arithmetic stays on the integer path.

## Verification

The Test262 inventories of every accelerated builtin, including species,
proxies, accessors on indices, and intrinsic replacement. Task 42's gate
treats every protector as tripped. Each fast path agrees with its row's reference definition on generated
inputs against the existing generic implementation.

## Definition of done

- Every acceleration shares semantic operations with its exact generic fallback.
- The accelerated set follows the measured ranking, and the ranking is
  recorded.
