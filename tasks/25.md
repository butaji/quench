# 25: Use a measured residual-only execution boundary

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select this work only for a
measured V8-v7 Score or RSS gap; it is not a stage-completion gate. Use affected
suite scopes during changes. The current dependencies in [index.json](index.json)
supersede older prerequisite claims.

## Outcome

Release specialization and residual-decoding pages before interpretation when
the same-binary boundary improves Quench's measured Score/RSS results. Dynamic
JavaScript and host behavior continue through the same VM and process path.

## Current gap

Source specialization and residual execution currently share one process, so
compiler pages may remain resident at the runtime high-water. Residual decoding
also has a temporary staging buffer whose freed pages may remain in the macOS
allocator. V2 tasks 93 and 192 measured these phase-boundary effects; task 356
measured a macOS allocator policy on its retained artifact. Each is a candidate
to reproduce on Quench, not a result assumed to transfer.

## Dependencies

See `depends_on` in [index.json](index.json). Task 86 must verify Stage A, and
task 62 supplies the matched measurement path. Task 61 owns the cross-engine
Score/RSS qualification. Eval, Function, modules, and non-Unix execution remain
in-process through the same Engine.

## Scope and implementation sequence

1. On Unix, let a static file entry write a checked residual and `exec` the
   same binary into residual-only mode. Preserve argv, host setup, errors,
   cleanup, and exit status. Keep dynamic compilation in-process.
2. Drop the decoder staging buffer and remove the residual file before VM
   construction. If the macOS allocator retains freed pages, evaluate the
   pressure-relief edge and task 356's bounded-magazine settings separately.
   Apply a host allocation policy only when a matched Quench experiment shows
   a Score/RSS benefit; leave other hosts unchanged.
3. Keep the residual format versioned and validated. Malformed or stale input
   fails before guest execution, and interruption cleanup removes owned files.

Task 62 owns runner provenance, sample storage and paired comparison. Task 84
owns build profiles and PGO. This task adds no competing lab, instrumentation
format, or build-profile control.

## Verification

Check static-file phase equivalence, malformed/stale residual rejection,
cleanup after signals, dynamic compilation after the phase boundary, and the
non-Unix in-process path. Run only affected Test262 stages and compare-runs,
plus the affected implemented Node or Wasm scope when that shared path changes.

## Definition of done

- The boundary preserves guest and host behavior on affected cases.
- A retained boundary or allocator policy improves or holds paired Score/RSS
  on the measured Quench workloads; otherwise record the negative result and
  remove the candidate.
- The same binary remains the only VM executor.

## Performance evidence

Use task 62/61's matched reports to record compile/exec split cost, residual
bytes, startup, peak RSS and per-benchmark Score/RSS. Attribute allocator
