# 25: Add two-mode residual execution and the v2 lab

## Outcome

Preserve v2's physical specialization/execution boundary and reproducible comparison tooling without constraining dynamic Node behavior.

## Current gap

The next runtime can serialize residual programs but lacks Quench CLI phase handling, full provenance, paired lab comparison, and an explicit in-process path for eval/modules.

## Dependencies

See this task's `depends_on` in [index.json](index.json). The lab is
performance tooling, so it starts only after task 24. Eval, `Function`, module,
and non-Unix compilation run in-process from the start (task 18); this task
adds only the exec phase split and measurement.

## Scope and implementation sequence

1. On Unix, let static file entry securely write a verified residual and `exec` the same binary into a private residual-only mode while preserving argv, host setup, errors, cleanup, and exit status.
2. Compile eval, Function constructors, require/import, modules, and non-Unix execution in-process through the same Engine/verifier.
3. Port bounded aggregate/trace/memory instrumentation and stable opcode/effect names without guest values or source in traces.
4. Port the rotating paired lab, provenance, interruption-safe partials, drift checks, and opt-in AOT PGO build; PGO may shape the Rust interpreter but never generate guest code.

## Verification

Test phase equivalence, stale/malformed files, cleanup after signals, dynamic compilation after exec, non-Unix fallback, instrumentation-off binary parity, report combination, and compromised-run detection.

## Definition of done

- OXC pages can be released before residual-only static execution.
- Dynamic language/host behavior stays in-process and exact.
- Measurement reports identify every source, executable, toolchain, host, and environment input.

## Performance evidence

Report compile/exec split cost, residual bytes, startup, peak RSS, and instrumentation overhead.
