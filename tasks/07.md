# 07: Extend the tracing heap and root lifecycle

## Outcome

Extend v2's indexed non-moving tracing heap to own every full-language and host lifetime safely.

## Current gap

The remaining gap is suspended async/module lifetimes and their queued ownership;
the heap now covers persistent roots, weak collections/references, finalization,
and external buffers.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Keep slabbed indexed cells, explicit free slots, packed marks, contiguous property storage, and collection at named safepoints.
2. Derive precise roots from residual frame maps plus realms, jobs, modules, suspended activations, native call scopes, and explicit `RootId` entries.
3. Add generation-checked weak handles, ephemeron fixpoint processing, WeakRef clearing, and ordered FinalizationRegistry job creation.
4. Model ArrayBuffer/SharedArrayBuffer and host resources as traced owner cells with explicit external backing lifetime and accounting.
5. Validate every unsafe heap/cache edge and clear or revalidate handle-bearing caches before slot reuse.

## Verification

Use forced collection at every allocation/safepoint class, slot reuse, cyclic graphs, ephemeron chains, weak/finalization ordering, suspended frames, reentrant host calls, detached buffers, and allocation-failure tests.

## Definition of done

- No host or runtime subsystem stores an unrooted value across a safepoint.
- Strong, weak, ephemeron, finalization, and external ownership are explicit phases.
- Heap reuse cannot resurrect a stale cache or weak handle.

## Performance evidence

Report allocation payloads, peak live cells/RSS, collection counts, phase work, and root-map density.

## Implementation evidence

The imported heap now owns generation-checked `RootId` handles. `Vm` and
`Runtime` expose explicit insert/update/release operations, and roots are
included in every mark phase; slot reuse increments the generation so stale
handles cannot resurrect or mutate a new value. The root table has focused
stale-handle coverage.

The next-runtime heap now also represents `WeakRef` targets as generation-
checked `WeakHandle` values. Weak targets are excluded from marking, cleared in
the weak phase when their slot is dead or stale, and dereference validates both
generation and liveness before producing a `Value`; focused coverage exercises
collection followed by slot reuse. WeakMap/WeakSet ephemeron behavior remains
the existing mark-fixpoint path.

Heap access now has a named boundary module that checks tagged slot indices
before every slab `unsafe` read/write. Weak-handle resolution delegates to that
same checked accessor, and forged-index regressions verify invalid values cannot
cross the heap boundary or trigger undefined behavior.

ArrayBuffer and SharedArrayBuffer cells now expose explicit external backing
accounting through the heap statistics path. Allocation, collection, resize,
grow, and transfer/detach transitions update the owner accounting, with a
forced-collection regression proving backing bytes remain charged while the
owner is live and are released after sweep.

FinalizationRegistry now has an explicit traced cell: callbacks and held values
are strong children, targets and unregister tokens are generation-checked weak
handles, and the GC weak phase emits ordered callback/held-value jobs. The VM
keeps those jobs rooted through the existing interpreter call path and drains
them after top-level execution; registration/unregistration, heap job-order,
generic property traversal, and a cleared-target callback drain are covered.
Finalization output is normalized into the VM's single `PendingJob` queue with
explicit receiver and argument roots, so re-entrant callbacks use the same
drain and GC-root path as future promise/module jobs.
The VM now also owns an explicit `Continuation` root set covering frame
environment, receiver, locals, registers, and completion value; the four
return/throw/yield/await completion states share that representation. Compiler
suspension slots now have generation-checked suspend/resume transitions, so a
stale resumer cannot consume a replacement activation. Await and synchronous
generator producers now use this continuation authority; module and host-job
producers remain in Task 09/17, so this task stays active.
The runtime now exposes a validated explicit collection safepoint for hosts and
tests. That path uses the same frame maps, pending-job roots, continuation
roots, and persistent roots as threshold-triggered collection. Every
realm-owned intrinsic prototype is also a direct GC root, so liveness does not
depend on incidental reachability through a global constructor.
General suspended/module job ownership remains in Task 09/17, so Task 07
remains active.
