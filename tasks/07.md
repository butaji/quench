# 07: Verify shared heap and root lifetimes

## Outcome

Extend v2's indexed non-moving tracing heap to own every full-language and host lifetime safely.

## Current gap

[Suspended-scope qualification](evidence/task20-suspended-with.json) closes
task 11's lost `with` bindings through continuation-owned scope segments.
The root inventory and collection lifecycle checks cover ownership transfer
and release after resume. All five suspended-GC controls pass; the broader
producer and host re-entry audit remains open.

The heap covers persistent roots, weak collections/references, finalization
and external buffers. Frame entry and reuse now call `Frame::prepare_registers`,
which initializes every GC-scanned register; the earlier uninitialized-vector
defect is closed. Attached async continuation registry ownership is now
verified by the evidence below. Dynamic-import queued/taken-batch handoffs are
also verified. Remaining work is the producer and queued-owner audit across
other suspension and host re-entry boundaries, with affected forced-GC evidence.
Fallback descriptor ownership is now closed by the evidence below.
Producer adoption stays with tasks 09, 17 and 18 as described below.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Keep slabbed indexed cells, explicit free slots, packed marks, contiguous property storage, and collection at named safepoints.
2. Derive precise roots from residual frame maps plus realms, jobs, modules, suspended activations, native call scopes, and explicit `RootId` entries.
3. Add generation-checked weak handles, ephemeron fixpoint processing, WeakRef clearing, and ordered FinalizationRegistry job creation.
4. Model ArrayBuffer/SharedArrayBuffer and host resources as traced owner cells with explicit external backing lifetime and accounting.
5. Validate every unsafe heap/cache edge and clear or revalidate handle-bearing caches before slot reuse.
6. Every guest value live across a safepoint has a traced owner: a frame
   register, scoped native root, rooted owner cell or `RootId`. Local handle
   copies do not replace that owner. Keep the current collector non-moving;
   moving-collector preparation belongs to task 82 only if a measured Stage B
   gap selects that mechanism.

## Verification

Use the existing pinned Test262 inventory and unchanged harness for semantic
verification. Keep the harness unchanged; add Rust regression coverage as
required by the shared completion rules.
Inspect rooting, weak-handle, finalization, and safepoint paths directly for
ownership invariants that Test262 cannot observe.

## Closure boundary

Promise, generator, async, module, and host-job producers are implemented by
tasks 09, 17, and 18, which depend on this task. Requiring them here would be a
dependency cycle. This task closes when the root, weak, finalization,
external-backing, continuation, and safepoint mechanisms exist and pass the
forced-GC controls above; each later producer must adopt them as part of its
own definition of done.

## Definition of done

- No host or runtime subsystem stores an unrooted value across a safepoint.
- Strong, weak, ephemeron, finalization, and external ownership are explicit phases.
- Heap reuse cannot resurrect a stale cache or weak handle.
- Every native/host handle live across a safepoint has a traced owner.

## Implementation evidence

Async-generator return setup roots its request Promise, receiver and value.
The shared `promise_then` operation roots its source and handlers through
observable species/capability creation. The retained internal lifetime test
verifies handler-state survival during forced collection and release after
queued execution. [Ownership evidence](evidence/task07-async-return-owner.json)
records 4,076/4,077 affected cases with zero regressions and 463 library tests;
the separate return-value timing mismatch in that snapshot is closed by
[task 20's follow-up](evidence/task20-async-return-await.json).
Detached iterator cleanup now roots the continuation through its shared
operation, so synchronous and asynchronous callers use the same rule.
The broader producer/host audit and Stage A remain open.

Dynamic-import job waiters are explicit queue roots. Taking a batch transfers
all its waiter roots into the existing scoped-call operation until settlement
or transfer back to a queue/module record. A forced-GC regression that formerly
failed with `invalid Promise state` now verifies queued retention, requeue,
in-flight batch retention and collection after settlement.
[Compact evidence](evidence/task07-dynamic-import-owner.json) records 462
library tests, six integration checks, six matching end-to-end Node controls
and 2,458/2,459 affected suite cases with zero regressions. The sole failure is
the unchanged keyed-Promise fixture conflict; this is not Stage A closure.

Async callback associations now own their suspended-frame roots. Collection
derives those edges from `async_resume_jobs`; unreachable callback cycles no
longer retain frames forever. Queued callbacks retain frames until execution,
and abandoned generation-checked tokens are retired. Unattached internal
tokens retain their explicit suspend/resume lifetime. Promise preparation for
`await` runs in the active frame, preserving catch/finally handling before
suspension. [Compact evidence](evidence/task07-continuation-owner.json) records
461 internal units, six integration checks, 46 matching Node controls and
14 affected scopes passing 2,970/2,971 with zero regressions. The sole failure
is the unchanged keyed-Promise fixture conflict. This closes this mechanism
only; task 07 and Stage A remain open.

The imported heap now owns generation-checked `RootId` handles. `Vm` and
`Runtime` expose explicit insert/update/release operations, and roots are
included in every mark phase; slot reuse increments the generation so stale
handles cannot resurrect or mutate a new value. The root table has focused
stale-handle coverage.

The next-runtime heap now also represents `WeakRef` targets as generation-
checked `WeakHandle` values. Weak targets are excluded from marking, cleared in
the weak phase when their slot is dead or stale, and dereference validates both
generation and liveness before producing a `Value`; focused coverage exercises
collection followed by slot reuse. WeakMap/WeakSet ephemeron behavior remains
the existing mark-fixpoint path.

Heap access now has a named boundary module that checks tagged slot indices
before every slab `unsafe` read/write. Weak-handle resolution delegates to that
same checked accessor, and forged-index regressions verify invalid values cannot
cross the heap boundary or trigger undefined behavior.

ArrayBuffer and SharedArrayBuffer cells now expose explicit external backing
accounting through the heap statistics path. Allocation, collection, resize,
grow, and transfer/detach transitions update the owner accounting, with a
forced-collection regression proving backing bytes remain charged while the
owner is live and are released after sweep.

FinalizationRegistry now has an explicit traced cell: callbacks and held values
are strong children, targets and unregister tokens are generation-checked weak
handles, and the GC weak phase emits ordered callback/held-value jobs. The VM
keeps those jobs rooted through the existing interpreter call path and drains
them after top-level execution; registration/unregistration, heap job-order,
generic property traversal, and a cleared-target callback drain are covered.
Finalization output is normalized into the VM's single `PendingJob` queue with
explicit receiver and argument roots, so re-entrant callbacks use the same
drain and GC-root path as future promise/module jobs.
The VM now also owns an explicit `Continuation` root set covering frame
environment, receiver, locals, registers, and completion value; the four
return/throw/yield/await completion states share that representation. Compiler
suspension slots now have generation-checked suspend/resume transitions, so a
stale resumer cannot consume a replacement activation. Await and synchronous
generator producers now use this continuation authority; module and host-job
producers remain in Task 09/17, so this task stays active.
The runtime now exposes a validated explicit collection safepoint for hosts and
tests. That path uses the same frame maps, pending-job roots, continuation
roots, and persistent roots as threshold-triggered collection. Every
realm-owned intrinsic prototype is also a direct GC root, so liveness does not
depend on incidental reachability through a global constructor.
General suspended/module job ownership remains in Task 09/17, so Task 07
remains active.

Guest-call entry now roots its callee, receiver, and argument values for the
entire native/user call. This closes a lifetime gap where bytecode operands had
been popped from the active frame before a nested call could allocate or
collect. Promise resolver state is now a traced heap cell (including its
promise reference) rather than an untraced Rust-side map entry. Existing
Test262 stage 0 passes 116/116 in batches capped at 100 with a 30-second
per-case timeout; Task 07 remains active for the remaining continuation and
module/job ownership work.

All four frame-entry paths now grow GC-scanned register vectors with initialized
`undefined` values instead of extending `Vec<Value>` with `set_len`. This
removes reads of uninitialized handles from the collector and prevents pooled
frame capacity from exposing stale register contents. `cargo check --profile
iteration --offline -p quench-runtime-next -p quench-test262` passes; the
ordered Stage 0 Test262 run passes 116/116 in batches capped at 100 with
`TEST262_TEST_TIMEOUT_MS=30000`. No unit tests, new tests, or harness changes
were made. Task 07 remains active for suspended/module ownership and host-job
producers.

Frame tracing now consumes each active function's compiler-derived register
mask at the published safepoint PC. Functions without a representable mask keep
the conservative initialized-register scan. Plain object literals no longer
store an unnecessary hidden home-object root; method and accessor literals
still store it. This lets an otherwise dead FinalizationRegistry target reach
the weak phase. The existing root-release callback regression and a new
specialized/unspecialized `super` home-object collection regression both pass.
The focused 10,000-allocation finalization control passes with 44 collections,
3,474 peak live cells, 370,786 mark work items, and a 48-entry (384-byte)
register-root table with 14 distinct masks and 41 mask runs. Runtime allocator
peak RSS was 24,150,016 bytes. Full profiler output is preserved at
`target/iteration/task07-focused-gc.log`; this is focused structural evidence,
not a speed claim.

Persistent root handles now also carry an opaque root-table identity. A handle
from another VM cannot resolve, update, or release a coincident slot and
generation. The root-table tests pass 4/4, including cross-table aliasing and
generation exhaustion.

Fallback descriptor keys/getters/setters are now traced only when their object
is reachable, including objects discovered in the WeakMap ephemeron fixpoint.
The previous unconditional accessor roots could retain a dead accessor/owner
cycle forever. A retained internal GC regression failed before the fix and now
proves direct-root retention, ephemeron retention, cycle collection and dead
descriptor pruning. The per-collection edge index is derived from the existing
descriptor authority; no persistent duplicate state is introduced.
[Compact evidence](evidence/task07-descriptor-owner.json) records 7,045/7,045
passing cases across the eight affected Test262 stages, matching before/after
inventories and zero compare-runs regressions. Runtime checks pass 459 library
and six integration tests, plus both profiling features. Full suites and
performance benchmarks were not run. The remaining ownership audit keeps this
task active.

Promise records now contribute result/reaction edges from their reachable
Promise owner instead of rooting every Promise permanently. The retained
internal lifetime test proves Promise and resolving-function retention, dead
Promise/result cycle collection and record pruning. Removing the accidental
permanent roots also exposed missing temporary owners: async entry/resume,
reaction dequeue, dynamic-import coercion, Array.fromAsync setup/await and
async-generator execution now use the existing scoped-call root mechanism.
No cell-storage refactor or new persistent side table was required.
[Compact evidence](evidence/task07-promise-record-owner.json) records
2,969/2,970 passing cases in 13 affected scopes, matching inventories and zero
compare-runs regressions; the unchanged remaining fixture conflict belongs to
task 20. All 30 forced-GC controls match local Node in specialized/generic
modes. Runtime checks pass 459 library and six integration tests, plus both
profiling features. This established Promise-record ownership; the following
check extends the same rule to the remaining identity-keyed tables.

Promise callbacks, jobs, reaction capabilities and aggregates now derive their
owner/child edges through `PromiseRuntime::owned_edges`. The collector combines
these with fallback descriptor edges in one temporary index and visits them
only from marked owners, including ephemeron-discovered owners. Queued and
active callbacks retain their explicit roots; table membership alone does not
retain an unreachable cycle. The internal pending-chain regression fails before
the fix and passes after it, proving both live retention and dead-owner cleanup.
[Compact evidence](evidence/task07-promise-table-owner.json) records unchanged
2,969/2,970 affected outcomes with zero regressions, 30 matching forced-GC Node
controls, 460 passing library tests, six integration tests and profiling checks.
The sole fixture conflict remains task 20's responsibility. Continuation
retirement and queued-owner transfer still require audit; task 07 stays active.

The consumer audit removed the never-populated second finally-reaction
pipeline: its per-Promise vector, two job tables, three record types, four
handlers and two registered native intrinsics. `finally` now has only the
existing ordinary-then handler/continuation path. Task 17 describes that
authority; task 86 owns repository-wide cleanup completion.
[Removal evidence](evidence/task07-finally-pipeline-removal.json) records
2,970/2,971 passing affected cases, including intrinsic traversal, zero

and profiling checks. The unchanged remaining corpus conflict stays open.
