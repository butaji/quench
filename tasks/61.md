## RegExp literal-site matcher reuse

Each compiled RegExp literal site now caches its immutable compiled matcher in
the owning program. Executing the literal still creates a fresh JavaScript
RegExp object, so identity, `lastIndex`, `.compile()` and realm-specific
prototypes remain per object. This follows ECMAScript's `RegExpCreate` step
for every literal evaluation and reuses only the compiled matcher. Node v24.19.0
matched Quench on five direct semantic probes, including reentrant use of a
second RegExp object from the same literal site with capture groups; the
existing runtime foreign-realm regression remains covered by the unit suite.

On Linux x86_64, eleven alternating production pairs on the materialized
V8-v7 RegExp fixture raised median Score from 40.3 to 52.5 (+30.27%; paired
95% interval +10.9 to +14.4 points). Median maximum RSS fell from 38,383,616
to 31,911,936 bytes (-6,471,680 bytes; paired 95% interval -6,537,216 to
-6,352,896); candidate RSS was lower in all eleven pairs. Benchmark output
matched in every pair. The runtime library suite passed 520/520, and Test262
RegExp stages 64–70 passed 3,681/3,681. Retain this measured RegExp
optimization as a Stage B candidate; it is one-fixture evidence and does not
close the all-eight, all-engine gate.

The Linux report, paired samples, runner, source patch, Node oracle and
Test262 report are in the [literal-site cache record](evidence/task61-regexp-literal-site-cache-linux-2026-10-09.json).
The [paired production report](evidence/task61-regexp-literal-site-cache-linux-pairs-2026-10-09.json)
and [raw pair log](evidence/task61-regexp-literal-site-cache-linux-pairs-2026-10-09.jsonl)
record binary and fixture hashes. The [ECMAScript literal evaluation
algorithm](https://tc39.es/ecma262/#sec-regular-expression-literals-runtime-semantics-evaluation)
creates a RegExp via `RegExpCreate` each time; the Rust `regex` crate's
[compiled Regex documentation](https://docs.rs/regex/latest/regex/struct.Regex.html#method.new)
recommends compiling once and reusing the result because compilation is
relatively expensive.
