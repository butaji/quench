# 61: Lead no-JIT engines on every V8-v7 benchmark

## Outcome

After Stage A is verified, on the Apple M4/macOS execution host recorded in
the evidence, Quench achieves the highest median Score
and lowest median maximum RSS on each V8-v7 benchmark: Crypto,
DeltaBlue, EarleyBoyer, NavierStokes, RayTrace, RegExp, Richards, and Splay.
Compare against QuickJS, Bun/JSC with JIT disabled, and Node/V8 --jitless.
Both targets must hold on every benchmark, not just the aggregate.

## Indexed writes without per-index descriptor proofs (Linux)

Callgrind on Crypto put `set_index_mode` at 17% inclusive, with
`lookup_array_index_atom` (decimal formatting, UTF-8 validation, atom hashing) at

## Splay focus: measurement method and boxed frames (Linux)

Splay was chosen as the first fixture to win (smallest gap: Quench 790 versus
Node `--jitless` 3251, Bun 2950, QuickJS 2350 in one same-session run).

Method findings that change how results here should be read:
- A/A control: two byte-identical binaries showed +10.5% with 8/9 "wins" in
  the alternating Score harness; swapping roles gave +2.7% (5/9) and a
  same-file run 0.0%. Splay Score pairs on this host carry roughly ±10% drift,
  so single-digit Score deltas from that harness are not evidence. A
  fixed-work timer (setup, then 2,000 `SplayRun` calls timed internally) is
  used instead, together with deterministic callgrind instruction counts.
- `gdb` sampling of the timed loop (150 samples): GC 16.7%, dispatch loop 15.3%,
  property reads 13.3%, malloc/free 10.7%, object literals 8.0%, call setup
  7.3%, heap-cell loads 7.3%, frame moves 4.7%, property writes 4.7%.
- Disabling collection for large heaps (experiment only) raised the Score
  22.4% (bootstrap 95% interval 15.8% to 33.5%) at +333 MB RSS, so GC is about
  a fifth of the time and the mutator must still get about 3x faster.
- Rejected: doubling large-heap GC headroom (Score -1.1%, interval -4.8% to
  +6.4%, +98 MB RSS); caching global-name lookups (a 7,500-instruction path,
  but binding `Math.random`/`String` locally left Splay unchanged).

Retained: frames live in `Vec<Box<Frame>>` with a boxed pool (`pool_frame`,
`adopt_frame`), so a call or return moves an 8-byte pointer instead of a
216-byte `Frame` (callgrind: memcpy was ~234 instructions per call). Per-call
instructions fall from 2,713 to 2,456, the empty loop from 689 to 663 and a
field-read loop from 988 to 951. Fixed-work Splay: faster in 4/4 alternating
pairs (1.0%, 1.0%, 3.5%, 5.0%). Test262 stages 1, 11, 35-39, 49, 50 pass; stage
26 (`with/12.10-0-9.js`) and stage 48 (`call-bind-this-realm-value.js`) each
have one failure that also fails on the unmodified source. Lib tests: 530 pass
plus the pre-existing failure.

Two changes first rejected with the noisy Score harness were re-measured on the
fixed Splay workload (setup plus 200 `SplayRun` calls) by callgrind instruction
count, which is deterministic: inline handling of `LoadLocalPlain`,
`StoreLocalPlain` and `Move` in the general loop (these cannot allocate, collect
or throw, so they skip the root-map PC store and `step`), and a direct slot read
in `load_environment_binding` for environments not owned by a program's root
function (global var, global lexical and module-import projections exist only
there). Together: 14.19G to 13.72G instructions (-3.33%); fixed-work timing
median +2.5% (4/6 pairs faster). Node-oracle scripts unchanged; Test262 stages
1, 8, 11, 13, 14 pass and stage 26 has its pre-existing failure; lib tests 530
pass plus the pre-existing failure.

String concatenation of two string operands now skips `with_coerced_operands`
(three nested root scopes and two `ToPrimitive` calls, which are the identity
for strings; concatenation cannot collect). On the fixed Splay workload this
cuts instructions from 13.72G to 13.29G (-3.1%); Splay's leaf literal performs
two such concatenations. Oracle scripts unchanged; Test262 stage 70 passes,
stage 10 has the same 15 failures as before; lib tests unchanged.

The `prototype` atom is cached per program reset (`Vm::prototype_atom`,
`known_prototype_atom`) instead of hashing the string at each of 90 call sites;
`new` hashed it on every construction. Fixed Splay workload: 13.29G to 13.23G
instructions (-0.43%). Oracle scripts unchanged; Test262 stages 10, 26, 31, 48,
60 show only their known pre-existing failures; lib tests unchanged.

Two further Splay reductions, measured on the fixed workload by instruction
count with peak RSS from fresh binary copies:
- The in-loop frame push no longer wraps itself in `with_call_roots`: collection
  happens only at back edges, tail calls and explicit host safepoints, none of
  which can run during a push, and the pushed frame roots the callee, receiver
  and arguments. 13.23G to 12.98G instructions (-1.9%).
- Property-arena compaction ordered every live owner with a comparison sort of
  `(offset, slot)` tuples on each collection (4.0% of instructions). Owners are
  now packed into `u64` keys and ordered by a two-pass 16-bit radix sort on the
  unique offset; the order is identical (unit test against `sort_unstable`).
  12.98G to 12.44G (-4.1%); peak RSS 222.6/222.6 MB versus 222.8/223.1 MB. An
  unpacked first version cost +8.3 MB RSS and was replaced.
Rejected again on fixed-work timing: compacting the arena only when half of it
is released cut instructions 6.2% but ran slower in 5/6 pairs (median -2.4%)
with +3.5 MB RSS; compaction order matters for locality.
Test262 stages 1, 11, 47, 79-81 pass; stage 48 has its known failure; lib tests
531 pass plus the pre-existing failure.

Two GC passes and one lookup walk removed from Splay (fixed workload, Linux):
- Shape compaction derived the live-shape set from a second walk over every
  heap slot after sweep. The mark callback already sees each marked object's
  shape exactly once (`shape_rooted`), and marking has a single site, so that
  set is used directly. Property-arena compaction owners are gathered by the
  sweep itself (a plain per-slab loop) and compaction runs right after sweep,
  before any allocation can take a freed range. 12.44G to 11.95G instructions
  (-3.9%); fixed-work time faster in 8/8 pairs (median +7.0%); peak RSS
  219.7-219.9 MB versus 222.8-223.1 MB.
- Global-object reads (`Math`, `String`) walked the global object's
  non-dictionary shape chain, about 3,700 instructions per read and 22% of all
  D1 read misses. A shape that has 8 lookups each walking at least 32
  transitions now builds its existing lookup index, so index memory stays
  proportional to walking work already spent. 11.95G to 11.79G instructions
  (-1.3%); fixed-work time faster in 7/8 pairs (median +3.6%); peak RSS +0.8 MB.
Oracle scripts and a GC/shape churn script unchanged against the previous
binary and Node; Test262 stages 10 and 26 show only their known failures,
stages 31, 47, 53, 54, 60, 66 and 79-81 pass; lib tests unchanged.

Calls in CommonJS modules (compiled as `ProgramKind::Eval`) walked the callee's
whole environment chain on every call to collect inherited `with` objects.
`Native::WithEnter` is the only source of with objects, so a VM flag set there
and never cleared lets the walk return immediately until a `with` statement has
run. Fixed Splay workload: 11.79G to 11.63G instructions (-1.4%). Oracle scripts
and a with/eval closure script unchanged against the previous binary and Node.

Construction and polymorphic field adds on Splay (fixed workload, Linux):
- `new` hashed the string "prototype" on every construction and read the
  constructor's `prototype` through generic [[Get]]. It now uses the cached atom,
  and a function's own data `prototype` (confirmed non-accessor) is read directly;
  any other receiver keeps [[Get]]. 11.63G to 11.54G instructions (-0.8%).
- The field-add cache held one source shape per site, so add sites reached with
  several shapes (Splay nodes gain `left`/`right` in either order) thrashed it,
  and each miss cost about 3,000 instructions. Each site now keeps up to
  `FIELD_ADD_CACHE_WAYS` (4) source shapes, evicting the oldest. Slow adds fell
  from 95k to 48. 11.54G to 11.21G (-2.9%).
Together, fixed-work time is faster in 6/8 pairs (median +3.5%) with unchanged
peak RSS (220.5 MB). Oracle scripts plus an add-order, late-prototype-accessor,
non-writable-prototype-field and replaced/bound-`prototype` script match Node.

String concatenation built its result with three allocations and two copies and
then hashed the whole result into the dynamic-string dedupe table. It now
collects both unit slices into one exact-size allocation, and concatenation
results are not interned (string equality compares units; the operand-pair
concat cache still reuses repeated concatenations). Fixed Splay workload:
11.21G to 11.17G instructions; fixed-work time faster in 5/8 pairs (median
+1.7%); peak RSS 219.7 MB versus 220.4 MB. EarleyBoyer and RegExp scores
unchanged in three interleaved runs. A surrogate/key/accumulation script matches
Node; Test262 stages 53 and 70 pass, stage 10 has its known failures.

GC trigger headroom for large heaps (at least `LARGE_HEAP_LIVE_CELLS` = 65,536
survivors) raised from 1x to `LARGE_HEAP_HEADROOM_FACTOR` = 2x the surviving
set; small heaps keep half. Each collection re-marks every survivor, so on
Splay's ~1M-cell live set this halves mark work. Paired production Score
(12 pairs): Splay 1414.5 to 1842.5, median +24.2%, 95% CI [+9.1%, +35.4%],
12/12 wins, peak RSS +97.3 MB (220 to 317 MB; Node --jitless uses 371 MB).
EarleyBoyer (8 pairs): +3.1%, CI [0.0%, +6.0%], RSS +9.3 MB. The other six
fixtures keep their RSS. This follows the user's Score-first, RSS-may-grow
direction and is an interim point for task 82's Pareto-chosen headroom; the
earlier halving experiment remains rejected. The 384-allocation floor and the
small-heap divisor are now named constants. GC/weak Test262 stages 47 and
79-81 pass; lib tests unchanged.

Call-path trims on Splay (fixed workload, Linux):
- An in-loop call rebuilt the caller's code cursor (with a hot-decoding entry
  check) when the callee returned or unwound. The pending call now carries the
  caller's cursor; a hot decoding never moves once built, and a cold caller keeps
  reading packed code. The field and method cache-index helpers are forced
  inline (2M out-of-line calls). 10.74G to 10.64G instructions (-0.9%).
- Call, known-call and construct arguments are copied from the contiguous
  register window as one slice instead of a per-register iterator.
  10.64G to 10.59G (-0.5%).
Together, fixed-work time is faster in 6/6 pairs (median +6.6%). Oracle scripts
and a call/throw/unwind/construct script match Node.

`this` reads in ordinary functions (`this.root_`, constructor field stores)
resolved the frame's lexical-this dynamic binding on every access (about 140
instructions over 560k reads per fixed Splay run). Only `super()` rebinds
`this`, and only in derived constructors, whose binding starts deleted, so a frame
that pushed its own live binding now records `fixed_this` and reads `frame.this`
directly; every other frame, resumed continuation, recycled frame and discarded
Wasm frame keeps the lookup. 10.59G to 10.55G instructions (-0.4%). A
derived/arrow/field-initializer/eval/with-eval/generator/sloppy-strict/tail-call
`this` script matches Node. Fixed-work time is a tie (median -0.6%, 2/6 pairs
faster; within noise for a 0.4% instruction change). Test262 stages 8, 11 pass;
10, 26, 48 show only known failures; lib tests unchanged.

The mark worklist received every property value and array element, so a fixed
Splay run popped 11.2M work items to mark 2.0M cells (Splay's 643k live leaf

references (`ValueArena::append_heap_references`; deleted slots were already
non-references). 10.55G to 10.51G instructions (-0.4%).

Unary operators cloned the operand's whole heap cell to test for BigInt, even
for `!` on an object (Splay's `!current.left`), and `truthy` read the heap up to
three times. The BigInt probe now borrows the cell and runs only for the

instructions (-1.2%). A truthiness/unary script over every value kind is

BigInt console formatting.

Local operands (the right side of compares such as `i < n`) resolved through the
general `load_local_binding` path even when the slot is plain. Compilation and
validation each re-derived the per-slot plain proof; that derivation is now one

(`Function::plain_local`, never serialized), and a plain local operand reads the
frame's local array exactly as `LoadLocalPlain` does. Fixed Splay workload:
10.39G to 10.34G instructions (-0.45%); an empty counted loop: 637 to 539
instructions per iteration (-15%).

`new F(...)` on an ordinary constructor re-entered the interpreter through
`construct_value` -> `call_value` (a nested dispatch loop per construction, about
4,000 instructions each on Splay). The general loop now pushes such a constructor
as an in-loop frame, like a call: a non-class, non-derived, field-free user

object (`Vm::inline_construct_target`) gets a freshly allocated receiver,

receiver (`PendingGeneralCall::construct_this`). Every other `new` keeps
`construct_value`. Fixed Splay workload: 10.34G to 10.00G instructions (-3.3%);
cachegrind: I1 misses 57.8M to 41.0M, D1/LL unchanged, branch mispredicts
88.3M to 91.8M. Wall time is within this host's noise: paired Score median +6.5%
(8/12 wins, CI [-13.0%, +15.0%]), fixed-work median -2.0% (4/12), 16-round
min/median 1.252/1.405 s to 1.290/1.392 s. A constructor-semantics script (return
override, new.target, throw, recursion, replaced/non-object prototype, classes,
arrows, bound, many arguments) matches Node.

Heap cells shrink from 96 to 64 bytes. Every heap slot stores an `Option<Cell>`,

Temporal calendars, time zones, epochs and fields; Wasm memory types; RegExp
source, flags and legacy owner (`RegExpMeta`); and an environment's provenance and

inline for slot reads. `cell_layout_tests` asserts the bound. Peak RSS: Splay 311
to 240 MB, EarleyBoyer 55 to 49 MB, Richards unchanged; paired Splay Score median
+7.2% (5/8, CI [-6.7%, +20.9%]).
Cells then shrink from 64 to 40 bytes: iterator protocol caches, helper state and
generator records move into `IteratorExt` (stepping keeps `source`, `kind`, `index`,
`done` inline), and Wasm GC objects and tables box their declarations and value
vectors; the layout test bound is now 40. Peak RSS: Splay 240 to 186 MB,
EarleyBoyer 49 to 43 MB, RegExp 31 to 30 MB; paired Splay Score median +4.4%
(5/8, CI [-1.1%, +11.7%]). The 64-byte step's conformance run matched a HEAD
baseline on Test262 stages 8, 10, 26, 32-33, 43, 47, 52, 54-55, 62, 64-68, 74,
