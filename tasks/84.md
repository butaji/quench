## Plan scope

Use affected-stage checks plus compare-runs during changes. The current

## Outcome

Admit a compiler or linker setting to production only when a paired run on
Quench's pinned V8-v7 corpus improves the selected Score/RSS objective without
breaking correctness or regressing the cumulative gate. v2 results identify
candidates to reproduce; they are not transferred wins.

## Current gap

v2 task 218 found corpus PGO gains on Richards, DeltaBlue, Splay and Crypto;
task 335 retained the composed PGO profile at `opt-level 2`. Task 343 made
training deterministic, but its artifact scored 4.4% lower and used 160 KiB
more RSS than task 335. Determinism is therefore a reproducibility instrument,
not evidence that the deterministic artifact should ship. Other v2 settings
such as native ARM64 tuning (43/231), machine-function splitting (242),
identical-code folding (243), static relocation (245), and outlining of
PGO-cold regions (235/260) remain candidates for paired Quench measurements.
Further proposals—sampled PGO (270), stack protection (271), MIR inlining
(246/253), branch hints (240), and CPU tuning variants (254/269)—are not
production policy without such evidence. Task 84 owns the opt-in PGO build and
production/benchmark profile policy.

The M4 pre-gate probe is recorded in
[task84-pgo-instrumentation-probe-2026-10-07.json](evidence/task84-pgo-instrumentation-probe-2026-10-07.json).
That host's instrumented binary crashes during LLVM profile shutdown under
fat-LTO and no-LTO, and its raw profiles cannot be merged. The Linux follow-up
challenged whether this was a general Quench limitation: Linux Rust 1.99.0 /
LLVM 23.1.1 produced mergeable profiles from 100 disjoint microbench inputs,
and the resulting candidate matched Node on all 100. Eleven paired Richards
runs improved Score by 21.5 with a 95% interval of +16 to +25.8 and lowered
median RSS by 1,261,568 bytes with a 95% interval of -1,396,736 to -1,196,032.
The all-eight one-round candidate screen still placed Quench fourth in Score
on every fixture. This is a Linux pre-gate candidate result, not a production
win; the clean M4 baseline, all-eight paired gate and policy integration
remain open. Details are in the
[Linux PGO evidence](evidence/task84-linux-pgo-screen-2026-10-08.json).

A current-source recheck challenged the earlier PGO Richards result. The
opt-level-2 profile build was rebuilt at this branch's clean revision using the
existing 100-input microbench profile from revision `ac8febd`. A one-round
four-engine screen matched outputs on all eight fixtures, but PGO scored lower
on six and used more maximum RSS on six; Quench remained fourth in Score on
all fixtures and never had lowest RSS. Only Splay improved both measures in
the screen. Eleven paired Splay runs gave Score delta +33 (95% interval -10
to +80) and maximum-RSS delta -270,336 bytes (interval -860,160 to +139,264),
with both intervals including a tie. I did not promote this build policy. The
[current-source PGO recheck](evidence/task84-current-source-pgo-2026-10-08.json)
records the profile provenance, reports, output checks and paired follow-up.

A separate one-round, all-eight screen of opt-level 2 without PGO is recorded
in [task84-opt-level-2-screen-2026-10-07.json](evidence/task84-opt-level-2-screen-2026-10-07.json).
It scored lower on seven fixtures and raised RayTrace RSS by about 10 MB, so
opt-level 2 alone is not promoted. This does not test the PGO-plus-opt-level-2
composition from v2 task 335.

## Scope and implementation sequence

1. Start from the pinned v8-v7 submodule and the same M4 host configuration
   used by the four-engine gate. Establish matched Score and maximum-RSS
   baselines for all eight benchmarks before changing build policy.
2. Reproduce task 335's PGO plus `opt-level 2` candidate against that baseline.
   Keep the training corpus disjoint from the scored fixtures; report the
   deterministic task 343 artifact separately and retain it only if its own
   paired Score/RSS result qualifies.
3. Test a setting only when a measured benchmark gap motivates it. Change one
   setting at a time, record all eight benchmark results against QuickJS,
   Bun/JSC without JIT, and Node/V8 `--jitless`, and retain cumulative results.
   Do not copy v2 flags as a bundle.
4. Use task 83's region report to evaluate linker ordering or cold-code layout
   only when the paired measurements show a material RSS/code-layout gap.
5. Derive error and cold-path annotations from the selected production
   profile. Keep architecture-specific fast paths separately guarded by the
   JavaScript operation's exact fallback semantics.
6. Define production and benchmark build policy once; derive both profiles
   from that shared policy.
