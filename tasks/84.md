# 84: Port and extend v2's ahead-of-time toolchain policy

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select this work only for a
measured V8-v7 Score or RSS gap; finishing it is not a stage-completion gate.
Use affected-stage checks plus compare-runs during changes. The current

## Outcome

The production binary is built with the compiler and linker policy that
wins the paired gate on the eight fixtures: profile-guided optimization on a
deterministic training corpus, native CPU tuning, hot/cold splitting, code
folding, and hot-text ordering. Every flag has a recorded measurement.

## Current gap

The release profile uses fat LTO, one codegen unit, `panic = "abort"`, and
stripped symbols. v2 measured and retained more: corpus PGO (218, 229–231),
deterministic training (343), native ARM64 tuning (43, 231), `opt-level` 2
for the interpreter (335), machine-function splitting (242), identical-code
folding (243), static relocation (245), and outlining of PGO-cold regions
(235, 260). v2 also proposed further settings: tune-cpu separate from
target-cpu (254), function alignment (269), sampled PGO (270), stack
protector (271), MIR inlining (246, 253), and branch hints (240). Task 25 adds
only an opt-in PGO build.

## Scope and implementation sequence

1. Port v2's retained settings, and re-measure each one on this core, because
   the handler set and binary are larger.
2. Train PGO on a deterministic corpus of Test262, the Node set, and
   held-out JavaScript that excludes the eight scored fixtures. Report
   Score with and without training on the fixtures, to show that the gain
   generalizes. Production uses the corpus without the fixtures.
3. Generate a linker order file from the PGO profile, since BOLT does not
   support Mach-O, and check the page savings with task 83's region report.
4. Test only settings selected by the measured gap, one at a time against
   the paired gate. Record each tried result; a complete flag sweep is not
   required. Prioritize deterministic corpus PGO at opt-level 2, as measured
   by pinned v2 tasks 218/335/343.
5. Mark error, exception, and slow-coercion edges `#[cold]` or with
   `core::hint::cold_path`, guided by the profile rather than by guesswork.
6. Enable the CPU features the host has and the kernel can use, starting
   with `jsconv`: the ARMv8.3 `FJCVTZS` instruction computes ECMAScript
   `ToInt32` of a double in one instruction. Use it as a fast path on the
   `ToInt32` operation row, with the spec conversion as its reference
   definition.
7. Keep the policy in one profile definition. Production and bench profiles
   inherit it.
