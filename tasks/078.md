# 078: Generate Node dispatch from its registry

## Outcome

Derive capability lookup and handler registration from the active registry.

## Current gap

`registry.rs` has declarative registration while `dispatch.rs` still carries mechanical lookup knowledge.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering live there.

## Scope and implementation sequence

1. Inventory capability IDs, construction/call distinctions, ranges and exceptional dispatch.

2. Extend canonical registry rows with typed handler facts and generate lookup/aliases from them.

3. Remove duplicate literals and unreachable arms; leave exceptional host effects explicit.

## Verification

`cargo test -p quench-node`; `cargo run -p quench-node-test --bin run-compat`; local Node comparisons for values, descriptors, identity, ordering, errors and host effects. Test registry coverage and duplicate-ID rejection.

Apply the shared [completion checks](README.md), including named baseline failures
and independent semantic controls. Record commands and artifact identity.

## Definition of done

- Each capability has one declaration and every registered row has a valid dispatch path.
- IDs, ordering, constructors and error/effect behavior are preserved; no duplicate lookup authority remains.

## Performance evidence

Structural milestone; compare dispatch cost and binary size if generated layout changes.
