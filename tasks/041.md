# 041: V8-informed JS-scenario stencil coverage survey

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 040

## Context

Task 040 widens coverage by *quench's own measured* hotness evidence (call,
property, loop glue, array, `ForI`). This task is a systematic cross-check
against the categories of JS operation production engines (V8's Ignition/
TurboFan design, publicly documented) have found worth a dedicated fast path
for — not to copy V8's implementation, but to make sure quench's stencil
catalog isn't blind to a whole *category* of common JS usage that task 040's
evidence-driven list, built from quench's own current corpus, might
under-sample. Every item below stays inside this project's existing
Proven/Guarded/Unknown fact discipline and complete-fallback rule — this is a
coverage survey against known JS usage patterns, not a license to import any
V8-specific representation wholesale (see Non-goals).

## Scope
- crates/quench-runtime/src/stencil_select.rs
- crates/quench-runtime/src/stencil_fact.rs
- crates/quench-runtime/src/quickening.rs (fact reuse only, not a second
  representation)
- The build-time stencil catalog generation path

## Deliverables — survey first, then close only real, evidence-backed gaps

1. **Inventory pass.** For each category below, check the actual current
   code (not assumption) and record Present/Partial/Absent in
   `docs/deegen-stencil-coverage.md`, same discipline as task 035's audit:
   - **Keyed/element access with representation specialization.** V8
     distinguishes packed-SMI / packed-double / packed-generic / holey /
     dictionary elements kinds and fast-paths the dense numeric cases hard.
     Check whether quench's `AGetI`/`ASetI` (task 040 item 4) admission
     already distinguishes packed-numeric arrays from holey/sparse ones, or
     treats all arrays uniformly — if uniform, a holey/sparse array
     currently either gets an unsound fast path or (correctly, but
     wastefully) never gets one at all.
   - **Global variable access.** `ResolveNameOrUndefined`/
     `LoadCurrentGlobal`-shaped opcodes (seen live in `execution_trace`
     output during module/script startup) resolve through the general
     property-like path today. V8 gives global access its own IC bound to a
     property cell specifically because global lookups are extremely common
     in top-level and module code. Check whether this is worth its own
     `RegionKey`.
   - **Comparison/relational and `typeof`/`instanceof`.** These sit inside
     `Binary`/`Unary`'s generic dispatch today (per task 040 item 1's
     finding that `Binary` is a hot, currently-uncovered op). Loop
     conditions are dominated by `<`/`<=`/`===` — check whether these
     deserve their own guarded fast path distinct from arithmetic `Binary`,
     since the guard shape (both-numbers, both-strings, same-type) differs
     from arithmetic's guard shape.
   - **`for-in`/enumeration.** The quadratic enumeration bug this session
     found and fixed (see git history) was a correctness/complexity issue,
     not a stencil gap — confirm there's no *additional* stencil-tier
     opportunity here (an enum-cache-shaped fact reusing the existing shape
     system) now that the underlying complexity bug is fixed, or explicitly
     record why not.
   - **String concatenation.** Confirmed separately (curriculum case 032,
     ~30x slower than Node) to be a real cost center, but this is a
     *representation* question (rope/cons-string vs. eager concatenation),
     not a stencil-admission question — record it here as Absent but do NOT
     attempt it in this task; it needs its own task scoped to
     `value.rs`/string representation if pursued, since it changes a data
     structure, not a dispatch fast path.
2. **Close only what the inventory shows is both Absent and evidence-backed**
   (cite a specific curriculum case or `execution_trace` count — same bar
   task 040 uses, not "V8 has this so we should too"). Do not add a stencil
   for a category with no supporting evidence in this project's own
   measurements.

## Validation

Same per-item discipline as task 040: CFG-soundness unit test, differential
test (admitted vs. forced-fallback, plus a hostile counter-example that must
correctly fall through — e.g. a holey array for the elements-kind item, a
`Proxy` for the global-access item), `cargo test -p quench-runtime --lib`,
before/after measurement on the relevant curriculum case, and an update to
`docs/deegen-stencil-coverage.md`.

**Fail condition**: adding a specialized fast path for an "array" that
doesn't distinguish packed-numeric from holey/dictionary would be unsound
(wrong results on sparse arrays) or, if implemented defensively, silently
never admit real-world sparse arrays while claiming coverage — either way,
the differential test against a genuinely holey/sparse array is mandatory,
not optional, for the elements-kind item specifically.

## Non-goals
- Copying V8's actual internal data structures or elements-kind enum
  wholesale — quench's own `Certainty`/`Shape` fact vocabulary stays the one
  representation; V8 here is a checklist of *scenarios to survey*, not an
  implementation to port
- String rope/cons-string representation — real, evidenced gap, but a
  separate task if pursued (representation change, not stencil admission)
- Any new tier, speculation, or deoptimization — still not paper scope, per
  the standing project constraint
