# 94: Collect the active V8-v7 fixture's heap without re-marking old data

## Outcome

On the fixture Task 61 has active (Splay at the time of writing), the
collector lets the heap stay within the RSS bar without giving up the Score
bar. The bar engine for Splay is Bun with JIT disabled at 57,950,208 bytes
median maximum RSS on the M4.

## Current gap

The collector is a full non-moving mark-sweep. Marking is about 90% of its
time. Every collection re-marks Splay's ~781K old survivors, most of them the
splay tree, which changes slowly.

- Large-heap headroom at 0.75x survivors cost 5.75% cycles for 11% less RSS,
  and 0.5x cost 12.1% cycles for 21.5% less RSS, both measured before Task
  61's record compaction.
- Raising large-heap headroom to 2x survivors bought 24% Splay Score at
  +97 MB RSS (Linux). Halving full collections is therefore worth about a
  quarter of Splay's time.
- With 32-byte records, Task 61's arithmetic puts the RSS bar at headroom
  near 0.5x.

Only a collector whose common cycle does not trace the old tree reaches both
bars.

## Scope

1. Model the collector as a named state machine: idle, minor marking, full
   marking, sweeping.
2. Implement sticky-mark generations. Marks persist across minor
   collections. A write barrier on property, element and environment-slot
   stores into marked cells records them once in a remembered set. A minor
   collection traces roots, the remembered set and young cells only, and a
   full collection runs on a named growth trigger.
3. Add a debug verifier that runs a full mark after each minor collection and
   asserts that both mark the same live set.
4. Sweep lazily, by block, on allocation demand.
5. Remeasure the large-heap headroom curve (1.0, 0.75, 0.5) for cycles and
   RSS. Propose the factor to the trunk; the trunk owns the named policy.
6. Return fully free pages to the operating system after a sweep crosses a
   named threshold.

Retained specification [82](82.md) holds the broader collector design space:
nursery copying, Immix and pretenuring. This task delivers the generational
step the active fixture needs. The heap record layout belongs to Task 61.

## Gates

Task 92's sync protocol and M4 gates. Add the GC, weak-reference and
FinalizationRegistry Test262 stages, and run the full Wasm suite whenever
barriers touch shared store paths.
