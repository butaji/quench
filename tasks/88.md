# 88: Freeze the web-framework Node inventory

## Plan scope

Deferred outside the current two-stage strategy. This proposal adds no Stage A
suite gate, implemented Node membership, or cutover dependency. The retained
material below records prior investigation; it is not an active requirement.

## Outcome

This deferred proposal would require production `quench-node` to run popular web frameworks
without issues. This task owns the definition of that requirement: pinned
real-framework scenarios plus the upstream `test/parallel` fixtures for every
builtin those frameworks use, frozen in
[node-framework-inventory.json](node-framework-inventory.json). Membership
follows framework use and the local Node oracle, never Quench outcomes.
[Task 89](89.md) makes the inventory pass.

## Frozen state

- **Scenarios:** [`tests/frameworks`](../tests/frameworks/README.md) pins
  Express 5.2.1, Koa 3.2.1, Fastify 5.12.5, Hono 4.13.13 with
  `@hono/node-server` 2.1.3, NestJS 12.1.2 on Express, h3 2.0.1 (the
  Nuxt/Nitro server core) and Next.js 16.3.8 with a prebuilt App Router app.
  Each serves the same five loopback requests: HTML, a JSON POST body, a
  streamed body, a static file and a 404. All seven match local Node v26.10.0.
- **Builtins:** the packages request 29 builtin modules. `tls` enters as the
  base of `https`/`http2`, and `web_globals` covers the undici and WHATWG
  globals (`Request`, `Response`, `Headers`, streams, encoding,
  `structuredClone`) that the scenarios load or call.
- **Fixtures:** those 31 families contain 2,990 upstream fixtures at the pinned
  `tests/node` (27.0.0-pre):
  - **2,660 required**: the oracle passes them.
  - **233 excluded**: 194 request `--expose-internals`, and Node itself skips
    39 on this host.
  - **97 pending oracle alignment**: the v26 oracle fails or times out on
    these newer fixtures.

  The current `parallel.txt` holds 480 of the required fixtures.

- **Integrity:** the deferred inventory retains fixture hashes, rule IDs and
  family membership for its future audit. Active queue checks validate task
  19's implemented-Node inventory; this deferred inventory does not block them.
- **Evidence:** the
  [evidence file](evidence/task88-framework-builtin-trace.json) records traces,
  scenario hashes, method limits and the quench-node review.

## quench-node review

[butaji/quench-node](https://github.com/butaji/quench-node) (head `a1cd68ea`)
gated Ajv, debug, Chalk, ms, Prettier and `process.argv0`; it gated no web
framework. Its Hono example called `app.fetch(new Request(...))` inside a
`node:http` handler rather than `@hono/node-server`. Its Next.js benchmark
never started a Next server. quench-v2 inherited Rust facsimiles of `ajv`,
`chalk` and `prettier` in `crates/quench-node/src/modules/npm.rs` that
`require.rs` resolves before `node_modules`. The `crates/quench-node-test/
examples/{express,hono,nextjs}-server.js` files are hand-written route tables
that load no framework. None of this is framework evidence.

## Remaining scope

1. **Oracle alignment.** Qualify an oracle that matches the pinned
   `tests/node` revision, either a Node build of that commit or a pin moved to
   the matching release. Then resolve each `pending_oracle` fixture to
   `pass`, `skip` or a new named rule with its reason. Re-derive the totals.
2. **Derivation tool.** Check in one tool that installs from the lock, builds
   `next-app`, runs both tracers under local Node and the oracle over the
   family fixtures, and writes the inventory. It must reproduce the file
   byte for byte. Record the oracle invocation, including the clean test-tree
   copy that avoids the root `"type": "module"` package scope.
3. **Runners.** `run-parallel` gains a mode that runs the inventory's
   required fixtures through production `quench-node` and records raw
   outcomes. The `parallel.txt` entries inside these families then come from
   the inventory instead of a second list; the 106 entries outside it remain
   the regression manifest. Add a scenario runner that starts each scenario
   under `quench-node` and compares status, headers (`Date` by format only),
   body bytes and exit status with local Node.
4. **Remove non-evidence.** Delete the "-style" examples.

Adding a framework re-runs the derivation. Membership can grow from measured
use but never shrinks to reach a pass target.

## Verification

Reproduce the inventory twice from a clean checkout. The coherence-check
controls for a changed hash, an omitted family fixture and an unknown rule
already fail as required. A scenario must fail when its framework package is
missing.

## Definition of done

- No `pending_oracle` entries remain; every exclusion names its rule.
- The checked-in tool reproduces the frozen inventory exactly.
- The inventory and scenario runners run on production `quench-node` and
  record exact provenance.

## Performance evidence

None. Framework startup and request throughput are not Stage A targets.
