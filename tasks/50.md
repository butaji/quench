# 50: Measure and reduce cell, object and string footprint

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select this work only for a
measured V8-v7 Score or RSS gap; finishing it is not a stage-completion gate.
Use affected-stage checks plus compare-runs during changes. The current
dependencies in [index.json](index.json) supersede older prerequisite claims.

## Outcome

Reduce cell, object-header and string costs only where a current Quench census
connects them to a V8-v7 Score or RSS gap. Pinned v2 layouts are comparison
evidence, not target sizes. Preserve one semantic authority for each fact;
derive or cache host-facing views only where measured cost justifies them.

## Current gap

The `-Zprint-type-sizes` census in
`target/reviews/core-review-2026-09-23/type-sizes.txt` is historical, not
current layout or compile evidence. Refresh type sizes and per-kind allocation
costs on the selected production build before claiming a footprint gap. Treat
the old findings as hypotheses to verify: uncommon object state in the common
header, large cell variants, a cached UTF-8 view beside UTF-16 units, and
quadratic string concatenation.

V2 task 66 measured compact parameter/local counts and one flattened method-
argument table on DeltaBlue. Quench already stores method arguments in
`ResidualProgram.method_arguments` and static atom text in an arena. It still
retains parameter/local names for eval, dynamic scope and environment lookup;
removing those names by analogy would change live semantics. Reconsider them
only if a current Quench census identifies their cost and the needed name
lookups can be derived from a semantics-preserving representation.

## Scope and implementation sequence

1. Refresh type sizes, allocation counts and retained bytes for the current
   production build. Reuse task 77's selected attribution rows where available;
   do not require an all-domain census.
2. Identify the field or payload responsible for a measured gap. Trace its
   semantic readers, writers, serialization and GC edges before changing its
   representation.
3. Change one representation at a time. Derive layouts and metadata from one
   authority, preserve exact generic behavior, and keep compile-time layout
   assertions only where a specific invariant requires a fixed layout.
4. For strings, keep one semantic unit representation. A cached encoded view
   is derived state; retain it only with explicit lifetime rules and measured
   benefit. Do not prescribe UTF-16, Latin-1 or a rope by analogy.
5. Consider cell variants, object headers, arrays, strings, concatenation and
   suspended frames only when the selected measurements identify that cost.
   Stop with the census when a proposed representation cannot recover a
   meaningful Score/RSS cost.

## Verification

Run affected Test262 stages plus compare-runs. Select string, object, arguments,
and module cohorts according to the changed representation. Run affected Node or
Wasm cases only when their shared execution path changes. Full-suite runs
belong at gates and stage transitions. Units cover internal invariants or
scenarios not covered by the conformance suites.

## Definition of done

- Each retained change has an attributable Score/RSS benefit and preserves
  JavaScript/Wasm semantics on affected cases.
- No representation is required to match a v2 size. Record the measured
  Quench layout and why its fields are necessary.
- Each fact has one semantic authority; each retained cache is a derived view
  with measured benefit and explicit lifetime rules.

## Performance evidence

Report `Cell`/`Object`/`JsString` sizes, per-kind allocation bytes
(`profile-memory`), and maximum RSS for the affected V8-v7 benchmarks before
and after. Measurement only; this task does not prescribe a target layout.
