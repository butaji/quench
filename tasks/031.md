# 031: Tag register optimization for the boxing scheme

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 030

## Context

Paper §5.3: boxing-scheme operations often need large 64-bit constants;
Deegen scans generated LLVM IR for large constants expressible as a pinned
"tag register" base plus an 8-bit offset, and rewrites them to use the small
offset instead of embedding the full 64-bit immediate. Audit confirmed:
`tagged_value.rs` embeds NaN-tagging constants (`TAG_PREFIX`/`TAG_SHIFT`/
`TAG_MASK`) as immediates directly; nothing pins a base constant in a
register for small-offset field access anywhere in the crate.

## Scope
- crates/quench-runtime/src/tagged_value.rs (or wherever the boxing constants
  now live)
- crates/quench-runtime/src/stencil_arena.rs / stencil_patch.rs (JIT-emitted
  code is where this optimization actually pays off — interpreter-only code
  gets little benefit since it's not per-instruction immediate-heavy)

## Deliverables
- Depends on 030's register-pinning outcome: this technique only makes sense
  once a register is reliably pinned to hold the tag-scheme base constant
- In the stencil-rendered JIT code path specifically, replace large boxing
  constant immediates with small-offset-from-pinned-register accesses where
  the stencil emits them
- Profile before/after on boxing-heavy neutral corpus cases (property access,
  numeric tagging)

## Validation

**Gate 0**: Check task 030's recorded outcome first. If 030 concluded "not a
measured cost, no implementation" or otherwise has no pinned register
available, mark this task **blocked** in `docs/deegen-alignment.md` with a
one-line reason and stop — do not build a substitute mechanism that isn't
actually register-pinning.

If 030 produced a usable pinned register:
1. Identify the specific boxing constants replaced (list them in the PR/
   commit description — e.g. which `TAG_PREFIX`/`TAG_SHIFT`/`TAG_MASK` use
   sites in stencil-rendered code).
2. `cargo test -p quench-runtime --lib` — all pass, tagged-value differential
   tests (NaN-boxing edge cases: NaN itself, ±Infinity, all tag classes)
   unchanged.
3. Profile boxing/property-access-heavy neutral-corpus cases specifically
   (not just the aggregate geomean) before/after; record the delta.
4. Full `node quench-bench/micros/verify.mjs ... --from 1 --to 100 --runs 3` — 100/100, no regression anywhere in the corpus even outside the targeted cases.

**Fail condition**: any change to tagged-value bit layout or semantics (not
just where the constant comes from) fails this task immediately — this is a
constant-materialization change only.

## Non-goals
- Changing the boxing/NaN-tagging scheme itself — this is a codegen-level
  constant-materialization optimization only
