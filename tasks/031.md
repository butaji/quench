# 031: Optimizing JIT IR — instruction selection, register allocation, speculative type specialization

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 030

## Context

This is the large gap named in `docs/deegen-alignment.md`: quench has no
DFG-style IR, no runtime instruction selection or register allocation, and no
speculative type specialization beyond the region-stencil tier's build-time
type-check elimination (which only proves facts already known at build time —
it never speculates on a runtime-observed type feedback profile). This task
builds that tier last, on top of every prerequisite: 027's profiling signal
decides *when* to compile into it, 028's OSR entry decides *how* execution
gets into it mid-loop, 029's deopt protocol is the mandatory safety net for
every speculative guard it emits, and 030's shared IC means it reuses cache
state rather than duplicating it.

## Scope
- New: an optimizing-JIT IR/codegen module (name and file layout TBD during
  implementation — likely mirrors `stencil_*.rs`'s arena/lifecycle split)
- crates/quench-runtime/src/vm/vm_runtime.rs (tier-up call site)

## Deliverables
- A DFG-style IR built from the same `vm_op!`/fact catalog that already
  generates the interpreter and baseline JIT — no second bytecode semantics
  source of truth
- Real instruction selection and register allocation at compile time (this is
  what makes it "optimizing" rather than another stencil tier — the paper is
  explicit that the baseline tier does none of this)
- Speculative type-based optimization consuming 027's profiling feedback,
  with every speculation point wired to 029's deopt protocol from the start
- Compiles reachable via 027's tier-up policy and 028's OSR entry

## Acceptance
- Every speculative guard has an exercised deopt test (029's acceptance bar
  applies here directly)
- Differential tests confirm identical observable behavior compiled vs.
  interpreted for the same program
- Neutral corpus geomean improves (this is the first task in the backlog
  whose entire purpose is a performance win, not just infrastructure — measure
  it, don't assume it)
- Complete ordinary-interpreter fallback remains reachable for every Unknown
  fact, exactly as required of every other guarded fast path in this project

## Non-goals
- Changing the region-stencil baseline tier's own scope (021-026, closed) —
  this is a new, higher tier above it, not a replacement
