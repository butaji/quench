# 096: Resolve one measured non-core semantic bottleneck

## Outcome

Resolve the highest-impact non-core semantic bottleneck identified by a current
profile. This lane is deliberately finite per activation; it is not a promise
to redesign every subsystem before the VM path advances. A later profile may
create a new queued item with fresh scope, but a completed item is removed
rather than reopened.

## Current gap

Existing string/RegExp/BigInt and collection helpers can dominate workloads even when bytecode dispatch improves.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering live there.

## Scope and implementation sequence

1. Profile the remaining micro groups and V8-v7; select exactly one bottleneck
   using sampled production time and controlled contrasts.

2. For that subsystem, distinguish wrapper/conversion/descriptor cost from
   backend work, then implement one shared general correction. Do not widen the
   activation to unrelated strings, RegExp, BigInt or collection work.

3. Build the semantic matrix required by the selected subsystem (including
   effects, identity/order and exceptional inputs where applicable).

4. Finish a correctness/measurement matrix for the selected group. Record
   neutral/rejected hypotheses as artifact conclusions; activate a follow-up
   only when a new profile identifies another bottleneck.

## Verification

`cargo test -p quench-runtime`; `cargo test -p quench-node`; full reserved/all-size/legacy micros and complete V8-v7. Use Node differential cases for changed builtins and effect logs.

Apply the shared [completion checks](README.md), including named baseline failures
and independent semantic controls. Record commands and artifact identity.

## Definition of done

- The selected subsystem has current coverage and a classified result.
- Its correction is implemented, semantically verified and measured against
  independent workloads; untouched subsystems remain explicitly outside scope.
- Unresolved semantic failures have explicit tasks; no benchmark-specific backend or hidden exception is added.

## Performance evidence

This is a profiled side lane, not a prerequisite for task 097. Require supported
per-subsystem gains and a complete suite comparison; do not infer backend
weakness solely from a benchmark name.
