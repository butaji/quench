# 023: Bump-pointer code arena and typed-hole patch writers

- **Theme:** copy_patch_jit
- **Executor:** codex
- **Depends on:** 022, 026

## Scope
- crates/quench-runtime/src/stencil_arena.rs (new, edge effects only, target ≤150 lines)
- crates/quench-runtime/src/stencil_patch.rs (new, pure straight-line writers, target ≤150 lines)

## Deliverables
- `stencil_arena.rs`: a bounded bump-pointer executable-memory arena (mmap RW, then RX; W^X respected). This file is the *only* place in the tier that touches `mmap`/`unsafe` memory-mapping — every other file in this theme stays effect-free. No malloc-per-region.
- `stencil_patch.rs`: one small straight-line writer function per `HoleKind` (`write_imm32`, `write_disp32`, `write_rel32`, `write_ptr64`) reading from `PatchValues`; no loops, no `switch`/`match` inside a writer — dispatch on `HoleKind` happens once, in the caller, via the closed enum from task 021
- The hot sequence end to end: `select_stencil(facts) -> arena.alloc(size) -> copy_nonoverlapping(bytes) -> apply_holes(dst, holes, &patch_values) -> make_executable -> jump`; every step fallible, falling back to the complete ordinary interpreter path on any failure
- A region's stencil ends with a direct jump/fallthrough to the next region's installed address, not a return through the driver loop — this depends on task 026's continuation-passing dispatch existing for the *interpreter* path first, since the JIT fast path's fallthrough elimination (Deegen §7.1 point 1) only has meaning once "the next thing to run" is a callee-supplied address rather than a value handed back to a loop

## Acceptance
- `stencil_arena.rs` has an explicit, tested upper bound on mapped bytes and can be torn down without leaking pages
- No instruction selection, register allocation, or CFG analysis happens anywhere in this task's code — only `select -> alloc -> copy -> patch -> execute`, matching the operational bright line: if any of those four steps grows a decision procedure, it belongs at build time (022), not here
- A patched region executes and produces identical observable results to the ordinary interpreter path for the same operations and inputs, verified by differential tests including exceptions and control-flow exits
- Any copy/patch/mmap failure deterministically falls back to ordinary semantics; no partial or corrupted code ever executes
- A stencil's exit is a direct branch to the next installed region's address (or a return to the ordinary interpreter driver on fallback), never a value returned up through a generic dispatch loop

## Non-goals
- Repatching an already-installed region's code bytes (task 024 covers *data*-only repatch first)
- Any OSR, deoptimization, or tiering policy beyond "install once, run, or fall back"
