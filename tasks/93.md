# 93: Close the active V8-v7 fixture's speed gap on the call and dispatch path

## Outcome

On the fixture Task 61 has active (Splay at the time of writing), Quench's
marginal cost per `run()` reaches the no-JIT Score bar's engine. The 2026-10-10
M4 distance is 1.96x Node `--jitless`; the target is at most 1.0x.

## Current gap

Measured on Splay:

- Calls: 6,961 per `run()`. An empty call costs 1,653 retired instructions
  more than the loop control on Linux Callgrind, 989 of them inside
  `run_frame_general_until`, with 7 extra dispatches per call.
- Locals: `LoadLocalPlain`, `StoreLocalPlain` and `Move` were 49% of the run's
  dispatches. Promoting immutable parameters to frame registers removed 22% of
  dispatches and 6.8% of cycles. Promoting mutable locals cut another 4.65% of
  instructions but was rejected for a 2.18% RegExp RSS increase whose cause is
  not yet attributed.
- Constructs: `new SplayTree.Node` costs 7,679 instructions per iteration on
  the per-op table, against 582 for Node `--jitless`.
- A simple dispatch costs about 110 instructions on the Linux Callgrind
  control loop.

## Scope

1. Call and return: header-only frames over one contiguous value stack, with
   arguments written directly into the callee's parameter registers. Derive
   from the function body whether `this` and `new.target` bindings are
   observable and skip them when they are not. Confirm Node's semantics for
   legacy `f.arguments` before changing how original arguments are kept.
2. Mutable-local promotion: attribute the RegExp RSS increase (rooted dead
   registers, duplicate frame sizing, or a shift in collection timing), fix
   it, and re-gate.
3. Construct sites: cache the callee identity with its prototype root shape
   and predicted inline capacity, the latter shared with Task 61's record
   layout.
4. Per-dispatch residue: the per-instruction PC store, bounds-checked frame
   indexing and operand decode, attributed by Callgrind line counts.

Measure first and choose by attributed size. Retained specifications [49](49.md)
and [78](78.md) hold the earlier analysis of the call/local facts and
dispatch alternatives.

## Status

2026-10-10, Linux screening on the merged head (`75e21625b`).

**Method.** Marginal instructions per Splay `run()`: Callgrind totals for
`splay-runs-200.js` minus `splay-runs-0.js`, divided by 200. Both scripts are
the stock `splay.js` with `SplaySetup()` followed by 200 or 0 `SplayRun()`
calls. Build: `cargo build --profile profiling -p quench-runtime --bin quench`.
Command: `valgrind --tool=callgrind <bin> splay-runs-N.js`. Max RSS is measured
with `posix_spawn` and `ru_maxrss` on the 200-run script.

**Attribution at `75e21625b`.** 37.05M instructions per run.
`load_environment_binding` took 7.58M of that (20%) across 10.6K calls per run.
These are closure reads of script-level `var` bindings, such as `splayTree`,
`kSplayTreeSize` and `SplayTree`. Each read went through program lookup,
`root_global_var_atom` (a linear scan of the root's global atoms) and then a
generic `get_property` on the global object, about 715 instructions in total.

**Retained: global `var` read cache.** A direct-mapped table of 64 entries is
keyed by (root environment, slot). Each entry records the global object's shape
and the property slot of the own data property.
- *Valid while:* the collection epoch is unchanged (cells keep their identity
  between collections), no direct-eval var program is active, and the global
  object still has the recorded shape.
- *Why the shape suffices:* shapes are append-only per add, delete or
  descriptor change, so an unchanged shape keeps both the slot and its data
  attributes.
- *Clearing:* shape compaction clears the table along with the field caches.
- *Fallback:* every miss runs the unchanged generic path.

rejects the layout only when the name is a promoted local. Previously any

parameters failed validation ("invalid promoted-local layout"). This was also
present on `origin/v2` `891319e92`. Test262 `language/directive-prologue` went
from 60/62 to 62/62.
