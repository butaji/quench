# 73: Eliminate allocations that provably do not escape

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select this work only for a
measured V8-v7 Score or RSS gap; finishing it is not a stage-completion gate.
Use affected-stage checks plus compare-runs during changes. The current
dependencies in [index.json](index.json) supersede older prerequisite claims.

## Outcome

Allocations whose identity can never be observed are replaced by registers
in the residual. Candidates are object and array literals, destructuring
temporaries, iterator result objects, and `arguments` objects. The proof is
static and holds for every input.

## Current gap

`const {x, y} = {x: a, y: b}` and `[a, b] = [b, a]` each allocate an object
or array only to read it back immediately. Every `for-of` step over a
generator allocates a `{value, done}` result. The docs note on
[closure environments](../docs/v2/closure-environments.md) puts closure
escape out of scope, and no task covers the other allocation kinds.

## Dependencies

See this task's `depends_on` in [index.json](index.json). This task needs

## Scope and implementation sequence

1. Census hot allocations and retention first. Pinned v2 task 368
   rejected lazy unobserved function prototypes (-0.6% Score, +32 KiB RSS);
   tasks 360/367 rejected precise/compact GC root changes despite reduced
   retention or metadata. Saved allocations alone do not admit a transform.
   Add the escape domain to the binding-time analysis. An allocation escapes if it is stored to
   the heap or to a captured binding, passed to a call that is not known and
   summarized, returned, thrown, yielded, or live across a `reenters` edge.
2. A non-escaping allocation with a static layout (task 72) becomes one
   register per slot. Property reads and writes on it become register moves.
3. Array destructuring runs the iterator protocol, which guest code can
   observe. It is eligible only behind the array-iterator protector from task
   34. When the protector has tripped, execution falls back to the full
   protocol at the declared resume point.
4. `arguments` objects in strict functions that only read `arguments[i]`
   and `arguments.length`, and never let the object escape, become parameter
   reads (together with task 31). `f.apply(this, arguments)`, lowered by task
   71, forwards the caller's argument registers without materializing the
   object.
5. Generator result objects consumed by a `for-of` in the same function
   are eligible only when the generator is a known callee (task 71) and the
   iterator never escapes.

## Verification

Test262 cases for destructuring order with getters and proxies, iterator
closing, `arguments` mapping in sloppy functions, and generator `return`
and `throw`. Protector trips in the middle of destructuring. Generic-mode
controls allocate every candidate and compare with the existing path. Forced
guard failure resumes generic execution with equal results for every guarded
case.

## Definition of done

- No scalar-replaced allocation is observable through identity, reflection,
  getters, proxies, or stack traces.
- Every case that depends on the iterator protocol is guarded by a protector
  and has a resume point.
- Escape facts come only from the binding-time analysis.
