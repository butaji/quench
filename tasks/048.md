# 048: Grow region scope from hot glue sequence to whole loop body / small function

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 042

## Context

Task 042 built a real bounded multi-op sequential region executor, but
today's regions are still short (arithmetic glue, a handful of
instructions). Sparkplug-class baseline-JIT value — the realistic ceiling
for this project's build-time-proof-only design, per
`docs/deegen-alignment.md`'s tempered expectations — comes from turning as
much of a hot function's *entire* body into one native sequence as
build-time admission allows, not from more coverage breadth alone. This is
the single largest lever left inside the existing architecture: nothing in
042's design requires regions to stay short, it just hasn't been pushed
further yet.

## Scope
- crates/quench-runtime/src/stencil_fact.rs (CFG single-entry-point proof —
  extend to whole loop bodies/functions, not just short spans)
- crates/quench-runtime/src/stencil_select.rs
- crates/quench-runtime/build.rs (longer sequential byte emission)

## Deliverables
- Profile-identify the largest loop-body/function-body spans in the
  neutral corpus and curriculum that are fully covered by Proven/Guarded
  facts end to end (no Unknown fact forcing an early exit)
- Extend the CFG-soundness proof to whole spans of this size — the same
  single-entry-point invariant applies, just over more instructions
- Emit the longer sequential stencil using task 039's const-fn encoder
  discipline for every instruction in the span
- Complete ordinary-interpreter fallback for any point in the span where a
  fact goes stale — same partial-match discipline task 042 already proved

## Validation

Same bar as 042: CFG-soundness test for the larger span, differential test
comparing whole-span fused execution vs. one-instruction-at-a-time
interpretation, a partial-match/hostile fallback test, before/after
measurement on the curriculum cases whose loop bodies/functions match the
extended span, and an update to `docs/deegen-stencil-coverage.md`.

**Cross-check once task 052 exists** (may land before or after this task —
check `tasks/index.json`): re-run the v8-v7 suite (Richards, DeltaBlue,
Crypto, RayTrace, EarleyBoyer, NavierStokes are the loop/function-body-heavy
ones) before/after this task's change and record the delta in
`docs/architecture-evidence.md`. The curriculum is a useful proxy but it is
not the actual comparison target this whole task chain exists to move — a
region-scope change that helps the curriculum but not v8-v7's real
benchmarks is an incomplete result, not a finished one. If 052 hasn't landed
yet when this task completes, note that the v8-v7 cross-check is
outstanding rather than skipping it silently.

**Fail condition**: same as 042 — a span that claims full-body fusion but
silently executes fewer instructions, or that partially executes before
falling back mid-span, is a correctness bug.

## Non-goals
- Any speculation about which span will be hot at runtime — spans are
  chosen by build-time fact coverage, never runtime profile-guided
  selection of *which code to compile*
