# 26: Match v2 Score and RSS

## Outcome

Reach the agreed Apple M4/macOS throughput and memory gate against the pinned v2
interpreter. This is the first step of phase C and the fastest route to a high
V8-v7 score: `../v2` is the reference for reaching high scores, so its measured
mechanisms are ported before anything new is invented. Task 61 then goes beyond
v2 to lead the no-JIT reference engines on all eight fixtures.

## Current gap

Full semantics and hostability add representation and dispatch costs that have not been measured against the clean reference implementation.

Starting point (single runs, 2026-09-23 core review,
`target/reviews/core-review-2026-09-23/`; ../v2 was at 072ca256…, not the
pinned commit): pinned-v2-class `rqj` scores Richards ≈1,930–1,970 at 2.1 MB
maximum RSS. The next core fails v2's bundled Richards, DeltaBlue, and Splay
fixtures in the residual validator (task 10). On the base.js harness it scores
Richards 45–49 at 7.6 MB. The known causes are v2-fidelity regressions owned
by tasks 08 (cache invalidation and pre-cache work, shape cloning), 49 (static
facts rediscovered per call), and 50 (104-byte cells, dual-authority strings).
Those tasks, not this one, remove them; this task starts from their result.
Mechanisms that would exceed v2 rather than match it belong to task 51.

## Dependencies

See this task's `depends_on` in [index.json](index.json). This task runs on the
single core after the design gate (task 59). Its baseline is the cutover
measurement that task 27 records, re-measured at task 59.

Work v2-first. For each Score or RSS gap, find the v2 mechanism that covers it,
in the pinned `../v2` source and its recorded decisions under
[`docs/v2/`](../docs/v2/), and port that mechanism onto the watermark tables
(an accelerated primitive with its reference definition, or a binding-time
row). Depart from v2 only with a measurement that beats v2's recorded result
under the same paired gate.

## Scope and implementation sequence

Build production standalone binaries for pinned v2 and the next Quench core with matched toolchain/profile/PGO policy. Run odd rotating paired tournaments for Richards, DeltaBlue, Crypto, and Splay, and record the other four V8-v7 fixtures for both engines wherever v2 runs them. Optimize only general v2-style mechanisms—binding-time facts, residual rewrites, dispatch, shapes/caches, allocation/GC, layout, and AOT compiler policy—with exact fallback and held-out semantic controls.

## Verification

Use at least 11 complete pairs per comparison. Reject runs with missing samples, more than 5% control drift, mismatched sources/binaries/page size, or invalid benchmark results. Run task 24's focused safety controls after every retained mechanism change and the full gate before completion.

## Definition of done

- For each workload, Quench median Score is at least the pinned v2 median.
- For each workload, Quench median maximum RSS is no greater than the pinned v2 median.
- Reports include ordered raw samples and 95% paired intervals; no benchmark-shaped behavior exists.

## Performance evidence

The matched reports are this task's primary deliverable. Also report startup, specialization time, residual bytes, GC, and regression analysis.
