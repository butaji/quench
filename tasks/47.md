# 47: Derive the generating extension and prove the Futamura equation

## Outcome

Make the kernel swappable while Test262 stays at 100%. Kernel experiments
change only kernel code and kernel tables. The generating extension follows
from the tables. The reference kernel proves that the residual still means
what the interpreter means.

## Current gap

Task 46 declares the watermark tables and their binding-time columns, but the
compiler still carries its own folds, fast paths, and exotic-object branches.
Nothing yet checks that a kernel change leaves semantics intact apart from
Test262 itself.

## Dependencies

See this task's `depends_on` in [index.json](index.json). The tables and crate

## Futamura and Ershov obligations

This task carries out the rules in
[task 46](46.md#futamura-and-ershov-across-the-watermark):

- **P1 over kernel + library.** `mix(interpreter, program) = residual`, where
  the interpreter is the kernel plus the library.
- **Ershov's one definition, two binding times.** Every compiler fold runs a
  statically evaluable table entry on static inputs. No compiler-side copy of
  a semantic definition survives.
- **Binding-time classes read from the tables.**
  - Static: statically evaluable entries.
  - Specialization environment: intrinsics, registry entries, and object-kind
    rows addressed by index.
  - Dynamic: accelerated primitives, emitted unguarded under a `StaticValue`
    proof or guarded, with their reference definition as the exact fallback.
- **Congruence from effect classes.** `reenters` and `throws` end static heap
  facts. Observed values never become unguarded static facts.
- **P2/P3 in practice.** The generating extension's derivable parts are
  generated by Rust macros from the kernel tables: opcode identities, effect
  tables, rewrite legality, fold eligibility, and guard/fallback pairs. There
  is no self-application.
- **The Futamura equation.** `⟦residual(p)⟧(d) = ⟦interpreter⟧(p, d)`, with the
  reference kernel as the executable right-hand side.

## Realm lifecycle

Library installation is a named state machine, so no operation runs against a
half-built realm:

`Allocated → KernelReady → LibraryInstalled → Running → ShuttingDown → Released`

`KernelReady` means the heap, shapes, and fundamental primitives are usable.
`LibraryInstalled` means the registry is resolved and intrinsics are created.
Opcode fallbacks and guest code are legal only in `Running`. Each transition
is explicit and checked; a failed installation goes straight to `Released`.

## Scope and implementation sequence

1. Move exotic-object semantics into the object-kind table. Re-express
   existing kernel fast paths as accelerated primitives with reference
   definitions.
2. Model the realm lifecycle transitions above.
3. Derive the generating extension from the tables:
   - route constant folding through statically evaluable entries;
   - address intrinsics by index;
   - emit accelerated primitives as a guard plus reference-definition
     fallback;
   - drive binding-time congruence from effect classes;
   - delete any compiler-side duplicate of a library or kernel definition.

   This reroutes the folds and fast paths that already exist; adding new ones
   is tuning and waits for task 24.
4. Build the reference kernel. Every accelerated primitive is replaced by its
   reference definition, and specialization and static folding are disabled
   (task 42). It must match the default kernel on the full conformance run
   with an unchanged library crate.
5. Run one experiment kernel that changes one internal representation or
   dispatch choice. It must pass the same run, with its generating extension
   regenerated from the edited tables alone.

## Verification

- A structural test rejects accelerated entries without a reference
  definition, and compiler code that reimplements a table entry's semantics.
- Every fold the compiler performs calls a statically evaluable table entry.
  A differential test compares folded and unfolded residuals of the same
  source.
- The reference kernel and the default kernel agree on the full Test262 run,
  with the ratchet showing no regressions.
- The experiment kernel passes the same run without library edits.

## Definition of done

- Every exotic behavior lives above the watermark. The kernel has no per-kind
  semantic branches, only accelerated primitives with reference definitions.
- Static folding, specialization-environment addressing, and guarded
  acceleration each read their binding-time facts from the tables.
- Changing a kernel representation requires no library edits unless the
  primitive table itself changes, and no hand edits to the generating
  extension beyond what the tables derive.
- The residual equals the reference interpretation on the full run.
