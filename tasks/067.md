# 067: JIT/stencil-tier algorithmic-complexity invariants

- **Theme:** architecture_invariants
- **Executor:** codex
- **Depends on:** none

## Context

Same technique as 062, scoped to the region-stencil tier itself — the
foundation tasks 048/049 (region-scope growth, multi-variant regions) and
058 (shape hash-consing) need proven sound before more regions/variants
are piled on top. A complexity bug in `RegionKey` lookup or the stencil
arena would compound as coverage breadth grows (exactly the kind of
foundation-first insurance this whole invariant-suite theme is for).

## Scope
- `crates/quench-runtime/src/architecture_invariants.rs` (same module)

## Deliverables — invariants to pin
1. `RegionKey` lookup/selection cost is independent of the total number of
   admitted regions in the catalog (a program using one region shouldn't
   pay a cost that scales with how many *other* regions exist).
2. Rendered-region memoization lookup (`RegionKey` → rendered bytes) cost
   is independent of how many distinct `(region, fact)` combinations have
   been rendered and memoized so far in the process's lifetime.
3. Stencil arena allocation (bump-pointer render/copy/patch) cost is O(1)
   regardless of the arena's historical allocation count since last reset.

## Validation

Same bar as 062: validate each test fails against a deliberately-broken
version first, `cargo test -p quench-runtime --lib` and
`--features execution-trace` both green (the stencil tier's ARM64
execution path, per task 039, only activates under real conditions —
confirm these tests actually exercise it, not just the interpreter
fallback, or they're not testing what they claim to).

**Fail condition**: same as 062, plus: a test that silently only exercises
the ordinary interpreter fallback (never actually reaching the stencil
tier) provides no evidence about the stencil tier's complexity at all —
verify the tier is actually engaged via `execution_trace` counters before
trusting the result.
