# 81: Represent closures as flat captures with safe-for-space environments

## Outcome

A closure reads every captured binding in constant time. Captured bindings
that are never written after capture are copied into the closure, and only
mutable captured bindings share a box. A closure never keeps alive a binding
it cannot read.

## Current gap

v2 promotes frame locals to a heap environment lazily
([closure environments](../docs/v2/closure-environments.md)) and captures
only the bindings closures need (v2 task 361). Capture lookup still walks
`capture_depth` environment links (v2 task 281 proposed flattening it). An
environment is shared by every closure created in its scope, so one
long-lived closure keeps every sibling binding alive. Scheme-compiled code
like EarleyBoyer creates many closures, and Splay keeps a large live heap.

## Dependencies

See this task's `depends_on` in [index.json](index.json). This task reads the
capture and write sets from the binding-time analysis.

## Scope and implementation sequence

1. Classify each captured binding with the binding-time analysis's facts: immutable after
   capture (`const`, or never written after the closure is created), or
   mutable.
2. Copy immutable captures into the closure's own slot vector when it is
   created (flat closure conversion). Mutable captures share one box per
   binding, and loop iteration bindings get a fresh box per iteration, as the
   spec requires.
3. Address every capture by a direct slot index in the closure, so loads
   and stores take constant time regardless of nesting depth.
4. Keep v2's lazy promotion as the transition that allocates boxes, so calls
   that create no closure allocate nothing.
5. Keep dynamic scope (direct `eval`, `with`) on the linked-environment
   representation. It is the generic fallback, selected statically per
   scope.

## Verification

Test262 cases for closures in loops (per-iteration bindings), TDZ through
closures, direct `eval` adding bindings, `with`, generators capturing
bindings, and `arguments` mapping. GC tests showing that a closure does not
retain unreferenced sibling bindings.

## Definition of done

- Capture access takes constant time outside dynamic scopes.
- No closure retains a binding it cannot reference.
- One representation choice per scope, decided statically.

## Performance evidence

Report closure bytes, box counts, capture-access cost, and peak live heap on
EarleyBoyer and Splay, plus the paired gate.
