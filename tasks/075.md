## Implementation order and acceptance

1. **Close real-caller ownership and reentry.** Resolve the verified typed entry
   and acquire its retaining lease before native invocation. Release pool/cache
   `RefCell` borrows before calling it; wrapping a still-borrowed dispatch in a
   lease is insufficient. Exercise actual native -> Rust helper -> mutable pool
   access/retirement/admission -> return through the normal region caller. Verify
   roots, exact continuation, stale-entry rejection and no post-effect replay.
2. **Unify physical facts and generated artifacts.** One selected physical view
   owns the association between bytes/data, ABI, entry bounds, relocations,
   continuations and identity. Rust macros derive mechanical consequences from
   canonical declarations. Use rustc-built Rust leaves and minimal Rust-generated
   assembly for explicit continuation contracts; no C/Clang or runtime LLVM.
   Validate multi-hole identity/addends/ranges and fingerprint entry metadata; see
   `target/stencil-review-1788646448/extractor-contract-review.md`. Test real schemas.
   Derive one immutable image identity from that view and carry it with finalized
   bytes through composition; publication must not accept independently selected
   bytes, key, ABI or cache identity. Published entry metadata is immutable
   authority; a disposable cache hit must validate against it rather than
   relabeling an address. This
   borrows AsmJit's `CodeHolder` data shape without adding its runtime assembler,
   compiler or allocator.
   The current linear builder may repeat one audited linked-fragment contract and
   derives its key/transfers transactionally. `a060937d8e` makes its internal
   register continuation ABI a canonical macro fact carried by the generated
   artifact and selected physical view; mismatched linked fragments reject before
   layout/publication. Generalize this through additional declared internal roles;
   never infer concatenation safety from external ABI equality. `2a3f650924`
   replaces the fixed two-add admission case with a bounded ordered-series fact
   `(base, repeated operand, repetition count)` derived from the disposable value
   graph; source depth changes data, not the plan hierarchy. `411f38c7fa` makes
   the region image builder consume a bounded sequence of selected physical views
   and derives opcodes, transfers and the combined physical cache identity from
   that sequence. Repetition is now only an adapter over the shared chain path;
   `ccb0b9b01e` adds a second compatible Add/Sub fragment family and `bb40c59f69`
   extends that same ordered series to Mul/Div, covering the scalar Number
   arithmetic family without new plan shapes. Scalar leaf and linked
   continuation keys are generated as distinct views, so external ABI/opcode
   similarity cannot route a nonreturning fragment as a leaf. The next composition
   step is effect-scoped branch/control layout, not another whole-sequence plan.
3. **Compact admission state.** Replace parallel per-instruction native-plan
   arrays with a compact index and sparse, lazily allocated typed specializations.
   Preserve bounded legitimate alternatives and shared immutable descriptors.
   Remove superseded storage as consumers migrate; test cold/disabled footprint.
4. **Derive bounded regions from existing control flow.** Use canonical operand
   roles, predecessors, use/def, liveness and effect facts rather than adjacency
   and raw operand scans. Use bounded worklist analysis and a simple documented
   register/spill convention. Preserve aliases, loop-carried values, live-outs,
   exact PCs and interruptible backedges. No second semantic IR or optimizer VM.
   Implement the bounded stencil-selection pass specified in section 2: a
   disposable block-local value/use graph over canonical PCs, then known-fact
   specialization, constant propagation, effect-safe DCE/local value numbering,
   declared strength-reduced recipes, fixed register roles, costed fusion and
   hot/cold layout. A narrow verified post-relocation peephole may remove only
   declared identity operations and jump-to-next transfers. Tests must show both
   semantic equivalence and eliminated fragments/guards/moves; broken facts must
   select exact ordinary execution. No general SSA construction, legalization,
   global register allocation or general machine-code optimizer is in scope.
   **Immediate frame-sizing defect:** `Instruction::call_named(None)` encodes
   c=65535 as absent argument, but `register_count_for` treats every CallN c as a
   register. This saturates frame width to 65535 and `functions_arguments` fills
   about 512 KiB per invocation. Confirm with lowered-code width tests, then
   derive width from opcode/flags/metadata operand roles (including argument
   windows), never raw max(a,b,c) or a global sentinel exclusion. Distinguish
   nested callee-owned frames from structured fragments sharing the current
   frame; freeze the correct width once instead of recursively walking bodies
   at every call. Preserve all real slow-op temporaries and boundary register IDs.
   Test zero/one/many-argument calls, small caller with large nested callee,
   branches/loops/handlers, and initialized-word/release counts. Optimized Richards
   samples with tracing disabled show 1563 `RegisterFile::clear` leaf samples out
   of 2283 worker samples, plus 289 memset samples, in
   `target/stencil-review-1788646448/richards-trace-disabled.sample.txt`.
   This corroborates frame work, not an exact portable CPU-time percentage or
   proof that it explains the entire score gap. Fix sizing before changing release
   semantics, then verify time/RSS on the unchanged workloads.
   Counterfactual on production SHA256
   `04005dac8a01f5cd583247dffb91bae81d6af3f6bab9daa90d869bd07d70adc4`:
   `o={m:function(){return 1}}; function f(o){return o.m()}` called 5000 times
   takes 158/159/158 ms; changing only the call to `o.m(0)` takes 5/6/6 ms,
   alternating order across three process pairs, identical sum=5000. These
   coarse exploratory timings corroborate the sentinel path; they are not a
   general benchmark-win estimate or a substitute for frame-width unit tests.
5. **Make native execution remove meaningful work.** Compose supported hot
   interiors without per-operation/per-iteration Rust dispatch. Consume existing
   IC facts for native receiver/layout/dependency guards and property slot access,
   leaving complete miss/exotic semantics in shared helpers. Reduce avoidable
   boxing and retain/release through region liveness, with explicit root and
   ownership boundaries. Baseline and optimizing adapters share semantic facts.
   The guarded own-property get/set slice is the first known-fact specialization:
   machine code must consume the canonical layout/descriptor/slot proof and
   perform the access itself. Continue through actual CFG compositions rather
   than adding native calls that leave lookup, decoding and commit in Rust.
6. **Bound all physical resources.** Enforce per-owner and aggregate code, data,
   cache and metadata budgets across compiled owners. Retired-but-live allocations
   stay charged. Allow safe independent reclamation without reclaiming active
   code; verify actual slab packing, bounded churn and disposal accounting.
   Code ownership stays separate from JS object collection. `CodeArena::freeze`
   now converts nested same-store links to deferred weak resolution while escaping
   callable/frame/native-lease owners retain the store explicitly. The focused
   weak-drop regression passes at `6b6dcaf99a`; keep execution-after-program-drop,
   nested branch/loop/static-field ownership, repeated compilation and final-owner
   disposal tests in the gate. A temporary weak upgrade must never back a borrowed
   `CodeView`, and source residuals may be discarded only after flattening/linking
   and fact consumers finish. Measure store/code/cache retained bytes before
   attributing process RSS to the JS collector.

Use `lisp-mindset`: facts once, derived views, explicit state/effects and shallow
composition. Follow its size caps with cohesive modules, not giant macros or
arbitrary file chunks. Preserve passing slices; do not restart the architecture.

### Fact and pattern contracts

- Reuse existing facts/quickening/canonical lowered operations. A fact store is a
  shared interface to authoritative facts, not a new heap-wide mutable database
  or second semantic graph. Distinguish Proven, Guarded and Unknown from observed
  probabilities; field type and callee observations are not proofs.
- For supported loop admission, use a bounded affine range vocabulary: exact
  initial value, constant step, comparison limit and checked offset arithmetic.
  Eliminate a bounds check only when all accesses follow from the entry guard and
  induction proof and array storage/length facts remain valid. Unknown, overflow,
  mutation or coercion falls back; no general theorem prover or SSA optimizer.
- Declare each supported rewrite's semantic domain, required facts, effect kills
  and live-state obligations. Generic Add may coerce/call/throw; I32 inputs do not
  guarantee an I32 result. `0 + x -> x` is not valid generic JS, nor valid for all
  Numbers because of negative zero. Repeated property reads may be reused only
  for proven ordinary data access with no invalidating writes, aliases or calls.
- Guards imply only facts encoded by the actual shape/layout/dependency contract.
  Establish object identity/tag before dereferencing; shape does not automatically
  prove field representation, prototype-chain identity or immutable callee.
- Pattern selection is bounded and deterministic but not blindly longest-first:
  account for guards, spills, exits and emitted bytes. Preserve scalar/generic
  fallback and cap variant enumeration. No benchmark names or fixed benchmark
  object schemas in production declarations. Keep bounded local placement, not
  runtime instruction selection or a general register allocator.
- Dependency invalidation reuses existing identities and entry/lifetime machinery;
  test dependency mutation, stale-version/ABA handling, replacement and exact live
  state recovery. Every exit maps required values to slots/registers/constants
  without replaying effects. Not every guard belongs at entry: revalidate after
  effects that can invalidate it.

### Executed coverage

- Executable Cargo unit coverage for extractor, relocations, selection, ABI,
  publication, ownership and failure paths; build-script tests alone do not count.
- Every implemented core stencil: results, guard misses, numeric/property/binding
  edge cases and independent canonical ordinary-execution expectations.
- Ordinary source -> admission -> identified generated artifact -> native
  execution -> exact exit, including composition, helpers and reentry.
- Deterministic efficiency: stable hits reuse code without redundant rendering,
  patching or executable allocation; supported interiors avoid Rust dispatch;
  loop initialization occurs once; cold state is sparse; churn/retries and memory
  obey policy bounds; incompatible specialization facts never alias in caches.
- Current-revision runtime/host/trace and generated/non-generated regressions.
  Record actual nonzero counts and distinguish native execution from simulated
  callbacks or cross-compilation. No timing/RSS/comparator thresholds in unit tests.

## Research guidance and finite gate

### JS-pattern and compiler-contract coverage

Pair each stable fast-path case with a fact-breaking counterpart:

- Loop-carried arithmetic and ordered reductions: cancellation, signed zero,
  NaNs/infinities, nonzero initial state and zero/one/many iterations.
- Dense indexed updates: overlapping aliases, bounds, holes and inherited access.
- Repeated own/prototype property access: receiver, descriptor and chain mutation.
- Numeric/tagged alternation and mono/poly/mega transitions: bounded specialization
  with correct generic fallback, not repeated rendering under churn.
- Nullish/truthiness branches: distinguish null/undefined from false/zero/empty
  string; preserve evaluation order and short-circuit effects.
- Locals/captures across allocation, calls and exceptions: exact live state,
  ownership, roots and continuation. Existing B boundaries remain acceptable.

Trace compiler assumptions to Proven facts or dominating, still-valid guards.
Use checked Number arithmetic and canonical ToInt32 plus wrapping/masked bitwise
operations. Never manufacture alias guarantees with overlapping mutable Rust
references or retain invalidatable pointers across helper calls. Guard bounds,
alignment, lifetime and CPU features before execution. Fingerprint actual source,
ABI/layout and effective rustc/LLVM configuration; inspect representative IR and
object output without making exact instruction selection a portable test quota.

SIMD/fused recipes are optional physical choices. Preserve JS ordering and results;
do not enable fast-math to make floating reductions vectorize. LLVM's
[vectorization contracts](https://llvm.org/docs/Vectorizers.html) and Rust's
[assembly boundary](https://doc.rust-lang.org/reference/inline-assembly.html)
guide validity, not a promise that all compiler features improve this VM.

### Design references and completion

Apply mechanisms, not entire foreign VM architectures:

- [Deegen](https://arxiv.org/abs/2411.11469): generated contracts, quickening/ICs,
  register retention, check removal and hot/cold separation.
- [Sparkplug](https://v8.dev/blog/sparkplug): cheap compilation from existing
  bytecode, compatible frames and shared semantic helpers. Helpers are legitimate;
  dispatch-free requirements concern supported hot interiors, not all JavaScript.
- [JavaScriptCore](https://webkit.org/blog/10308/speculation-in-javascriptcore/):
  guarded property specialization and precise dependency invalidation. Reuse
  Quench's identities and mechanisms; do not create a parallel IC universe.

LLVM optimizes template bodies before extraction, not across runtime-patched
fragments. Preserve JS arithmetic/order, Rust alias/lifetime validity and guarded
CPU features. No speculative fast-math or unproven compiler assumptions.
