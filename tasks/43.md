# 43: Adapt the existing Node host to the shared VM

## Outcome

Provide the shared VM operations needed by the existing `quench-node` host,
so task 21 can migrate implemented compatibility behavior without a second
host implementation.

## Current gap

The host calls legacy property, call, object, buffer, realm and job operations.
These call sites must reach the shared VM before legacy removal. The frozen
implemented cases in task 19 determine which behavior must be preserved.

The shared runtime exposes rooted property reads, writes and callable
invocation through existing VM operations. Program context comes from the
program store; generation/owner checks precede guest effects. Reads/calls
retain results and all operations share exception retention. Writes use
`Reflect.set` with an explicit receiver and boolean refusal; Node owns refusal
policy. [Current qualification](evidence/task43-rooted-property-writes.json)
records six embedding lifecycle and three existing root/collection checks,
extending the [read/call baseline](evidence/task43-rooted-host-operations.json).
These units cover host ownership invisible to guest suites.

Rust native functions now come from the host's stable operation table;
`host_functions!` derives descriptors and the VM uses its existing native
callable representation. `NativeContext` borrows the shared VM, scopes callback
inputs/results/exceptions, and promotes roots only through explicit retention.
It re-enters the same property/call operations without a second executor or
callback registry. [Qualification](evidence/task43-native-host-registration.json)
records ownership, collection, re-entry and invalid-handle controls alongside
affected Test262 comparisons. Native classes, conversions, jobs and actual
Node registration/migration remain open; production still uses legacy and
task 43 is not closed.

`Host::initialize` now installs host-owned objects after shared intrinsics and
native globals, before guest execution. Its context roots follow the same
scope/error validation as callbacks. `NativeContext::object_rooted` uses shared
`Object.create` with the realm's intrinsic prototype, independently of mutable
guest globals. Error transfer preserves typed failure metadata and accepts
guest identities only through validated roots. The existing Node host uses these operations for its first
process binding ([qualification](evidence/task21-shared-process-uptime.json)).

The canonical process cache now holds an explicit legacy value or a shared VM
root, rather than parallel caches. Shared initialization retains its process
identity independently of the mutable global and replaces the root on fresh
execution. [Ownership qualification](evidence/task43-process-module-root.json)
checks collection, global replacement and reset; a detached uptime/descriptor
control matches local Node. CommonJS and builtin aliases remain migration work;
this does not close any upstream case.

Rooted construction now delegates to the shared constructor operation with an
explicit `newTarget`. Call and construction arguments use one root-validation
projection before guest effects; both public and callback surfaces retain their
existing completion policy. Public ordinary-object creation uses the intrinsic
prototype. [Construction qualification](evidence/task43-rooted-construction.json)
covers dynamic program ownership, native re-entry, collection, thrown identity,
invalid inputs and fresh-execution invalidation. Rust native constructor roles
and Node class registrations remain open.

The standalone native binding commit is qualified independently of other
uncommitted runtime work ([commit qualification](evidence/task43-native-commit.json)).
Its scoped callback and initialization contract includes constructor re-entry
through the rooted API. This installs mechanism; Node classes, jobs and module
loading still prevent closing this task.

## Scope and verification

Adapt operations required by the frozen cases through cohesive shared domain
operations. Use the shared VM's scoped handles and explicit roots for retained
objects and callbacks. Keep Node semantics in the existing host. Derive
registrations and metadata from their owning operation definitions.

A temporary adapter may help a migration slice, but a new framework, a complete
facade over legacy, or a full legacy suite replay is not a prerequisite.
Remove transitional adapters at task 27. Production never selects an engine
through a runtime flag; pre-cutover checks use development binaries.

Run affected implemented cases against local Node and relevant upstream source.
Verify internal root lifecycle, host re-entry, and error propagation at the
changed boundaries. Task 22 owns full implemented-case closure.

Node calls the runtime only through `quench_runtime::embed`, the runtime's
one public surface for embedders. It covers:

- realms and globals;
- scoped handles and explicit roots;
- value conversion and property access;
- native functions and classes registered through a macro that derives their
  descriptors;
- calls, exceptions and error construction;
- promise and job hooks, with the host owning the event loop and the runtime
  draining microtasks;
- a module-loader trait for resolve/load, the CommonJS wrapper and ESM;
- external ArrayBuffer storage;
- interrupts;
- capability tables registered by the embedder.

The fixed `CapabilityId` enum in `host.rs` (`WriteLine`, `ClockMillis`, `Done`,
`CreateRealm`, `IsHTMLDDA`) becomes embedder-registered capabilities;
`IsHTMLDDA` belongs to the Test262 adapter. `embed` exposes mechanism, not
Node policy.
`quench-node` currently reaches legacy internals (`quench_runtime::execute`,
`ops`, `vm`, `value`, `builtins`) about 3,800 times. Each call site migrates to
the shared VM's public API. A missing operation is added to that API as a
cohesive domain operation, not exposed as VM internals. `quench-node-test`
runs fixtures through `quench-node` rather than depending on the runtime.

As call sites migrate, organize `quench-node` by Node module (`fs/`, `net/`,
`http/`, `stream/`, `crypto/`, `process/`, …), each owning its bindings and
registrations. Today's size-numbered files (`js_runtime_dispatch_misc_a`…`e`,
`js_runtime_fs_a`/`_b`, `module_surface_*`) are replaced, not ported.

## Definition of done

- `quench-node` depends only on `quench_runtime::embed` and owns all Node
  semantics; the runtime has no Node knowledge and no fixed host capability
  enum.
- `quench-node` source is organized by Node module, with no size-numbered
  files.
- Required host operations use shared VM semantics and ownership.
- Node behavior has one implementation, with no legacy semantic fallback.
- Affected case comparisons and necessary internal boundary checks pass.
