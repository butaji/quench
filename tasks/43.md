# 43: Put quench-node behind an engine-neutral host facade

## Outcome

Make `quench-node` depend on one narrow, engine-neutral host facade instead of
legacy runtime internals, while it still runs on the legacy engine, so task 21
becomes "implement the facade on the next engine" rather than a big-bang port
of the host.

## Current gap

`quench-node` (~173k lines, 146 files) calls legacy runtime internals directly:
190 distinct `quench_runtime::` paths at 3,765 qualified call sites plus 244
`use quench_runtime` imports. Usage is concentrated: the 30 most frequent paths
(`execute::get_property`, `is_callable`, `get_property_result`, `set_property`,
`host_api::object`, `vm::current_global_object`, `execute::call`,
`builtins::error`, ...) account for ~80% of call sites. Porting the host
directly onto the next engine would fork it into two copies and leave the
tracked Node inventory unverifiable until the whole port lands.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Derive the facade from measured usage: one operation table (property
   get/set/define/delete/own-keys, call/construct, callable/type predicates,
   object/array/error/function creation, global/realm access, promise/job
   submission, buffer backing access) whose value handles follow task 09's
   rooting contract: scoped handles valid within a host call and `RootId`s for
   anything retained beyond it. No heap cell, shape, or raw `Value` crosses it.
2. Implement the facade over the legacy runtime as a thin adapter.
3. Migrate `quench-node` call sites onto the facade in reviewable slices,
   collapsing the `js_runtime_dispatch_*` match fan-out into the data-derived
   capability table that task 21 requires. Keep the Node behavior in
   `quench-node`; the facade adds no Node semantics.
4. Enforce the boundary: after migration, `quench-node` has no dependency path
   to `quench_runtime` internals except through the facade (checked by
   `tools/check-boundaries.sh`).

Engine selection stays compile-time (a separately named development binary for
the next engine); production never selects an engine through a flag.

## Verification

After every migration slice, run the complete tracked `tests/node-compat`
inventory on the legacy engine and require the per-fixture outcomes to match
task 19's frozen legacy baseline exactly. Stress GC during host callbacks that
retain facade roots.

## Definition of done

- `quench-node` compiles against the facade only; legacy internals are
  unreachable from host code.
- Tracked Node outcomes on the legacy engine are identical to the frozen
  baseline.
- The facade's operation list is the complete contract task 21 implements on
  the next engine.

## Performance evidence

Report host-call overhead introduced by the adapter on bootstrap and a
representative I/O fixture; no threshold applies.
