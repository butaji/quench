## Scope and verification

Task 24 is the sole owner of the initial complete suite qualification and its
baseline. Tasks 20, 22 and 23 close implementation gaps using affected-scope
checks; they do not require separate full-suite campaigns. If this gate exposes
a failure, reopen the owning task, fix it with affected checks and repeat this
gate after all three owners are ready.

Run the complete pinned Test262 inventory, every pinned Wasm directive, the
full `framework-core` Node profile and the pinned Express, Koa and Fastify
scenarios in one frozen build. Require nonempty exact inventories. Every
Test262 case consistent with the local Node oracle must pass; preserve the raw
outcome for the one Stage 94 conflict and exclude only that identity from the
adjudicated pass denominator. Every Wasm and scoped Node case must pass. Check retained
internal/uncovered regression units and
focused boundary controls for residual validation, GC/root lifecycle, jobs,
modules, host re-entry, cross-language calls, errors, and resource exhaustion.
Check unsafe code at its owning boundaries, using supported focused tooling.

For existing specializations, compare affected cases through the same VM's
generic fallback and verify the intended specialized path is actually bypassed.
Use affected Test262 stages plus compare-runs and affected Node/Wasm cases; do
not add a second full generic-mode campaign. This integrated check owns the
existing-specialization fallback obligation. Later Stage B experiments retain
their own affected-path fallback controls.

Audit one heap, Value, root set, opcode vocabulary, dispatch loop, activation
stack, and Engine entry. No crate outside the shared runtime executes Wasm;
`quench-wasm` only decodes, validates, and drives wast scripts. No next-engine
path calls legacy semantics or falls back to a second engine.

## Definition of done

- All Node-consistent Test262 cases, every Wasm directive, and the complete
  scoped Node gate pass in the same build. The exact Stage 94 corpus conflict
  is separately identified as waived and is never counted as a pass.
- Shared VM structure and affected safety controls pass.
- Reports identify source, binaries, toolchain, commands, suite revisions,
  inventories, and host; they become task 27's cutover baseline.

Support tasks own any required fixes, but completing their historical plans is
not an independent prerequisite. This gate checks the three suite results and
necessary internal invariants directly. No performance ranking, fuzzing
campaign, host expansion, or kernel rewrite blocks it.
