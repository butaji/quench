# 24: Prove integrated correctness before cutover

## Outcome

Verify all three suite inventories together on the shared OXC/Wasm VM before task 27
switches production to it. This is a Stage A checkpoint; Stage A closes only
after legacy removal and cleanup, with final verification in task 86.

## Current gap

Lane-local passes do not prove shared heap, jobs, modules, host roots,
re-entry, or cross-language behavior in one configuration.

## Dependencies

See `depends_on` in [index.json](index.json).

## Scope and verification

Run the complete pinned Test262 inventory, pinned Wasm directives, task 19's
frozen implemented Node compatibility suite in one frozen build. Require nonempty exact
inventories and 100% passing outcomes. Check retained internal/uncovered regression units and
focused boundary controls for residual validation, GC/root lifecycle, jobs,
modules, host re-entry, cross-language calls, errors, and resource exhaustion.
Check unsafe code at its owning boundaries, using supported focused tooling.

Audit one heap, Value, root set, opcode vocabulary, dispatch loop, activation
stack, and Engine entry. No crate outside the shared runtime executes Wasm;
`quench-wasm` only decodes, validates, and drives wast scripts. No next-engine
path calls legacy semantics or falls back to a second engine.

## Definition of done

- All three exact suite inventories pass 100% in the same build.
- Shared VM structure and affected safety controls pass.
- Reports identify source, binaries, toolchain, commands, suite revisions,
  inventories, and host; they become task 27's cutover baseline.

Support tasks own any required fixes, but completing their historical plans is
not an independent prerequisite. This gate checks the three suite results and
necessary internal invariants directly. No performance ranking, fuzzing
campaign, host expansion, or kernel rewrite blocks it.
