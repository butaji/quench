# 24: Prove integrated correctness and safety

## Outcome

Demonstrate that the complete next engine and all hosts are safe and green
together on one shared JS/Wasm VM. With cutover (task 27), this closes phase A
(make it work). Phase B (make it right) and phase C (make it efficient)
follow.

## Current gap

Lane-local passes do not prove shared heap, jobs, modules, host roots, interruption, and cross-language behavior under one production configuration.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Run the complete workspace and all three conformance gates in one frozen build. Add adversarial residual, GC-at-every-safepoint, weak/finalization, host-root/re-entry, module-cycle, worker/shared-buffer, Wasm boundary, allocation-failure, recursion, interrupt, and shutdown tests. Audit unsafe blocks against verifier/root/heap invariants.

## Verification

Require warning-denied check/test/clippy, sanitizers or Miri where supported for focused unsafe code, 100% Test262, 100% pinned Wasm directives, and every fixture in the frozen legacy Node passing set (task 19). Re-run a representative subset under forced-GC and constrained-resource modes.

This task is the correctness boundary. Cutover (27) depends on it, all
phase-B work depends on 27, and all engine-changing phase-C work depends on
task 47.

Add a structural single-VM check. It fails if any crate other than the shared
runtime contains a Wasm execution path, if `quench-wasm` depends on an
execution crate, or if Wasm and JavaScript use different heap, value, root,
opcode, dispatch, or activation types.

## Definition of done

- All suites are green in the same source/build configuration.
- No next-engine path calls legacy semantic code or silently falls back to another engine.
- The single-VM check passes: JavaScript and Wasm execute on one VM.
- Unsafe assumptions are documented at their owning boundary and exercised by negative controls.

## Performance evidence

Capture startup/RSS and instrumentation overhead so performance binaries can exclude diagnostic features.
