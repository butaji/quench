# 082: Factor stencil render and eviction paths

`stencil_arena.rs` has near-duplicate eviction methods and four typed
`render_selected_*` implementations that repeat validation, rendering,
protection, execution, witness marking, and error cleanup.

## Plan

- Extract one eviction core with an optional cache-pruning callback.
- Extract one render lifecycle parameterized by ABI and typed invoke/fallback
  adapters; keep architecture-specific stubs at the edge.
- Preserve borrow-release ordering and `PhysicalExecutionWitness` semantics.
- Add focused success, protection failure, execution failure, and cache tests.

## Acceptance

All typed renderers share the lifecycle, no executable-memory or cache behavior
changes, and runtime/stencil tests pass on supported and unsupported targets.

## Current reduction

`94586e4d01` routes leaf and composed bytes through one finalized image before
publication. The image owns its callable-entry offset; cache reuse validates its
exact bytes, and the arena derives the callable address from the image rather
than assuming allocation offset zero. This removes the duplicate patch/copy and
publication-metadata path. Eviction and the remaining typed execute/fallback
adapters still need the separate task acceptance before 082 can close.
