# 95: Extend Node API compatibility on the shared VM

## Outcome

More upstream Node APIs behave exactly as local Node does, without changing
the Stage A gate or slowing the shared VM. This is a side lane outside both
stage gates. Task 43's Stage A boundary still defines what is required.

## Scope

- Implement Node APIs in `quench-node` (process, events, timers, net, dgram,
  async_hooks, AsyncLocalStorage, worker messaging and similar), keeping
  JavaScript semantics in `quench-runtime`, as AGENTS.md requires.
- Verify each changed behavior against the local Node oracle and the upstream
  source: values, descriptors, identity, ordering, errors, exit status and
  host effects. Add the matching upstream `tests/node` cases to the runner.
- Changes to `quench-runtime` or the vendored parser must not alter hot
  JavaScript paths. Run Task 92's fixed-work instruction and RSS screen, or
  ask the trunk owner to gate the change on the M4.
- Track progress as passing upstream cases per module in
  [node-compat-inventory.json](node-compat-inventory.json).

## Gates

Task 92's sync protocol. The framework-core profile and the Express, Koa and
Fastify scenarios stay byte-identical to Node on every merge.
