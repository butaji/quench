# 15: Port numeric, Date, Intl, and Temporal semantics

## Outcome

Implement numeric and calendrical builtins without retaining legacy values or object storage.

## Current gap

The reference implements a small Number/Math/Date surface; Quench carries broader BigInt formatting, Date, Intl, and Temporal algorithms tied to its old value model.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Port Number, BigInt, Math, parsing/formatting, Date/time zones, all current ICU-backed Intl services, and Temporal objects/rounding/calendars/durations. Keep ICU and arbitrary-precision libraries behind explicit conversions and canonical object slots. Intl, Temporal, Date, and numeric formatting algorithms come from task 45's shared crates; this task owns only their guest objects, slots, and effect ordering, expressed as the next core's `AlgorithmBoundary` implementation (slot records, brand checks, intrinsic prototypes) and task 46 registry rows that install each shared-crate entry point. Do not reimplement a Temporal, Intl, or Date algorithm inside the next core; a missing behavior is either moved from legacy through task 45 or, if legacy also fails it, added once in the shared crate.

## Verification

Run Number/BigInt/Math/Date/Intl/Temporal Test262 families across NaN, infinities, signed zero, huge integers, locale options, DST boundaries, calendar transitions, rounding modes, and accessor effect order.

## Definition of done

- Numeric results and formatting match Test262 and Node.
- Locale/time-zone data dependencies are reproducible.
- Temporal identity and slots use the new heap exclusively.

## Performance evidence

Report dependency footprint, cold startup/RSS, and numeric workload regressions.

## Implementation evidence

`Date.now()` is installed as a static native and reads the existing
`CapabilityId::ClockMillis` host capability. The deterministic runtime host
regression observes the expected zero clock; full Date/Intl/Temporal methods
remain open. Date construction now preserves an explicit millisecond value,
and `getTime`, `valueOf`, `toISOString`, and `toJSON` share the same receiver
authority; JSON serialization emits the ISO string for finite dates.
The global `Number` constructor and `isNaN`/`isFinite`/`isInteger` predicates
use exact numeric-tag checks, with `NaN` and `Infinity` installed as canonical
globals. `isSafeInteger`, `parseInt`, and `parseFloat` now share the numeric
authority, and standard Number constants (`EPSILON`, safe bounds, infinities,
and extrema) are installed with focused regressions. `Date.parse` now accepts
RFC3339 timestamps and `Date.UTC` constructs deterministic UTC milliseconds.
`Math.abs`, `ceil`,
`round`, `trunc`, `sqrt`, and `sign` preserve signed-zero and tie behavior;
numeric string coercion canonicalizes `-0` to `"0"`.

`Duration.compare` now consumes the shared runtime-independent relative-date
nanosecond algorithm from `quench-temporal`; the same shared duration
totalization validates resulting date-times against Temporal's representable
endpoints. The existing Stage 74 out-of-range-relativeTo subset passes 3/3.
The current bounded Duration total and compare cohorts are 48/78 and 32/50;
missing ZonedDateTime construction and timezone-aware relativeTo conversion
remain the dominant gaps. No unit/new tests or harness edits were made.

The next core now has a typed `TemporalZonedDateTime` heap cell with epoch,
time-zone, calendar, and prototype authority, plus its constructor and core
slot getters. Zoned local fields are derived from the epoch and zone instead
of being duplicated in the cell. Stage 74 passes 1,134/4,603 (up 122 from the
offset-sharing checkpoint) in batches capped at 100 with
`TEST262_TEST_TIMEOUT_MS=30000`; the ordered Stage 0–74 total is 41,144/44,613.
Stage 74 remains open: 3,469 failures remain, led by missing Temporal
constructors, non-callable methods, and undefined properties. This slice does
not claim complete ZonedDateTime methods or Temporal coverage. No unit tests,
new tests, or harness changes were made.

The focused existing `ZonedDateTime/` subtree run is 108/901. The dominant
failure family is non-callable methods (334 cases), demonstrating that typed
slots and getters alone do not complete this surface. The next implementation
slice must port callable `from`/`compare` and prototype algorithms rather than
adding descriptor-only stubs.

ISO UTC-offset syntax and offset-to-minute/second conversion now have one pure
implementation in `quench-temporal`, consumed by legacy relativeTo validation
and the next core's PlainDate string parser. The next-core Stage 74 Temporal
sweep improved from 1,008/4,603 to 1,012/4,603; missing Temporal constructors
and slots still dominate. No unit tests, new tests, or harness changes were
made.
