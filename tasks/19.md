# 19: Freeze Stage A suite inputs and shared-VM runners

## Outcome

Keep each Stage A suite input set pinned and give it one executable shared-VM
path. The full Test262 suite and full Wasm directive suite remain gates. The
Node gate is limited to the framework behavior Quench has selected for Express,
Koa and Fastify.

## Gate contract

- Test262 uses the pinned corpus and stage ownership in [STAGES.md](../docs/STAGES.md).
- Wasm uses every directive in the pinned `crates/quench-wasm-test/testsuite`.
- Node uses every entry tagged `profile=framework-core` in
  [`parallel.txt`](../crates/quench-node-test/node-tests/parallel.txt), plus the
  three pinned package scenarios defined by [`tests/frameworks`](../tests/frameworks/README.md).

The manifest owns Node fixture membership; the framework README and lockfile
own the package scenarios. Do not keep a second fixture list or expand the
gate to unrelated Node APIs. `node-compat-inventory.json` and its owner audits
remain diagnostic material, not Stage A membership or completion requirements.
Passing or failing outcomes never change membership. Suite fixtures and
expectations stay unchanged.

## Scope and verification

Keep the three suite authorities and runner selections derived from their
existing manifests. Run only affected stages or cases during implementation;
run complete suite gates at tasks 24, 27 and 86. Do not add unit tests that
duplicate suite cases. Retain internal tests only for invariants or scenarios
the pinned suites do not cover.

Verify nonempty discovery, deterministic selection, per-case deadlines,
complete worker outcomes and source/input provenance. The Node framework
profile is selected from `parallel.txt`; compare all three package scenarios
with local Node on exit status and raw stdout/stderr. Task 24 owns the initial
same-build integrated qualification. Task 27 and task 86 reuse it only when
source, binaries, configuration and suite inputs remain unchanged.

## Definition of done

- Test262 and Wasm suite inputs and stage/directive inventories remain pinned.
- The framework profile and three package scenarios are the complete Node
  gate, with their membership derived from the manifest and pinned package
  inputs.
- Shared-VM suite runners preserve nonempty inventories, completion outcomes
  and reviewable provenance.
- No suite expectation, selection or status is changed to hide a failure.
