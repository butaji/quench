# 56: Bound guest recursion by a runtime-owned stack budget

## Outcome

Deep guest recursion throws a catchable `RangeError` at a limit the runtime
controls. The same program fails at the same depth under the CLI, the Test262
runners and the Node runners. No path depends on how much stack the OS
reserves for a thread.

## Current gap

- `quench-node/src/main.rs` runs the CLI on a 2 GiB thread stack because
  Rust recursion in call paths overflows the default stack (Earley-Boyer).
- The harnesses each choose a different size: `run-all-next` 32 MiB,
  `run-stages` and `triage` 256 MiB, `compare-runs` and `run-all` 512 MiB,
  the node-test runner 256 MiB, and the determinism tests 128 MiB.
- Where a stack overflow happens depends on which binary runs the code, and
  a real overflow aborts the process instead of throwing. Task 20 records
  stack-overflow failures.

## Dependencies

See `depends_on` in [index.json](index.json). This task is on the critical
path ahead of task 20. Test262 `staging/sm/extensions/recursion.js` needs a
catchable `RangeError` for unbounded recursion, and today that test overflows
the Rust stack. Task 20 cannot close until this task does. The budget applies
to the call path as it exists today. Task 09 later takes the check over into its
activation model, without waiting for this task and without blocking it. Task 51
may later replace Rust recursion per call.

## Scope and implementation sequence

1. Give the runtime one named stack budget, measured from the entry stack
   pointer or as a derived frame-depth limit. Check it at every
   recursion-introducing transition: calls, construct, getters and setters,
   proxy traps, `toString`/`valueOf` conversions, and compiler recursion.
2. Exceeding the budget throws the realm's `RangeError` ("Maximum call stack
   size exceeded"), which guest code can catch, as V8 does.
3. Derive the worker stack size in every binary from one shared constant: the
   budget plus a named headroom. Remove the per-runner literals.
4. Reduce the CLI stack to the derived size once the budget covers the paths
   that needed 2 GiB.

## Verification

- Run the current Test262 stages. Outcomes must not regress, and the
  recorded stack-overflow cases must now throw `RangeError`.
- On macOS, run V8-v7 Earley-Boyer with the derived stack size.
- Deep recursion, mutual getter recursion and deeply nested `JSON.parse`
  must throw a catchable `RangeError` in every runner.

## Definition of done

- One budget constant owns the stack policy.
- No binary reserves more stack than that budget plus the named headroom.
- A guest stack overflow never aborts the process.

## Implementation evidence

The next core has a shared RAII transition budget in `src/stack.rs`: a 32 MiB
budget divided by a named 64 KiB transition reservation, plus 2 MiB of host
and unwind headroom. The resulting worker reservation is 34 MiB. The next
CLI and both next Test262 case entry points use that derived reservation.
The transition reservation still needs qualification across all recursive
compiler and legacy paths; this task remains in progress.

Shared general/numeric execution, native calls, construction, property reads
and writes, proxy calls, primitive conversion and JSON parsing/traversal
consume the budget. Exhaustion creates a RangeError directly from the
realm's captured intrinsic prototype, without reading guest-modified global
bindings or invoking guest code. Those prototypes are traced through GC.
The required `$262.gc` method invokes the existing VM collector for the main
host object and created-realm wrappers.

Both next runners pass `staging/sm/extensions/recursion.js`
(`target/iteration/task56-recursion-staging-gc.log`). The budget/GC build
rechecks stages 0–113 at 51,900/51,900
(`prefix0-113-task56-runtime-budget-gc.log`). Adding GC exposed a false pass in
ArrayBuffer slice: the missing gc method previously threw TypeError during
index conversion. Slice now rechecks detachment after species construction
and copies the current backing store. Its affected final-build slices pass
ArrayBuffer 221/221, SharedArrayBuffer 104/104 and JSON 165/165
(`stage32-task56-runtime-budget-arraybuffer.log`,
`stage69-task56-runtime-budget-arraybuffer.log`,
`stage53-task56-runtime-budget-arraybuffer.log`). Task 20 owns the full
staging frontier numbers.

Seventeen focused Rust regressions pass, including specialized/generic
recursion, post-error recovery, realm intrinsic identity, GC rooting and
buffer mutation/detachment ordering
(`task56-runtime-regressions-arraybuffer.log`). Six recursion cases and the
buffer effects match the local Node oracle
(`task56-node-recursion-oracle.log`, `task56-node-arraybuffer-oracle.log`);
Node's upstream `test-stack-size-limit.js` also checks catchable call-stack
exhaustion. Buffer copy ordering follows
[ArrayBuffer.prototype.slice](https://tc39.es/ecma262/multipage/structured-data.html#sec-arraybuffer.prototype.slice).
The full unit suite has the same eight failures owned by task 58, with no
ignored tests (`task56-runtime-unit-suite-arraybuffer.log`).

On Apple M4/macOS, the saved uninstrumented production budget/GC binary
completes V8-v7 Earley-Boyer successfully using the derived 34 MiB stack
(`task56-earley-boyer-stack-qualification.json`). This is functional stack
qualification; concurrent conformance work prevents a speed claim. Runner
and production manifests retain the exact sources and binaries under
`target/iteration/task56-runtime-budget-*-runner/` and
`target/iteration/task56-runtime-budget-gc-production/`.

Remaining work: bound compiler recursion, route the legacy CLI and remaining
runners through the policy, and qualify the transition reservation for their
largest recursive paths before removing their independent stack sizes.

The isolated staged tree passes the runtime/runner/next-CLI compile check and
all 17 focused regressions (`task56-index-check-isolated-forced.log`,
`task56-index-regressions.log`). The checkpoint also completes registrations
for NumberFormat methods already installed by HEAD and routes the remaining
WeakMap computed-insertion caller through `WeakMapEntries::get/insert`; these
