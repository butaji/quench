# 56: Bound guest recursion by a runtime-owned stack budget

## Outcome

Deep guest recursion throws a catchable `RangeError` at a limit the runtime
controls. The same program fails at the same depth under the CLI, the Test262
runners and the Node runners. No path depends on how much stack the OS
reserves for a thread.

## Current gap

- `quench-node/src/main.rs` runs the CLI on a 2 GiB thread stack because
  Rust recursion in call paths overflows the default stack (Earley-Boyer).
- The harnesses each choose a different size: `run-all-next` 32 MiB,
  `run-stages` and `triage` 256 MiB, `compare-runs` and `run-all` 512 MiB,
  the node-test runner 256 MiB, and the determinism tests 128 MiB.
- Where a stack overflow happens depends on which binary runs the code, and
  a real overflow aborts the process instead of throwing. Task 20 records
  stack-overflow failures.

## Dependencies

See `depends_on` in [index.json](index.json). This task is on the critical
path ahead of task 20. Test262 `staging/sm/extensions/recursion.js` needs a
catchable `RangeError` for unbounded recursion, and today that test overflows
the Rust stack. Task 20 cannot close until this task does. The budget applies
to the call path as it exists today. Task 09 later takes the check over into its
activation model, without waiting for this task and without blocking it. Task 51
may later replace Rust recursion per call.

## Scope and implementation sequence

1. Give the runtime one named stack budget, measured from the entry stack
   pointer or as a derived frame-depth limit. Check it at every
   recursion-introducing transition: calls, construct, getters and setters,
   proxy traps, `toString`/`valueOf` conversions, and compiler recursion.
2. Exceeding the budget throws the realm's `RangeError` ("Maximum call stack
   size exceeded"), which guest code can catch, as V8 does.
3. Derive the worker stack size in every binary from one shared constant: the
   budget plus a named headroom. Remove the per-runner literals.
4. Reduce the CLI stack to the derived size once the budget covers the paths
   that needed 2 GiB.

## Verification

- Run the current Test262 stages. Outcomes must not regress, and the
  recorded stack-overflow cases must now throw `RangeError`.
- On macOS, run V8-v7 Earley-Boyer with the derived stack size.
- Deep recursion, mutual getter recursion and deeply nested `JSON.parse`
  must throw a catchable `RangeError` in every runner.

## Definition of done

- One budget constant owns the stack policy.
- No binary reserves more stack than that budget plus the named headroom.
- A guest stack overflow never aborts the process.

## Implementation evidence

`quench-stack` owns the shared RAII transition counter, 32 MiB budget, named
64 KiB transition reservation and 2 MiB host/unwind headroom. Both runtimes
use that one policy and counter; the next core reexports it for existing
callers. `quench-next`, `quench-node-next` and both next Test262 case entry
points use the derived 34 MiB worker reservation.

Next-core general/numeric execution, native calls, construction, property
reads and writes, proxy calls, primitive conversion and JSON parsing/traversal
consume the budget. Exhaustion creates a RangeError from the realm's captured
intrinsic prototype, without reading guest-modified globals or invoking guest
code. Those prototypes are traced through GC. Error intrinsics are constructed
before guarded initialization; their global bindings are published at the
original point, using one constructor table. Starting another runtime while
the thread budget is exhausted returns RangeError and recovers after release,
instead of panicking during bootstrap.

Legacy JSON parsing, reviver traversal and serialization now consume the
same shared budget. Parser errors distinguish invalid syntax from exhaustion;
`JSON.parse` and `JSON.rawJSON` preserve that distinction. Recursive traversal
returns a catchable RangeError and releases the budget on every return path.
Legacy ordinary/direct calls, receiver-updating calls, bound functions,
construction, native dispatch, property reads, object conversion, proxy
internal methods and loop entry also consume the shared budget. Iterative
call activations own a reservation until return; tail replacement releases
that reservation before entering the next activation. Function-entry
exhaustion builds the error in the callee's captured realm.
