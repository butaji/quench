# 02: Remove JIT, stencils, and the migrated native core

## Outcome

Leave one interpreter-only legacy runtime that can serve as the behavioral oracle during the rewrite.

## Current gap

The migrated VM, executable-memory publication, and native build generator are
removed. Legacy physical-selection compatibility code remains coupled to the
interpreter and is retired with the engine at task 27. The feature-only stencil
test corpus has also been deleted; the maintained interpreter inventory is
unchanged. Remaining optional migration checks still refer to removed native
contracts and are not a supported execution target.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Remove `quench-runtime-core`, its workspace/dependency edges, `vm_core`, and the environment-controlled native-core entry.
2. Remove build-time stencil catalogs/templates/artifacts, executable-memory arenas, native value bridges, native admission/tier policy, and all stencil-only modules and tests.
3. Collapse `machine` onto the canonical interpreter path without changing semantic operations, completions, or observable host behavior.
4. Delete the 342 execution-profile corpus, native-only lane expectations and tools, `crates/quench-runtime/tasks`, obsolete native/JIT documents, and checked-in native performance reports.
5. Retain general V8-v7 fixtures/runners and semantic compatibility tests.

## Verification

Build and run the focused interpreter/runtime and host smoke suites. Search manifests, source, tests, tools, docs, and build scripts for remaining executable-memory, stencil, migrated-core, or native-tier consumers.

## Definition of done

- The legacy runtime executes exclusively through its interpreter.
- No build script generates guest machine code and no runtime maps executable memory.
- General benchmark and conformance assets remain usable.

## Performance evidence

Report interpreter-only startup, Score, and RSS changes for diagnosis; no threshold gates deletion.

## Completion evidence

- Removed the migrated `quench-runtime-core` workspace member and environment-selected native entry.
- Removed the object compiler, stencil declaration/encoding/catalog generator, executable-memory mapping,
  native-only archive, and native benchmark contract tooling.
- Default runtime policy admits no physical regions; `StencilArena::make_executable` is a fail-closed
  legacy compatibility boundary and owns ordinary heap storage only.
- `cargo check -p quench-runtime -p quench-node` passes; the maintained interpreter suite passes 705 tests
  with no failures or ignored tests after native-only tests are isolated behind `legacy-native-tests`.

### Retired stencil test cleanup evidence

Removed 24 feature-only stencil test files (7,005 source lines) and 18 module
declarations. Their assertions require the removed physical artifacts or
executable arena; they were outside the maintained interpreter inventory.
General architecture, interpreter, semantic, continuation, and host tests remain.

`target/legacy-cleanup/` owns the removal manifest, source patch/provenance, and
terminal logs. The default runtime test inventory is byte-for-byte identical
before and after: 711 tests, all passing, zero ignored. Node library tests pass
16/16. Runtime/Node production targets and the all-feature runtime library
compile. The optional `--all-targets --all-features` native test target still
fails: 44 compile errors after removal versus 56 on the unchanged baseline,
with no new error messages. No full Test262 run or performance claim was made.

### Native function-entry cleanup evidence

The empty catalog makes every physical loop lookup fail. Removed nine
native-only function-entry probes, 21 implementation/selector files, their
orphaned counted-loop facts and entry methods, and 22 unused catalog keys.
The portable counter recurrence, affine handlers, and ordered-neighbor loop
remain live; counter execution no longer carries an impossible native flag.
Unused intrinsic graph variants and their projections are removed as well.

New fallback coverage exposed the legacy postfix-update double coercion:
`ToNumeric` ran again after `PutValue`. Lowering now converts before the write
and returns that same numeric value. The compact local update and portable
counter/named-loop validators consume the corrected order. Ninety hot-IR
contracts move the existing `Unary` before update/store; their semantic result
expectations are unchanged.

`target/legacy-native-entry-cleanup/` owns the removal plan, source/binary
provenance, exact focused Test262 report, Node oracles, and terminal logs.
Maintained runtime tests pass 714/714 with zero ignored, including three new
regressions for numeric boundaries, coercion order/thrown identity, and a setter
that replaces the coercion hook. Node library tests pass 16/16; production
runtime/Node targets compile without warnings. The CLI matches Node's stdout,
stderr and exit status for the setter case. All 180 pinned prefix/postfix update
and while-loop cases pass through the legacy runner with four workers and a
30-second per-case deadline. No whole Test262 run or performance claim was made.

## Removed native ABI and policy remnants

The native function-entry removal also made eight ABI rows unconstructible:
I32CounterLoop, BooleanReductionLoop, BranchRecurrenceLoop, NestedXorLoop,
SwitchReductionLoop, MatrixReductionLoop, TypedLaneLoop and TwoStateI32Loop.
Their catalog rows, explicit policy rejections, invocation error arms and
retired test inventory entries are now removed. Portable counter and named-loop
execution retain their own facts and unchanged semantics.

Production policy now derives directly from one `ExecutionPolicy::DISABLED`
constant. The unused `OnceLock`, initialization wrapper and duplicate disabled
capability literals are gone. Two new unit tests verify fail-closed admission
and restoration of nested thread-local test overrides after unwinding.

Evidence is in `target/legacy-policy-cleanup/`: the maintained runtime suite
passes 716/716 with zero ignored; all four policy tests pass; runtime/Node
all-target checks and the all-features runtime library check pass without
warnings. The optional legacy native test target remains outside the maintained
suite. This slice changes no guest semantics and runs no additional Test262
inventory. The preceding 180-case update/while evidence remains recorded above.
Task 27 still owns whole-core deletion after the shared JS/Node/Wasm gate.
