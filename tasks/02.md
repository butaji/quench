# 02: Remove JIT, stencils, and the migrated native core

## Outcome

Leave one interpreter-only legacy runtime that can serve as the behavioral oracle during the rewrite.

## Current gap

The workspace still contains a private migrated VM, copy-and-patch build generation, executable-memory publication, hundreds of stencil modules/tests, 342 native-lowering contracts, and an internal 430-file task archive.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Remove `quench-runtime-core`, its workspace/dependency edges, `vm_core`, and the environment-controlled native-core entry.
2. Remove build-time stencil catalogs/templates/artifacts, executable-memory arenas, native value bridges, native admission/tier policy, and all stencil-only modules and tests.
3. Collapse `machine` onto the canonical interpreter path without changing semantic operations, completions, or observable host behavior.
4. Delete the 342 execution-profile corpus, native-only lane expectations and tools, `crates/quench-runtime/tasks`, obsolete native/JIT documents, and checked-in native performance reports.
5. Retain general V8-v7 fixtures/runners and semantic compatibility tests.

## Verification

Build and run the focused interpreter/runtime and host smoke suites. Search manifests, source, tests, tools, docs, and build scripts for remaining executable-memory, stencil, migrated-core, or native-tier consumers.

## Definition of done

- The legacy runtime executes exclusively through its interpreter.
- No build script generates guest machine code and no runtime maps executable memory.
- General benchmark and conformance assets remain usable.

## Performance evidence

Report interpreter-only startup, Score, and RSS changes for diagnosis; no threshold gates deletion.
