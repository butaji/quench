# 09: Unify activation, realms, jobs, and the host ABI

## Outcome

Create one activation/lifecycle model and a narrow, GC-safe capability boundary for Node, Test262, and Wasm.

## Current gap

V2 owns simple frames and two host effects; Quench requires realms, suspended execution, jobs, interrupts, re-entry, and persistent host-held values without exposing VM internals.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Define one frame, continuation, handler, and completion representation for calls, returns, throws, yield/await, and resumption.
2. Move globals, intrinsics, module state, and job queues into explicit runtime-owned realms rather than thread-local semantic authority.
3. Define `Host`, `HostContext`, `CapabilityId`, and `RootId`; capability calls receive borrowed arguments and return values/errors through the runtime.
4. Require persistent roots for callbacks or values retained beyond a call; make release, cancellation, interruption, and shutdown named transitions.
5. Support safe host-to-guest re-entry and separate VM instances for workers; share only explicitly thread-safe external backings.

## Verification

Test nested calls, throws, recursion exhaustion, suspended roots, realm isolation, microtask ordering, host re-entry, persistent-root release, interrupts, workers, and allocation failure at every growth boundary.

## Closure boundary

Promise and module producers belong to tasks 17 and 18, which depend on this
task. This task closes when the frame/continuation/completion representation,
realm-owned state, `HostContext`/`CapabilityId`/`RootId` contract, rooted job
queue, and re-entry/interrupt transitions exist and are tested; tasks 17, 18,
21, and 43 adopt them.

## Definition of done

- Hosts cannot inspect heap cells or retain raw `Value` handles across safepoints.
- Every activation and job transition has one owner and root set.
- No implicit current-VM global is needed for semantics.

## Performance evidence

Measure frame/root/job bytes and call/host-boundary overhead; no cutover threshold applies.

## Implementation evidence

The next runtime now exposes stable `CapabilityId` values and a borrowed
`HostContext`. Print and clock effects route through that context, whose API
accepts only typed host-boundary data and never exposes heap cells or guest
handles. Root handles are generation-checked and owned by the same runtime.

The runtime now exposes generation-checked root lookup and rooted job enqueue /
drain operations. Hosts submit callback and argument roots, the VM copies those
values into its single pending-job owner, and the shared interpreter drains the
queue after roots may be released; stale roots are rejected before enqueue.
Promise/module producers and realm persistence remain pending dependencies.
