## Outcome

The Rust V8-v7 runner (`quench-bench`) measures Quench against QuickJS, Bun
with the JSC JIT disabled, and Node with `--jitless`, on all eight fixtures,
with per-fixture Score and maximum RSS. Each run records proof that the
reference engine's JIT was off. The runner captures peak RSS and available
process counters through the operating system's `wait4` accounting, with a
process-group timeout and RSS normalized to bytes.

## Current gap

The Rust runner now has one engine specification per runtime, probes Node's
`--jitless` flag and Bun/JSC's `useJIT=false`, records QuickJS and Quench
interpreter identities, and rejects samples without finite Score and RSS. Its
schema-4 report keeps all four raw samples together per fixture and round,
with engine commands, versions, binary hashes and an explicit measurement
environment stored once and referenced by each matched row. Linux reports also
record the cgroup CPU quota and memory limit. The benchmark
submodule is now clean at the repository pin
`64e1860c736c1b899708f4cd646721bc71e53d8b`. The required eleven-round campaign
remains open. Stage A task 86 is now qualified on the cleaned production build.

The runner now supports an atomic per-fixture checkpoint and a provenance-bound
resume path. A resume reuses only complete valid fixtures with matching source,
host, corpus inputs, engine identities, round count, and timeout; incomplete or
invalid fixtures are rerun from the start. This protects long campaigns from
losing completed fixture records after an interruption.

The Linux runner no longer requires an external `time` utility. `wait4` RSS
conversion and exit/resource capture tests pass, and the four-engine no-JIT
preflight passes with the pinned QuickJS binary, Bun 1.4.2 and Node 24.19.0.
These checks validate runner setup only; scored Stage B sampling still waits
for the eleven-round baseline.

## Scope and implementation sequence

1. Add a `--qjs <path>` engine that uses the same materialized suite wrapper as
   the other engines.
2. Add no-JIT modes for Node (`--jitless`) and Bun (JSC `useJIT=false`, set
   through Bun's JSC option environment). Record the engine version and the
   effective flags or options in each sample.
3. Verify that each mode is really interpreter-only, with an engine-reported
   option dump or an equivalent check. Mark a run invalid when the check fails
   or cannot run. Missing engine version, effective argv/environment, or this
   proof invalidates the sample.
4. Require finite per-fixture Score and maximum RSS for all four engines;
   missing, non-finite, or unavailable RSS invalidates the sample rather than
   silently allowing a Score-only comparison.
5. Store one matched fixture/round row containing all four engine samples and
   derive summaries from those rows. Record each binary hash, version, command,
   effective JIT mode, suite/base hashes and host provenance in the row.
6. Update [`docs/v8_v7.md`](../docs/v8_v7.md) with the commands.
7. Save completed fixture records atomically and reject a resume if its
   provenance differs from the original campaign.
