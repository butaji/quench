# 033: JIT-side self-modifying-code IC stub chain and inline slab

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 032

## Context

Paper §7.1: in JIT-generated code, an IC starts as a jump to the miss slow
path (λi logic); each miss creates a new IC stub (λe logic) that checks its
own key and branches to the next stub on miss, forming a chain — and if a
stub is small enough and the self-modifying-code (SMC) region has room, the
stub lives inline in that region ("inline slab"); otherwise it's outlined.
Audit found: quench's stencil `Repatch` (`stencil_patch.rs`) only rewrites
`PatchValues` holes in pre-rendered bytes within a bounded RW arena — there
is no runtime-growing stub chain and no inline-vs-outlined-stub decision.

## Scope
- crates/quench-runtime/src/stencil_arena.rs
- crates/quench-runtime/src/stencil_patch.rs
- crates/quench-runtime/src/stencil_lifecycle.rs

## Deliverables
- Design a bounded SMC IC stub-chain mechanism for the stencil tier's
  polymorphic call/property sites: each new observed key gets its own small
  compiled stub appended to the chain, up to the existing degrade-tier bound
  (task 024's Megamorphic ceiling) before falling back to the ordinary
  interpreter path
- Implement the inline-slab-vs-outlined decision: stub fits in the region's
  reserved inline space → written there; otherwise → outlined stub with a
  jump from the region
- Every stub chain keeps the ordinary interpreter as its complete fallback on
  chain exhaustion or key miss, per this tier's existing invariant
  (`docs/copy-and-patch-jit.md`)

## Acceptance
- Differential tests confirm identical behavior across cold/warm/polymorphic/
  megamorphic states
- Neutral corpus geomean improves on polymorphic call/property-heavy cases
- The bounded arena's total size budget is respected; no unbounded SMC growth

## Non-goals
- Changing the interpreter-side IC (already correct, item 2/3 in
  docs/deegen-alignment.md) — this is JIT-code-generation only
