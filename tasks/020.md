# 020: Reach a measured 2,000 Richards score with reusable interpreter work

- **Theme:** deegen_codegen
- **Executor:** codex
- **Depends on:** 019
- **Status:** implementation gate complete; Richards performance phase pending

## Objective

Raise the valid `v8-v7/richards` score from the current ~84.7 five-run median
toward 2,000 without changing benchmark source, timing, output validation, or
JavaScript semantics. A score of 2,000 means about 23.6x less time per inner
iteration (approximately 41.7 ms to 1.77 ms), so every slice must be measured.

## Design facts

- `vm_op!` remains the one declaration for opcode identity, operands, controls,
  guards, handlers, and generated dispatch views.
- A fast path is admitted only from `Proven` or `Guarded` facts and returns to
  complete ordinary semantics for `Unknown`, mutation, accessors, proxies,
  dynamic scope, and observable errors.
- `SlotWord` is the canonical physical register/property word. `Value` is the
  semantic boundary and is not materialized for proven word-level operations.
- Object layout/atom indexes are derived caches; canonical property names and
  values remain the only semantic storage.
- Benchmark code is measurement only. Runtime code must not inspect fixture
  names/source/scores or identify another engine.

## Ordered implementation slices

1. **020-a — neutralize regressions and freeze evidence.** Keep direct generated
   opcode dispatch, remove measured-negative layout/frame experiments, and record
   five-run median score, wall time, retired instructions, and cycles.
2. **020-b — generated word operand facts.** Extend opcode facts with guard-derived
   input and result word kinds; select number/boolean/object/array/callable word
   probes from the same declaration used by arithmetic, branches, locals, moves,
   and dense arrays. Generic coercion stays in cold handlers.
3. **020-c — Deegen-style direct call-frame entry.** Extend the callable IC from
   identity admission to a bounded `(function, arity, receiver-mode, frame-shape)`
   entry. On a hit, populate the canonical callee frame and enter the existing
   completion driver directly; retain full call continuations on misses.
4. **020-d — QuickJS-style atom/layout lookup.** Intern property names to compact
   atom IDs at the canonical property boundary, use hashed shape buckets only
   after a measured size threshold, and guard `(shape, atom, slot)` with exact
   mutation invalidation. Verify accessors, duplicate writes, deletion markers,
   prototypes, and proxies against Node.
5. **020-e — hot/cold generated layout.** Generate `#[inline(always)]` hot
   handlers and `#[cold] #[inline(never)]` complete fallback bodies from the
   same operation facts. Keep tracing feature-gated out of release hot paths.
6. **020-f — neutral-suite gate.** Run Richards plus representative object,
   numeric, call, regexp, and async fixtures. Accept a slice only when output,
   status, errors, and descriptors remain equal and the geometric-mean score
   does not regress.

## Acceptance

- Each accepted slice has a reproducible five-run record and a named reason for
  any regression or rejection.
- The full benchmark runner reports valid status and preserved observable output.
- `cargo fmt --all -- --check`, VM tests, architecture checks, and `git diff --check`
  pass.
- No JIT, executable memory, source/fixture detection, score detection, or
  benchmark-specific production kernel is introduced.
