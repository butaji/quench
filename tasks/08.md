# 08: Rebuild objects, shapes, descriptors, and caches

## Outcome

Provide one ECMAScript object/property authority built on v2's immutable shapes and bounded inline caches.

## Current gap

V2 shapes encode ordered names and data slots only; complete semantics require attributes, accessors, prototypes, exotic behavior, mutation invalidation, and exact own-key ordering.

The 2026-09-23 core review (`target/reviews/core-review-2026-09-23/`) found
that the full-semantics extensions defeat v2's caches. These are regressions
from pinned v2, not tuning, and they fall under step 5 and the task 44 rule
that cache hits are justified by shape identity alone:

- `set_shape_property` previously invalidated field and method caches on every
  write, including ordinary add-property transitions. v2 invalidates only on
  transitions that can change a cached lookup's result.
- `get_field_cached` previously re-hashed virtual-property names and walked
  accessors before checking a field cache. These facts belong on interned atoms,
  shapes/cell kinds, or the recorded cache entry.
- `transition_property_shape` clones the parent's key vector, key→slot hash
  map, and descriptor vector for every new shape. Transition chains cost
  quadratic memory and three allocations per step; v2 shares this data along
  the chain.

## Dependencies

## Scope and implementation sequence

1. Define immutable shape entries from one ordered `PropertyKey` sequence, slots, and descriptor attributes, with transition interning and dictionary fallback. String and Symbol properties share this authority; derive `ownKeys` ordering from it rather than keeping a symbol-property side table.
2. Implement canonical internal methods for get/set/define/delete/has/ownKeys/prototype/extensibility; all specialized paths call or exactly guard these operations. These operations become the object half of the kernel API (task 46), which is the porting target for legacy builtins, so keep them close to the spec's essential internal methods.
3. Separate ordinary storage from exotic dispatch while preserving one object identity and prototype representation.
4. Extend field/method caches to monomorphic, bounded polymorphic, and megamorphic states keyed by shape/prototype/callable facts.
5. Invalidate or revalidate caches on descriptor, prototype, callable, backing, replacement, and collection transitions. An ordinary data-property add or write is not one of these transitions: the receiver's new shape already misses stale entries. Invalidation is scoped (by shape, prototype, or site), never a whole-program flush on a data write.
6. Keep the cache-hit path to the checks the recorded entry proves: receiver shape, owner identity or shape, and slot presence. Exotic, accessor, and virtual-property facts are decided at record time and encoded in the shape, cell kind, or entry.
7. Share shape key, slot, and descriptor data along transition chains (a parent link plus the added entry, with a derived lookup index built once per shape that needs it) rather than cloning three containers per transition.

## Verification

Use existing Test262 cases for descriptor matrices, accessors and re-entry,
integer/string/Symbol ordering, prototype mutation, delete/re-add, and
non-extensible objects. Keep the Test262 harness unchanged and cover repaired
regressions with Rust unit tests as required by the shared completion rules.
Check dictionary/cache/handle invariants by inspection and the full Test262 run.

## Definition of done

- Ordinary and exotic objects share one internal-method contract.
- Cache hits preserve exactly-once effects and have an observable generic fallback.
- Object identity and property authority are not duplicated in adapters.

## Performance evidence

Report shape/property bytes, cache hit/miss/promotions, transition counts, and property-heavy workload effects.

## Implementation evidence

The prototype transition now has one named mutation boundary: it rejects cycles
before changing the graph and invalidates field and method caches after a valid
prototype replacement. A warmed-cache regression verifies reads follow the new
prototype, and the cycle path produces the required failure. Dictionary
fallback work remains pending for this task.

Shape keys remain the immutable authority while a derived atom-to-slot index is
rebuilt at each interned transition and reset with the realm shape table. The
index is used by ordinary get/set/delete/enumerability paths and has focused
alignment coverage, avoiding duplicate property-name authorities.

The shape authority is now represented by one immutable `Shape` record: ordered
keys and its derived atom-to-slot index travel together through every shape
transition. Realm teardown clears the shape table as one unit, and object
lookup, JSON enumeration, and static key ordering all read that same record;
there is no parallel key/index array to drift.

The canonical descriptor transition now rejects mixed data/accessor fields,
rejects kind changes on non-configurable properties, and permits configurable
accessor-to-data replacement for ordinary and indexed array properties. The
regression and local Node oracle agree on the observable values and errors;
indexed-exotic descriptor folding remains pending.

`Object.defineProperties` now snapshots own descriptor keys, routes each entry
through the same `defineProperty` authority, and supports string and Symbol
keys without a parallel mutation path. `Object.create` now consumes its
optional descriptor map through that same route.

Symbol descriptors and values used to remain in `PropertyKey`-indexed side
tables while ordinary string descriptors were shape-owned. The current
implementation removes those ordinary Symbol value/order/descriptor tables:
strings and Symbols now share the immutable shape's ordered `PropertyKey`
sequence, slot map, and descriptor vector. Indexed-exotic descriptors remain
in their keyed storage path.

Ordinary string-property descriptor attributes travel with the immutable
shape record. Before the parent-linked transition change recorded below,
descriptor transitions cloned the descriptor vector; descriptor redefinition
publishes a new shape, and the canonical accessor/write/enumerability paths
read that shape authority before falling back to symbol or indexed-exotic side
tables. Shape-held accessor values are included in the VM root scan.
