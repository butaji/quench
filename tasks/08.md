# 08: Rebuild objects, shapes, descriptors, and caches

## Outcome

Provide one ECMAScript object/property authority built on v2's immutable shapes and bounded inline caches.

## Current gap

V2 shapes encode ordered names and data slots only; complete semantics require attributes, accessors, prototypes, exotic behavior, mutation invalidation, and exact own-key ordering.

The 2026-09-23 core review (`target/reviews/core-review-2026-09-23/`) found
that the full-semantics extensions defeat v2's caches. These are regressions
from pinned v2, not tuning, and they fall under step 5 and the task 44 rule
that cache hits are justified by shape identity alone:

- `set_shape_property` previously invalidated field and method caches on every
  write, including ordinary add-property transitions. v2 invalidates only on
  transitions that can change a cached lookup's result.
- `get_field_cached` previously re-hashed virtual-property names and walked
  accessors before checking a field cache. These facts belong on interned atoms,
  shapes/cell kinds, or the recorded cache entry.
- `transition_property_shape` clones the parent's key vector, key→slot hash
  map, and descriptor vector for every new shape. Transition chains cost
  quadratic memory and three allocations per step; v2 shares this data along
  the chain.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Define immutable shape entries from one ordered `PropertyKey` sequence, slots, and descriptor attributes, with transition interning and dictionary fallback. String and Symbol properties share this authority; derive `ownKeys` ordering from it rather than keeping a symbol-property side table.
2. Implement canonical internal methods for get/set/define/delete/has/ownKeys/prototype/extensibility; all specialized paths call or exactly guard these operations. These operations become the object half of the kernel API (task 46), which is the porting target for legacy builtins, so keep them close to the spec's essential internal methods.
3. Separate ordinary storage from exotic dispatch while preserving one object identity and prototype representation.
4. Extend field/method caches to monomorphic, bounded polymorphic, and megamorphic states keyed by shape/prototype/callable facts.
5. Invalidate or revalidate caches on descriptor, prototype, callable, backing, replacement, and collection transitions. An ordinary data-property add or write is not one of these transitions: the receiver's new shape already misses stale entries. Invalidation is scoped (by shape, prototype, or site), never a whole-program flush on a data write.
6. Keep the cache-hit path to the checks the recorded entry proves: receiver shape, owner identity or shape, and slot presence. Exotic, accessor, and virtual-property facts are decided at record time and encoded in the shape, cell kind, or entry.
7. Share shape key, slot, and descriptor data along transition chains (a parent link plus the added entry, with a derived lookup index built once per shape that needs it) rather than cloning three containers per transition.

## Verification

Use existing Test262 cases for descriptor matrices, accessors and re-entry,
integer/string/Symbol ordering, prototype mutation, delete/re-add, and
non-extensible objects. Do not add tests or alter the Test262 harness. Check
dictionary/cache/handle invariants by inspection and the full Test262 run.

## Definition of done

- Ordinary and exotic objects share one internal-method contract.
- Cache hits preserve exactly-once effects and have an observable generic fallback.
- Object identity and property authority are not duplicated in adapters.

## Performance evidence

Report shape/property bytes, cache hit/miss/promotions, transition counts, and property-heavy workload effects.

## Implementation evidence

The prototype transition now has one named mutation boundary: it rejects cycles
before changing the graph and invalidates field and method caches after a valid
prototype replacement. A warmed-cache regression verifies reads follow the new
prototype, and the cycle path produces the required failure. Dictionary
fallback work remains pending for this task.

Shape keys remain the immutable authority while a derived atom-to-slot index is
rebuilt at each interned transition and reset with the realm shape table. The
index is used by ordinary get/set/delete/enumerability paths and has focused
alignment coverage, avoiding duplicate property-name authorities.

The shape authority is now represented by one immutable `Shape` record: ordered
keys and its derived atom-to-slot index travel together through every shape
transition. Realm teardown clears the shape table as one unit, and object
lookup, JSON enumeration, and static key ordering all read that same record;
there is no parallel key/index array to drift.

The canonical descriptor transition now rejects mixed data/accessor fields,
rejects kind changes on non-configurable properties, and permits configurable
accessor-to-data replacement for ordinary and indexed array properties. The
regression and local Node oracle agree on the observable values and errors;
indexed-exotic descriptor folding remains pending.

`Object.defineProperties` now snapshots own descriptor keys, routes each entry
through the same `defineProperty` authority, and supports string and Symbol
keys without a parallel mutation path. `Object.create` now consumes its
optional descriptor map through that same route.

Symbol descriptors and values used to remain in `PropertyKey`-indexed side
tables while ordinary string descriptors were shape-owned. The current
implementation removes those ordinary Symbol value/order/descriptor tables:
strings and Symbols now share the immutable shape's ordered `PropertyKey`
sequence, slot map, and descriptor vector. Indexed-exotic descriptors remain
in their keyed storage path.

Ordinary string-property descriptor attributes now travel with the immutable
shape record. Shape transitions clone the descriptor vector, descriptor
redefinition publishes a new shape and invalidates derived caches, and the
canonical accessor/write/enumerability paths read that shape authority before
falling back to symbol or indexed-exotic side tables. Shape-held accessor
values are included in the VM root scan.

Builtin methods installed by the Object authority now publish their standard
own-property attributes through one named transition: writable and
configurable, but non-enumerable. `Object.getPrototypeOf`'s descriptor case
passes on the existing Test262 suite. Array callback methods now use lazy
array-like traversal, and `map` rejects a `ToLength` above the Array length
limit before invoking its callback; the existing `Array.prototype.map` test
with an infinite array-like length passes. The strict accessor-without-setter
case's compiler binding issue is addressed below; broader descriptor families
remain open.

The three strict setter Test262 failures in the descriptor subset were traced
to the compiler's local collector omitting `var` declarations used as
`for-in`/`for-of` left-hand sides. The collector now binds those declarations
before body traversal. The existing cases `15.2.3.6-4-243-2.js`,
`15.2.3.6-4-292-2.js`, and `15.2.3.6-4-293-4.js` pass on stage 60 with the
next runtime. The in-flight uncapped report was built before this compiler
fix, so its counts do not yet include the change.

The uncapped 53,404-file Test262 sweep initially recorded 27 failures under
`Object/defineProperty` and 31 under `Object/defineProperties`. After moving
the Function, Array, Map, Set, Date, and Atomics builtin methods through the
same descriptor transition, the existing `Object/defineProperty` subset is at
1,115/1,133 (18 failures). Remaining families include strict setter
completion, Symbol membership, array length descriptor edges, and missing
String/Date function properties. The full failure inventory is recorded in
the task-48 report rather than duplicating test paths here.

The unified shape uses stable property-arena slots distinct from its active
insertion-order key sequence. Deletion publishes a shape without the key while
leaving the old backing slot deleted; re-addition appends at a fresh slot, so
own-key order and storage layout agree. Symbol get/set/define/delete,
descriptors, reflection, integrity checks, builtin `@@iterator` attributes,
and JSON/string-key projections now consult that authority. Shape-held Symbol
handles are conservatively rooted along with shape-held accessor values; safe
reclamation of symbol-bearing shape metadata remains pending because the
current raw heap `Value` identity can be recycled after collection.

Shape slot indices and the property arena's shape-length table now use `u32`
rather than `u16`; the arena has buckets for the full representable shape
length range, and insertion rejects index overflow before narrowing. Field
cache entries remain `u16`-addressable by design: slots outside that range take
the generic shape/storage path and are never truncated into cache entries. This
removes the prior 65,535-property panic/alias boundary, but it is not yet the
task's full dictionary fallback; property-arena address exhaustion and
Symbol-handle reclamation remain explicit gaps. The 1,170-case stage-10
object-expression subtree ran in twelve batches of at most 100 and reported
1,158 passes, 12 failures across 11 existing compiler/semantic families; no
pass-count increase is claimed from this storage-width change.

100% (1,157/1,157); the latest stage-10 run reaches 9,568/11,101 in
stage 10. Batches stayed at or below 100 cases, with
`TEST262_TEST_TIMEOUT_MS=300000`. Arrow lexical-this capture is represented by

project tests or harness edits were made. Named function-expression

`Object.keys` now enumerates proxy keys through the proxy's `[[OwnPropertyKeys]]`
and obtains each string key's enumerability through the existing
`[[GetOwnProperty]]` descriptor operation. This also covers proxies whose
`ownKeys` trap is absent, since the default key list still requires descriptor
traps to be consulted. Direct Proxy Test262 verification is deferred until the

The ordered indexed-key projection now includes valid TypedArray element
indices as well as Array indices, without inventing an Array-style `length`
property for TypedArrays. The corresponding own-descriptor path returns the
data descriptor for in-bounds canonical decimal indices and uses the same
length and indexed-element read paths as ordinary indexed access. TypedArray
Test262 verification remains deferred to its later stage under the
sequential-run constraint; BigInt typed-array element representation remains
a separate semantics gap.

Own-key consumers now share the ordered `[[OwnPropertyKeys]]` projection.
Ordinary keys derive indices, live shape strings, and symbols in canonical
order; Proxy keys use the trap path. `Object.keys` then consults
`[[GetOwnProperty]]` for each string key's enumerability, while
`getOwnPropertyNames`/`Symbols` and descriptor-copy consumers filter that same
projection. Only the `\0rqj:` engine namespace is filtered, preserving other
NUL-prefixed user keys. `cargo check -p quench-runtime-next -p quench-test262`
passes. Existing stage-10 object-expression coverage remains 1,158/1,170; this
change has not yet shown a full-stage pass-count gain. TypedArray conformance
remains pending its sequential stage.

Symbol-keyed primitive lookup now derives the primitive wrapper prototype from
the intrinsic constructor (with String.prototype as the canonical String
prototype) before walking the ordinary prototype chain. String primitive
property reads also consult String.prototype after virtual index/length
properties, making prototype mutation observable instead of bypassing shapes.
The related stage-10 String and custom-iterator cohorts pass; this does not
close all primitive internal methods or task 08.

The field-read hit path now compares VM-interned `byteLength`, `byteOffset`,
and `buffer` atoms instead of rebuilding UTF-16 vectors and hashing those
spellings on every access. The accessor/prototype scan remains in the generic
miss path; existing descriptor/prototype mutation invalidation continues to
protect cached facts. `cargo check -p quench-runtime-next -p quench-test262`

Field cache entries now include the looked-up atom. Hit validation checks
receiver shape, intervening prototype absence for that atom, owner identity,
owner shape, and slot presence. Ordinary add/delete transitions and ordinary
data writes no longer flush field caches; descriptor and prototype mutations
retain their correctness invalidation. Proxy prototypes take the generic
`[[Get]]` path before an entry can be recorded. The cache-write path retains
method-cache invalidation only when replacing a callable own value; ordinary
method-cache invalidation from the generic mutator remains pending.

Method-cache records now retain their property atom, and data/descriptor/delete
mutations invalidate only entries for that name. Prototype replacement still
clears method caches because it changes the receiver's lookup path. Normal and
`profile-aggregate` `cargo check` both pass. The ordered release stage-10 sweep
after both field and method guard changes passes 10,891/11,101 (210 failures
across 190 families), in 112 batches of at most 100 with
`TEST262_TEST_TIMEOUT_MS=900000`. No unit tests, new tests, or harness edits
