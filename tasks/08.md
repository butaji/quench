# 08: Rebuild objects, shapes, descriptors, and caches

## Outcome

Provide one ECMAScript object/property authority built on v2's immutable shapes and bounded inline caches.

## Current gap

Closed by the structural acceptance review below. Shapes, property storage, descriptors, exotic dispatch and guarded caches have one authority. The Test262 gate uses the explicit user assumption recorded by tasks 20/48; focused runs check affected expectations without claiming an observed whole-inventory pass. Task 07 owns the remaining native/suspended root-lifecycle review, and later semantic, Node and Wasm tasks retain their own acceptance gates.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Define immutable shape entries from one ordered `PropertyKey` sequence, slots, and descriptor attributes, with transition interning and dictionary fallback. String and Symbol properties share this authority; derive `ownKeys` ordering from it rather than keeping a symbol-property side table.

2. Implement canonical internal methods for get/set/define/delete/has/ownKeys/prototype/extensibility; specialized paths call or guard those operations.

3. Separate ordinary storage from exotic dispatch while preserving one object identity and prototype representation.

4. Extend field/method caches through monomorphic, bounded polymorphic, and megamorphic states keyed by shape/prototype/callable facts. These states form the README's monotone cache-degree lattice. Dictionary mode is a named, counted, one-way shape transition with property-count, deletion-pattern, and prototype-use triggers; cached sites treat it as a normal miss.

5. Invalidate or revalidate caches on descriptor, prototype, callable, backing, replacement, and collection transitions. Ordinary data writes do not flush caches globally; invalidation is scoped by shape, prototype, or site.

6. Keep cache-hit checks limited to recorded facts. Exotic, accessor, and virtual-property behavior stays on an exact generic fallback unless its facts are captured by the shape, cell kind, or entry.

7. Share shape key, slot, and descriptor data along transition chains, deriving a lookup index only for shapes that need one.

## Implementation evidence

### Shape and property authority

Shapes are immutable parent-linked records with one `Add`, `Delete`, `Descriptor`, `Vacant`, or `Dictionary` transition and a storage length. Ordered `PropertyKey` entries, slot lookup, and attributes derive from that chain; one lazily built lookup index is memoized when repeated access warrants it. String and Symbol keys share shape-owned descriptors and enumeration order. Symbol transitions bypass string interning because raw heap handles can be reused.

Heap tracing reads live shape-owned Symbol keys and accessor values from reachable objects. At GC, live shapes are rebuilt from active slots and latest descriptors, deleted slots become vacant transitions, and stale branches/descriptors are dropped. The property arena compacts live ranges at the same boundary. Its stable slots fall back to per-object dictionary storage when arena addresses are exhausted. Dictionary transitions are named and counted for property-count, deletion-pattern, and prototype-use triggers; reads, writes, roots, release, shape remapping, compaction, and accounting share `ValueArena` dispatch.

### Internal methods and caches

Ordinary assignment, descriptor definition, deletion, own-key projection, and prototype changes route through shared property operations. Descriptor fields are converted once into `PropertyDescriptorRecord`; ordinary properties, Array indices/length, and TypedArray indices share conversion and validation while retaining their distinct exotic constraints. Proxy and accessor operations preserve their receiver, re-entry, and trap behavior through the generic path.

Field-cache entries validate receiver shape and the recorded property path, including intervening prototype absence, owner identity/shape, and slot. Method-cache entries carry the property atom and resolved receiver/prototype/owner/slot facts. Hits avoid an unnecessary property-chain walk; accessors and exotic paths use generic lookup. Callable replacement, descriptor changes, prototype mutation, and dependent inherited-property additions invalidate only entries whose facts can change. Ordinary writes to non-callable data do not globally clear caches. Megamorphic entries and post-GC refill preserve rooted call targets.

The property arena's growth threshold, reserve divisor, and representable slot boundaries have named owners. Rare per-object state uses one lazy `ObjectExtras` record; a plain `Object` is 24 bytes rather than 168 bytes, and both memory-accounting paths include the side payload.

### Shape lookup eligibility (2026-10-01)

Implementation `04d40f74b` gives cache admission, field-cache hit validation and
method guard construction one `shape_property_lookup` operation. Shapes alone
do not prove indexed, virtual, private, namespace, Proxy, restricted caller or
dictionary lookup. Every receiver and intervening prototype must satisfy that
operation before a stored slot can serve a cached read. Array indices and
canonical TypedArray numeric names use the shared generic Get operation;
noncanonical TypedArray names and ordinary numeric names retain shape caching.
Accessor misses likewise use generic Get. Cache-miss virtual buffer/view reads
are removed instead of maintaining another implementation of those semantics.
Depth overflow now falls back rather than saturating a cached path length.

The API regression fails on `8599e4a18`: specialized direct/inherited Array and
TypedArray reads of a literal '0' return undefined. It now matches Node in both
modes for those reads, boxed strings, prototype values, later element writes
and canonical '-0' suppression of inherited getters. A separate VM control
proves ordinary numeric names and noncanonical TypedArray names actually
populate the cache while canonical indexed storage does not.

The existing field overflow budget has a named layout owner,
`FIELD_MEGAMORPHIC_LIMIT`, without changing its value. It bounds each site's
recorded shape payload to 256 times `size_of::<FieldCache>()`, plus table
storage. Full tables can refresh existing shapes; unseen shapes remain misses
and use the exact generic fallback. A new control disables threshold collection
after initialization, asserts zero collection, fills the budget, and verifies
the next shape still reads correctly in both modes. This separates capacity
exhaustion from collection clearing a table.

### Shared Proxy Set and receiver writes (2026-10-01)
