# 77: Attribute selected V8-v7 Score and RSS gaps

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select this work only for a
measured V8-v7 Score or RSS gap; finishing it is not a stage-completion gate.
Use affected-stage checks plus compare-runs during changes. The current
dependencies in [index.json](index.json) supersede older prerequisite claims.

## Outcome

Attribute a selected V8-v7 Score/RSS gap to measured execution and memory
costs. The map below is a candidate catalogue, with an owner and prior evidence
for each mechanism. Task 61 closes when all eight benchmarks meet its two
targets; untried map rows never block it.

## Current gap

Task 25's lab and task 62's runner report end-to-end Score and maximum RSS.
v2 attributed Crypto in depth (tasks 236, 332, 382, 390–392), but no tool
splits every fixture's time into dispatch, library, allocation, and
collection, or its RSS into text, heap, residual, and allocator regions.
Without that split, a mechanism's benefit is visible only through the noisy
end-to-end gate. Mechanisms are also spread across tasks, and attribution must identify the concrete cost before selecting another
mechanism. Exhausting the design space is not a goal.

## Dependencies

See `depends_on` in [index.json](index.json). This is Stage B diagnostic
work selected by a measured gap. Correctness diagnostics may run earlier
where needed; a performance attribution campaign does not block Stage A.

## Scope and implementation sequence

1. Record host facts once per report: performance-core and efficiency-core
   L1D, L2 and page sizes from `sysctl hw.perflevel*` and `hw.pagesize`.
   Mechanisms that size structures to caches read these facts. They never
   hard-code cache sizes.
2. Time attribution for the selected engines and gap: cycles, instructions, branch
   mispredictions, and L1D/L2 misses from macOS kperf counters (v2 task 391),
   plus sampled native call trees. Quench also splits time by an interpreter
   / library / allocation / collection phase counter in an instrumented build
   (task 25).
3. RSS attribution: text, data, stack, heap cells, property and element
   arenas, strings, residual and metadata, and malloc zones, from `vmmap`
   and `footprint` snapshots at peak (v2 task 236). Report `phys_footprint`
   next to `ru_maxrss`, because the gate measures the latter.
4. Profiles for the selected losing paths: the dispatch-class × opcode matrix and adjacent-pair
   matrix (v2 tasks 392, 394), the allocation profile by cell kind and site
   (v2 task 156), and builtin time by builtin.
5. Record the selected mechanism and its prior evidence. Expand the
   catalogue only when a measured gap needs it.
