# 80: Raise RegExp execution throughput

## Outcome

The RegExp matcher is a compact backtracking bytecode VM with the
optimizations that the no-JIT modes of Irregexp (V8), YARR (JSC), and QuickJS
lre rely on. RegExp built-ins allocate only what the caller can observe.

## Current gap

`quench-regexp` validates and matches patterns, but none of these mechanisms is
tracked. RegExp is one of the eight V8-v7 fixtures, and v2 never reached it
(v2 tasks 109, 110 were proposed).

## Dependencies

See this task's `depends_on` in [index.json](index.json). Task 45 moves the
engine into its shared crate. Task 75 compiles literals at load time. This
task makes the compiled program fast.

## Scope and implementation sequence

1. Compile patterns to a register/backtrack bytecode with a peephole pass:
   merge adjacent literal characters into string checks, turn simple greedy
   loops over a single class into counted loops without backtrack records,
   and remove redundant position checks.
2. Scan before matching: for a required literal prefix, use a SIMD byte search;
   for longer literals, use Boyer–Moore–Horspool; for alternations, use quick-check masks
   over the first characters (Irregexp).
3. Represent character classes as Latin-1 bitmaps plus sorted UTF-16 ranges,
   and case-insensitive matching as precomputed canonicalization tables.
4. Reuse one backtrack stack and one capture buffer per agent. A match
   allocates only the result array and the capture strings the caller
   observes, and captures are slices (task 79).
5. Materialize the legacy `RegExp.$1`-style static properties and match
   indices lazily.
6. Add a bounded result cache for `split` and global `replace` with a string
   replacement, keyed by the identity of the subject string and of the
   RegExp, and valid only while the RegExp and `lastIndex` are unmodified
   (V8's RegExp results cache). The cache holds its own copy of the result,
   and each hit returns a fresh array.
7. Fast paths for `replace`, `split`, and `indexOf` with string (non-RegExp)
   patterns, accelerated with the full algorithm as the reference definition.

## Verification

The full Test262 RegExp inventory, `annexB` RegExp features, and the
`Symbol.match`/`replace`/`split` protocol tests, including subclass and
`exec` overrides that must bypass every fast path. Each accelerated path
agrees with the reference matcher on generated inputs (task 47's reference
definition).

## Definition of done

- Every fast path is a kernel acceleration with the backtracking matcher or
  the spec algorithm as its reference definition.
- Observable behavior (`lastIndex`, result identity, protocol calls) is
  unchanged.
- The result cache is bounded, is keyed only by object identity and
  unmodified state, and never returns a shared mutable object.

## Performance evidence

Report the time split between matcher and built-ins on the RegExp fixture, the
share of scan hits, allocations per match, and the paired gate.
