# 083: Partition host state by ownership and lifetime

## Outcome

Make host resource ownership explicit without changing realm identities.

## Current gap

`host.rs::HostState` combines loader, builtin caches, bindings, decoders, abort graphs and process resources.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering live there.

## Scope and implementation sequence

1. Map fields by lifetime and owning subsystem, including roots and asynchronous resources.

2. Move related fields and initialization into cohesive records; use keyed builtin storage only where identity/lifetime rules match.

3. Update borrows, root traversal and disposal together; delete duplicate cache facts.

## Verification

`cargo test -p quench-node`; `cargo run -p quench-node-test --bin run-compat`; Node-oracle module identity, event ordering, process-resource and abort/disposal tests.

Apply the shared [completion checks](README.md), including named baseline failures
and independent semantic controls. Record commands and artifact identity.

## Definition of done

- Every moved resource has one owner and tested creation/reentry/disposal behavior.
- Per-realm builtin/module identity is unchanged and resources survive while live, then release correctly.
- No additional wrapper or keyed lookup is retained without semantic or measured justification.

## Performance evidence

Ownership milestone; compare retained/released RSS and startup when storage changes.
