# 083: Partition `HostState` by ownership domain

`HostState` mixes event-loop/module state, CJS loading, builtin caches,
bindings, string decoder state, abort graphs, identity roots, and child-process
resources. Group related facts without merging values with different lifetimes.

## Plan

- Define cohesive records such as `LoaderState`, `BuiltinModules`, `Bindings`,
  `StringDecoderState`, `AbortGraph`, and `ChildProcessState`.
- Move fields and initialization together; preserve realm identity and cache
  ownership explicitly.
- Replace repeated optional builtin fields with a typed keyed cache where the
  lifetimes and canonical-identity rules permit it.
- Update borrow boundaries and run host/oracle tests after each group.

## Acceptance

Ownership and mutation paths are easier to audit, canonical identities remain
stable per realm, and Node behavior, GC, and event-loop tests are unchanged.
