# 63: Capture stack traces from residual source positions

## Outcome

Errors carry V8-compatible stack traces derived from one source-position
authority in the residual program. `Error.prototype.stack`,
`Error.captureStackTrace`, `Error.stackTraceLimit`, and
`Error.prepareStackTrace` behave as in the local Node oracle, and uncaught
errors report file, line, and column.

## Current gap

- The next core's `stack` getter returns the error's string form, with no
  frames (`crates/quench-runtime-next/src/vm/error.rs`, `error_stack_getter`).
- Task 05's residual contract has no table that maps instruction positions
  back to source, so no frame can name a line or column.
- Legacy Quench implements `Error.captureStackTrace` and the related V8
  extensions (`crates/quench-runtime/src/builtin_meta/error.rs`), and
  `quench-node` depends on them. Tracked node-compat fixtures read `.stack`
  and call `captureStackTrace`, and Node's uncaught-error output needs the
  same location data.
- Test262 does not observe stack traces, so no current ratchet catches the gap.
  Without this task it would first appear late, as task 22 failures.

## Dependencies

See this task's `depends_on` in [index.json](index.json). Task 21 depends on
this task because Node's error printing and bootstrap need it. The frame walk
uses the activation model that exists today, and it adopts task 09's frame and
continuation representation when that lands.

## Scope and implementation sequence

1. Extend the residual contract (task 05) with a compact, versioned position
   side table from instruction ranges to source spans, emitted by the OXC
   specializer (task 10) and by dynamic compilation (task 18). Change the
   residual format fingerprint. Keep positions out of the eight-byte
   instruction and off the dispatch path.
2. Define one frame-walk operation over activations, including suspended
   generator and async frames, native builtin frames, and Wasm frames (task 37).
   Stack capture, `captureStackTrace`, and host diagnostics all use it.
3. Capture frames lazily. Record the minimal frame data when the error is
   created, bounded by `Error.stackTraceLimit`, and format the string on first
   read. Formatting follows V8's layout: function name, `new`, method receiver,
   `async` frames, `eval` origins, and file:line:column.
4. Implement `Error.captureStackTrace(object, constructorOpt)`,
   `Error.stackTraceLimit`, and the `Error.prepareStackTrace(error,
   callSites)` hook with CallSite objects, matching Node's descriptors and
   property order.
5. Expose source location of a thrown value through the host facade (task 43),
   so `quench-node` can print uncaught errors with the source line and caret.

## Verification

Compare stack strings, CallSite results, descriptors, and uncaught-error output
with the local Node oracle for plain calls, constructors, methods, getters,
`eval`, `Function`, modules, generators, async functions, and Wasm frames.
Rust regression tests cover the position table round trip and frame
truncation. Test262 must not regress.

## Definition of done

- One position table in the residual owns every source location.
- One frame walk serves stack capture, `captureStackTrace`, and host
  diagnostics.
- The tracked node-compat fixtures that read `.stack` match the Node oracle.
- Error creation does not format strings or allocate a frame record beyond
  `Error.stackTraceLimit`.
