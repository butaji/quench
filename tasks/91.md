# 91: Win ten popular npm package workloads against Node and Bun

## Outcome

Using `quench-node` as Quench's runner, qualify representative hot workloads
from React/react-dom, Next, Vite, esbuild, sharp, Fastify, undici, ws, Pino and
Zod against Node and Bun, each with JIT enabled and disabled. Quench remains an
interpreter; this task does not add a JIT to Quench.

Work one package at a time. Finish the no-JIT comparison for one package before
moving to the next; after that pass, repeat the package sequence with JIT
enabled on Node and Bun. Quench remains interpreter-only in both phases.

Winning means Quench is fastest (highest median throughput, or lowest median
elapsed time for build workloads) and uses the least memory (lowest median
maximum RSS) against both Node and Bun in the current phase. Paired intervals
must exclude ties.

## Workloads

Pin package versions, lockfile, fixtures and operation counts before the first
baseline. Use these representative entry points, refining each only when a
package's public hot path requires it:

| Package | Workload |
| --- | --- |
| React + react-dom | Repeated server rendering of a fixed component tree |
| Next | Production build and repeated request to a fixed route |
| Vite | Repeated module transform and production build |
| esbuild | Transform and bundle a fixed application corpus |
| sharp | Resize and encode fixed image inputs |
| Fastify | Repeated JSON route requests with schema serialization |
| undici | Pooled service-to-service requests against a fixed local server |
| ws | Fixed-count WebSocket echo messages |
| Pino | Fixed-count structured JSON records to a discard transport |
| Zod | Repeated parse and safeParse of representative valid and invalid data |

Use the same workload program with `target/production/quench-node`, Node, and
Bun. Node modes are default JIT and `--jitless`; Bun modes are default JIT and
`BUN_JSC_useJIT=0`. Record and validate the effective mode before timing. Where
a package depends on a host capability Quench does not yet implement, retain
the exact failure as a compatibility blocker and close it through the owning
Stage A/API task before measuring that workload.

## Verification and definition of done

- Every package has a pinned workload, input hash, operation count, output
  check, and runner command using `quench-node`.
- Each workload passes correctness checks on all five engine/mode rows before
  its performance samples are admitted.
- Collect at least 11 matched rounds on the target Apple M4/macOS host. Record
  source, binaries, versions, commands, JIT evidence, elapsed time or
  throughput, and maximum RSS. Use paired 95% intervals; reject incomplete or
  mismatched rows.
- Quench beats Node and Bun in both JIT modes on every workload for the
  workload's primary metric and maximum RSS. Report package results separately;
  no aggregate can conceal a loss.
- Keep benchmark selection and results out of production behavior.
