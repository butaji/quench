# 030: Cross-tier generic inline cache (λi/λe) shared by baseline and optimizing JIT

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 029

## Context

The paper reuses one generic IC implementation — split into an idempotent
probe (λi) and an effectful apply (λe) — across the interpreter, baseline JIT,
and optimizing JIT (§5.2). Quench's existing `QuickeningSite::observe`
already implements exactly this split (documented in
`docs/copy-and-patch-jit.md`), but only for the interpreter/stencil path. This
task generalizes that IC body so the optimizing JIT (031) consumes the same
cache state and observation/apply functions instead of inventing a second IC
implementation — mirroring the paper's single-source-of-truth principle this
project already follows for bytecode semantics.

## Scope
- crates/quench-runtime/src/quickening.rs
- crates/quench-runtime/src/stencil_patch.rs

## Deliverables
- Extract the λi/λe interface from `QuickeningSite` into a form callable from
  optimizing-JIT-generated code (029/031's frame boundary), without changing
  interpreter/baseline-tier behavior
- One IC state representation read by all three tiers; no per-tier duplicate
  cache

## Acceptance
- Existing interpreter/baseline-tier IC tests pass unchanged
- Neutral corpus geomean does not regress
- A future optimizing-JIT-emitted IC probe/apply call reuses this interface
  verified by a direct unit test, even ahead of 031 existing

## Non-goals
- The optimizing JIT tier itself (031)
