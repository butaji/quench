## Outcome

`cargo test -p quench-runtime-next --lib` passes. Each failure is fixed in the
runtime, or the test is changed because its expectation described an old
representation. No test is ignored, deleted to go green, or weakened.

## Dependencies

See `depends_on` in [index.json](index.json). The Owner column names the task
whose contract each test checks. It does not add a dependency.

## Scope and implementation sequence

1. Classify each failure. Either it is a semantic defect (compare with the local
   Node oracle or the spec), or its expectation describes a superseded
   representation (compare with the task that changed that representation).
2. Fix defects in the runtime. Update stale expectations so they check the
   current authority, and state the changed fact in the commit message.
3. From then on, a runtime change keeps the unit suite green, together with
   the Test262 ratchet (task 48).

## Verification

- `cargo test --profile iteration -p quench-runtime-next --lib` runs 119 or
  more tests and reports 0 failed and 0 ignored.
- The ordered Test262 prefix recorded in task 20 does not regress.

## Definition of done

- The runtime unit suite is green and has no `#[ignore]`.
- Every changed expectation traces to a named representation change or an
  oracle check.
