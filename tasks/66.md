# 66: Fuzz the front end and VM against differential oracles

## Plan scope

Deferred outside the active two-stage plan. This specification is a retained
proposal, not a prerequisite for Stage A or Stage B. Its mechanism may be
revisited only for a concrete correctness need or a measured performance gap.
The former restructuring-stage and mandatory-gate requirements are superseded by
[index.json](index.json) and [README.md](README.md).

## Outcome

Continuous, reproducible fuzzing of JavaScript and Wasm input through the full
pipeline: parsing, specialization, residual verification, and execution. It
checks crashes, verifier and invariant failures, and differential mismatches
between specialized and generic execution and against the local Node oracle.

## Current gap

Task 05 fuzzes only residual decoding. The interpreter relies on unsafe heap,
register, and cache edges (task 07 records one inherited root UB), and the
specializer's exact-fallback rule is checked only by task 42's gate over
existing suites. No generator explores programs outside the conformance
inventories.

## Dependencies

See this task's `depends_on` in [index.json](index.json). This deferred campaign
is non-blocking; task 24 checks required safety invariants directly.

## Scope and implementation sequence

1. Add `cargo fuzz` targets for OXC-to-residual compilation, residual execution
   under forced GC at every safepoint, and Wasm decode-validate-run through the
   shared VM.
2. Add a grammar-aware JavaScript generator. It emits programs over the
   constructs the conformance suites cover: getters and proxies that re-enter,
   shape transitions, holes, exceptions in iteration, generators, and async
   code.
3. Add differential oracles: task 42's disable-specialization mode against the
   production configuration, and the local Node oracle for deterministic
   programs. Normalize only the documented nondeterminism.
4. Minimize every failure into a Rust regression test that is committed with its
   fix. Store corpora and crash artifacts under ignored `target/` paths with
   provenance.

## Verification

Show that each target finds a deliberately planted defect: a skipped root, a
wrong cache hit, and a verifier hole. Record campaign duration, executions, and
coverage for the selected future build. This deferred campaign never blocks task
24 or task 27.

## Definition of done

- Fuzz targets exist for compile, execute, and Wasm, and each runs under
  sanitizers where supported.
- Differential mismatches between specialized and generic execution fail the
  campaign.
- A campaign of recorded length on the selected build finds no open failure; it
  is non-blocking for the active two-stage plan.

## Performance evidence

None. Campaign throughput is tooling, not engine performance.
