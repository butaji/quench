# 18: Port modules, dynamic compilation, and realm semantics

## Outcome

Complete scripts, modules, eval, dynamic import, and multiple-realm execution on the next engine.

## Current gap

V2 specializes one script as a closed program; Quench requires module graphs, live bindings, cycles, namespaces, dynamic compilation, and realm-specific intrinsics.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Port parse/link/instantiate/evaluate state machines, live binding cells, namespace exotics, reexports, cycles, dynamic import, import attributes, top-level await, eval goals, Function constructors, and ShadowRealm. Compile dynamic sources in-process through the same Engine and verifier.

## Verification

Run module/eval/ShadowRealm Test262 families and graph controls for cycles, ambiguous exports, failures, repeated imports, namespace ordering, top-level await, realm isolation, and GC retention.

## Definition of done

- Script, Module, and Eval share the compiler and semantic authorities.
- Module lifecycle and binding state are explicit and idempotent.
- Dynamic compilation never enters the legacy reducer.

## Performance evidence

Report module compile/cache time, graph metadata, and retained heap cost.
