## Implementation evidence

The next VM now owns Promise state in a traced runtime-side table keyed by the
ordinary Promise object. `new Promise`, `Promise.resolve`, `Promise.reject`,
`then`, and `catch` settle exactly once and enqueue reaction jobs through the
same rooted `PendingJob` queue used by finalizers and host re-entry. Reaction
handlers resolve or reject the next Promise through the same authority, and
`Promise.resolve` preserves identity for an existing Promise. A focused API
regression covers identity, ordered chaining, rejection handling, and queue
drain. Resolution now performs thenable assimilation through an explicit
rooted thenable job and rejects self-resolution before settlement; a second
regression covers both paths. `Promise.prototype.finally` now has its
own queued cleanup reaction, preserving the original settlement unless cleanup
throws; ordering and propagation are covered by a focused API regression.
`Promise.all` and `Promise.race` now use explicit aggregate records and rooted
aggregate callbacks, preserving input order for `all` and first-settlement
order for `race`; the aggregate regression covers fulfillment and rejection.
`finally` cleanup now assimilates a returned Promise through separate rooted
continuation callbacks, so the downstream promise waits for cleanup and
rejects with a cleanup failure; the adoption regression covers both outcomes.
`Promise.allSettled` now records indexed fulfillment/rejection objects and
settles only after every input callback; its regression verifies ordered
`{status, value|reason}` results. `Promise.any` now
short-circuits on fulfillment and produces an AggregateError-shaped object
with indexed `errors` after all rejections; its regression covers both paths.
All four combinators now consume the shared iterator protocol, including Set
and String fallback iterators, with rooted iterator/result values across guest
calls; the iterable regression covers Set aggregation and String race.
Iterator abrupt-completion parity and constructor/species edge cases remain
pending. Async functions now carry explicit residual-function metadata, and
their first `await` lowers to a shared continuation resumed by rooted Promise
jobs. Fulfilled and rejected resumes preserve register state, re-enter catch
handlers, and can suspend again; focused regressions cover immediate values,
pending Promises, ordering, catch, and propagation. Disposal now has explicit
LIFO entries and normal synchronous cleanup, while async cleanup is represented
as a Promise aggregate owned by the same Promise runtime.
Synchronous generator functions now
materialize iterator records backed by the same continuation authority;
`yield`, sent values, completion, and repeated post-completion `next()` calls
are covered by a focused regression.
Iterator self-return is installed on the shared iterator prototype, so generator
objects participate in `for...of` through the same iterator protocol.
Async `for await...of` over synchronous iterables now lowers each `next()` result
through the same `Await` producer; ordering and accumulation are covered by a
focused regression. `GetAsyncIterator` now prefers `Symbol.asyncIterator` and
wraps synchronous iterators in a shared Promise-producing adapter, with focused
coverage for both custom async iterators and array fallback. Async generator
objects now use the same iterator record and continuation authority; yielded
values, awaited yields, completion, and `for await...of` consumption are covered
by a focused regression. Async-generator `return`/`throw` requests and disposal
now transition the shared generator record and settle/reject the corresponding
Promise; synchronous and asynchronous control requests are covered by a focused
regression. Synchronous `throw()` now re-enters suspended catch handlers through
the same frame error boundary. `return`/`throw` through suspended `finally`
blocks remain pending. `DisposableStack` now owns explicit LIFO entries through
the ordinary object/property graph, supports `use`, `adopt`, `defer`, idempotent
`dispose`, and `Symbol.dispose`, with focused ordering and closed-state coverage.
Synchronous `using` declarations now lower to that stack and dispose on normal
block exit, with focused coverage. `await using` now prefers
`Symbol.asyncDispose`, falls back to `Symbol.dispose`, invokes callbacks in LIFO
order, and awaits their returned values before async-function completion, with
focused Promise-returning coverage. Sequential async error suppression,
abrupt cleanup, and disposal through suspended `finally` blocks remain pending.
