# 17: Port promises, generators, async execution, and disposal

## Outcome

Implement all suspended and asynchronous ECMAScript execution through the shared activation/job state machines.

## Current gap

The reference interpreter has no promises, generators, async functions, async iterators, or explicit resource management.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Port generator yield/resume/throw/return, Promise construction/resolution/reactions/combinators, async functions/generators/iterators, topological job ordering, unhandled rejection tracking, `using`/`await using`, and DisposableStack variants. Root suspended state through task 09's continuation authority.

## Verification

Run Promise, Generator, AsyncFunction, AsyncGenerator, iterator, and disposal Test262 families plus thenable re-entry, self-resolution, finally ordering, abrupt cleanup, nested suspension, GC, and interruption tests.

## Definition of done

- There is one suspended-frame representation.
- Every job and resource-disposal transition is explicit and exactly once.
- Host event loops observe canonical microtask and rejection ordering.

## Performance evidence

Report suspended-state/job allocations and async host overhead.

## Implementation evidence

The next VM now owns Promise state in a traced runtime-side table keyed by the
ordinary Promise object. `new Promise`, `Promise.resolve`, `Promise.reject`,
`then`, and `catch` settle exactly once and enqueue reaction jobs through the
same rooted `PendingJob` queue used by finalizers and host re-entry. Reaction
handlers resolve or reject the next Promise through the same authority, and
`Promise.resolve` preserves identity for an existing Promise. A focused API
regression covers identity, ordered chaining, rejection handling, and queue
drain. Resolution now performs thenable assimilation through an explicit
rooted thenable job and rejects self-resolution before settlement; a second
regression covers both paths. Generators, async functions, combinators, and
disposal remain pending on this task. `Promise.prototype.finally` now has its
own queued cleanup reaction, preserving the original settlement unless cleanup
throws; ordering and propagation are covered by a focused API regression.
