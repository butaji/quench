# 36: Move object integrity state onto the object cell

## Outcome

Store per-object extensibility and frozen-integrity state as fields on the
heap-resident `Object` cell instead of in VM-global `Value`-keyed side tables,
so the state is freed automatically with the object rather than swept by hand
on every collection.

## Current gap

`Vm` holds `non_extensible: FxHashSet<Value>` and `frozen: FxHashSet<Value>`
alongside `Object { proto, properties }`, where `properties.auxiliary()`
already stores the shape id inline on the object itself. Extensibility and
frozen-ness are the same kind of per-object fact as shape but were not given
the same treatment. Because they live in side tables keyed by object identity,
`gc.rs::collect_slow` must run a `retain(|k| self.heap.get(k).is_some())`
sweep over each of them after every collection purely to prevent stale
entries for dead objects — bookkeeping that exists only because the fact is
not co-located with the object it describes.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Add integrity state directly to `Object` (e.g. an `extensible: bool` field,
   or a packed flags byte alongside `proto`/`properties` if a bare bool proves
   too wide relative to existing layout), making the object cell the single
   authoritative representation of both shape and integrity state.
2. Update every read site (`object_is_extensible`, `object_set_integrity`,
   `object_is_integrity_level`, `check_property_write`, property-add paths)
   to read the new field on `Object` instead of querying `non_extensible`/
   `frozen`.
3. Remove `non_extensible` and `frozen` from `Vm` along with their two
   `retain` sweeps in `collect_slow`; verify no other consumer depends on
   enumerating all non-extensible/frozen objects independent of visiting
   objects directly.
4. Leave `descriptors: FxHashMap<(Value, Atom), PropertyAttributes>` as-is for
   this task: per-property attributes are a genuinely different fact than
   per-object integrity (two objects can share a shape while differing in
   attributes), and folding it into the shape table is a shape-forking design
   decision, not a mechanical field move. Note it in follow-up rather than
   attempting it here.

## Verification

Differential tests against Node/Test262 for `Object.preventExtensions`,
`Object.seal`/`isSealed`, `Object.freeze`/`isFrozen`, extensibility checks
across GC cycles (allocate, freeze, force collection, verify state survives),
and dead-object cases (freeze an object, drop all references, force
collection, confirm no leaked state and no panic).

## Definition of done

- `non_extensible` and `frozen` no longer exist as separate `Vm` fields; their
  two `retain` sweeps are removed from `collect_slow`.
- Integrity state survives GC correctly by construction (freed with the cell),
  verified by a GC-cycle test rather than asserted.
- `descriptors` is explicitly left out of scope with the reasoning recorded
  above, not silently dropped.

## Performance evidence

Report `collect_slow` time delta and `Vm` struct size delta; no speed claim is
required for this functional change.

## Implementation evidence

Object integrity is now packed into the existing `ValueVec` metadata owned by
each heap object: the shape id remains derived from the auxiliary word, while
the vector start word carries non-extensible and frozen flags. `Object` exposes
the single integrity authority, so arrays, ordinary objects, prototype guards,
and Reflect all read the same state. The VM-wide identity sets and their GC
sweeps are removed. The compact object header remains 16 bytes, and a GC test
keeps frozen state alive through collection while unreachable allocations are
reclaimed.
