# 050: Fix console.log crash when detached from `this` (P0 Node-compat bug)

- **Theme:** vm_completeness
- **Executor:** codex
- **Depends on:** none
- **Priority: P0, ahead of everything else in this theme.** Blocks running
  the v8-v7 benchmark suite at all.

## Context

Found while trying to run `quench-bench/js-engine-benchmark/v8-v7`'s bundled
harness: `var print = console.log; ...; print(x)` crashes with
`TypeError: Cannot read property '_stdout' of null or undefined`.
`crates/quench-node/src/modules/console.rs`'s `log` implementation reads
`this._stdout`, which is `undefined` once `console.log` is called unbound
from its receiver — a common, valid JS idiom (`const log = console.log`),
and real Node's console does not have this fragility.

## Scope
- crates/quench-node/src/modules/console.rs
- crates/quench-node/src/polyfills/bootstrap/console.rs
- crates/quench-node/src/polyfills/bootstrap/globals.rs

## Deliverables
- Console methods must not depend on `this` binding for their target stream
  — capture/bind the stream at console-object construction time (matching
  how Node's real console methods behave when detached), not read via
  `this` at call time
- Audit every console method (`log`, `error`, `warn`, `info`, `debug`,
  `trace`, `table`, `group`/`groupEnd`, etc.) for the same class of bug, not
  just `log`

## Validation

1. `var print = console.log; print("x")` (and the same for every other
   console method) must not throw and must produce the same output as
   `console.log("x")`
2. `node quench-bench/js-engine-benchmark/v8-v7`'s bundled `run.js` (or
   equivalent) no longer crashes on this error
3. `cargo test -p quench-runtime --lib` / existing quench-node test suite —
   no regressions
4. Existing test262/Node-oracle console-related tests still pass

**Fail condition**: any console method still reading a receiver-dependent
field at call time is incomplete — fix the whole family, not just `log`.
