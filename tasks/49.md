# 49: Restore static binding times on the call and local paths

## Plan scope

Deferred outside the active two-stage plan. This specification is a retained
proposal, not a prerequisite for Stage A or Stage B. Its mechanism may be
revisited only for a concrete correctness need or a measured performance gap.
The former restructuring-stage and mandatory-gate requirements are superseded
by [index.json](index.json) and [README.md](README.md).

## Outcome

Call/activation facts that the current VM still rediscovers through
engine-internal names are encoded once in residual metadata, with explicit
dynamic fallbacks. Ordinary lexical accesses that already use `LoadLocal` and
capture slots are outside this task.

## Current gap

The next core encodes some activation facts as `\0quench:` atom names and
rediscovers them during execution. Pinned v2 uses a direct frame load for
ordinary `this`, but does not implement Quench's arrow, derived-constructor,
or `new.target` cases; it is a representation precedent, not equivalent
coverage for these paths:

| Path                                                            | Runtime work                                                                        | Static fact it rediscovers                                    |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `call_user_frame`, `prepare_user_tail` (`vm/dispatch_frame.rs`) | scans every local name with `contains("\0quench:self-binding:")`                       | which slot, if any, is the named-function self-binding        |
| same                                                            | compares the function name with `"\0quench:arrow"`                                     | the function is an arrow                                      |
| `initialize_activation_bindings` (`vm/dispatch_frame.rs`)      | interns up to two reserved names and probes the atom table                           | atoms for new.target and lexical-this                          |
| same                                                            | pushes up to two `(Atom, Value)` entries into pooled `dynamic_bindings`               | per-activation new.target and lexical `this` state             |
| same                                                            | `captured_with_objects` walks the whole environment chain and allocates two `Vec`s  | whether any enclosing scope is a `with` scope                 |
| same, arrows                                                    | `captured_lexical_this` walks the chain comparing names with `"\0quench:lexical-this"` | the depth of the environment that owns lexical `this`         |
| same                                                            | `function_values[&(program, id)]` hash lookup plus a reverse scan                   | the closure value for the self-binding                        |
| `Op::StoreLocal` (`vm/dispatch.rs`)                             | substring search of the local's name on every store                                 | the slot is the self-binding                                  |
| `Op::StoreLocal` in function 0                                  | `global_immutable_atoms.contains` on every store                                    | the slot is an immutable global lexical binding               |
| `LoadThis` and `FieldBase::This` (`vm/object.rs`, `vm/dispatch.rs`) | hashes/probes lexical-this, checks active bindings, writes `Frame.this` back | whether `this` is an ordinary frame value or needs lexical resolution |

The atom lookup was made allocation-free on a hit by task 61's
[measured atom-table change](evidence/task61-allocation-free-atom-lookup-2026-10-08.json):
`intern_atom` hashes and compares UTF-16 units before constructing a string on
a miss. Reserved-name calls still repeat that hash and table probe. The
activation vector is pooled: frame recycling clears its entries while
retaining capacity up to 256, so the pushes do not establish a steady-state
allocation on every call (`vm/dispatch_frame.rs`). Ordinary calls find their
own lexical-this entry immediately; they do not scan static bindings or walk
outer environments on that path (`vm/environment.rs`). The outer lookup is
relevant to arrows and eval roots that inherit a binding.

These remaining lookups violate the binding-time table in
[README.md](README.md): static facts should be decided once in the generating
extension and encoded in residual or activation metadata. The V2 frame-local
`LoadThis` path is a design precedent, not measured evidence for removing
Quench's hidden bindings. Task 68 owns the census needed to establish how much
of a Stage B fixture's work reaches each path. `with` affects identifier
resolution, not the `this` keyword, so with-scope handling remains a separate
name-resolution fact rather than a reason to make `ThisMode` dynamic.

This is not a blanket port of v2's static lexical addressing: Quench already
lowers ordinary lexical reads and writes to local/capture slots. Keep this
proposal deferred until a Stage B census shows that the remaining activation
work is a measured gap; preserve dynamic resolution for `with` and direct eval.

## Dependencies

See this task's `depends_on` in [index.json](index.json). This is a deferred restructuring proposal: encoding a static fact once in the residual is the README's
binding-time and one-authority rule, not tuning. Speed gains are recorded as
evidence, not claimed as a gate. Task 44 owns moving
`function_values` onto the function cell or a realm table. This task removes
the per-call lookup and consumes whichever home task 44 chooses.

## Scope and implementation sequence

1. Add compiled per-function facts to the residual function record: arrow,
   derived constructor, self-binding slot, uses new.target, uses lexical
   `this`, uses super-called state, and "may observe an enclosing `with`" for
   identifier lookup.
   Derive them in the existing compiler passes (`compile/binding_time.rs`,
   capture and scope analysis), not with a new name matcher.
2. Add per-slot facts (self-binding, immutable global lexical, TDZ-possible)
   as a compact slot-kind vector or bitset on the function record. Local
   operations dispatch on that data.
3. Give new.target, lexical `this`, and super-called state fixed activation
   slots (frame fields or compiler-assigned locals), captured through the
   ordinary environment when a closure needs them. Remove the per-call
   `dynamic_bindings` pushes. `dynamic_bindings` remains only for real dynamic
   scope (sloppy direct eval, `with`).
4. Resolve lexical `this` for arrows by compiler-known environment depth and
   slot rather than a name search.
5. Keep the `with`-object stack as explicit environment state that exists
   only when some enclosing scope is a `with` scope. Calls whose closure chain
   has no `with` do no chain walk and no allocation.
6. Intern every engine-internal atom once per atom-table lifetime and retain
   the IDs with VM state. `initialize_shared` rebuilds the program atom prefix
   on each execution, so seed cached IDs after that reset, before guest or
   dynamic compilation can observe the prefix. No hot path calls `intern_atom`
   or `lookup_atom` with a constant string.
7. Extend residual validation to check the new function and slot facts
   (task 05's contract).

## Verification

Run affected Test262 stages plus compare-runs. The existing function-name, arrow `this`,
`new.target`, derived-class `super()`, `with`, TDZ, and named
function-expression cohorts cover the changed behavior. Full-suite runs belong
at gates and stage transitions. Keep units only for internal invariants or
uncovered scenarios; do not alter the harness. Review by inspection that no `atom_name(...) ==` or
`.contains("\0quench:` comparison remains on a call, local, or cache path.

## Definition of done

- A user call with no `arguments`, rest, or closure allocates nothing beyond
  pooled frame storage.
- Call entry and local load/store read only residual data, frame state, and
  pre-interned atoms.
- No engine-internal semantic fact is represented as an atom name.

## Performance evidence

Measurement only; do not tune beyond restoring v2's static encoding. The
2026-09-23 review (`target/reviews/core-review-2026-09-23/`) measured Richards
at 45–49 on the base.js harness, against pinned v2 ≈1,930 on its bundled
fixture, with 7.6 MB maximum RSS against 2.1 MB. The profile's top frames are
`set_shape_property`, malloc/realloc/free, `atom_hash`/`lookup_atom`/
`intern_js_atom`, `property_accessor`, and `call_user_frame`. Report
per-call allocations and the same fixtures after the change.
