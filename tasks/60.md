# 60: Model the core as categories and check the laws

## Outcome

The design of the single core is written down as a small set of categories,
functors, and natural transformations. Each Futamura/Ershov rule becomes a law
that is derived from the watermark tables and checked by tests. The model says
precisely why one VM can serve JavaScript and Wasm, and what a kernel change
must preserve.

## Current gap

Tasks 46, 47 and 59 state the staging rules in prose: one definition for both
binding times, congruence from effect classes, accelerated primitives equal to
their reference definitions, and the Futamura equation. No single model ties
these rules together, and so nothing checks that they compose. The JS and Wasm
front ends share a residual vocabulary (task 37), but nothing states that
lowering is compositional for both.

See this task's `depends_on` in [index.json](index.json). This is phase B. It

## The model

| Structure | Objects | Morphisms | Authority |
| --------- | ------- | --------- | --------- |
| Representation category `Rep` | value representations: JS language types, the Wasm value types `i32`, `i64`, `f32`, `f64`, `v128`, and references | conversion rows in the kernel primitive table (`ToNumber`, `ToInt32`, `i32.wrap_i64`, boxing, …) | primitive table |
| Residual category `Res` | typed register interfaces of residual fragments | residual fragments, composed by sequencing and structured control | `opcodes!` table |
| Front ends | `Js` (OXC AST fragments), `Wasm` (validated function bodies) | functors `F_js : Js → Res` and `F_wasm : Wasm → Res` | the two lowerings |
| Semantics | `Res` | `⟦−⟧ : Res → Kl(T)`, where `T` is the effect monad graded by task 46's effect classes (`pure`, `allocates`, `throws`, `reenters`) | effect columns |
| Specialization | — | natural transformation `σ : ⟦−⟧ ∘ mix ⇒ ⟦interpreter⟧` | generating extension (task 47) |
| Kernel/library | fundamental primitives (task 59) | the category they generate; accelerated primitives are parallel morphisms equal to their reference composites | primitive-table roles |

Reading the model:

- **One VM.** Both front ends are functors into the same `Res`, and `⟦−⟧` is
  defined once on `Res`. A second Wasm interpreter would be a second semantics
  functor. The model forbids that, and task 24's single-VM check enforces it.
- **Ershov.** A static fold evaluates a morphism of `Rep` or of the library
  category on static objects. It is the same morphism the dynamic path runs,
  not a copy.
- **Congruence.** Grades compose: a fragment's grade is the join of its parts.
  A static heap fact survives a composite only if no part is graded `reenters`
  or `throws`.
- **Futamura.** The naturality square of `σ` is
  `⟦residual(p)⟧(d) = ⟦interpreter⟧(p, d)`, and task 47 checks it with the
  reference kernel.

## Scope and implementation sequence

1. Write `docs/design/categories.md`, one page, with the table above tied to
   the concrete Rust tables and types that own each object and morphism.
2. Derive the law checks by macro from the existing tables, with no second
   authority:
   - `Rep`: identity and associativity for every declared conversion
     composite, and every folding rule in `compile/binding_time.rs` names the
     `Rep` morphism it evaluates.
   - Functoriality: `F(a ; b) = F(a) ; F(b)` for sequencing and structured
     control, as property tests over generated JS and Wasm fragments. Compare
     semantics, not bytes.
   - Grades: each opcode row's effect class equals the join of the effect
     classes of the primitives its generic path calls.
   - Accelerations: every accelerated primitive agrees with its reference
     composite on generated inputs (shared with task 59's audit).
3. Record every law violation as a finding against the owning table row, and
   fix it there.

The model is a specification and a test generator. It adds no runtime category
framework, trait hierarchy, or abstraction to ordinary Rust code (see
[AGENTS.md](../AGENTS.md)).

## Verification

- Law tests run in the ordinary unit suite, in both specialized and
  unspecialized execution (task 42's gate).
- The three-suite ratchet (task 48) shows no regressions.
- A negative control shows that each law catches a deliberately wrong table row.

## Definition of done

- `docs/design/categories.md` exists and names the authority for every object
  and morphism class.
- The identity/composition, functoriality, grade, and acceleration laws are
  derived from the tables and pass.
- No law has a hand-maintained list of cases that duplicates a table.
