# 23: Port Wasm and close the specification suite at 100 percent

## Outcome

Execute every directive in the pinned WebAssembly testsuite through the one
VM that also runs JavaScript. This is a Stage A critical-path task: 100% of the
pinned Wasm suite is part of the correctness gate (task 24).

## Current gap

The shared VM now executes scalar/control operations, multi-results, globals,
Memory32/Memory64 and custom pages, Table32/Table64 resources, segments, references, starts and Wasm-to-Wasm
imports through the same heap, call ABI and residual vocabulary as JavaScript.
Typed Rust host functions and standard spectest print functions now use ordinary
native callable cells, shared structural signature checks and rooted reference
leases. Host effects are real, recorded observations, not successful no-ops.

## Scope and implementation sequence

Execution lowering is task 37 (Wasm operators to the shared residual
bytecode, consuming validator-derived types). Do not port the
legacy `hir`/`wasm/emit` path onto the next engine: it is ~4k lines that task
37 would immediately replace. Keep `quench-wasm` ownership of binary/text
decoding and validation, then adapt instantiation, values/references, functions, tables, memories, globals, exceptions, SIMD, threads/atomics, GC/reference proposals, imports/exports, and host effects to new runtime handles and roots.

## Verification

During implementation, run affected pinned `.wast` scopes plus compare-runs
against matching directive inventories. Include relevant internal GC,
shared-memory, re-entry, growth, aliasing, and JS/Wasm boundary controls.
At the Stage A gates, discover the complete pinned inventory, including
proposals, and require correct parse/validation/runtime/trap classification
for every directive. Reuse unchanged qualifying gate reports.

## Definition of done

- Every discovered directive passes; there is no Quench skip list.
- Wasm and JavaScript share one heap, one `Value` representation, one root
  set, one `opcodes!` vocabulary, one dispatch loop, one activation stack, and
  one `Engine` entry (tasks 37, 40). There is no second interpreter, heap,
  or value model for Wasm.
- The qualified shared-VM path uses `quench-wasm` only for decoding,
  validation and wast scripting, with no legacy execution fallback.
  Task 27 switches production consumers and deletes the legacy dependency.
- Repeated runs have identical inventory and classification.
