# 35: Unify typed array cell representation by kind

## Outcome

Replace the nine structurally identical `Cell` variants for typed arrays with
one variant carrying a `TypedArrayKind` tag, and collapse the three
per-family install/construct files into one table-driven implementation.

## Current gap

`heap/cell.rs` declares `Uint8Array`, `Uint8ClampedArray`, `Uint16Array`,
`Uint32Array`, `Int8Array`, `Int16Array`, `Int32Array`, `Float32Array`, and
`Float64Array` as separate `Cell` variants, each with the identical field set
`{ object, buffer, offset, length, length_tracking }`. The shared-logic layer
(`typed_array_access.rs`) already dispatches on a `TypedArrayKind` enum for
`typed_array_get`/`typed_array_set`/`typed_array_length`/`typed_array_kind`/
`signed_bits`, so the unification already exists one layer up. The
representation and the installer layer (`typed_array_signed.rs`,
`typed_array_float.rs`, `typed_array_uint16.rs`) never adopted it: each file
has one generic `install_*_array`/`construct_*_array_native` helper wrapped by
2-3 thin per-type functions that only supply a kind constant.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Introduce a single `Cell::TypedArray { kind: TypedArrayKind, object: Object,
   buffer: Value, offset: usize, length: usize, length_tracking: bool }`
   variant replacing the nine existing ones, reusing the `TypedArrayKind`
   enum already defined for the access layer as the one authoritative kind
   representation.
2. Update every match on the nine variants (heap tracing/GC visitation,
   `typed_array_access.rs`, `data_view.rs`, `atomics.rs`, and any other
   consumer) to match `Cell::TypedArray { kind, .. }` and dispatch on `kind`
   where per-element behavior differs, reusing the existing kind-dispatch
   helpers rather than reintroducing per-variant branches.
3. Replace `typed_array_signed.rs`, `typed_array_float.rs`, and
   `typed_array_uint16.rs` with one table of `(name, TypedArrayKind,
   byte_width)` entries consumed by one generic `install_typed_array`/
   `construct_typed_array_native` pair, per the repository's macro-declared
   table convention (AGENTS.md: "Use Rust for implementation and Rust macros
   for code generation").
4. Preserve exact observable behavior per element kind (rounding/clamping on
   store, signed/unsigned read, byte width, `BYTES_PER_ELEMENT`, constructor
   name) — this is a representation change, not a semantic one.

## Verification

Differential tests against Node/Test262 for every typed array kind: construction
from length/buffer/iterable, element read/write clamping and rounding
(`Uint8ClampedArray`), `DataView` interop, `Atomics` operations, `length_tracking`
resizable-buffer behavior, and prototype/constructor identity per kind. Confirm
no behavioral difference before/after the variant collapse via a full oracle
run.

## Definition of done

- `Cell` has one typed-array variant; `TypedArrayKind` is the sole
  per-element-type authority.
- Installer/constructor logic exists once, parameterized by a data table, not
  duplicated per kind across three files.
- All existing typed array Test262/Node-oracle coverage passes unchanged.

## Performance evidence

Report binary size and match-arm count delta for typed-array-touching code
paths; this task has no required speed claim, only a representation-size and
maintainability claim, consistent with functional work not owning a
performance gate.

## Implementation evidence

The heap representation now has one `Cell::TypedArray` variant carrying the
existing `TypedArrayKind` authority; heap tracing, object access, JSON,
iterators, memory accounting, construction, and typed-array get/set/metadata
paths all dispatch through that tag. The focused runtime matrix remains green.
Constructor registration and construction now flow through one descriptor-
parameterized install/construct path; the family files retain only thin native
entry wrappers. Element conversion, byte width, clamping, signedness, and
floating-point encoding are all selected from `TypedArrayKind`.
