# 31: Derive arguments-object need statically

## Outcome

Skip generic argument coercion, `arguments`-object materialization, and
parameter padding at call sites whose callee identity and argument shape have
been stable, using the existing call-target cache as the stability signal.

## Current gap

`method_cache.rs` already tracks monomorphic `CallTarget`s per site, but nothing
observed uses that stability to specialize the argument-binding path itself.
Every call still pays full generic binding cost (arity checks, padding,
`arguments` object setup when potentially unused) regardless of how stable the
site has proven to be.

## Dependencies

See this task's `depends_on` in [index.json](index.json). Start only after
task 25's lab attributes a measured Score/RSS gap to the mechanism this task
adds; per the repository rules, a cache or specialization needs measured
benefit, and speculative specializers add fallback surface that every
semantics change must keep exact.

## Binding-time correction

Whether a callee needs an `arguments` object is static: it follows from
syntax (an `arguments` reference, direct `eval`, non-simple parameters,
sloppy-mode mapping). It belongs in residual function metadata from the one
scope analysis, not in call-site cache state observed at runtime. Arity match
is dynamic, but it is a single compare at frame entry and needs no cache. v2
already passes arguments directly from caller registers and recorded the
argument-copy opportunity as exhausted
([source distillation](../docs/v2/runtime-source-distillation.md), task 195).
The steps below that key specialization on observed callee/arity stability are
replaced by: emit the static `needs_arguments_object` fact, skip materialization
when it is false, and add call-site state only if the task 25 lab then shows a
remaining measured gap.

## Scope and implementation sequence (superseded where it conflicts above)

1. Extend the call-site cache entry (task 29's structure, or `method_cache.rs`
   directly) with argument-shape facts: observed argument count and whether
   `arguments` is referenced by the callee's body per the existing capture/
   lexical-address analysis from task 10.
2. When callee and argument count are both stable and the callee does not
   reference `arguments`, emit a specialized binding path that writes arguments
   straight into parameter slots without an intermediate arguments object.
3. Guard on both callee identity and argument count at entry; any mismatch falls
   back to exact generic binding, which remains the single spec-authoritative
   implementation.
4. Coordinate invalidation with the existing method-cache clear/retain paths so
   a callee-identity change invalidates the argument-binding specialization too.

## Definition of done

- Generic argument binding remains the exact fallback and single spec authority.
- Specialization only activates under the stated stability conditions, verified
  by tests that flip those conditions.
- No dependence on fixture identity or benchmark vocabulary.
