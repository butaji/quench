# 13: Port arrays, buffers, typed arrays, and Atomics

## Outcome

Implement indexed collections and shared memory with exact backing, species, detachment, and atomic semantics.

## Current gap

V2 arrays are dense/sparse ES5 containers; full Quench behavior includes holes, exotics, ArrayBuffer variants, DataView, typed arrays, resizable/growable backing, and Atomics.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Port Array construction/mutation/iteration/species, arguments arrays, ArrayBuffer/SharedArrayBuffer lifecycle, transfer/detach/resize, DataView, every typed-array constructor and method, numeric conversions, and Atomics including wait/notify/waitAsync. Use explicit external backing owners and generation stamps.

## Verification

Run all corresponding Test262 families plus overlap, detach-during-coercion, species re-entry, holes/inheritance, endianness, shared/non-shared rejection, worker visibility, and GC/backing lifetime tests.

## Definition of done

- Indexed properties obey object descriptors and array/typed-array invariants.
- Detached, resized, and shared backing transitions are validated at each effect boundary.
- The Atomics failure fixed in task 03 remains covered in the new runtime.

## Performance evidence

Report dense/sparse/backing bytes, transitions, and array workload Score/RSS.

## Implementation evidence

The next VM now exposes `Array.isArray` through the native builtin table and
checks the heap cell kind directly, distinguishing dense arrays from ordinary
objects and primitives. Array `slice` now preserves dense and sparse indexed
values for ordinary arrays and is used by array destructuring rest bindings.
Slice bounds use the shared numeric coercion path, including string and
fractional arguments with truncation toward zero.
`Array.prototype.includes` now uses the collection SameValueZero authority,
including `NaN` and `undefined` holes, with coerced `fromIndex` bounds.
`Array.prototype.join` now preserves separator positions for holes and
`undefined`/`null`, while routing other elements through canonical string
conversion. `Array.prototype.concat` now allocates a non-mutating dense result,
flattening array arguments one level and preserving scalar arguments in order.
`Array.prototype.flat` now materializes a non-mutating dense result with
numeric depth coercion and recursive array flattening.
`Array.prototype.reverse` now reverses indexed storage in place and returns the
same array identity. `Array.prototype.shift` and `unshift` now preserve order,
receiver identity, and updated lengths for dense arrays.
`Array.prototype.splice` now coerces start/delete counts, returns removed
elements, and updates the receiver in place for dense arrays.
`Array.prototype.fill` now coerces numeric bounds, writes through the indexed
array path, and returns the original array identity.
`Array.prototype.at` and `lastIndexOf` now support relative/coerced indexes,
sparse reads, and strict equality (including `NaN` exclusion for search).
`Array.prototype.indexOf` now shares the strict-equality authority with forward
bound coercion and sparse indexed reads.
`Array.prototype.copyWithin` snapshots overlapping source ranges before indexed
writes, and `Array.prototype.with` returns an immutable indexed replacement.
The callback methods `forEach`, `map`, `filter`, `some`, `every`, `find`, and
`findIndex` now invoke user functions through the VM call path and preserve
their result/short-circuit contracts for dense arrays.
`reduce` and `reduceRight` now apply callbacks with accumulator/value/index/
receiver arguments, including initial values, reverse traversal, and empty
array errors without an initial accumulator.
`flatMap` now invokes callbacks through the shared call path and flattens each
returned array one level into a new result.
The immutable `toReversed` and `toSpliced` methods now allocate result arrays
without mutating or changing the identity of their receivers.
`sort` now supports default string ordering, undefined-last placement, and
user comparators; `toSorted` applies the same ordering to a new array.
Array `toString` and `toLocaleString` now use canonical join semantics instead
of inheriting ordinary object stringification.
Array `keys`, `values`, and `entries` now create dedicated iterator kinds with
length-aware indexed results and standard iterator result objects.
`Array.from` now consumes the shared iterator protocol for arrays, strings, maps,
and sets with optional mapping callbacks; `Array.of` preserves its arguments.
The next heap now has an explicit GC-traced `ArrayBuffer` backing owner with
constructor length coercion and observable `byteLength`; typed views and
detachment transitions remain pending.
`ArrayBuffer.prototype.slice` now copies a coerced byte range into a distinct
owned buffer while leaving the source backing store unchanged.
`Uint8Array` now creates views over owned buffers or array inputs, exposes
length/byteLength, shares backing bytes across views, and coerces indexed reads
and writes to unsigned bytes.
Typed views now also implement `set`, `subarray`, copying `slice`, numeric
`includes`/`indexOf`, `join`/`toString`, and keys/values/entries iterators while
preserving shared-buffer versus copied-buffer identity.
Views expose their `byteOffset` and original `buffer` identity through the same
virtual-property path as `length` and `byteLength`.
`ArrayBuffer.isView` recognizes the new typed views, and constructor/prototype
`BYTES_PER_ELEMENT` metadata is installed as an observable numeric constant.
`SharedArrayBuffer` now has an explicit shared backing-owner bit and constructs
typed views that preserve the shared buffer identity; Atomics operations remain
the next shared-memory boundary. `Atomics.load`, `store`, `add`, and
`isLockFree` now use that bit, reject non-shared views before effects, and
preserve unsigned-byte conversion/previous-value results.
The read/modify/write family also covers `sub`, `and`, `or`, `xor`,
`exchange`, and `compareExchange`, including bounds and non-shared rejection
before mutation.
`ArrayBuffer.prototype.transfer` now moves the owned backing bytes, marks the
source detached, and makes existing views observe zero length while preserving
the moved buffer's bytes.
`DataView` now creates offset/length views over the same owners, exposes
`byteLength`/`byteOffset`/`buffer`, implements `getUint8`/`setUint8`, and shares
detachment and `ArrayBuffer.isView` validation with typed arrays.
`DataView` integer accessors now cover signed 8-bit and signed/unsigned 16-bit
reads and writes, including bounds checks, numeric wrapping, and explicit
big-endian/little-endian selection.
The DataView surface also covers signed/unsigned 32-bit and Float32/Float64
accessors with bit-preserving endian conversion and effect-boundary bounds
validation.
`Uint16Array` now uses a traced typed-view cell over the same backing owner as
`Uint8Array`, including constructor coercion, indexed numeric conversion,
byte-width metadata, inherited view methods, subviews, and shared identity.
Full typed-array/backing-store and Atomics parity remain on the critical
conformance path.
