# 029: Slow-path outlining — CPS `EnterSlowPath` construct, AOT non-inlined slow paths

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 028

## Context

Paper §4: the user may implement slow-path semantics as a plain C++ function,
entered via `EnterSlowPath` — "a CPS-style control transfer that never
returns." At JIT compile time, only the fast path compiles into JIT code; the
slow path stays a pre-compiled (AOT) out-of-line function the JIT branches
to, never inlined. Audit confirmed: quench's `Opcode::Slow` /
`run_instruction_fallback` are ordinary fallback handlers reached by normal
control flow, not this CPS "enter and never return" construct, and there's no
confirmed guarantee the stencil tier keeps slow paths out-of-line rather than
inlining/duplicating fallback code per region.

## Scope
- crates/quench-runtime/src/vm/vm_dispatch.rs
- crates/quench-runtime/src/vm/vm_runtime.rs
- crates/quench-runtime/src/stencil_select.rs / stencil_arena.rs

## Deliverables
- A named `EnterSlowPath`-equivalent control-transfer primitive: a handler
  that hands off to fallback semantics via a one-way tail transfer (matching
  the callee-directed `DispatchTransition` mechanism from task 026), not a
  value returned to a caller that decides what happens next
- Confirm (or make true) that slow-path bodies are never duplicated into
  stencil-rendered code — the stencil tier should branch to one shared
  out-of-line fallback, matching the paper's AOT-non-inlined-slow-path design

## Validation

1. Identify at least 3 opcodes whose slow path is reachable in the neutral
   corpus (e.g. a megamorphic property miss, an arithmetic type coercion, a
   guard-fail fallback) and write a differential test per one: same input,
   same observable output, before and after this task's control-transfer
   change.
2. `cargo test -p quench-runtime --lib` — all pass.
3. Run `node tools/architecture-size-report.cjs target/debug/quench-node > target/architecture-size-after.json` and diff it against the pre-task baseline recorded by task 027 — generated-code-size fields must not grow (a growth means slow-path bodies got duplicated per stencil region instead of shared).
4. `node quench-bench/micros/verify.mjs --engine target/debug/quench-node --oracle node --from 1 --to 100 --runs 3` — 100/100, geomean within noise of baseline.

**Fail condition**: any code-size growth in step 3 without an explained,
justified reason means slow paths are still being duplicated — go back and
fix the sharing, don't just note it and move on.

## Non-goals
- Changing what the slow path computes — this is a control-transfer/codegen
  shape change only
