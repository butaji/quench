# 029: Deoptimization protocol and frame reconstruction

- **Theme:** deegen_full_jit
- **Executor:** codex
- **Depends on:** 028

## Context

Per project constraints (tasks/index.json), no speculative optimization may
ship without a working bailout path — this task is that safety net, and it
must exist *before* 031's optimizing JIT is allowed to speculate on anything.
The paper's deopt protocol (§3) reconstructs interpreter/baseline-tier frame
state from optimizing-JIT execution state when a guarded assumption fails, and
resumes in the lower tier at the equivalent point. The stencil tier's existing
`Repatch`/`Retired` degrade path (task 024, closed) is the nearest analog but
only handles *stale facts discovered before re-entry*, not a guard failing
*mid-execution* inside speculative code — deopt is a strictly harder problem:
it must reconstruct a valid lower-tier frame from a higher-tier frame that was
never running the same code shape.

## Scope
- crates/quench-runtime/src/stencil_lifecycle.rs
- crates/quench-runtime/src/vm/vm_runtime.rs
- New: a deopt frame-reconstruction module (name TBD during implementation)

## Deliverables
- A named bailout trigger point: what a speculative guard failure looks like
  and where it's checked
- Frame reconstruction: given optimizing-tier execution state, produce a
  correct interpreter/baseline-tier frame (locals, operand stack position,
  pending exception state) and resume there
- Complete fallback semantics: every speculative guard this protocol serves
  must have deopt as its failure path, never a silent wrong answer

## Acceptance
- Differential tests: force a guard failure via a synthetic speculative op
  and confirm the resumed lower-tier execution produces identical observable
  results to never having entered the higher tier
- Neutral corpus geomean does not regress
- No speculative optimization is admitted anywhere in the codebase without a
  corresponding deopt path exercised by a test

## Non-goals
- The optimizing JIT tier's actual speculation logic (031) — this task builds
  the bailout mechanism generically, ahead of having real speculative ops to
  bail out of (use a synthetic guard for testing, as above)
