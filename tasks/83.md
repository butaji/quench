# 83: Touch only the pages a program needs

## Plan scope

Stage B candidate after task 86 verifies Stage A. Select this work only for a
measured V8-v7 Score or RSS gap; finishing it is not a stage-completion gate.
Use affected-stage checks plus compare-runs during changes. The current
dependencies in [index.json](index.json) supersede older prerequisite claims.

## Outcome

Running a plain script touches only the text, data, and heap pages its
execution requires. Node host facilities, Intl and Temporal data, threads,
and intrinsic families are created when first used where that improves the
eight V8-v7 RSS results. Empty-script RSS is a diagnostic, not another target.

## Current gap

The production V8-v7 binary is `quench-node`
([V8-v7 commands](../docs/v8_v7.md)). Every page it touches counts toward
maximum RSS: its Node bootstrap, statics initialized at startup, ICU and
Temporal data, and any threads it starts. Task 25 keeps v2's clean
residual-only process, and task 67 makes lowering and intrinsics lazy. No task
covers the host, data, or binary layout.

## Dependencies

See this task's `depends_on` in [index.json](index.json). Stage B.

## Scope and implementation sequence

1. Measure the empty-script RSS for `quench-node`, the residual-only process,
   and QuickJS, split into regions (task 77).
2. Create Node host facilities (module loader, event loop, thread pool,
   process and os facts) on first use, as named transitions of the host
   facade (task 43). A script that uses none of them pays for none.
3. Load Intl, ICU, Temporal, and Unicode data lazily from read-only mapped
   sections, and replace eager statics with lazily initialized ones.
4. Start no thread until a facility needs one, and give helper threads the
   smallest stack their work requires.
5. Order hot functions contiguously with a linker order file from task 84's
   profile, so the text the V8-v7 fixtures touch occupies the fewest pages.
6. Map the source file read-only instead of copying it (v2 task 292), and
   release parser and compiler memory before execution (v2 tasks 53, 58,
   192).

## Verification

Node compatibility tests for every facility made lazy, including the order
of its observable initialization. A script that uses no Node facility makes
no thread-creation or data-mapping system calls (checked with `dtruss` or an
equivalent trace).

## Definition of done

- Empty-script and per-fixture RSS reports split by region show no region
  that the program does not use.
- Every lazily created facility has a named first-use transition.

## Performance evidence

Report empty-script RSS and startup time for Quench and QuickJS, and the
paired per-fixture RSS change.
