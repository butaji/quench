# 068: Fix ARM64 native stencil call overhead; flip default-on once net-positive

- **Theme:** vm_completeness
- **Executor:** codex
- **Depends on:** 067
- **Priority: highest leverage in the current backlog.** Every bit of work
  from tasks 039/040/042/048/049/058 currently contributes zero to any
  measured score — native ARM64 stencil execution requires
  `QUENCH_ENABLE_AARCH64_STENCILS=1` and is **off by default**
  (`machine.rs:26`), and per task 039/042's own recorded evidence, turning
  it on today makes the neutral-corpus score *worse* (252.757 → 221.143)
  and some curriculum cases slower or timeout. Nothing else in this backlog
  matters for the real v8-v7 score until this is fixed.

## Context

The stencil tier's own bytes execute correctly (differential tests pass)
but cost more than the interpreter fallback in practice on this
architecture. This is almost certainly call-boundary overhead: crossing
from the Rust dispatch loop into a tiny (1-5 instruction) rendered
fragment and back likely costs more than the fragment saves, especially
before task 048 grows region scope to whole loop bodies. Fixing this
unblocks the entire JIT-tier investment made so far.

## Scope
- crates/quench-runtime/src/stencil_arena.rs (call boundary into rendered
  code)
- crates/quench-runtime/src/vm/vm_runtime.rs (call site into the arena)
- crates/quench-runtime/build.rs (if the entry/exit sequence itself needs
  changing, using task 039's const-fn encoder discipline)

## Deliverables
- Profile the actual call-boundary cost specifically (not the whole
  dispatch loop) — DWARF/`sample` isolating the transition into and out of
  `StencilArena::render_or_get`/`execute_f64`-class calls, on both a
  currently-covered single-leaf case (e.g. curriculum 017) and a
  currently-covered sequential-bridge case (042's arithmetic glue span)
- Identify and fix the specific cost: likely candidates are unnecessary
  register spill/reload at the boundary, a heavier-than-needed calling
  convention for such a small callee, or missed inlining opportunity for
  the boundary shim itself — profile first, don't guess
- Once native execution is a measured net win on the neutral corpus AND
  the deegen-curriculum AND a majority of currently-covered v8-v7
  benchmarks (not just one), flip the default: remove the
  `QUENCH_ENABLE_AARCH64_STENCILS` opt-in gate on ARM64 so native execution
  is the default path, matching x86_64's existing default-on behavior

## Anti-cheat validation (mandatory, in addition to normal correctness/perf gates)

1. **Generalization check**: construct a synthetic microbenchmark with the
   same algorithmic shape as whichever v8-v7 benchmark most influenced this
   fix (same loop/call/property-access pattern) but different variable
   names, function names, and literal constants. Confirm the fix helps the
   synthetic clone by a comparable margin to the real benchmark — if it
   only helps the literal file, that's overfitting even without any
   explicit cheat, and this task is not done.
2. **No identity detection**: `grep -rniE "richards|deltablue|splay|crypto|raytrace|earley|navier|regexp" crates/quench-runtime/src crates/quench-node/src` must return zero matches introduced by this task.
3. Full gates: `cargo test -p quench-runtime --lib` and
   `--features execution-trace`, neutral corpus (`micros/verify.mjs`),
   curriculum (`deegen-verify.mjs`), and the full v8-v7 suite (task 052's
   runner) — all must show improvement or no regression, not just the one
   benchmark that motivated the investigation

**Fail condition**: flipping the default-on switch without the neutral
corpus AND curriculum both confirming a net win (not just v8-v7 benchmarks)
is not acceptable — this must be a general dispatch-cost fix, not a
benchmark-specific tune that happens to move v8-v7's number.
