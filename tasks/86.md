# 86: Clean the repository after cutover

## Outcome

The first phase-B (make it right) task. After cutover (task 27) the tree holds
nothing that exists only for the legacy engine or the migration, the workspace
builds warning-free, and every document describes the single VM. The
restructuring tasks (45, 44, 49, 46, 47) start from that clean tree.

## Current gap

Task 27 deletes the legacy runtime and renames the next core, which is what
makes the single engine work. Migration tooling, a second vendored OXC, stale
configs and documents, tracked artifacts, task diaries, and dead code the
deletion exposes remain until this task removes them.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

Re-derive each list from the tree; each item is deleted unless a phase-B or
phase-C task names it as an input. One reviewable commit per category, each
re-running the three-suite ratchet (task 48):

1. `vendor/oxc-parser-legacy`: unify OXC on one exact release so
   `cargo tree -d` has no duplicate OXC family from workspace code.
2. Migration-only tools and scripts under `tools/` (differential
   next-versus-legacy runners such as `diff-next.mjs` and `run-all-next.mjs`,
   orchestration and audit scripts with no remaining consumer) and their
   `package.json` entries. Measurement tools that phase C uses stay.
3. Stale paths in `package.json`, lint and format configs, git hooks, and CI
   scripts (for example the deleted `native_core/PROVENANCE.md`).
4. Documents that describe the legacy engine or migration state:
   `docs/spec.md`'s legacy ownership, `CONTEXT.md`, `GOAL.md`, and any `docs/`
   page or README section whose subject no longer exists. `AGENTS.md` and
   `docs/README.md` describe only the single VM.
5. Tracked reports, logs, generated artifacts, and dead fixtures or examples
   that no runner reads.
6. `Implementation evidence` diaries in task files: done tasks keep their
   specification plus a short completion record; Git history keeps the log.
7. Dead code the deletion exposes: `#[allow(dead_code)]`, unused features,
   dependencies, re-exports, and compatibility shims.

## Verification

From a clean build directory, run warning-denied check/test/clippy, the three
conformance gates through task 48's ratchet, the task-queue coherence check,
and a local-link check over all Markdown.

## Definition of done

- No tool, script, document, config entry, vendored crate, or tracked artifact
  exists only for the legacy engine or the migration.
- Every Markdown link resolves; workspace builds are warning-free.
- The three suites are unchanged against the task 48 ratchet.

## Performance evidence

None. This task changes no engine behavior and makes no speed claim.
