# 084: Remove or gate unused direct-call polyfill API

`AbilityKind`, `DirectCallable`, `DirectCallArgs`, and `DirectCallResult` have
no production consumers; the active registration path always creates a
`JsBridge` ability.

## Plan

- Confirm no external or generated consumer depends on the types.
- If native direct calls are not being implemented now, remove the sketch or
  gate it behind an explicit feature/design module.
- Simplify `Ability` and registry storage to observed facts only.
- Keep the polyfill migration seam documented without storing unused runtime
  metadata.

## Acceptance

Bootstrap output and ordering are identical, no dead abstraction remains in the
default build, and any retained experimental API is feature-isolated and tested.
