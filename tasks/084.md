# 084: Remove unused direct-call polyfill abstractions

## Outcome

Remove speculative direct-call metadata from the active polyfill API.

## Current gap

`polyfills/mod.rs` declares AbilityKind/DirectCallable-related types while registration creates JsBridge entries.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering live there.

## Scope and implementation sequence

1. Audit production, generated, test and external API consumers.

2. Remove unused traits/variants/argument-result wrappers and simplify registration; migrate any real consumer first.

3. Retain compatibility only for a demonstrated public contract, with a documented removal path.

## Verification

`cargo test -p quench-node`; `cargo check --workspace`; compatibility runner and Node-oracle bootstrap checks. Compare registration order and output bytes.

Apply the shared [completion checks](README.md), including named baseline failures
and independent semantic controls. Record commands and artifact identity.

## Definition of done

- No unused direct-call sketch contributes default runtime state.
- All real consumers compile and bootstrap behavior is unchanged; any compatibility remainder has an explicit owner and follow-up.

## Performance evidence

Cleanup milestone; implementation of new native direct calls is not silently substituted for deletion.
