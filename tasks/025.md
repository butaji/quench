# 025: Memoize rendered regions by canonical RegionKey

- **Theme:** copy_patch_jit
- **Executor:** codex
- **Depends on:** 022, 024

See `docs/copy-and-patch-jit.md` for the full design.

## Scope
- crates/quench-runtime/src/stencil_select.rs
- crates/quench-runtime/src/stencil_arena.rs

## Deliverables
- Add `RenderedRegion = memo(RegionKey -> installed code address)`: a cache mapping a canonical `RegionKey` to an already-copied-and-patched arena address, so an identical `(region, fact_vector)` combination is never re-selected, re-copied, or re-rendered — state as `state = memo(f(events))`, not ad hoc "have we seen this before" flags scattered across call sites
- Cap the memo table's size against the complexity budget documented alongside the interpreter's own bounded caches; justify the cap as workload-independent (same fixed bound for any program with the same region/fact diversity, never sized to one benchmark — see `docs/benchmark-integrity.md`)
- Prefer the zero-copy path first: if a site's fact delta is expressible as a `PatchValues` update against an already-`Installed`/cached region (task 024's `Repatch`), reuse it without consulting the memo table at all; only promote to a distinct rendered/copied region when the fact vector genuinely differs and the saved loads/branches justify the added arena bytes — and state that promotion rule as a fixed, fact-driven admission check (mirroring 014's degrade-tier admission rule), not a runtime-tunable heuristic
- Type-specialized variants (e.g. a region proven all-`Number` vs. a `Guarded`-shape variant) are simply distinct `RegionKey`s feeding the same memo table — no separate variant-selection mechanism

## Acceptance
- Re-executing the same region under the same facts hits the memo table and performs zero new copy/patch work
- The promotion-to-distinct-region admission rule is stated as a single, reviewable predicate over facts, and the same predicate applies to every region regardless of which benchmark or source produced the facts
- Memo table growth is bounded and disposable, reported as evidence alongside the interpreter's own complexity ledger
- Removing any specific fixture from the neutral corpus does not change which `RegionKey`s are eligible to be cached

## Non-goals
- Speculative type inference beyond the existing Proven/Guarded/Unknown facts
- A general-purpose optimizing compiler or SSA-based JIT
- Any hotness-triggered tier-up/profiling-driven compilation policy: this tier installs a stencil eagerly per admitted fact combination, not on a hotness threshold. A future hotness-gated tier-up (the Deegen paper's §3) is explicitly out of scope and would need its own task, since it reintroduces the profiling/threshold machinery this exception excludes
