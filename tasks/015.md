# 015: Feed execution_trace profile facts into quickening-site decisions

- **Theme:** deegen_codegen
- **Executor:** codex
- **Depends on:** 007, 014

## Scope
- crates/quench-runtime/src/execution_trace.rs
- crates/quench-runtime/src/quickening.rs

## Deliverables
- Define a narrow, generic profile-fact interface (shape fingerprint, loop iteration count, call-site miss reason) that quickening sites may consult to order guard checks or size the degrade tier
- Keep execution_trace's existing telemetry/reporting output unchanged; the new consumer is additive
- Ensure profile facts are derived only from runtime execution shape (types, shapes, call targets), never from fixture identity, file path, or source text

## Acceptance
- Quickening decisions demonstrably use at least one execution_trace-derived fact (e.g. guard-check ordering by observed hit frequency)
- Removing a specific benchmark from the corpus does not change which facts are eligible to be consulted
- No new code path branches on a benchmark or fixture name

## Non-goals
- A profile-guided JIT or persistent cross-run profile cache
