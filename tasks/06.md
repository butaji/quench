# 06: Adopt tagged values and JavaScript strings

## Outcome

Make one eight-byte tagged value and exact JavaScript string/key model authoritative across the next engine.

## Current gap

V2's tags cover numbers, booleans, nullish values, and heap indices, while its UTF-8 `String` cells cannot represent lone surrogates, Symbols, BigInts, or private names required by full ECMAScript.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Preserve v2's immediate i32/double encoding, canonical NaN handling, signed zero, and heap tag.
2. Represent BigInt, Symbol, strings, and other identity-bearing values as heap cells without adding a second public value model.
3. Store strings as exact UTF-16/WTF-16 code units with explicit UTF-8 host conversion boundaries and bounded atom interning.
4. Define one `PropertyKey` authority for string atoms, Symbols, and private names; residual tables use stable IDs derived from it.
5. Port equality, hashing, coercion, display, and serialization primitives with Node/Test262 controls.

## Verification

Cover NaN payloads, signed zero, i32 boundaries, lone surrogates, astral characters, Symbol identity/registry keys, arbitrary BigInts, property-key conversion, and serialized constants.

## Definition of done

- `Value` remains one machine word on supported 64-bit targets.
- Every JavaScript string and property key round-trips without lossy internal conversion.
- Host-facing conversions are explicit edges.

## Performance evidence

Report value/cell sizes, atom/string allocation counts, and string-heavy reference regressions.

## Implementation evidence

The one-word `Value` representation remains authoritative for immediates and
heap handles. BigInt literals now compile as dedicated heap-backed constants,
survive residual round trips under the bumped ABI/format version, and stringify
without numeric truncation; Symbols now use distinct heap identities with
explicit display conversion. The next-engine regressions cover a 20-digit
BigInt and Symbol identity/display behavior.

The string boundary now has a dedicated `JsString` cell payload whose UTF-16
units are authoritative and whose lossy Rust-text view is explicit. Heap
allocation, `charCodeAt`, `charAt`, empty-separator splitting, boxed indexed
properties, and string iteration preserve lone surrogates and astral pairs;
constructors and host conversions route through the same type. The next-engine
gate is green with 61 unit tests, 204 aggregate subset tests, the module-size
guard, and `clippy -D warnings`. Property-key authority and the remaining
string/serialization algorithms stay in later slices, so task 06 remains in
progress.
