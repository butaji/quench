# 32: Resolve capture binding time at specialization

## Outcome

Choose `LoadLocal`/`StoreLocal` versus `LoadEnvLocal`/`StoreEnvLocal` once, at
OXC-specialization time, instead of branching on `self.frames[f].captured` on
every local access at runtime.

## Current gap

`dispatch.rs`'s `LoadEnvLocal`/`StoreEnvLocal` handlers check
`self.frames[f].captured` on every execution to decide whether a local lives in
frame storage or a heap environment cell. Task 10 already scopes capture
analysis as a static data pass ("lexical-address, capture ... analyses as data
passes"), so the runtime branch is a binding-time fact being re-decided
dynamically instead of consumed once statically—the core move a Futamura-style
specializer is supposed to make.

## Dependencies

See this task's `depends_on` in [index.json](index.json).

## Scope and implementation sequence

1. Confirm from task 10's capture analysis whether "is this local ever captured
   by a nested closure" is fully static per function, or whether any dynamic
   case (e.g. `eval` introducing captures) makes it genuinely undecidable ahead
   of time.
2. For the fully static case, have the specializer emit `LoadLocal`/`StoreLocal`
   or the environment-slot variants directly per local, so the residual encodes
   the binding-time decision and the interpreter no longer branches on
   `captured` for that local.
3. For any local whose captured-ness depends on dynamic compilation (direct
   `eval` in scope), keep the existing runtime-checked opcode form as the exact
   fallback—this is a case where the runtime guard is necessary, not a gap.
4. Ensure one authoritative capture-analysis representation feeds both the
   opcode-selection decision and any other consumer of capture facts (e.g.
   closure-environment layout), per the "one fact, one representation" rule.

## Verification

Differential tests against Node/Test262 for closures, nested functions, loop-
scoped `let`/`const` capture per iteration, direct `eval` introducing new
captures, and functions with no closures at all (confirming no needless
environment-cell allocation). Add a control that perturbs source without
changing captured-ness and confirms opcode selection is unchanged.

## Definition of done

- Statically-decidable locals no longer branch on `captured` at runtime.
- The `eval`-introduced-capture case has an explicit, tested fallback path.
- Capture facts have one authoritative analysis, consumed (not recomputed) by
  opcode selection.

## Performance evidence

Report the fraction of locals resolved statically versus left dynamic, and
dispatch-time delta for closure-heavy workloads plus the existing four-benchmark
suite.
