## Outcome

Every RegExp literal's pattern and flags are compiled once per literal site,
when the residual is loaded. Static pattern facts select a faster matcher
entry without changing results. Each evaluation of the literal still creates
a fresh RegExp object, as the spec requires.

## Current gap

`compile/regexp.rs` validates literal patterns for early errors and then
discards its work. The matcher program is compiled again at runtime. Static
facts about a pattern are never derived, such as a required literal prefix,
anchoring, capture count, or the absence of backtracking. RegExp is one of
the eight V8-v7 fixtures.

## Scope and implementation sequence

1. Compile each literal site's matcher program at load and keep it in the
   specialization environment, indexed by the literal's operand. The early
   error validation and the compilation are one pass over the pattern.
2. Derive static pattern facts in the shared RegExp crate: required literal
   prefix or substring, start and end anchoring, capture count, whether
   backreferences or lookbehind are present, and whether the pattern is free
   of backtracking. These facts belong to the compiled program, not to the
   runtime object.
3. Use the facts to select a matcher entry (a substring search for a
   literal prefix, early failure for an anchored pattern) with the full
   backtracking matcher as the reference definition.
4. Share compiled programs between literal sites with identical pattern and
   flags. The program is immutable, and `lastIndex` and the object stay per
   evaluation.
5. `RegExp(pattern)` with a runtime string keeps the runtime compile path,
   which may use a bounded compiled-program cache keyed by pattern and flags.

## Verification

The full Test262 `built-ins/RegExp` and `annexB` RegExp inventory, including
`lastIndex`, `Symbol.match`/`replace` overrides, and subclassing. Each
matcher entry agrees with the reference matcher on generated inputs (the existing shared matcher). Task 42's gate uses the reference matcher only.

## Definition of done

- No literal pattern is parsed or compiled more than once per program.
- Every accelerated matcher entry has the backtracking matcher as its exact
  reference.
- Object identity and `lastIndex` semantics are unchanged.
