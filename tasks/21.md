# 21: Migrate framework Node APIs to the shared VM

## Outcome

Run the Stage A Node framework gate through the shared VM using the existing
`quench-node` host. Keep Node API behavior in the host and JavaScript semantics
in the runtime.

## Current state

The `framework-core` profile passes 43/43 selected upstream fixtures. The
pinned Express, Koa and Fastify scenarios each exit successfully and match
local Node byte-for-byte on stdout and stderr. The current source, manifest,
scenario, binary and output hashes are recorded in
[framework evidence](evidence/task21-framework-core-final-2026-10-07.json).

The profile membership comes only from
[`parallel.txt`](../crates/quench-node-test/node-tests/parallel.txt); the three
package scenarios are defined in
[`tests/frameworks`](../tests/frameworks/README.md). The broad Node inventory
and unrelated profiles are not Stage A gate requirements.

The development shared-VM entry is qualified; production still uses the old
runtime path until task 27. Task 43 owns the public embedding boundary, and
task 27 owns production cutover and legacy deletion.

## Dependencies

See `depends_on` in [index.json](index.json).

## Scope and implementation

Implement only Node behavior exercised by the framework profile or the three
package scenarios. The current slice includes HTTP request/response handling,
Node and Web Streams interoperation, file reads, paths, Buffer text operations,
EventEmitter, StringDecoder, util inheritance, async context and diagnostics
channels. The manifest remains the sole upstream fixture-selection authority;
do not create a duplicate list or infer membership from imports.

Route required host operations through one `NodeHost` and the shared runtime's
public embedding surface. Preserve value identity, descriptors, ordering,
errors, exit status and host effects against local Node. Keep fixture setup and
process isolation in `quench-node-test`. Remove fixture-shaped output or API
facsimiles when they affect a selected obligation. Do not add unrelated Node
APIs or expand the profile to the broader proposals in tasks 88/89.

## Verification

During implementation, run the affected profile fixtures and compare them with
local Node. At task 22, run the full `framework-core` profile and all three
package scenarios on the same build. No unit test may duplicate a selected
fixture or package assertion; retain internal tests only for uncovered runtime
invariants.

## Definition of done

- Every `framework-core` manifest entry passes on the shared VM without a
  skip, timeout, crash or unclassified result.
- Express, Koa and Fastify pass the pinned scenarios and match local Node on
  exit status and raw stdout/stderr.
- Selected Node behavior uses the shared host/runtime path without a second
  engine or fixture-specific success simulation.
- Evidence records the manifest, scenario inputs, source snapshot, binaries
  and raw comparison results.
