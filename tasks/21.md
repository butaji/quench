# 21: Migrate implemented Node APIs to the shared VM

## Outcome

Run task 19's frozen implemented Node cases through the existing `quench-node`
host on the shared VM. Preserve one authority for each Node API.

## Current gap

The production host uses legacy runtime operations. The development
`quench-node-next` entry now uses the same `NodeHost` through the shared VM's
rooted initialization/callback boundary. Its first process binding is
`process.uptime`: both adapters use the existing process state's monotonic
clock, initialized at process construction rather than the first uptime call.
The redundant JavaScript uptime fallback is removed.
[Qualification](evidence/task21-shared-process-uptime.json) records matching
local-Node script/module observations and affected Test262 comparisons.
This is a host migration slice, not compatibility-suite closure. The unchanged
upstream uptime case still fails on missing shared module loading; its existing
legacy stack abort remains a failure. Process prototype/global accessors,
remaining APIs, module identity and scheduling still need migration.

Production invocation facts now come from explicit CLI arguments and the existing
child/worker relay, rather than guest comments or source words. Fixture metadata
is interpreted at the runner boundary. [Invocation qualification](evidence/task21-node-invocation.json)
records seven full local-Node observation matches, two repaired counterexamples,
metadata/relay controls and six retained internal runner checks. This fixes a
configuration boundary used by the migration; production execution remains legacy.

The production child-process layer still includes source-text output simulation
(`cp_script_output`, `cp_script_stdout`, `cp_spawn_script_stdout` in
`dispatch_handlers.rs`). The hard-coded `JSON.stringify(process.execArgv)`
shortcut is removed. Ordinary file-backed children now execute the requested
engine, preserving real stdout/stderr, exit status and file effects
([boundary qualification](evidence/task21-real-child-execution.json)). File and
eval entries use the canonical host installer; shell/spawnSync no longer
substitute diagnostic launchers. CLI completion preserves host exit status,
and the exit setter and process.exit share Node's validation/storage operation.
All 23 affected case identities preserve their prior passes; 39 focused Node
observations match exactly. This closes that boundary slice only. Replace the
remaining IPC/stdin/timer and command simulations with actual child
execution and observable host effects before qualifying affected implemented
cases. Passing a source-recognition shortcut is not Node conformance.

The module registry also returns hand-written `ajv`/`chalk`/`prettier`
facsimiles in `modules/require.rs`. Preserve any implemented inventory cases
while routing packages through ordinary resolution and real package code;
this correctness/cleanup obligation does not require the deferred framework
expansion in tasks 88/89.

Fixture-helper facsimiles in `polyfills/bootstrap/support.rs` and
`js_runtime.rs`, plus eager fixture-temp creation in `NodeHost::new`, also
remain production cleanup obligations. Run helpers through ordinary module
loading and keep fixture setup at the runner boundary. Do not migrate those
shortcuts into the shared runtime or remove their implemented case identities.

The current socket pump also treats terminal read failures as EOF. Preserve
Node's distinct read error/close events when migrating this path; the
[read-turn cleanup](evidence/task86-read-turn-cleanup.json) preserves existing
behavior and internal half-close ownership, but its unchanged upstream cases
still abort before reaching I/O and remain unqualified.

The existing Node host now has a standalone shared-VM registration chunk
([qualification](evidence/task21-node-host-commit.json)). Process uptime derives
from one monotonic origin in `ProcessState`; its canonical object is retained
in the existing VM-owned cache. Native source text derives from the shared
builtin-name operation rather than Node formatting. The unchanged upstream
uptime case still fails: legacy aborts with stack overflow, while the shared
entry lacks `require`. These remain migration failures, not excluded cases.

## Scope and verification

Use task 43's host operations to adapt the existing host in slices. Preserve
implemented globals, modules, scheduling, errors and host effects required by
the frozen cases. Retained guest objects and callbacks must follow the shared
VM's root lifecycle. Keep Node behavior in `quench-node` and JavaScript
semantics in the runtime; do not fork the host or add unimplemented APIs.

Use one authority for equivalent host operations and derive their registrations.
Do not require a new capability framework or a full legacy-facade migration
before connecting an implemented path to the shared VM.

Run only affected frozen cases against local Node and relevant upstream source,
checking values, descriptors, identity, ordering, errors, exit status and host
effects. Check internal root retention/release under GC and host re-entry.
Task 22 owns complete implemented-case qualification.

## Definition of done

- The implemented host paths run on the shared VM without legacy calls.
- The existing host remains the sole owner of Node semantics.
- Retained guest objects and callbacks obey the shared VM root contract.
- No new host capability or discretionary architecture blocks closure.
