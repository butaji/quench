# 074: Slow-lane dispatch constant-factor survey

- **Theme:** vm_completeness
- **Executor:** codex
- **Depends on:** 071

Task 071's execution-trace evidence ruled out IC/layout mismatch as the main
constant-factor cost in the motivating workloads. The remaining slow lane was
dominated by generic `Branch`, `TraceSite` (trace builds), `CheckInitialized`,
and `Unary` handlers. This task is a profile-first survey of those ordinary
paths, not a benchmark-specific rewrite.

## Scope

- `crates/quench-runtime/src/vm/`
- `crates/quench-runtime/src/ops_*`
- `crates/quench-runtime/src/execution_trace.rs`

Measure each candidate on a synthetic workload with the same opcode shape but
different names/constants, using execution-trace counters and DWARF samples.
If one handler's fixed overhead is material in a non-trace build, reduce it
through a generic compact path while retaining complete fallback semantics.
If the cost is trace-only or not material, record a no-go finding.

## Validation

- The synthetic clone must show the same before/after movement as any
  motivating workload; no fixture identity may appear in production code.
- `cargo test -p quench-runtime --lib` in both feature configurations,
  neutral corpus, deegen curriculum, and v8-v7 runner must remain correct.
- Report both Score and peak RSS; reject any speed gain that increases RSS
  without an explicitly bounded budget.
