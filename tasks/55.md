# 55: Read process and os host facts from the OS

## Outcome

Every `process` and `os` value that Node gets from the kernel is read from
the kernel on every supported platform, with macOS first. When a mechanism
is unsupported, the fallback is an explicit, named transition, never an
invented value.

## Current gap

Memory and CPU:

- `dispatch_handlers.rs:process_memory_usage` and
  `process_memory_usage_rss` read `/proc/self/statm`, which only exists on
  Linux, so `rss` is always 0 on macOS. They also multiply by a hardcoded
  page size of `4096`, while Apple Silicon uses 16 KiB pages.
- `process.cpuUsage()` always returns `{user: 0, system: 0}`. The
  `process.resourceUsage()` polyfill
  (`polyfills/post_bootstrap/process_surface_00.rs`) returns all zeros.
- `process.availableMemory()` and `process.constrainedMemory()` return
  `f64::MAX`.
- `os.cpus()` puts a usage percentage in `times.user`, and `nice`, `sys`,
  `idle` and `irq` are always 0.
- `os.totalmem()` and `os.freemem()` call `sysinfo::System::new_all()`,
  which scans every process on the machine on each call.

Identity and credentials:

- `os.userInfo()` hardcodes `uid: 0, gid: 0` and takes username and shell
  from `USER`/`SHELL`. It does not read the user database.
- `os.hostname()` falls back to a made-up `"quench-node"`.
- `process.geteuid()`/`getegid()` return the real uid/gid, not the effective
  ones.
- `process.setuid`/`setgid`/`seteuid`/`setegid` do nothing when given a
  number.

Process control:

- `process.umask()` is only a stored number, initialised to `0o022`. It is
  never read from or applied to the real OS umask, so file creation modes
  ignore it.
- `process.kill()` never sends a signal (`_kill` is undefined). It decides
  `ESRCH` from the host's `alive_pids` table.

## Scope and implementation sequence

1. Memory and CPU: macOS gets RSS from `task_info(MACH_TASK_BASIC_INFO)` and
   Linux from `/proc/self/statm`, scaled by `sysconf(_SC_PAGESIZE)`.
   `cpuUsage`/`resourceUsage` use `getrusage(RUSAGE_SELF)`, with Node's
   field units. `os.cpus()` times come from `host_processor_info` or
   `/proc/stat`. `totalmem`/`freemem` come from `sysctl hw.memsize` plus
   the VM statistics, or from `sysinfo`'s narrow refreshers, not
   `new_all()`.
2. Limits: implement `constrainedMemory`/`availableMemory` as libuv does
   (cgroup limits on Linux, `RLIMIT_AS`/`RLIMIT_DATA`, then free memory).
3. Identity: `userInfo` uses `getpwuid_r(geteuid())`, and `homedir` falls
   back to the same source. `geteuid`/`getegid` call the effective-id
   syscalls. The `set*id` calls invoke the real syscalls and map `errno` to
   Node's errors. Name lookup uses `getpwnam_r`/`getgrnam_r`.
4. `hostname` uses `gethostname`, and a failure throws as Node does.
5. `umask` reads and sets the real process mask through `libc::umask`. This
   removes the host copy.
6. `kill` calls `libc::kill` and maps `errno` (`ESRCH`, `EPERM`, `EINVAL`).
   Remove the `alive_pids` authority once nothing else uses it.
7. Delete the polyfill defaults that these capabilities replace.

## Definition of done

- No `process` or `os` value that the kernel owns is hardcoded, zeroed or
  virtualized on macOS or Linux.
- Every unsupported-platform fallback is a named, documented transition.
- Tracked Node outcomes are identical to or better than the frozen baseline.
