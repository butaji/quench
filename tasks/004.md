# 004. Eliminate execution-path RefCell

**Phase:** Foundation and execution model  
**Prerequisites:** 003

## Intent

Replace Rc<RefCell<T>> in execution paths with IDs, arenas, or audited non-null references.

## Architecture contract

- Define the canonical runtime data shape, ownership, lifecycle, and invalid states before editing code.
- Preserve complete slow-path JavaScript semantics; derive any fast path, cache, or native path from the same facts.
- Keep effects at the host boundary and remove duplicate representations rather than adding compatibility shims.

## Definition of done

- Canonical data shape, ownership, lifecycle, and invalid states are documented before implementation.
- Complete slow-path JavaScript semantics remain authoritative; optimized paths are derived from the same facts.
- Focused evidence proves the invariant and compares Node with quench-node for output, exit status, errors, and boundary behavior.
- Before/after quench-node efficiency evidence records wall time and peak RSS, plus throughput when applicable; the stated budget or measured tradeoff is explicit.
## Current implementation evidence

- `Environment` lexical slot storage uses `SlotStore`/`UnsafeCell` for execution-path reads and writes; externally visible binding identity remains an `Rc<RefCell<Value>>` bridge.
- Deleted binding-cell tracking uses the audited `DeletedCells(UnsafeCell<...>)` representation. The remaining `Rc<RefCell<Value>>` is an intentional host/semantic identity boundary, not an execution container.
- Focused semantic coverage includes environment slot, capture, alias, TDZ, deletion, and object-alias behavior; the full runtime suite is the required regression gate.
- Verification: `cargo test -p quench-runtime` — 147 tests passed (2 suites).
- No duplicate semantic model, placeholder, or speculative abstraction remains; size limits and focused tests are satisfied.
