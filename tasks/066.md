# 066: Allocation/memory algorithmic-complexity invariants

- **Theme:** architecture_invariants
- **Executor:** codex
- **Depends on:** none

## Context

Same technique as 062, scoped to raw allocation cost — the foundation
tasks 056/057 (cycle-leak audit and collector) and 059 (arena allocation)
need proven sound before building on top of it. This is specifically about
the common acyclic case's allocation cost, not the cycle-collector's own
behavior (057 covers that once it exists).

## Scope
- `crates/quench-runtime/src/architecture_invariants.rs` (same module)

## Deliverables — invariants to pin
1. Allocating a new object's cost is independent of the current live heap
   size (no accidental full-heap scan or linear structure touched on every
   allocation) — this is the most basic amortized-O(1)-allocation claim
   any `Rc`-based or arena-based design depends on; worth proving directly
   rather than assuming.
2. Dropping an object (refcount reaching zero, no cycle) is independent of
   total live object count — same reasoning, for deallocation.
3. If task 059's arena allocation lands before this task starts, add: bump-
   pointer allocation within the arena is O(1) regardless of how many prior
   allocations the arena has served since its last reset (mirrors the
   existing invariant already implicitly relied on by `stencil_arena.rs`
   for JIT code — make it explicit and tested for the object-heap arena
   too).

## Validation

Same bar as 062: validate each test fails against a deliberately-broken
version first, `cargo test -p quench-runtime --lib` green.

**Fail condition**: same as 062.
