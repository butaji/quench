# 076: Remove unreachable legacy host implementation

## Outcome

Remove only host implementation files proven unreachable, while preserving the
active Node surface and any directly included fragment.

## Current gap

`crates/quench-node/src/js_runtime*.rs` is actively included by the current host
modules, so the tree cannot be classified as legacy by filename. Reachability
and ownership must be established file-by-file; historical counts do not prove
that any implementation is removable.

## Dependencies

See this task's `depends_on` in [index.json](index.json); status and ordering live there.

## Scope and implementation sequence

1. Trace module declarations, include paths, build scripts, tests and tool references for every legacy file.

2. Move any still-used fragment into its real owning module and update consumers without changing behavior.

3. Delete only proven unreachable implementation; remove obsolete references and validate active host surfaces.

## Verification

`cargo check -p quench-node --lib`; `cargo test -p quench-node`; `cargo run -p quench-node-test --bin run-compat -- --list`, then `cargo run -p quench-node-test --bin run-compat`. Compare changed loading/import paths with local Node.

Apply the shared [completion checks](README.md), including named baseline failures
and independent semantic controls. Record commands and artifact identity.

## Definition of done

- Every removed file has a reachability justification and no active include/tool consumer is broken.
- All retained host functionality has a single active owner; module loading and compatibility results have no new failures.
