# 67 — Equality saturation as the primary optimization strategy

Status: planned

[[23-egraph-rewriting]], [[61-confluence-critical-pair-check]], and [[66-normal-form-checkpoint]] currently frame e-graph rewriting as a supplementary peephole pass layered on top of the existing composition machinery. Following the production-proven `egg`/`egglog` line of work (Willsey et al. — equality saturation scaling to real compiler IRs, used in CAD toolchains and TensorFlow-adjacent optimizers), promote it to the *primary* optimization strategy for `StencilNode`: the one algorithm here that turns "many correct rewrites, unknown best application order" into a solved problem via saturation-to-fixpoint plus cost-based extraction, rather than an engineering judgment call about pass ordering.

This is a scope elevation, not new mechanism: [[23-egraph-rewriting]]/[[61-confluence-critical-pair-check]]/[[66-normal-form-checkpoint]] already specify the pieces (equivalence classes, confluence, normal form). The concrete change is architectural priority — new optimizations proposed anywhere in this task set (loop transforms, guard placement, arithmetic simplification) should default to "express as a rewrite rule and let saturation find it" rather than "write a dedicated pass," unless a rule-based expression is demonstrably impossible for that optimization.

Acceptance: at least two optimizations currently scoped as dedicated passes elsewhere in this task set (candidates: [[18-identity-erasure-peephole]], parts of [[21-loop-invariant-hoist-associativity]]) are re-expressed as rewrite rules under this strategy with no loss of the guarantees their original task specified; a documented policy exists for when a dedicated pass is still justified over a rewrite rule (e.g. an optimization requiring global program state unavailable at the term level); saturation-based optimization is measured end-to-end against the current pass-ordered pipeline via [[05-performance-harness]].
