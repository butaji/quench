# 347 — rustc/LLVM cooker configuration matrix

Status: planned

Extend Task 273's completed optimization-level experiment into one fail-closed matrix
over relocation model, code model, target CPU/features, and optimization level. The
cooker, not the runtime, owns this experiment. Runtime stencil selection and benchmark
identity never influence a template's compiler flags.

Represent every matrix point as a `CookerConfiguration` value with named enums for
`RelocationModel`, `CodeModel`, `TargetCpu`, `TargetFeatures`, and `OptimizationLevel`.
Generate rustc/LLVM invocations and report paths from that value so shell branches do not
become a second configuration representation. At minimum compare supported PIC/static,
tiny/small/default code models, generic/native CPUs, and Task 273's accepted optimization
levels where the host target permits them.

Each point must extract and validate every template, classify relocations, verify the
connector tail transfer, report text/data/padding bytes, and disassemble representative
linked images. Missing compiler support, unsupported relocations, cross-template edges,
or ABI drift reject the point explicitly.

Acceptance: the matrix is reproducible from one script; every supported cell has an
artifact manifest and validation result; invalid cells fail closed; the selected global
or semantic-family configuration passes release tests and an alternating full V8v7 A/B.
If generated bytes and performance are equivalent, retain the simplest portable
configuration and record the no-op result.

Run [[367]]'s A/B/C differential cooker audit in every supported matrix cell. A
configuration is invalid if identical placeholder builds differ, a placeholder change
touches undeclared bits, or a declared hole does not change. This check precedes any
performance comparison and turns compiler-version drift into a build failure rather than a
runtime stencil fault.
