# 122 — rustc/LLVM AOT numeric-region templates

Status: complete

Current work: add a macro-generated rustc/LLVM AOT vocabulary for the operations in
Task 120. Numeric body templates rely on the Task 121 entry proof; dense templates keep
only the per-access bounds condition needed for exact bailout at the original bytecode
site. Each template uses the existing continuation/branch/slow holes and therefore
remains a normal composable stencil.

Use Rust macros plus the existing rustc/LLVM cooking pipeline to build the finite
template vocabulary consumed by typed numeric/dense regions. Templates operate only on
the validated context from [[121-hoisted-numeric-dense-guard]]: numeric arithmetic,
local load/store, bounds-proved dense load/store, loop-carried moves, conditional edge,
and region exit. They use the fixed internal stencil ABI and expose every relocation as
a named hole.

Templates are not handwritten runtime instruction selection and are not specialized to
V8v7 source. Macro expansion defines semantics once for families of operators. Build
validation rejects unrepresented relocations, external calls, jump tables, and ABI
drift. Compatible closed composites may be frozen and shared by reference.

Acceptance: extracted instruction and relocation audits pass; macro-family semantic
tests compare templates with canonical JS operations including NaN, signed zero, and
bounds behavior; no copied body calls an opcode switch or per-element Rust helper.

Actual implementation:

- `stencil-aot/handlers.rs` contains the complete `deegen_region_*` leaf vocabulary
  covering guard, identity/NOP, literal, local, captured-snapshot, move, arithmetic,
  comparison, bitwise, shift, unary, dense read/write, and diagnostic-only counted
  backedge operations. Operator families are generated by Rust macros.
- Numeric leaves trust the Task 121 proof and contain no tag/drop guard. Dense leaves
  retain only exact JS-index and backing-length checks so a failed access can transfer
  to the canonical slow stencil at that bytecode before the access effect.
- JavaScript `ToUint32` is implemented from IEEE-754 fields with named constants; it
  requires neither `%`/`fmod` nor an external helper relocation.
- The frame prefix has an explicit `RegionArrayView` connector. Existing fields retain
  compile-time offset assertions.
- `build.rs` now names the offending stencil when the single-continuation-hole law
  fails. During development this caught a two-continuation shift template; making the
  integer conversion structurally single-exit restored the Lego contract.

Evidence: 61 release tests pass. New tests require the complete catalog, execute cooked
arithmetic/bitwise and dense read/write bytes, check signed-zero behavior, assert dense
slow holes only where required, and scan every region image to reject direct or
indirect calls. The build extractor also rejects unexpected relocations and enforces
one tail continuation on every leaf.

Limitation: Task 122 supplies inert immutable templates. Task 123 is responsible for
quoting them into one traced region, patching symbolic edges, and placing the Task 121
guard before the internal loop entry.
