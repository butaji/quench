# 282 — Typed FP-accumulator connector experiment

Status: complete

Test whether a distinct typed stencil-category object can retain a numeric expression
value in the platform FP argument register across independently cooked copy-and-patch
templates. The experiment implemented the categorical chain

`Connector -> NumberConnector -> NumberConnector* -> Connector`

for guarded local, captured-name, and numeric-literal producers; add, subtract,
multiply, and divide steps in both operand orders; and register or dead-local sinks.
All variants were generated by Rust macros from a small source/operation product. The
selector was a general quoted-bytecode rewrite: it required at least two consecutive
numeric binary steps, exact data flow, canonical numeric proofs, dead intermediate
registers, and no branch into the expression interior. It used neither benchmark
identity nor runtime hotness.

The experiment found an important ABI constraint: Rust's explicit-tail-call `become`
requires the caller and callee signatures to match exactly. Both sides of every typed
edge therefore used `(frame, site, accumulator: f64)`; the producer accepted and
ignored the incoming FP value, while the exit adapter transferred back to the ordinary
two-argument connector. This made the category boundary real in the Rust type system,
not merely a selector convention.

Results:

- all 97 release tests passed and all V8v7 outputs remained correct;
- the generated immutable catalog grew from 124 templates / 11,808 bytes to 164
  templates / 13,404 bytes;
- two Crypto and three Navier-Stokes expression chains selected the new connector;
- representative selected code shrank from about 192 copied bytes to 100 bytes because
  intermediate register-file stores and reloads disappeared;
- the ten-pair targeted comparison in
  `reports/task282-number-connector-focused-ab-10/comparison.txt` regressed the
  Crypto/Navier-Stokes aggregate from 3055.72 to 3039.98 (-0.52%); and
- the complete five-pair comparison in
  `reports/task282-number-connector-full-ab-5/comparison.txt` moved aggregate from
  1922.09 to 1924.29 (+0.11%), below the noise floor and contradictory to the targeted
  result.

The candidate SHA-256 was
`42eb5c7716c1befb3c39b27d9cab505273c472174758d02ec84d0aa157090d1c`.
It was rejected and removed. The production tree was restored byte-for-byte to Task
281's accepted binary,
`98c720d83fcd5e9976a562f0fa174fcd257c32c11dcf88bf4c1953a90878fc35`.

Conclusion: typed machine-register connectors are sound and composable, but a
40-template cross product serving five static sites is the wrong granularity. Task 158
should obtain register residence from a generated whole-region allocation/selection
plan, where one connector vocabulary covers many expressions and CFG edges, instead of
adding a manually enumerated template family for each expression shape.
