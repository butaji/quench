what is quench ↓

A TypeScript, JavaScript and WebAssembly runtime with AOT compilation, written in Rust.

Quench runs your code through an interpreter, two JIT tiers, or compiles it ahead of time into a native binary. All of them come from one definition of what JavaScript means, so they agree with each other.

Why Quench

A JavaScript VM designed from first principles: one definition of the language, with every faster tier derived from it. Measured numbers are dated; targets are marked as targets.

A modern VM

The interpreter is the only definition of JavaScript, TypeScript and WebAssembly semantics. The b-jit is that interpreter partially evaluated on your bytecode; the u-jit and AOT specialize it further on proven facts. Tiers cannot disagree, and a faster operation is faster in every tier at once.

TypeScript types, natively

Quench runs .ts files directly and never erases the types. A declared type, or a JSDoc annotation in plain JavaScript, becomes a fact that is checked once where a value enters and then trusted by every tier, instead of re-checked on every operation.

Fast and small

With the JIT off, Quench scores 1.42x the best of Node and Bun on V8 v7 at 0.45x the memory (25 November 2026). With the JITs on, the target is the same: 1.5x the score at 0.5x the memory of Node and Bun. Today the JIT tiers are far from it (0.10x the score at 0.53x the memory), and closing that gap is the current work.

AOT to a native binary

Strict AOT runs your program at build time up to its first real input and ships only what is left. Hello world compiles to a 4,896-byte executable that starts in 0.96 ms. Larger programs still carry much of the runtime (63.2 MB for a static executable today); the target for every program is under 1 MB and 1 ms to start.

How Quench AOT works →

Native hot module replacement

quench --hmr app.ts watches the files your program loaded and swaps an edited module in place, keeping process state, when the module or its importers accept the update through import.meta.hot or module.hot. Edits nobody accepted restart the process with the same arguments. Built into the runtime: no bundler, no dev server, TypeScript included.

Built for agent Code Mode

Agents increasingly write code and run it inside the harness instead of chaining tool calls one by one, often hundreds of agents to a machine, each running code nobody reviewed. That needs a JavaScript engine that lives in the harness, stays small, runs without a JIT and runs whatever the model wrote. Quench is built for that slot.

The QuickJS slot, faster

Today it is QuickJS for small scripts or V8 for heavy ones. Quench aims at QuickJS's place (small, embedded, interpreter only) with an interpreter well ahead of V8's and JavaScriptCore's: with the JIT off it scored 1.49x to 2.57x the best of Node and Bun on V8-v7 (14 November 2026), and five of eight benchmarks peak at 6.4 to 8.2 MB against 43 to 50 MB for Node and 16 to 26 MB for Bun.

Not yet measured against QuickJS. That comparison is next, published either way.

Embeddable, Rust-native

quench-runtime is a Rust library. The harness creates a Runtime with its own Host, exposes its tools as host functions, and can stop runaway code from another thread with an execution interrupt. Generated code runs in the harness's process: no subprocess, no IPC.

Not on crates.io yet, and the API will still change.

No JIT required

--no-jit, also the library's default, runs the interpreter only, WebAssembly included. No machine code is generated while untrusted code runs, so JIT compiler bugs are off the attack surface and an attacker has far less control over the code that executes, which Spectre-style attacks rely on. The numbers above are with the JIT off.

Not a sandbox on its own: isolation and limits come from your host.

Full JavaScript and TypeScript

Test262: 53,353 passing, 0 failing. TypeScript runs directly with no build step, and node: APIs are there too. Code a model writes just runs, with no "Lua needs a C extension for that" step, and models write JavaScript and TypeScript far better than Lua.

How it runs code

  • Interpreter. Register bytecode, one 64-bit word per value.
  • b-jit. Copy-and-patch: prebuilt machine-code stencils, stitched together fast.
  • u-jit. An optimizing tier that generates code with Cranelift.
  • AOT. The whole program compiled to a native executable before it runs.

How it is built

  • One semantics. Each tier is the interpreter specialized to what is known (Futamura projections).
  • Check once. A fact about a value is proved once, then trusted.
  • Types are kept. TypeScript types are not erased. They feed the specializer, so typed code can start out specialized.
  • Measured against C. Instruction budgets for every operation, with the equivalent C as the reference.
  • Conformance. test262 runs in interpreter and JIT modes before changes merge.

Where it is going

  • Interpreter: 1.5x the score of the best of Node and Bun with JIT off, at half their memory.
  • With the JITs on: 1.5x the score of Node and Bun at half their memory.
  • Native tiers: interpreter < b-jit < u-jit by construction, with every operation in u-jit at most 3x the equivalent C plus 6 instructions.
  • AOT and startup: executables under 1 MB that start in 1 ms; 1 ms-class startup for the interpreter and JITs too.

Questions

What is Quench?

Quench is a runtime for TypeScript, JavaScript and WebAssembly, written in Rust. It implements JavaScript semantics and Node-compatible APIs, and runs code through an interpreter, two JIT tiers, or ahead-of-time compilation to a native binary.

Does Quench run TypeScript?

Yes, and it does not throw the types away. Quench parses TypeScript natively and keeps the type information, so the engine can use it: a declared type lets the compiler pick specialized code up front, checked once where a value enters, instead of waiting to observe types at run time. Using types for speed this way is the design and is being built out now.

Does Quench have hot module replacement?

Yes. Run with --hmr and Quench watches the modules your program loaded. An edited module is replaced in place when it or its importers accept the update through import.meta.hot or module.hot (accept, dispose, decline, invalidate); otherwise the process restarts with the same arguments. It works for TypeScript and JavaScript, CommonJS and ES modules, with no bundler or dev server.

Does Quench support WebAssembly?

Yes. WebAssembly modules run through the standard WebAssembly JavaScript API, and the WebAssembly workloads in JetStream 3 are part of what Quench is measured on.

What does AOT compilation mean in Quench?

Quench can compile an entry file and the modules it imports into a single native executable ahead of time. The AOT compiler is derived from the interpreter by specialization, so a compiled program follows the same semantics as an interpreted one. In strict mode the build evaluates the program up to its first run-time input and keeps only what is left: hello world becomes a 4,896-byte executable that starts in 0.96 ms.

How does Quench compare to Node.js and Bun?

With JIT turned off in all three, on the 56 JetStream 3 tests that all of them finish (17 November 2026), Quench scores 34.3 against 39.7 for Node --jitless and 32.2 for Bun, and peaks at 28.5 MB of memory against 110.1 MB and 47.7 MB. On V8 v7 (25 November 2026) the interpreter scores 1.42x the best of Node --jitless and Bun at 0.45x their memory; with the JITs on, Quench is at 0.10x the score of Bun at 0.53x the memory, against a target of 1.5x at 0.5x.

Is Quench Test262 compliant?

Yes. Quench passes 53,353 Test262 tests with 0 failing, with the JIT off and on. 53 cases are waived because they fail exactly the way Node fails them, and they stay counted as failures in every report. The WebAssembly spec suite passes 67,124 of 67,124. Details.

Can Quench run code written by AI agents?

That is a use Quench is built for. It embeds in a Rust harness as a library, runs interpreter only with no JIT, and runs full JavaScript and TypeScript (Test262: 53,353 passing, 0 failing). With the JIT off it scores 1.49x to 2.57x the best of Node and Bun on V8-v7, peaking at 6.4 to 8.2 MB on five of eight benchmarks. Details.

Is Quench compatible with Node.js?

Quench implements Node-compatible APIs in a separate host crate and checks changed behavior against Node itself: values, errors, ordering and exit status. Compatibility is being built out, so expect gaps.

Is Quench ready for production?

Not yet. Quench is early, under heavy development, and has no packaged releases. You build it from source with Cargo.
