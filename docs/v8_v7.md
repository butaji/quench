# V8-v7 measurement

Run from the repository root with an explicitly identified uninstrumented binary:

```sh
cargo build --profile production -p quench-node
cargo run --release -p quench-bench -- --all --runs 5 --timeout-ms 300000 --quench target/production/quench-node --node node --bun bun --out target/v8-baseline.json
```

Save stdout to a new artifact path. The Rust runner accepts one fixture path or
`--all`, plus `--node`, `--bun`, `--quench`, `--runs` and `--timeout-ms`.
It emits one JSON object per fixture, including raw engine samples, status, score,
wall time and available process accounting. `--out` additionally writes a
schema-2 aggregate report containing Git dirty-state, SHA-256 source/artifact
manifests, per-fixture medians, 95% score uncertainty and a geometric aggregate
only when all eight fixtures are valid. The path is create-new: existing evidence
is never overwritten. On macOS external accounting can include peak RSS,
instructions and cycles. Unavailable values remain null.

The eight fixtures are Crypto, DeltaBlue, EarleyBoyer, NavierStokes, RayTrace,
RegExp, Richards and Splay. Each engine executes the same materialized suite
wrapper. Never alter iteration counts or validations to manufacture a score.

Operational defaults and host dependencies: the default timeout is 120 seconds;
the runner inherits environment variables and relies on the host `timeout`,
`/usr/bin/time` and `shasum` tools. These are measurement-protocol details, not
VM or compilation ceilings. Explicitly use clean scoring environments and follow
[artifact/comparison rules](performance-lanes.md). It refuses to run when
`QUENCH_EXEC_TRACE` is inherited; diagnostic counters belong in a separate
instrumented run.
A five-minute bound is a starting point, not a permanent workload execution limit.

`valid` requires successful scored runs; it does not establish full conformance.
`output_equal` includes engine-dependent scores and is not a semantic verdict.
Timeouts remain missing performance evidence. Retain partial results without
publishing them as a complete aggregate. The Rust runner stops repeating a
fixture after the first invalid engine round, records the partial samples, and
continues with the remaining fixtures; this bounds failure diagnosis without
turning an incomplete fixture into a valid result.

The existing Quench-only recorder is also available:

```sh
node tools/record-v8-evidence.cjs --binary target/production/quench-node --runs 5 --timeout-ms 300000 --out target/v8-new-attempt.json
```

Choose a new filename: this legacy tool does not prevent overwrites. Its raw
runner does not provide the Rust runner's external RSS accounting. The Rust
runner is the authoritative source for reproducible baseline reports; existing
scripts remain usable for focused Quench-only experiments.

For attribution, use a separate trace build and the micros `diagnose` command,
or `tools/instruction-category-ledger.mjs` with a properly wrapped standalone
script. Raw V8 fixture files and micros registration modules are not standalone
workloads. Counters do not measure CPU shares.
