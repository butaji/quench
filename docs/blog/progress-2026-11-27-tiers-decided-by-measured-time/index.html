Progress, 27 November 2026: tiers decided by measured time, one call row, AOT for ARM

Daily progress on Quench, the TypeScript, JavaScript and WebAssembly VM in Rust. 206 commits: tier-up now follows measured run time and backs off when a faster tier is slower, the hand-written call path is deleted in favour of one staged call row, interpreter operators check tags once, and AOT images lower for other CPUs including AArch64. New V8 v7 numbers, with the JIT gap shown as it is.

Third daily post: 206 commits on v2-merged between yesterday's post and 12:36 UTC today, the busiest day this week. Numbers are measured and name their commit; targets are labelled as targets.

A correction first

Yesterday's post said the tier-order gate started with 22 violations. The list has 26 entries: 9 on the C-parity kernels (crc, fib, qsort, structs and sum run slower in b-jit than in the interpreter; dot, nbody and structs slower in default mode than in b-jit) plus 17 on V8 v7. The post is fixed. The list did not change today; it can only shrink.

The theme: stop guessing which tier is faster

The tier-order problem has a simple root: the engine moved code up a tier because a counter said it was hot, not because the next tier was measured to be faster. Today that changed.

Tier decisions from measured time. Tier-up decisions now come from measured run times. A u-jit loop region that measures slower than its b-jit region goes back to b-jit. u-jit compiles are priced on the IR they produce and charged in full against the tier below. b-jit region compiles are priced from their measured time, and a warming function counts its entries in place instead of being re-priced every 16 entries. A function whose loops ran keeps its loop regions instead of being replaced by a slower whole-body compile.

One call row. The hand-written call path is deleted. Calls and returns now complete in one staged call row and one return rule. The row's only guard (callee and admission) is a single branch, and a polymorphic call site finds its callee's entry in the row. b-jit direct calls now take up to six arguments.

The interpreter checks once. Many interpreter operators now test value tags once and then run a proven instance: arithmetic and comparisons on int32 pairs, compare-and-jump, strict and loose equality (identical words are settled before any tag test), truthiness, typeof and nullish tests. this is checked once per activation. A polymorphic property read keeps up to four prototype arms.

Typed arrays and BigInt. Every typed-array kind has its own interpreter element row, and the kind-dispatch row is gone. One typed-view proof per array is kept across copies, loops and calls. Float kinds read straight into float registers. Small BigInt add, subtract and multiply run in 128-bit integers, and BigInt.asIntN, asUintN and BigInt(n) answer in place.

Collections and arrays in the u-jit. Map, Set and WeakMap get and has run as one typed lookup. Array.prototype.at runs inline on a proven array. new Array(n) is built in place.

AOT. Images lower for --target and --target-cpu, and AArch64 call relocations patch through the same code as x86-64. Image bodies call each other by their entries. An image body is now the first rung of the tier ladder: if it keeps paying for leaving, the JIT respecializes it. Image field stores keep each field as the one class the program writes.

Build. The engine compiles one codegen unit per module, and the stencil build no longer reserves 10 GB per parallel job. Incremental builds stay under five minutes; that rule exists because a slow build is a bug.

Reverts. A change to lane environment slots was reverted because it broke V8 earley-boyer, and a comparison-jump change was reverted the same evening. Regressions are fixed forward or rolled back, never kept.

The interpreter's score rose from 2,986 to 3,467 since 25 November and memory dropped to 0.41x of Bun's. Four of eight benchmarks are at or above the 1.5x target; earley-boyer and deltablue are the weak ones.

With the JITs on, Quench is still far from the target of 1.5x the score of Node and Bun at half their memory: 0.08x the score today. The JIT modes now use a third to a quarter of Bun's memory, but default mode scores below the interpreter. That is the tier-order list in benchmark form, and today's measured-time tier decisions are aimed straight at it.

Startup, from the gate at the same commit: printing "hi" takes about 9.2 ms wall time in every mode (11.4 ms on 25 November). The AOT image for hello world is 16.5 KB and its executable starts in about 10 ms. Strict AOT still compiles hello world to 4,896 bytes starting in 0.96 ms. The target for every program is an executable under 1 MB starting in 1 ms.
