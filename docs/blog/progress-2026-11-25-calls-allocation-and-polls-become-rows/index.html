Progress, 25 November 2026: calls, allocation and polls become rows; AOT images drop the compiler

Daily progress on Quench, the TypeScript, JavaScript and WebAssembly VM in Rust. 159 commits: compiled calls, allocation, write barriers and interrupt polls are now staged rows shared by every tier, every row declares a C twin with a checked 3x C + 6 bound, and static AOT images ship without a parser or compiler. Plus today's measured V8 v7 numbers in all three modes.

This is the first of a daily series. Each post covers one day of work on the shared v2-merged branch: what landed, what it is for, and the numbers measured that day. Targets are labelled as targets. Everything else was measured.

The idea in one paragraph

Quench has one definition of JavaScript, TypeScript and WebAssembly semantics: its interpreter. Each operation is a staged row. The interpreter runs the row directly. The b-jit is the same row partially evaluated on bytecode, with dispatch and decode folded away. The u-jit and AOT specialize it further on proven facts (types, shapes, ranges). The point of building it this way is that the tiers cannot disagree, an improvement to a row lands in every tier at once, and the speed ordering interpreter < b-jit < u-jit holds by construction. Today's work was mostly about moving the last pieces of the runtime into that shape.

Calls are rows. Every target a compiled function can call is now a typed CallTarget, and every leaf call names a typed slow path instead of an untyped helper address. The b-jit and the u-jit push and pop native frames through one staged step. Direct calls between compiled functions rebind when a new closure of the same function appears, and a dead callee retires its code even when no record names it. Direct compiled-to-compiled calls are what the interpreter's share of an AOT binary is waiting on.

The runtime is rows too. Bump allocation is one staged row for the heap and the u-jit. The write barrier is one row for every tier, which also fixed a store gate the u-jit had inverted. Interrupt polls are staged rows. The only way out of compiled code is now one typed edge: each exit site names the fact it was missing and counts how often it is crossed, so a fallback is a measured, budgeted event instead of a hidden one.

Every row has a C twin. Each staged row now declares the C kernel it should cost about the same as; 64 rows moved from "no twin" to a real kernel and 11 new C kernels were written. The rule "u-jit costs at most 3x C + 6 instructions" is now a checked section of the instruction budget that can only shrink, fed by a static per-row instruction predictor. A tier homomorphism test runs each Number row through every stage and checks that they agree.

Facts as typed proofs. The issues for facts as typed proofs (checked once, invalidated at tracked mutations) and for private internals (tiers reach values and the heap only through the stage interface) were closed. AOT stopped computing its own facts: it now uses the same lattice, block leaders and fixpoint driver as the JITs.

AOT images. A static AOT executable no longer contains the parser, the bytecode compiler or the run-time compiler, and it links only the helpers its image names. RegExp literals and WebAssembly modules go through the same image driver as JavaScript. Strict AOT now runs the program at build time up to its first dynamic input, saves the runtime there, and resumes from that snapshot when the binary starts; a strict compile that meets a dynamic input links full support instead of failing.

Data-structure suite. A harness for nine classic structures (B-tree, linked list, hash map, binary heap, radix tree, red-black tree, R-tree, skip list, union-find) landed, measured against C, Node and Bun.

The interpreter is close to the goal of 1.5x the score at 0.5x the memory and already under the memory half. With the JITs on, Quench is far behind: the compiled tiers barely beat the interpreter today, which is exactly the tier-order problem the work above attacks at the root. The JIT-on target is the same 1.5x score at 0.5x memory against Node and Bun; it is a target, not a result.

Startup, measured by the gate at the same commit: an empty script runs in 12.0 million instructions and 3.9 MB peak RSS without the JIT; console.log("hi") peaks at 4.8 MB and takes about 11 ms wall time. The AOT image for hello world is 16 KB, but the executable around it is still large and starts in about 12 ms. The targets are an AOT executable under 1 MB starting in 1 ms, and 1 ms-class startup for the interpreter and JIT too.

Next

Direct compiled-to-compiled calls finish stage 1 of the call layer and unblock cutting the interpreter out of AOT binaries. The tier-order gate (interpreter < b-jit < u-jit on every row, primitive and benchmark) becomes a hard, shrink-only check. The data-structure suite gets its first full sweep in all three modes.
