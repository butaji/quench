Compile JavaScript to a native executable

Quench's AOT compiler turns a JavaScript or TypeScript program into machine code, not a bundled script.

Quench compiles a JavaScript or TypeScript entry file and its imports ahead of time into one native executable: quench --build-aot app.ts -o app. The program is lowered to machine code with the same meaning as Quench's interpreter; the full interpreter and JITs are left out unless the program uses eval or new Function. AOT is experimental. With quench compile --strict-aot, a program that reads no run-time input compiles to an image with no engine at all: hello world is a 4,896-byte executable that starts in 0.96 ms with 1.3 MB peak memory, level with C (14 KB, 0.89 ms, 1.36 MB). Compute speed of AOT code is not published yet.

Usage

cargo build --release -p quench --features aot
./target/release/quench --build-aot app.ts -o app
./app

# strict mode: evaluate at build time, keep only what depends on run time
./target/release/quench compile --strict-aot hello.js -o hello

Strict AOT: build-time evaluation that stays sound

Strict mode runs the entry at build time until it reads its first dynamic input (arguments, environment, files, the clock, standard input). Everything before that point is the same in every run, so the image keeps only its effects. Host operations outside a short allow-list are refused before they run, and the compile report names the input it could not fold, then links the full image instead. Small yes-or-no inputs, such as whether stdout is a terminal, become guarded variants chosen at start-up.

One semantics

Each opcode's meaning is written once. The interpreter runs it directly, the JITs and the AOT compiler emit it as machine code. That is the interpreter specialized to what is known about the program (a Futamura projection), so an AOT-compiled program and an interpreted one agree. Background: AOT without a second compiler.

Limits today

  • Built and tested on Linux, from a source build with --features aot.
  • Startup and size published only for programs with no run-time input; no compute speed numbers yet. The target is AOT code within 2x of Node and Bun.
  • Programs that read input (arguments, stdin) fall back to a full image of about 71 MB today.
  • Node API compatibility is still being built out.

Questions

How do I compile JavaScript or TypeScript to a native executable?

With Quench built with the aot feature, run quench --build-aot app.ts -o app, then ./app. The entry file and the modules it imports are compiled ahead of time into one native executable.

Is the Quench AOT compiler faster than Node?

Compute speed of AOT code is not published yet. Startup is: with quench compile --strict-aot, a program that reads no run-time input compiles to a 4,896-byte hello world that starts in 0.96 ms, against 27.5 ms for Node running the script. Programs that read input still use a full image that starts in about 5 to 6 ms.

Does an AOT-compiled Quench program include an interpreter?

The full interpreter and the JIT tiers are left out of the executable unless the program uses eval or new Function, which need to compile code at run time.

About Quench

Quench is a JavaScript, TypeScript and WebAssembly runtime written in Rust. Test262: 53,353 passing, 0 failing. Interpreter, two JITs, and AOT to native executables. It is MIT licensed, early, and built from source with Cargo. Source: github.com/butaji/quench. Machine-readable summary: llms.txt.
